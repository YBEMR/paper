# HPCA 2017能耗MPC：结构、参数与最小验证

日期：2026-09-21。承接F-DTM参考文献[47]。结论：**有可复用的基线结构，尚无可升级的新选题；停止沿这条引文链无限追加论文。** 本轮不扩展实验代码。

来源：Majumdar等，*Dynamic GPGPU Power Management Using Adaptive Model Predictive Control*，HPCA 2017，pp.613–624，DOI 10.1109/HPCA.2017.34。[作者原文](https://www.csl.cornell.edu/~albonesi/research/papers/hpca17.pdf)、[本地PDF](../papers/2017_Majumdar_Adaptive_MPC.pdf)、[共同作者论文页](https://computermachines.org/joe/publications/hpca2017_gpgpu_mpc.html)。下文以PDF物理页定位。

## 1. 先修正一个容易误解的关系

**搜索顺序不等于任务执行顺序。** §IV-A1、Fig.7（p.5–6）将未来内核按累计吞吐是否达标分组，再决定先给哪个内核选配置。例子中的搜索顺序为3、2、1、6、5、4，实际内核仍按1到6执行。不能据此说算法让未来任务提前运行，也不能把它当成多请求CPU–NPU联合排序。

原模型的CPU主要承担主机工作，在GPU内核运行期间通常忙等；决策是CPU/NB/GPU频率与GPU活动CU数，不是任意CPU核或NPU的任务映射。§II-A还明确GPU与NB共享电压、频率可独立设置；不能假设每资源电压独立。

## 2. 模型与降复杂度手段

| 内容 | 正文定位及事实 | 边界 |
|---|---|---|
| 目标 | §III式(1)，p.4：最小化全部内核能耗之和，累计指令吞吐至少达到Turbo Core参考值 | 不是每请求硬截止期，也没有在这些优化式中显式递推温度上限 |
| 输入 | 各内核配置下E_i(s)、T_i(s)、指令量I_i及参考总时间/指令量 | 固定工作量，不含精度/早退选择；执行时间和能耗由预测器提供 |
| 滚动窗口 | §IV-A1式(3)，p.5：优化未来H个内核，只执行当前配置，随后滚动和反馈 | 不保证全局最优，性能裕量来自已执行历史 |
| 跨内核搜索 | §IV-A1，p.5–6：按吞吐分组排序，配置优化后不回溯 | 降低成本的启发式，不是证明问题可精确多项式求解 |
| 单内核配置搜索 | p.6：按能耗敏感度排列控制项，逐项爬山，能耗上升即停止 | 会牺牲最优性；相互作用或非单峰曲线可能影响结果，实际损失仍需数据 |
| 窗口自适应 | §IV-A4，p.7：按历史执行和优化开销调H，实验取α=5% | 估计性的性能控制，不是硬实时保证；srad实测预测误差导致15.7%性能损失 |

作者给出的搜索成本从指数枚举降到按N、H及各控制项档数之和增长；19倍配置评价缩减和65倍综合搜索成本缩减是原文报告，不是本轮复测。

温度在平台背景、CPU漏电影响和Turbo Core基线中出现；**不能说系统完全不受温度影响**。准确差异是：已核对的式(1)–(5)及预测器说明未把未来温度状态作为优化状态和逐时热约束。扩展状态表达在数学上可行，但不构成新颖性证明，F-DTM本身已提供热预测近邻。

## 4. 哪个结构真正可以利用

以下为本轮基于式(1)/(3)的推导，**不是原文提出的新算法**。

设固定内核序列、固定工作量，I_i不随配置改变，配置能耗和时间仅依赖当前内核及所选配置。式(1)化为：

```text
min Σ_i E_i(s_i)
s.t. Σ_i T_i(s_i) ≤ D
s_i ∈ S_i
D = T_total * (Σ_i I_i) / I_total
```

同一工作量且ΣI_i=I_total时，D=T_total。窗口问题则先扣除已执行时间，再用窗口结束处的累计指令目标计算剩余预算。**不能把原文的所有前缀条件无条件简化成一个全局期限**；若选择比较式(2)或逐步性能约束，须逐前缀检查。

这是每组选择一个配置的离散资源分配/多选背包类结构。可以直接建立强基线：

1. 在原有静态E/T表下，删除同一内核中时间不更短且能耗不更低的配置。
2. 逐内核扩展累计(time,energy)标签，删除同时更慢且更耗能的标签；必要时检查各前缀预算。
3. 取满足预算的最低能耗标签，小实例以独立枚举验证。

标签法最坏仍可能指数增长；时间离散化DP是关于时间预算的伪多项式方法，离散化精度改变最优性口径。**不能把“写得出DP”当新贡献，也不能仅因指数最坏情形就否定它在当前规模中的价值。**

加入热状态后，原先只比较(time,energy)可能不够：两条前缀即使累计时间/能耗相同，末端CPU/NPU温度也可能不同，后续可行配置随之改变。但这只说明要补状态。最小办法是按真实执行顺序重放热模型、保留必要温度状态，或在候选中作局部修复；不必先引入新的任务排列变量。

特别注意：静态E/T上被支配的配置可能有更有利的热轨迹，加入热约束后不能继续无条件删除。温度向量支配也必须明确比较时刻、等待功率、到达约束、模式切换及温度相关能耗，不能只凭“当前更冷”给出一般剪枝定理。

## 5. 原文的剩余差距支持到什么程度

§VI-C、Fig.12（p.10）在完美预测、不计MPC开销、全窗口条件下，与穷举参照比较，报告达到最大理论**节能量的92%**。这不是“能耗距最优8%”，也不是每个实例保证。比如仅作代数说明：参考能耗100 J、最优节能25 J，获得92%的节能量对应77 J而非75 J，能耗相对差约2.67%；该例不是论文数据。

原文明确将部分差距归因于由PPK采样确定的搜索顺序。由此可测试多种搜索顺序、坐标回访、全配置枚举或标签法；**尚无证据这些简单改动之后仍存在值得设计新算法的困难**。

§VI-E（p.10）自适应窗口平均性能开销0.3%、平均能耗开销0.15%；这是原测试的低开销证据，不能沿用F-DTM的高开销结论认定这里也需要加速。§VI-E后半（p.11）还表明：忽略开销时，全窗口相较自适应窗口仅再减少2.6%能耗；计入开销后，全窗口效果更差。扩大窗口不是无代价强基线。

## 6. 最小验证设计与停止条件

不启动CPU–NPU新实验。若随后要检验这条求解线，第一关只能是**固定模型下，简单强基线是否已经足够**：

| 项目 | 预先限定 |
|---|---|
| 数据 | 优先同一公开平台的配置表；未取得时可用注明合成属性的表做算法正确性检查，不报告设备收益 |
| 实例 | 固定执行顺序，先4/8个内核、每个2/4个合法配置；不同时加入温度、争用和到达不确定性 |
| 共同模型 | 同一能耗/时间表、相同全局或前缀约束；固定H；不混入预测误差或不同信息量 |
| 对照 | 独立枚举、标签法、完整配置查表下的单次贪心、少量多起点/局部回访；原论文方法需把两层近似拆开评估 |
| 指标 | 可行率、能耗差、评价次数、运行时间与前沿规模；耗时明确MATLAB/主机环境，不能代替AMD在线成本 |
| 淘汰 | 简单方法已达精确解或预算内误差可接受，则结束求解候选；无规模成本证据不扩大算法复杂度 |

只有该关出现稳定、可解释的剩余困难，且能建立CPU–NPU与热/能耗的实质关系，才设计下一关热状态实验。温度状态增加本身不是必须做第二关的理由。新增温度后的收益与改求解方法的收益必须分开。

**本轮推荐：保留上述基线构造方式，暂不保留新主线候选；不再自动追下一篇引用。** 无硬件并非否决原因；缺的是“当前模型中具体问题尚未被合理简单方法处理”的证据。旧等待、粒度和跨场景方向状态不变。
