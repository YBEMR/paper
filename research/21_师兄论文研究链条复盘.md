# 师兄论文研究链条复盘

日期：2026-09-22。范围：重新分析研究组织方式，不为其全部创新性、模型正确性或实验可复现性背书；不启动新实验。

来源：[《面向端侧深度学习推理的高能效异构多核任务调度算法研究》](../main.pdf)。下文页码为论文印刷页，PDF物理页需加12。

## 1. 核心判断

论文把任务图、异构处理器、离散调频、多场景和能耗优化组织成一个有明确共享决策的联合问题，再针对约束展开成本和规模增长设计两种求解方式。它的研究链条不依赖每个组成部分都是全新机制。

最值得借鉴的结构是：**明确哪些决策相互制约 → 用统一模型表达 → 根据模型结构组织已有方法 → 比较解质量、可行性和计算成本。** 这与“先证明所有简单方法都失败，才能开始研究”不同。

## 2. 问题：共享部署与场景内需求之间的取舍

§3.2、§3.4–3.5，印刷19–28页：应用抽象为Stage级DAG，不同场景包含不同活跃应用组合；任务具有可执行处理器集合和截止期，系统考虑CPU、GPU、NPU。

关键约束在§3.5.1、印刷25页：同一个Stage在所有场景中共享处理器映射；处理器频率和任务执行时序可以随场景变化。映射变量没有场景下标，频率与时序变量有场景下标，见式(3-23)–(3-25)。

用于解释的例子（不是论文实测案例）：某Stage在轻载场景放到NPU较省能耗，但在多个应用同时活跃时，同样的映射可能加重NPU排队。因为不能为每个场景各选一套部署，映射需要兼顾多个场景，而频率和时序负责场景内调整。

这是一项建模选择及其引出的优化问题；本次未独立证明共享映射在所有实际平台上都是必要限制，也不声称这一关系由该论文首次提出。

## 3. 模型：把共享与局部决策分清

§3.3–3.5：选择共享映射x、各场景频率z和开始/结束时刻S、F；约束包含映射资格、DAG依赖、截止期和处理器执行容量。目标是按场景概率或驻留份额加权的期望能耗，包含评价时域内的空闲与执行能耗。

§4.3、印刷45页、式(4-4)–(4-5)进一步写为：

\[
\min_x\sum_s\pi_s\phi_s(x),\qquad
\phi_s(x)=\min_{z_s,S_s,F_s}E_s(x,z_s,S_s,F_s).
\]

这提供了明确的方法入口：映射是跨场景共享决策；固定映射后，各场景可以分别优化。模型的价值在于把这种结构表达出来，而非变量越多越好。

## 4. 方法：两章解决同一问题的两个层次

### 第三章：减少精确建模时一次展开的约束

§3.6、印刷29–33页、图3-3及算法3-1：处理器容量通过时间窗口约束表达，全部展开会带来大量辅助变量和线性化约束。LCG-MILP先求解只含当前约束的主问题，检查候选解中的违例窗口，再加入对应约束，重复求解。

这里的对应关系是“窗口约束很多 → 按违例增补”。MILP、频点预处理和延迟约束生成是可借用的方法组件，研究工作在于具体建模、违例识别及其适配。本次只复盘其设计意图，未独立核验分离过程完备性、全局最优证书或代码。

### 第四章：利用共享/局部结构降低规模成本

§4.3–4.4、印刷45–56页：DHA沿用第三章问题，通过三个步骤求近似解：

1. **初始共享映射。** 最高频率预调度得到局部时间/能耗代价，用场景权重、期限紧迫程度和相对最佳选择的代价构造评分。
2. **超时修复。** 尝试Stage重新分配，权衡超时场景的改善与其他场景增加的代价。修改的是搜索中的共享映射，不是允许上线后各场景任意迁移。
3. **场景内降频。** 固定共享映射后，逐档试降处理器频率，重建列表调度，保留满足期限且节能的动作。

分解、加权评分、局部修复和贪心降频本身都不需要被包装成全新算法原理。具体工作在于：让这些步骤遵守同一组共享约束，定义跨场景的收益/损害，并控制搜索成本。其修复可能失败，也不保证总能达到精确最优。

## 5. 验证：检验完整方法的取舍

§3.7、§4.5：比较LCG-MILP、DHA、EA-HEFT、EA-GA和Mapping-Only，评价能耗、可行性及求解时间。改变任务规模、场景/资源组合和截止期松紧；小规模对照精确方法，较大规模考察求解开销。第四章表4-3给出随机实例、离散频点及重复统计设置。

图4-9（印刷64页）报告精确方法随规模增长更快的求解时间，采用左右不同纵轴；这里不把图中数值当作独立复现结果。正文也承认DHA在部分条件下牺牲可调度性以换取计算效率，不要求它在所有指标、所有实例上获胜。

可借鉴但需改进的地方：已有实验不是三个步骤的完整组件消融；各算法仅在自身可行实例上统计能耗时，样本集合可能不同。我们应补共同可行集合的配对比较，并单独报告失败率。本次未核验原始实验数据、求解超时与最优性证书。

§5.2、印刷67页明确主要采用仿真，真实平台验证仍待开展，热约束等实际因素描述简化。这说明抽象模型研究可以形成完整链条；不意味着任意合成参数足以支持实际平台节能结论。

## 6. 对我们推进方式的修正

- **最小验证准入与论文贡献成立分开。** 有清楚问题、合理假设、可计算模型和公平基线，就可以开展小验证；无需在实验前证明复杂方法必不可少。
- **允许方法结合与适配成为贡献来源。** 说明每个模块解决什么、交换什么状态、共享约束如何保持，以及结合后新增的处理即可进入评估，最终价值由对照结果判断。
- **简单方法是基线，也是可能的最终方法。** 若简单组合已解决目标问题，就缩小贡献主张；不能只因组件简单就提前否定，也不能在同条件下已被简单基线追平后仍主张复杂算法收益。
- **参数可以是有解释的抽象设定。** 要标明来源、量纲、范围和敏感性，不能把异平台数据拼成真实标定，不能通过单点调参制造优势。
- **借鉴衔接方式，不照搬章节数量。** 不强制先MILP再启发式；也不因师兄模型没有温度，就认定加温度即可立题。

因此，后续应先形成一个能够比较的CPU–NPU热能效问题和直接组合基线，再通过小实例与规模实验决定是否需要协调改进。此前已完成实验的负面结论保留，旧方向不自动恢复；本轮没有确定新选题。
