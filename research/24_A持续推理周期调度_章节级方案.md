# A：持续推理周期调度——章节级方案

日期：2026-09-22。性质：论文构思与工作分解，未确定最终选题，未运行实验。按用户要求，先评价研究链条与工作量，不用既有小实例提前否决；下列方法是待实现方案，性质是待证明命题，不是已取得创新或收益。

**建议工作题名：面向持续推理的多核CPU–NPU温度感知周期调度与能耗优化。**

一句话主张：在输入持续到达、温度跨周期累积的条件下，联合安排执行配置与重复调度节奏，使系统按指定速率、期限和温度限制长期运行，并降低单位请求能耗。

## 1. 这篇论文怎样讲通

持续视觉处理等应用反复执行相同或少数几类计算图。CPU和NPU形成流水处理，不同请求可以占用不同资源。单个请求完成得快，不等于重复执行时能保持规定服务速率；平均功率相同，也不意味着不同重叠时序具有相同峰温。

因此，问题从“一批任务怎样完成”变为“怎样选择一套可以反复执行的低能耗配置和时间安排”。CPU配置影响阶段耗时与功率，耗时改变NPU前后的等待与跨请求重叠，重叠又影响温度和可用配置。CPU、NPU、温度和能耗由同一份调度连接。

**两章递进：第三章回答什么方案持续可行、怎样求小规模优解；第四章利用周期重复结构，在更大任务图上更快地寻找好方案。** 不是给第三章额外加一个无关因素，也不要求第四章必须改成在线问题。

固定执行配置、各状态功率及工作量后，单改相位可能完全不改变能耗。合理的节能路径是：调节重叠与等待，使另一组能耗较低的配置满足热与期限约束。该路径是否有收益留给后续验证，不能预设“错峰必然省电”。

## 2. 模型先固定到可写、可实现的范围

| 项目 | 基础方案 | 暂不默认加入 |
|---|---|---|
| 平台 | 抽象的多核CPU和一个NPU；明确CPU共享调频域 | 多NPU、任意核独立调频、专用固件控制 |
| 工作负载 | 预先合法划分的阶段DAG；周期释放；每请求有相对截止期 | 任意算子切分、精度变化、丢弃请求 |
| 执行动作 | 合法映射、CPU域配置、阶段次序与周期内启动偏移 | NPU执行中抢占或迁移 |
| 配置粒度 | 每套重复方案采用固定的CPU域频率；NPU先固定频率 | 跨周期边界任意改频影响尚未完成阶段 |
| 时间模型 | 给定配置下确定的阶段时长，转换开销按已声明模型计入 | 未标定的温度—时延反馈、并发争用模型 |
| 热模型 | 稳定、正性的线性多节点RC，连接CPU与NPU温度 | 无来源的复杂漏电或非线性参数 |
| 目标 | 固定服务速率、工作量与约束下最小化J/请求 | 用吞吐下降、提前结束计量获得低能耗 |

以上是本论文拟采用的抽象范围，不代表现有设备全部支持。若NPU阶段只能在NPU运行，保留CPU阶段的核映射、共享频率和时序决策即可；不强求所有阶段都能CPU/NPU二选一。基础版本将阶段视为不可抢占单元，CPU侧也采用调度抽象，不声称操作系统天然如此。

请求类别a的周期为P_a，释放偏移由输入给定，不是可随意调整的决策；优先采用相同或谐波周期，共同重复长度H内含固定数量N_H个请求。启动偏移允许形成跨周期流水线。资源冲突、依赖和截止期必须检查相邻周期副本，不能为了方便强制所有阶段都在H边界前结束而不声明限制。

温升向量θ=T−T_amb，基本状态方程拟用：

\[
\dot\theta=A\theta+Bp(t),\qquad
\theta(t+\Delta)=e^{A\Delta}\theta(t)+\int_0^\Delta e^{A(\Delta-u)}Bp(t+u)\,du.
\]

温度单位°C，时间统一用s，功率W，能耗J。分段恒功率调度在一个周期上诱导θ(H)=Mθ(0)+b。若ρ(M)<1，周期固定点为θ*=(I−M)^{-1}b。这是标准线性系统推导工具，不能单独称为创新。

评价需包含：①周期固定点下的完整峰温；②从声明的初始状态到重复运行的启动过程；③跨周期任务与资源状态。耦合RC可能出现区间内部温峰，仅查事件端点不够。拟采用分段响应求峰或有误差界的细化检查；如果最终只做采样，就只报告采样可行。

目标为E_H/N_H，其中E_H=∫_0^H P_system(t)dt，包括声明的活动、空闲与转换功率，不能重复累计共享部件。预热能耗另报，或在所有方法相同的有限服务时域内统一计入。

## 3. 第三章：持续热约束下的周期联合优化

| 节 | 具体内容 | 应交付的东西 |
|---|---|---|
| 3.1 | 持续输入场景、CPU–NPU依赖、单请求与持续服务的区别 | 一个解释性时序图；不预填收益数字 |
| 3.2 | 任务副本、合法映射、配置、启动偏移、资源与截止期 | 完整符号表和可直接实现的约束 |
| 3.3 | 周期热状态、周期内峰值、启动可行性、能耗时域 | 周期评价器与适用条件；固定点推导 |
| 3.4 | 联合优化与小规模求解 | 有限配置/时间网格上的精确参照，或通用求解器模型 |
| 3.5 | 模型行为分析与对照设计 | 固定配置只改时序、配置随时序调整等分开比较 |
| 3.6 | 本章实验与讨论 | 可行性、能耗、解界和计算耗时；当前仅规划 |

第三章不只有“列模型”。需要把连续热轨迹与有限调度选择连接，处理周期边界，明确可行性检查，并产出小规模参考解。参考求解可以采用配置枚举结合离散时序搜索，或固定网格的MILP/约束规划；最终依据表达规模选用，不预定新算法名。

**最优性必须限定搜索空间。** 网格最优不等于连续时间全局最优；数值温度检查也不自动等于连续热安全证明。通用求解器超时应报告上下界和可行解，不能记为不可行。

拟分析三个性质：给定重复功率下周期热状态的唯一性；初温上界与启动温度上界的关系；固定配置时相位改变能耗的条件。后两项用来明确算法何时应该搜索配置、何时仅做可行性修复，允许得出某些情形无需复杂搜索。

## 4. 第四章：利用周期结构的快速配置与时序搜索

核心分工：外层提出映射和CPU域配置，内层寻找满足资源、期限和热限制的重复时序。改变配置后时长、占用与热响应一起变化，不能把两个模块各自的局部优解直接拼接。

拟议步骤：

1. 按依赖关键路径和各资源负载产生多种初始配置、列表顺序及偏移方案。
2. 用时间窗、周期容量等必要条件筛掉确定不可行的候选；安全下界与启发式截断分开登记。
3. 固定配置，修复资源冲突和截止期，评价跨周期热轨迹；围绕温度紧张区间调整可移动阶段及其相关阶段。
4. 比较更低能耗配置、CPU核映射变化、NPU前后次序变化；每次变动重新检查依赖、共享域和受影响的热状态。
5. 缓存相同配置的时长/功率表和周期热响应；用增量更新减少重复评价，但热传播覆盖所有耦合节点，不能只更新DAG后继。
6. 在统一计算预算内保留最佳完整可行方案；多起点和局部邻域提供搜索范围，不宣称全局最优。

| 节 | 方法任务 | 为什么不是只换算法名字 |
|---|---|---|
| 4.1 | 分析配置与时序两层结构及重复计算 | 解释哪些量可复用、哪些必须重算 |
| 4.2 | 周期可行初解与必要条件筛查 | 指向跨周期占用与期限限制 |
| 4.3 | 面向热紧张区间的时序修复 | 同时处理热耦合与前后阶段传播 |
| 4.4 | 配置邻域、热响应复用与停止规则 | 给出输入输出、伪代码和成本分析 |
| 4.5 | 质量—耗时对照和组件消融 | 分别验证筛查、修复和复用的作用 |

这一章的工作量来自数据结构、可行性维护、搜索邻域与计算复用，不来自多加约束。若最终发现通用方法已经足够快，仍可报告适用规模，不需要捏造瓶颈。负载突变后的在线重构只列展望，暂不并入B线。

## 5. 验证设计：以后怎样支撑两章

先固定同一任务、服务速率、期限、初温、参数和评价器，再比较：通用小规模求解；负载均衡/能耗列表调度加完整热修复；多起点局部搜索及主动等待；本章利用周期结构的方法。强基线也允许等待、配置搜索和相同温度信息，不能只打败“忽略温度”的方案。

第三章验证模型关系：一次窗口与持续运行的区别；相同平均功率不同功率时序的峰温；配置固定与可调整时的能耗差异；冷启动、高初温与周期状态的区别。这些是待观察结果，不预设全部出现差异。

第四章固定模型，比较能耗、可行解比例、相对已证下界的差距和运行时间。改变图规模、规定输入速率、截止期及热耦合范围；记录热约束不活跃时的无收益条件。超过期限或未处理完整工作量的方案不参与“节能率”计算。

现实参数可得性与算法结构分开：S1提供CPU–GPU流水线组织依据，不能充当CPU–NPU实测参数；多节点热参数与合法配置表若只能合成，就明示抽象平台和参数区间。实验规模、次数和优势百分比尚未确定。

## 7. 实质工作量与适用性判断

完整工作包包括：周期任务/配置数据结构；跨周期资源与期限校验；周期及启动热评价；小规模优化参照；结构化快速搜索；公平基线和消融。第三章建立可信问题与质量参照，第四章处理同一问题的计算成本，符合师兄的组织方式。
