# B：执行波动下热安全与节能——章节级方案

日期：2026-09-22。性质：独立于A的论文构思，不是已验证方法；本轮未运行实验、不承诺收益或新颖性。

**建议工作题名：执行时间不确定性下多核CPU–NPU任务的热安全节能调度。**

一句话主张：先为有执行时间边界的任务图保留满足期限和热限制的执行方案，再根据真实完成事件回收余量，使在线节能动作始终保留可完成的后续安排。

## 1. 两章怎样形成递进

按最坏执行时间安排任务，容易留下实际运行中没有用到的时间；直接把后续任务提前或降低CPU频率，却会改变CPU与NPU重叠和热历史。时间上允许的动作，不一定热可行；当前阶段热可行，也不等于后续阶段仍赶得上截止期。

**第三章：离线构造保守可行计划及安全执行边界。第四章：在线回收余量，同时维护后续计划的可行性。** 前章给后章一个明确的起点与退路，后章改善前章的保守执行方式。这里“保守”是对区间内执行波动的覆盖，不代表真实设备的WCET已经测得。

比A更鲜明的论证是“保障与利用余量”；更重的负担是在线策略的保证条件。只写预测器加MPC不够，必须说明每次动作后，未完成任务为何仍有合法执行方案。

## 2. 控制范围与不确定性先限制清楚

| 项目 | 基础方案 |
|---|---|
| 平台和任务 | 多核CPU、一个不可抢占NPU；合法DAG阶段；给定释放时间和端到端期限 |
| 离线决策 | 合法映射、CPU配置、资源次序、保留执行区间；可先固定映射研究在线部分 |
| 在线动作 | 调整未启动阶段的启动时刻；在CPU共享调频域空闲边界选择下一配置；有限次序修复 |
| 不确定性 | 仅执行工作量/时长的有界波动；热参数、功率表和环境条件先给定 |
| 信息 | 已完成阶段、运行中阶段及剩余工作上界、当前温度、资源状态；不能读取未来真实耗时 |
| 目标 | 离线采用声明的能耗上界或标称代理；在线评价实际固定时域能耗；无分布时不称“期望能耗最优” |
| 不纳入 | 准确率变化、任意NPU抢占、不可获得的配额控制、同时学习多种未知模型 |

建议以每阶段潜在工作量ξ_i和配置相关时长c_i(q,ξ_i)表达波动。不同算法、不同频率复用同一组ξ，避免低频与高频分别抽样而改变实际工作量。区间集合可先采用矩形边界；这是建模选择，边界需有来源或明确标为合成，不能把普通运行样本最大值称为真实最坏上界。

温度仍采用声明的正性RC模型，单位、能耗时域与A一致。执行过程中改变频率是否允许、是否影响同域其他任务必须写清；基础版本仅在域空闲边界切换，避免以假定的独立核调频获得优势。

## 3. 第三章：面向有界时长的离线热安全计划

先从可解释的保守构造开始：为任务固定映射、次序和保留区间[s_i,s_i+c_i^max]；阶段提前结束后，后继仍按保留计划启动，空出的部分保持空闲。基础任务只含通常的前驱完成依赖与端到端期限；不直接继承TC论文的任意最大时间滞后约束。

对各资源建立功率上包络p_bar(t)，使保留区间覆盖活动功率、区间外覆盖空闲功率。若初始温度不高于声明上界、系统热响应正性成立且所有实际功率逐点不超过该包络，则其温度响应可作为实际温度上界。活动/空闲和切换的功率界必须完整计入。这提供一个可验证的基础安全计划，不假定所有阶段提前启动也会更冷。

第三章需要证明或检验的是：固定保留启动和最坏时长下的依赖/资源/期限可行性；功率包络的热上界条件；周期末或验证时域之后的热安全条件。多节点热系统可能在停止某个任务后继续升温，应检查热尾迹或给出安全终端集合，不能在最后任务结束时截断温度检查。

| 节 | 具体工作 | 输出 |
|---|---|---|
| 3.1 | 波动与余量的任务语义 | 区间/工作量定义、可观察信息、控制权限 |
| 3.2 | 保留计划及时间可行性 | 完整约束、配置相关最大时长 |
| 3.3 | 功率包络与温度上界 | 条件性安全命题及适用边界 |
| 3.4 | 离线配置与时间安排的求解 | 小规模参照、可行计划及功率上界轨迹 |
| 3.5 | 保守程度与模型验证 | 不确定区间宽度、热裕度、可调时间余量 |

第三章不是声称重新发明鲁棒调度，而是构造后续在线动作可以依赖的CPU–NPU执行计划。允许优先使用已有求解器；本文的实质工作是将时长范围、合法资源动作和完整热包络连接起来。

更灵活的部分序计划可以减少固定启动的保守性，但不能直接继承其热安全。TC 2013的部分序保证基于特定的最早启动策略；加入等待、改频或换序，必须重新检查保证条件。基础保留计划可作为强对照与回退机制，部分序是方法工具而非必须加入的标签。

## 4. 第四章：保留后续可行性的在线余量回收

状态可写为z=(t，完成集合，运行任务及剩余时长上界，温度，资源占用，剩余保留计划)。每个完成事件或合法配置切换边界触发以下过程：

1. 更新已执行能耗、温度和剩余任务，计算实际释放的时间余量。
2. 为未启动阶段提出有限动作：保持原计划、提前启动、降低CPU域配置、等待后执行，必要时局部交换合法次序。
3. 对每个动作构造覆盖剩余时长波动的完整保守后缀，而不是只预测当前阶段。已启动NPU按剩余最长运行区间继续占用资源和产生热量。
4. 检查动作及后缀的资源、依赖、期限、温度包络和热尾迹；只保留通过者，比较声明的能耗代理与切换/等待代价。
5. 接受动作时，同时保存新后缀作为当前安全退路；超时或没有更合适动作时，执行仍有效的已认证计划。

关键接口不是“剩余多少毫秒”，而是“当前温度和资源状态下，这些毫秒能在哪些阶段使用，使用后还有什么可行退路”。若新状态满足同一时刻原计划的温度上界、剩余任务及资源状态条件，可复用原后缀；否则必须重新构造后缀。**不能在改变状态后盲目退回旧时间表。**

不可抢占NPU不能等到超温才软件降频救场。提交前要覆盖整个不可中断区间及热尾迹，或明确另有硬件保护；基础方案不依赖后者。

| 节 | 具体方法任务 | 与第三章关系 |
|---|---|---|
| 4.1 | 完成事件、余量分配和动作集合 | 利用第三章保留区间与边界 |
| 4.2 | 当前动作＋可行后缀检查 | 扩展第三章包络到运行中状态 |
| 4.3 | 有限候选排序与局部修复 | 在统一预算内减少保守执行能耗 |
| 4.4 | 后缀复用、超时处理、可行性维持分析 | 说明退路始终有效所需条件 |
| 4.5 | 实际能耗与在线开销实验 | 验证保障与适应性各自的代价 |

可研究的结构在于：事件之间动作固定；每次只改变少量未启动阶段；可复用未受影响的时间窗和保守后缀。但热传播不局限于任务图后继，复用条件必须包含热状态。

在线策略的递归可行性是**待证明命题**：若当前计划覆盖全部允许波动，动作检查也覆盖全部后续波动，且真实执行始终处于这些边界内，则每次接受动作后仍保留可行后缀。若实现只检查有限场景，就降为该场景集的保证；蒙特卡洛零违规不能替代区间保证。

## 5. 后续怎样安排验证

第三章先验证保守包络与最坏边界，不急于追求节能曲线。第四章统一同一工作量样本、初温、任务约束、观察信息、频率权限和计算预算，对照：固定保留计划；时间余量回收加热检查；简单事件反馈/局部修复；带相同安全后缀的滚动优化；拟议快速在线策略。

完全知道未来时长的离线最优只能作为信息更强的参照，不与在线算法混称公平同条件比较。能耗在固定服务窗口内累计，包括等待、空闲和切换；未完成工作量或违约的方法不计节能胜利。

实验维度：执行区间宽度、实际偏离最坏时长的程度、初温、期限紧张程度、CPU/NPU阶段占比。指标：完整任务的实际能耗、截止期/热违规、在线时间及超时比例、退路使用率、包络保守程度。保证等级另报，不由成功率代替。

消融包括：仅回收时间余量；增加当前温度检查；增加完整后缀；增加后缀复用。前两种允许作为解释性非安全对照，但最终算法质量应和信息/保证条件相当的强基线比较。

## 6. 文献怎样衔接与哪些保证不能借用

| 来源 | 已核对事实 | 对本方案的作用与边界 |
|---|---|---|
| [Lombardi等TC 2013](../papers/2013_Michele_Robust_Scheduling_of_Task_Graphs_under_Execution_Time_Uncertainty.pdf)，§3–4，印刷100–101 | 时长上下界、预定资源需求；附加先后约束；最早启动语义；期望完成时间使用近似 | 借鉴离线规划与在线实现的分工，不把其完成时间目标写成能耗目标，不继承新增热约束后的保证 |
| [DATE 2009前作](../papers/2009_Michele_Robust-non-preemptive-hard-real-time-scheduling.pdf)，§III–IV | 不可抢占任务图的部分序方法线索 | 方法背景；其CPU协调角色不等于本方案CPU能耗模型 |
| [Tilli等2022](../papers/2022_A-two-layer-distributed-MPC-approach-to-thermal-control-of-Multiprocessor.pdf)，§5.2–5.3，PDF物理13页 | MPC与独立硬件滞回安全层，触发后立即最小功率 | 借鉴优化与保障的职责分离；本方案改为软件提交前检查，不能借原硬件保证 |
| Kim、RT-TAS、F-DTM既有核查 | 合法配置、热状态及执行安排的方法组件 | 用作配置/热评价参照，不混用各平台参数 |

本轮已直接查看TC 2013物理p.4（印刷101）的Definition 1，以及MPC物理p.13（作者稿12）的Fig.5和§5.2–5.3。前者将保证绑定最早启动，后者将紧急保护绑定硬件；这两点限定了融合时需要自行解决的接口。

## 7. 实质工作量与当前判断

工作包包括：一致的执行波动模型；保守计划与热包络；离线求解参照；事件驱动调度器；合法候选及完整后缀检查；后缀复用和可行性分析；同信息对照与消融。

**B具有完整故事，但作为第二选择。** 其优点是两章天然形成“先保障、再利用余量”的递进；风险在于波动边界与安全论证，且CPU调频与NPU不可抢占的动作权限必须严格自洽。无硬件条件下可做条件性抽象研究，不需要以预测训练或真实固件控制为前提。若用户更偏好在线算法及理论条件，B可以独立成为主线，而非给A加的一章。
