# 主线研究对象与固定执行单元边界

后续定位见[42号](42_固定执行单元下的主线问题与方法定位.md)：本文件固定对象，42号讨论阶段配置与完整请求安排的一致性。Band–Crown仅为历史方法参照，不限定后续方法；共享频率域是按平台输入决定的条件，不预设所有CPU均属同一域。可变核组仍暂缓。

日期：2026-09-24。依据用户确认，将可变核组保留为扩展、暂不考虑。本轮明确研究对象和决策边界，不建立完整数学模型、不修改实验代码或运行新实验。

**当前主线对象：单台抽象多核CPU–NPU端侧设备上的多请求推理调度。每个Stage选择一个合法执行单元，CPU执行单元的资源规模预先固定；不同Stage可以在不冲突的执行单元上并发。研究任务相关响应下，映射、合法频率与执行时序如何协调，在满足请求期限和瞬态温度约束时降低系统能耗。**

这是研究范围的确定，不是创新已经成立，也不表示已有实验验证了完整主线。当前题目“多核CPU-NPU下温度感知的高能效任务调度”保持不变。

## 1. 任务、平台和执行语义

| 对象 | 当前约定 | 依据与待确认项 |
|---|---|---|
| 请求 | 固定工作量与精度的端侧推理请求；有到达时间、端到端期限和预先给定的Stage级DAG | 借鉴21、32号任务表示；具体模型、合法划分和负载仍待确定，不强制每个请求仅两阶段 |
| Stage | 一个不可抢占执行段，只提交给一个合法执行单元完成；不在执行中改映射或拆成CPU与NPU共同执行 | 当前起步假设；不声称所有运行时都必须如此 |
| CPU执行单元 | 固定的CPU资源集合，可以是一颗核，也可以是内部线程数固定的worker；本阶段不选择其核数 | 主线要表达多个CPU单元之间的并发；具体单元数量、核类型与核数尚未绑定真实平台 |
| 物理资源占用 | 起步采用预先划定、不重叠的CPU资源集合，每单元同一时刻执行一个Stage | “核数固定”还需“占哪些核固定”；不能让两个worker暗中使用重叠核却被算作独立资源 |
| NPU | 起步采用一个固定服务模式的NPU执行单元，同一时刻执行一个Stage，可与CPU并发 | 沿用32号抽象；不默认NPU可调频或支持多个并发队列 |
| 合法映射 | 每个Stage都有可执行单元集合，可能仅CPU、仅NPU，也可能存在多个合法选择 | 支持集合必须来自运行时能力或明确假设；不能默认所有Stage都能CPU/NPU互换 |
| 未启动／已启动 | 未启动Stage的暂定映射与顺序可以重新评价；启动后执行单元、资源占用和频率保持不变 | 不将规划中的改映射称为执行中迁移；不预订未声明的未来资源 |
| 信息范围 | 起步论证采用有限、已知请求集，使用同一参数信息比较方法 | 在线未知到达及预测误差另行定义，当前不主张已解决在线调度 |

“一个Stage→一个执行单元”不等于“一个Stage必定单线程”。如果执行单元内部固定使用两个核，这两个核的占用和相应响应必须一起计入；只是**调度器此时没有1／2／4核宽度选择变量**。

概念性安排可以是A的CPU Stage在单元C₁运行，B的CPU Stage同时在不重叠的C₂运行，随后各自的合法NPU Stage竞争NPU。这是拟研究的并发语义，不是新数值案例或已有硬件能力证明。

## 2. 当前决定什么，暂时不决定什么

| 决策 | 当前主线中的含义 |
|---|---|
| Stage映射 | 从该Stage的合法集合中选择一个执行单元；CPU内部映射与CPU/NPU映射均受实际支持集合限制 |
| CPU频率 | 在合法频率域规则下选择运行配置，不把每颗核视为必然能独立调频 |
| 执行时序 | 决定各单元上的顺序、启动时刻及合法等待，满足DAG依赖、资源互斥和请求期限 |
| 温度评价 | 根据所有并发工作形成的完整注热轨迹、入口状态与热模型检查可行性；调整后重算完成时间和系统能耗 |

共享频率域沿用32号的保守起步边界：**域内有Stage运行时不切换该域频率；并发单元必须与当前域频率兼容。** 所以“C₁高频、C₂低频”只有在频率域允许时才是合法配置。域内全空闲时可以选择下一配置；这是一项研究假设，不是所有设备的控制能力结论。

可变核组规模、重叠候选核组选择、执行中增减核、跨设备共同执行一个Stage暂不展开。也不默认引入早退、精度调整、动态子图切分、批处理或跨场景共享映射。师兄论文中的共享映射结构可作组织方式参考，不能因采用Stage映射就自动继承为本题约束。

## 3. 效率刻画、能耗与温度的位置

导师提出的任务相关效率刻画继续保留。所需接口是：Stage i在合法单元p和频率f上的时长dᵢ,ₚ(f)、活动功率或明确计量边界的功率响应。单元资源规模固定后，该响应刻画固定实现，不再额外引入核数k或并行效率曲线。

它回答“映射到哪里、采用某个频率时，能执行多快、消耗多少能量”；完整调度再回答“这一变化是否缓解其他请求或NPU排队、是否满足期限、是否产生不利热轨迹”。**这种连接是待研究的问题关系，不把换公式直接称为模型贡献，也不把多单元并发直接称为新问题。**

共同目标沿用已有评价原则：相同工作量、期限、资源与热约束下，最小化同一窗口的系统能耗，计入完成后的空闲部分。新增平台描述还需明确公共功耗、单元活动增量与节点注热，不能对多个worker重复计算公共基准。交接、切换及并发干扰没有匹配数据时标为缺口；35–40号零额外开销和功率可加只属于旧抽象案例，不自动成为新平台事实。

热节点与调度单元不是同一个概念。若先采用CPU聚合节点＋NPU节点，可以评价多个CPU阶段的总注热与CPU–NPU热耦合；但不能声称刻画了C₁换到C₂的局部散热收益。只有后续补到相应节点和热参数，才讨论核间温差驱动的映射。此次不指定新的RC数值，也不把36号二节点参数直接标定给多CPU平台。

必须明确：35–40号只有一个供两个CPU阶段共享的固定独占资源，所以两个CPU阶段串行；CPU与NPU可以并发。阶段属于CPU还是NPU预先指定。那些实验既不是可变核组调度，也不是已经实现的“Stage在CPU₁／CPU₂间映射”。它们是主线的一组受限子问题，不能包办主线成立与否的判断。

40号的“P1解决全部无热可行条件”只在原L3输入与动作空间内成立。将P1扩展到多个CPU执行单元，需要检查资源日历、共享频率域、就绪优先级与并发注热；目前没有实现，不把原程序直接命名为已完成的新主线基线。

## 5. 当前研究问题及下一步

可向导师表述为：

> 面向多核CPU–NPU端侧多请求推理，在Stage合法划分和CPU执行单元规模固定的条件下，研究任务相关性能／功率响应、共享资源时序和瞬态热状态如何共同影响Stage映射与频率选择，并在请求期限内降低系统能耗。

现阶段已确定研究对象，**尚未确定相对近邻方法的具体贡献与算法结构**。下一项应先形成“代表性任务—合法执行单元—频率域—响应数据”对照，并用不带虚构收益的贯穿例子说明哪项映射／调频取舍需要协调；再决定最小验证。无需立即增加核数扫描、扩展40号或设计完整MILP／启发式。

可变核组候选保留其历史依据与记录；只有当前问题确实需要比较Stage内部并行宽度、并取得对应执行／功率依据时才重新讨论，不因固定执行单元上的结果无收益而自动恢复。当前无硬件、MATLAB仿真条件及证据分级要求不变。
