# 多CPU单元配置协调最小验证定义

日期：2026-09-24。承接[42号](42_固定执行单元下的主线问题与方法定位.md)。本轮只完成可实施的输入与公平对照定义，不写调度代码、不运行仿真、不提出新算法。

**推荐下一项：在两个固定CPU执行单元和一个NPU上，比较“合法无热联合配置＋逐次热检查”与同域热参考，检查简单协调能否自主完成请求并达到参考能耗。** 不以共享频率冲突本身为创新，也不预设一定存在剩余差距。

## 1. 本轮固定的对象与证据等级

使用两条抽象请求A₁→A₂、B₁→B₂。A₁、B₁是CPU阶段，A₂、B₂是NPU阶段。不是已标定的DNN模型或Band流程复现。C₁、C₂各代表一个固定单核执行单元，物理核不重叠、性能相同；合法集合均为{C₁,C₂}。NPU阶段只允许映射到N，固定模式、一次执行一个阶段。

这轮第一次允许两个CPU阶段真正并发；不改变Stage内部核数，不允许CPU/NPU共同执行同一Stage。CPU核对称，所以交换C₁/C₂标签没有收益。本轮验证的是**并发与频率协调**，不是异构核映射收益，也不是CPU/NPU替代映射。

主案例C₁、C₂属于同一频率域D₀。运行中不改频；域内有任务时只能启动相同频率的CPU阶段，域空闲时可切频。允许同频阶段错开启动，不限于两者同时开始／同时结束。执行区间采用左闭右开，完成事件先于同刻派发处理。该规则是41号的保守建模边界，不是硬件必然限制。

另设两个独立频率域诊断：C₁属D₁、C₂属D₂，其他输入不变。它们只隔离合法动作集合的影响，不模拟两台真实设备，也不用于声称独立调频硬件更节能。

| 项目 | 预先确定的规则 |
|---|---|
| 信息与目标 | 两请求0时刻到达，全部输入已知；固定工作量／精度，满足期限、资源、依赖和热约束下最小化系统能耗 |
| 执行 | 不抢占、不迁移；启动后单元与CPU频率保持到完成。未启动阶段可重新配置／重排，不预订资源 |
| 时间域 | 0–60 ms统一评价；启动网格1 ms，阶段结束与期限不取整，全部阶段须在各自期限内完成 |
| CPU频率 | 无量纲x=f/F_ref∈{0.5,1}，记L/H；不指定GHz，不声称设备真实档位 |
| NPU | 固定服务模式，可与CPU并发；本轮不调频、不批处理、不抢占 |
| 理想化边界 | 交接／切频额外时间与能量为零；无访存干扰、温度相关漏电、自动降频或执行时间波动 |
| 评价一致性 | 所有策略、参考和回放使用同一任务相关响应；本轮不再混入反比响应预测对照 |

## 2. 相容的L3输入，而非设备参数

冻结数据文件：[inputs_v1.json](coordination43_design/inputs_v1.json)。所有实际数值均为合成设定；来源只支持模型形式与机制，不支持其代表端侧设备。单位在文件中统一为s、W、J/K、W/K、°C。

CPU响应沿用34号已声明的函数族：

\[
d_i(x)=\bar d_i[(1-\alpha_i)+\alpha_i/x],\qquad Q_i(x)=u_i+v_ix^2.
\]

| 参数 | 固定值 | 选择理由／证据边界 |
|---|---|---|
| CPU参考时长 | A₁、B₁均4 ms，两核相同 | 合成；保持参考时长一致，只隔离频率敏感性 |
| 响应系数 | α_A=1；α_B=0.25，偏好一致对照改为1 | 合成；均在基础比例解释的[0,1]内，不来自端侧拟合 |
| CPU活动增量 | u_A=u_B=v_A=v_B=1 W | 合成且两任务相同功率曲线，避免分别调整功率比制造差异；Q_H=2、Q_L=1.25 W |
| NPU | 基础时长各3 ms，活动增量各1 W；长后缀对照仅B₂改为9 ms | 合成；固定服务模式，不因改变时长再改变单位时间功率 |
| 恒定基准 | CPU总空闲0.2 W、NPU空闲0.3 W、热边界外公共0.5 W | 明确选用旧抽象计量口径；CPU的0.2 W是两核总计，不是每核各0.2 W |
| 热网络 | Ta=25°C，节点上限均80°C；g_C=g_N=0.05 W/K，g=0.025 W/K，C_C=C_N=0.0025 J/K | 明确复用36号的L3数学网络作评价器对照；不是把旧单CPU模型标定成双核设备，亦非文献设备范围 |
| 入口温度 | [30,30]或[78,78]°C | 选旧协议的冷／热两个等级，不扫描中间点；热态距上限2°C，未计算是否触发任何拒绝 |
| 期限 | 宽期限A/B=16/20 ms；紧期限7/10 ms | 合成。最快隔离请求为4+3=7 ms，紧条件给A恰好隔离完成时间、B再留一个3 ms NPU槽；不是实测SLO |

模型形式的出处与计量缺口见[28号](28_CPU响应模型与CoDVFS全文核查及接口方案.md)、[34号](34_统一验证基座与参数依据.md)；共享域机制与JOSS阅读边界见[42号§2–3](42_固定执行单元下的主线问题与方法定位.md)。本轮不补充文献数值范围、不拼接服务器功率和移动芯片热参数。

以下只是公式代入校验，不是运行结果：A₁的H/L时长为4/8 ms、活动能量为8/10 mJ；基础B₁为4/5 ms、8/6.25 mJ，所以两者在宽裕的单请求期限下分别偏好H/L。B的α改为1时偏好与A一致。没有分别指定能量和功率来制造不相容参数。

系统功率与注热边界分别为：

\[
P_{sys}(t)=1+\sum_{i\in CPU运行}Q_i(x_i)+\sum_{j\in NPU运行}Q_j,\quad
p_C(t)=0.2+\sum_{i\in CPU运行}Q_i(x_i),\quad p_N(t)=0.3+\sum_{j\in NPU运行}Q_j.
\]

求和允许两个CPU项同时存在。恒定基准只计一次；完成后的空闲尾段保留。CPU聚合热节点不区分核位置，因此不能声称换核散热收益。域频率无关的恒定空闲功率是一项理想化限制，不能解释为真实共享域的总功耗曲线。

## 3. 预定案例：8项主案例＋2项诊断

每一行分别使用冷、热入口，共8项主案例；只有下表明确列出的变化，没有额外到达流、核型、功率或热参数扫描。

| 族 | 相对基础的变化 | 要检查的关系，不预设结果 |
|---|---|---|
| S1：偏好不同／宽期限 | 基础参数，D_A/D_B=16/20 ms | 不同阶段偏好与合法并发如何协调；错开执行是否已足够 |
| S2：偏好不同／紧期限 | 仅D_A/D_B改7/10 ms | 时间余量是否限制低能耗串行安排；仍允许同频错开启动 |
| S3：偏好一致 | 相对S1仅α_B改1 | 没有偏好冲突时，是否仍有热时序影响；不能强求出现配置差距 |
| S4：长NPU后缀 | 相对S1仅B₂时长改9 ms，期限不变 | NPU服务占用增加如何影响完整请求；同步报告新增能量和注热，不把所有差异归为纯排队 |

两个诊断只取S1、S2的热入口版本，将共享域改为两个独立域。总数10项。域对照仍有两个同样的CPU执行单元和同一热网络，只改变控制约束，不改变硬件功率或散热参数。

S4仍保持与S1相同的CPU计算和NPU单位时间功率，但NPU总工作量不同，因此它是**负载条件对照**，不能比较其总能量差并称节能收益。每个方法优劣只在同一案例内部比较。单纯排队吸收时间的数学解释仍以42号固定后缀公式为限。

所有案例先做输入与语义检查，再计算任何策略结果；不按输出改期限、初温或功率。若整体不可行、热不活跃、无变化或策略均最优，原样保留。不以这10项覆盖真实平台、整个主线或所有频率域规则。

## 4. 共同参考必须覆盖什么

未来参考对4个阶段枚举合法映射、CPU两档模式和网格启动时刻；检查两CPU资源互斥、共享域频率兼容、NPU互斥及DAG／期限。CPU核标签可以规范化去重，但须先用独立小夹具核对，不凭经验删除错开并发安排。

无热与热参考使用完全相同的启动域。无热参考去掉热约束，保留其余约束；热参考按完整60 ms轨迹检查。不能直接复用35号“单CPU顺序＋最早代表”枚举证明当前多CPU覆盖完备。热参考允许等待、同频重叠、混合频率串行、NPU顺序改变以及未启动阶段重新配置。

每个CPU模式组合的能耗在本模型内不随合法等待改变，但其可行性需要检查全部相关时间安排。热参考可在某组合找到安全见证后停止该组合的存在性搜索；要报告全部最优组合，须检查完该能量层。没有安全见证，只有穷尽且没有阈值未分辨安排才能排除。超时给上下界与未决项，不用一条见证断言全称热安全。

每例参考总预算60 s，包括无热与热部分；各策略另各60 s，均包括全部在线调用的配置规划和热检查。超时不扩预算，不把未决算失败。参考与策略用途不同，运行时间只作成本记录，不据此宣称部署可行或需要新算法。

## 5. 冻结两个直接组合对照

使用新名称C0、C1，**不修改或重命名38号P0/P1**。C0为合法无热联合配置的滚动执行，C1在同样决策上增加当前动作热过滤。它们属于有完整已知任务信息的强适配基线，不是Band／JOSS／Crown／F-DTM复现，也不宣称是新算法。

### 5.1 两版共同的动作与规划接口

每个1 ms派发时刻先处理已完成阶段，再枚举此刻的合法启动动作：可启动任意就绪阶段子集，包括两个CPU阶段、一个NPU阶段或其合法组合；同时保留“本刻不启动”的等待动作。运行中工作继续，不预占未来资源。共享域忙时沿用其频率；域空闲时为本次CPU动作选择公共频率；独立域诊断逐域处理。

**一次评价整个同刻动作集合。** 不能先各自通过热检查再把两个CPU动作一起启动，漏掉合并注热。空动作只禁止本刻其他新启动，下一网格点重新决策；阶段完成仍即时更新，不把结束时间取整。

对每个候选动作，配置模块求“已提交前缀＋本刻动作”条件下的最低能耗无热完整后缀，其余未启动模式、单元和顺序均可改变。本刻未被该动作选中的阶段不能由后缀规划偷偷在同刻启动。若不存在满足域、资源、依赖、期限的后缀，该动作被排除；这不是温度导致的排除。

这个无热子问题提供请求完成时间与能耗评价，比只给阶段分配固定局部期限更强。它可能有计算成本，先如实记录，不能将使用精确无热规划的结果宣传成低开销在线方法。两版都可以重新选择剩余配置，不把第一次局部节能建议永久锁定。

候选按以下共同顺序比较：无热完整计划能耗、两请求完成时刻之和、最大请求完成时刻、完整计划规范键。规范键依次按A₁、B₁、A₂、B₂登记启动时刻、单元编号、模式编号（L先H后）；只作可重复并列处理，不按案例或已知安全顺序设例外。前三项中只有能耗是主目标，其余均为并列规则。每一候选的后缀也采用相同规则；规划未完成不能冒称已知最优评分。

单请求偏好仅作解释字段：各请求孤立时，在相同期限、合法模式与自身NPU后继下取最低能耗组合。它不限制C0/C1可选动作；不合法的独立H/L并发方案不参与有效结果排名。

### 5.2 C0与C1唯一差别

| 版本 | 选择与提交 |
|---|---|
| C0 | 提交评分最优的无热可续接动作，下一时刻重新计算；只在事后报告热安全／违规 |
| C1 | 按同一评分顺序检查动作，提交第一个明确热安全动作；首选被拒绝后继续检查其他子集、频率及等待，不仅降频或冻结整个系统 |

C1的候选热轨迹包含：全部已执行片段、所有运行中阶段的完整剩余片段、本次整个启动集合，未启动后继按空闲功率延续到60 ms。候选等待时运行中工作不得漏算。**不检查无热后缀的未来热轨迹，不调用完整热搜索挑选安全后缀。** 这给出清楚可检验的组合边界：期限由无热完整计划检查，热准入只检查已经提交及拟立即提交的工作。

C1只接受明确安全；阈值带内未分辨的动作暂不提交并记录。如只有未分辨动作有望续接，最终结果标未分辨，不能说已证明策略无解。所有动作无无热可行后缀时记录“当前策略前缀无可行续接”，不称原实例不可行。预算内配置子问题未完成也单列未决。

C0／C1执行器只接收原始输入与自身状态，不接收热参考模式集合、见证或热分类。无热配置规划是其明确允许的模块，不是偷读热参考。未来实现应先执行策略，独立保存结果后才作热参考对比。

## 6. 评价、检查及归因

继续使用完整轨迹、分段恒功率RC精确传播，检查段端点与内部温度驻点。逐节点上限判定带宽10⁻⁶°C；时间比较10⁻⁹s，能量容差max(10⁻¹⁰J,10⁻⁸×比较能量绝对值最大者)。不能只检查阶段结束温度。无热参考和C0最终也需热复核，违规低能耗不计有效节能结果。

需要新增的检查是：双CPU并发活动功率求和；同域相异频率重叠被拒绝、同频错开重叠被允许；独立域相异频率可并发；域末项完成同刻可切频；同刻多启动的联合热检查；前缀不可改写；等待时NPU继续运行；关闭C1热过滤后与C0一致；等价CPU编号置换不改变参考能耗。另保留资源／依赖／期限、能耗积分双算、尾段温度和超时状态检查。

使用小型测试夹具验证参考覆盖与并列集合，夹具不计入10项研究案例。完整穷举与策略必须区分：参考找到安全后缀不等于策略已经自主找到。

每项保存：完成状态、实际模式组合、两请求完成时刻、系统能耗、CPU/NPU峰温及其时刻、模式／频率域合法性、实际并发区间、主动等待、热拒绝动作、候选与无热规划调用数、耗时和未决原因。能耗差只比较完整、安全、满足期限的方案；模式不同但并列最优不算严格翻转。

| 观察结果 | 允许的结论 |
|---|---|
| C0/C1都安全且达热参考 | 本组简单协调足够，热过滤无额外决策收益 |
| C0违规，C1安全且达参考 | 热准入有安全价值；是否节能需另看合法方案能耗，不用违规C0作分母 |
| C1完成但高于已证热最优值 | 定位首次退出所有参考最优可延续前缀的动作；不能只对比一条任选最优图 |
| C1无法续接、参考有安全解 | 说明该组合规则存在剩余差距；先排查无热后缀与热准入信息不一致、并列和实现，不直接证明复杂算法必要 |
| 热参考无解或未决 | 分别记录已证不可行或证据不足，不归咎某派发策略 |

共享／独立域诊断只支持域约束作用；S4改变NPU工作量与注热，不能单独证明热耦合因果。本轮不做CPU–NPU耦合消融，也不称发现NPU特有机制。请求/设备控制假设之外的运行中DVFS仍不在结论范围内。
