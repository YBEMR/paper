# 任务相关模式表与Zhou排序依据适用性审查

日期：2026-09-25。承接[48号](48_主线剩余问题清单与配置映射定位.md)的唯一后续行动。本文是原文复核与符号条件推导，没有新数值实例、MATLAB仿真、参数扫描或新算法。

**结论：模式表可以保留；Zhou的统一因子排序不能无条件保留；但目前没有因此形成新的算法缺口。** 任务相关响应可能破坏原动态能量的乘积分离，甚至使不同任务偏好不同频率；这些关系用完整模式表即可表达。真正受影响的是依赖统一排序的选择依据，不是联合调度问题突然无法求解。是否造成系统损失，仍取决于合法完整安排和候选覆盖。

本项审查到此完成，不另开“击败Zhou排序”的反例支线。主线继续采用固定执行单元、模式表、完整CPU–NPU时序和瞬态热评价；47号完整后缀能力继续保留。

## 1．原文到底依赖哪些条件

来源：[Zhou等，2018，*Thermal-aware correlated two-level scheduling of real-time tasks with reduced processor energy on heterogeneous MPSoCs*](../papers/2018_Zhou_Thermal_Heterogeneous_MPSoC.pdf)。本轮复核§3–5布局文本，重点目视检查印刷p.7–8的算法1及解释；p.5–6式(10)、(15)–(16)、定理1沿用48号已经检查的原页。

| 部分 | 原文事实与定位 | 对本题的意义 |
|---|---|---|
| 时长与动态功率 | §3.1式(1)：`d(i,p,k)=c_i/f_(p,k)`；§3.2式(3)：`Pdyn=μ_i δ_p v_(p,k)^2 f_(p,k)` | 频率在能量乘积中消去，任务因子`μ_i c_i`不依赖所选模式 |
| 动态能量分离 | p.5式(10)、(15)，p.6式(16) | 可以写成模式因子与任务子集因子的内积，支持特定交换比较 |
| 虚拟核表示 | §5.1、图3 | 每个真实处理器／频点对变成一个虚拟模式；表示方法本身不要求本题继续使用`c_i/f` |
| 排序与分配 | §5.2定理1、§5.3算法1 | 模式因子升序；独立任务按因子降序，依赖任务遵守拓扑关系；按可行性检查作first-fit分配 |
| 同一物理处理器的容量 | p.7算法1第17行及下方解释 | **已合并同一真实处理器的多个虚拟核利用率**，不能称原文忽略物理资源共享 |
| 其他约束与目标 | §3.3热独立假设；§4含温度相关泄漏；p.7–8检查共同期限、容量、依赖和温度 | 不能把动态能量排序直接当作总能量最优保证；本题耦合热、逐请求期限和共享频率域需另行适配 |

这里需收紧48号的一处潜在误读：提醒“虚拟模式要保留物理资源关系”是适配要求，不是指责Zhou将各频点视为可独立同时使用的硬件。其原算法明确已有容量合并。与此同时，利用率约束不能直接替代本题逐时刻互斥与域内频率兼容检查。

原算法末尾的失败退出属于启发式执行结果；移植时不能仅凭该退出宣称本题在全部映射／等待安排下无解。本文没有复现或发现Zhou原实验失败。

## 2．可继承的代数依据与保证边界

令模式`ℓ=(处理器p,频点k)`，原文动态能量中：

\[
e_{i\ell}=\xi_i\eta_\ell,\qquad
\xi_i=\mu_i c_i,\quad \eta_\ell=\delta_p v_{p,k}^{2}.
\]

若比较将任务i、j分别放到模式ℓ、k，与交换二者的方案，则原分配减交换分配的动态能量为：

\[
\Delta=e_{i\ell}+e_{jk}-e_{ik}-e_{j\ell}
=(\xi_i-\xi_j)(\eta_\ell-\eta_k).
\]

因此`ξ_i≥ξ_j`且`η_ℓ≤η_k`时，原分配动态能量不高于交换分配。对子集负载亦有相同交换恒等式。

**可靠继承的是这个交换比较，而不是无条件的调度最优性。** 将它用作调度改进还需要：两种分配均支持相应任务；存在满足期限／依赖／真实资源／控制域和热约束的安排；其余能量变化已被计入或证明相同。热相关泄漏变化、其他任务被迫换模式等不能被忽略。

还要区分“固定一组子集负载、仅改变它们的排列”和“可以任意重新分组”。重排交换论证直接覆盖前者；**仅固定负载总和不够**。例如符号上若`η_1<η_2`、`ζ_1≥ζ_2>0`，并允许将正量ε从第二组转给第一组，则能量变化为`ε(η_1−η_2)<0`；原来已经反向排序也不保证在可自由改组的问题中最优。实际任务不可分、迁移后可能不合法，所以不能据此宣称原算法有一个合法改进，或直接否定原论文全部结论。

本题采用的解释边界是：固定负载及合法交换下使用交换恒等式；带容量、依赖、支持与热约束的一般分组问题继续独立判断。算法1本身也按启发式描述，不将定理1扩写为本题通用全局最优定理。

## 3．换成一般模式表后，哪些性质可能保留

表中每项保存合法模式的时长`d(i,ℓ)`、活动增量功率`Q(i,ℓ)`及能量`e(i,ℓ)=Q(i,ℓ)d(i,ℓ)`。这里e是声明固定空闲基准后的活动增量，不等同于Zhou的动态能量加全部泄漏，也不是所有平台的完整系统能耗。

### 3.1 乘积分离是一个可检查的强条件

在所有被比较任务／模式都合法、能量严格为正的完整矩形子表上，能写成`e(i,ℓ)=b_i a_ℓ`，当且仅当所有二阶交叉乘积满足：

\[
e_{i\ell}e_{jk}=e_{ik}e_{j\ell}.
\]

必要性直接由乘积形式得到。充分性可选一个正的基准项，以基准列作为`b_i`、相应基准行比值作为`a_ℓ`重构全表。此时可重新计算因子并使用前述交换比较；新因子的排序不必与旧`μ_i c_i`及`δv²`排序相同，不能跳过核对。

缺失支持项不能用0填充，也不能把非法项设为无穷再做这种秩判断；有零能量项时亦需单独处理。这里仅给出正完整子表的条件，不把它当作通用数据算法。

### 3.2 不能乘积分离，不等于必须更换模式顺序

一个不变条件族为：

\[
e_{i\ell}=a_i+b_i\eta_\ell,\qquad b_i>0.
\]

在保证能量非负的参数域内，这张表一般不再是纯乘积，但每个任务仍按相同的η顺序偏好模式；两任务交换时行常数抵消，仍有：

\[
\Delta=(b_i-b_j)(\eta_\ell-\eta_k).
\]

因此若相关顺序与合法性均保持，原类型的排序依据仍可使用。这是代数不变条件，不是设备测量，也不意味着原first-fit在任意约束下最优。

反过来，所有任务都偏好同一个模式，仅说明行内大小关系一致，**不保证把有限的某类资源优先给哪个任务也有统一答案**。一般表的交换值应直接算`e(i,ℓ)+e(j,k)−e(i,k)−e(j,ℓ)`；只有在合法交换及明确任务／模式顺序下，该符号才说明相应局部选择是否更好。本文不从局部交换符号推出一般DAG调度最优性。

## 4．任务相关频率响应如何进入这个判断

本节只固定一个CPU单元或同质CPU单元，不添加异构核。沿用[33号](33_配置价值变化的条件论证与验证设计.md)已声明的响应族，`x=f/F_ref`：

\[
d_i(x)=\bar d_i[(1-\alpha_i)+\alpha_i/x],\quad 0\le\alpha_i\le1.
\]

为了隔离响应因素，本节**额外限定所有被比较任务共用同一活动增量功率函数Q(x)>0**；这不是35号所有任务都满足的事实，也不是CPU论文的通用实测结论。于是：

\[
e_i(x)=\bar d_iQ(x)+\bar d_i\alpha_iQ(x)(1/x-1).
\]

这是一张至多由两组行／列因子组成的表。令H为`x=1`、L为`x=q∈(0,1)`，`κ=1/q−1`，则两任务的交叉乘积差为：

\[
e_{iH}e_{jL}-e_{iL}e_{jH}
=\bar d_i\bar d_j Q_HQ_L\kappa(\alpha_j-\alpha_i).
\]

在上述正值条件下，存在不同α便使这两行不满足纯乘积分离；相同α仍可分离。特别是所有α=1时，`e_i(x)=\bar d_iQ(x)/x`，仍可分离。**任务相关模型并不必然打破旧结构；简单反比本身在数学上也非线性。**

但打破分离仍未证明模式偏好变化。直接比较得到：

\[
e_{iH}-e_{iL}=\bar d_iQ_L[r-1-\kappa\alpha_i],\qquad r=Q_H/Q_L.
\]

| 条件 | 结论 |
|---|---|
| `1<r<1/q`且任务α分布跨过`α_c=(r−1)/κ` | 阈值两侧任务分别偏好L和H；不能使用一个对所有任务都成立的严格频率优先序 |
| 所有α位于阈值同一侧 | 即使乘积分离失效，各任务仍可偏好同一频率 |
| `r≤1` | 在声明α区间，H不劣于L |
| `r≥1/q` | 在声明α区间，L不劣于H |
| 等号或α恰在阈值 | 保留并列，不能称严格翻转 |
| 期限／支持仅允许一个模式 | 局部能量偏好改变未必改变有效选择 |

如果沿用共同`Q(x)=u+v x²`，`u≥0、v>0`，上述内点阈值条件等价于`u>vq`；纯平方`u=0`落在不翻转区域。u指活动期间的固定增量，不得把始终存在的公共空闲功率塞入u以制造这个条件。这些是代数等价关系，没有设置新数值或扫描。

对“仅有一个H名额、另一个任务必须L”的合法两方案比较，令`h_i=e_iH−e_iL`，则`i用H,j用L`相对交换方案的能量差为`h_i−h_j`。这说明分配依据应与任务模式差值匹配；它不证明实际平台存在这种名额限制，也不是本轮新增调度实例。

[35号](35_配置价值首轮数值验证.md)已经检验过同类R1阈值和不变情形。本节将它们连接到可分离结构与排序依据，不把已有频率选择机制重新命名为异构映射创新。α是固定实现的频率响应参数，不是多核并行比例。

## 5．何时只是换表，何时需要改规则

| 处理部分 | 能否只换表 | 适用边界／最小处理 |
|---|---|---|
| 合法单元／频点的模式编码 | 可以保留表示 | 增加任务支持掩码、物理单元和控制域关联；不能将虚拟模式当独立资源 |
| 完整候选的时长、活动能量 | 可直接查表 | 同一计量边界；期限、后继就绪、完整注热随新时长一起重算 |
| 与任务无关的模式因子排序 | 不总能保留 | 先查分离或交换条件；不满足时按实际任务表评价，不强行给所有任务相同优先序 |
| 将较后模式永久排除 | 不能仅凭排序继承 | 表示上合法的模式保留；若要删除，须有本题系统约束下的支配／排除依据 |
| 先后顺序仅用于遍历全部候选 | 通常不改变完整搜索答案 | 必须覆盖相同合法集合、完整评价且预算足够；超时不能称穷尽，改变顺序可能改变限时结果 |
| first-fit或首个安全代表停止 | 不能因此继承最优性 | 查表修正评价，但早停仍只给见证；候选未覆盖部分和最优性由独立参考区分 |
| 温度、期限和资源检查 | 不只是换能量列 | 原文已有这些检查，但本题采用的耦合RC、逐请求期限、域内固定频率需匹配；不能删除原有能力再构造弱基线 |

需要特别避免把Zhou的first-fit说成它已使用了某个被证明安全的模式剪枝：本轮核查的是排序／选择依据，**没有发现原文承诺任意任务相关模式表下都可安全删除所有较后模式**。

本题44／47号库本来按实际模式计算完整安排能量，没有使用Zhou的η／ξ排序定理；因此“该定理不适用于一般表”并不使现有参考失效。现有代码的响应表尚无CPU单元维，泛化到`d(i,p,f)`确实需要数据结构适配；这是一项实现工作，不能假装原代码已经支持，也不能把多一个索引当算法创新。

### 从局部排序到系统损失还差什么

对两个完整合法安排，系统差可分成：`ΔE_system=ΔE_changed_tasks+ΔE_other`。在旧固定窗口、恒定公共基准、模式能量可加、其他Stage模式不变且零额外开销的条件下，后项为0；改变时序只影响可行性，局部活动能量差才直接成为系统差。

若交换后迫使其他任务换模式，或改了温度相关泄漏／切换／公共功耗，则后项不能忽略。若一个方案没有满足NPU后继期限或热约束，则这是可行性差，不能作为两条有效调度的节能比较。证明某局部模式更省电，也不能证明旧first-fit实际选择了差模式，更不能证明完整后缀复核或直接查表仍不能修正。

NPU在本轮代数中不负责制造乘积分离失效；它在完整安排中承担支持、依赖、服务排队及可能的热耦合。没有新增NPU发热特有收益证据。

## 6．主线判断及下一步

这次得到的是一项**有条件的模型／方法适配结论**：任务相关响应应通过任务模式表进入评价；旧排序只有满足相应结构和合法性条件时才能继承。不是“换非线性公式就必须换求解方法”，也不是“已有算法都能直接原样解决”。

目前最小修正已经明确：保留全部合法模式，按实际表计算候选及完整请求评价，将原排序视为有条件的启发式，不授予安全删模式或全局最优保证；完整后缀热复核继续作为强对照。它在一般扩展对象上的效果尚未验证，但没有理由先为已经能查表表达的偏好差异另立复杂排序算法。

**因此结束本次Zhou适用性审查，不追加排序反例或热参数扫描。** 主线对象不改：固定执行单元＋任务模式表＋多请求CPU–NPU时序＋完整热约束；异构核和可变核组不自动加入。下一步只做一项：**选定一个有公开依据的端侧代表性任务及其模式数据边界。** 优先沿既有Band公开材料核查固定Stage、合法CPU/NPU实现、时延／功率粒度和可用频率信息，形成一张来源表；仅有时延时不补造功率，允许部分实据＋显式L3，其目的不是复刻设备。

这项后续的交付应能回答“主线究竟调度哪类推理Stage、哪些模式是实际支持、哪些仍是假设”，从而决定下一项验证是否具有不同于旧合成族的代表性。没有匹配数据便明确缺口，不马上运行新实验、不重新全面搜方向。目前本次审查无需新增全文下载。
