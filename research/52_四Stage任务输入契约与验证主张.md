# 52．四Stage任务输入契约与验证主张

日期：2026-09-25。依据用户确认采用两个对称固定CPU单元。本轮只定义输入／评价契约、静态审查代码并设计对照；没有数值案例、扫描区间、新实验代码或仿真。

## 1．当前决定与证据边界

**研究对象固定为两个同模型请求，每个请求有四个Stage；S1允许CPU／NPU选择，其余Stage仅用CPU。** 平台采用两个对称、物理资源集合不重叠的固定CPU单元及一个固定服务模式NPU，CPU共享频率域。研究相同模式表下，配置和完整请求时序能否由联合无热规划＋完整候选后缀热复核充分处理。

唯一任务工件沿用[51号](51_模型分区证据补全与研究数据边界.md)：作者PR #226头提交`5af78b1644f77069b5f128bcc14f896cc65d8f5f`的EfficientDet-Lite0；本地模型SHA256为`33a3b622c7cac0762f96089353cd61495f3e993968d133af7871bfc2d5396704`。四组算子及数据边已有作者分区报告与本地静态核验，**不是Band图6身份确认或本轮推理复现**。

| 层次 | 本轮采用内容 | 证据性质 |
|---|---|---|
| 工件与图结构 | 固定模型、输入形状、267个算子和跨Stage张量 | 文件事实＋51号静态核验 |
| CPU／NPU类别支持 | 四组CPU可支持，指定NPU仅支持S1 | 作者后续版本的分区／准备报告；不外推任意NPU或driver |
| 固定四Stage | 采用作者unit边界作为不可抢占执行段 | 本研究选择；没有验证该划分的全部执行模式性能 |
| 两个CPU单元 | 对称、占核集合不重叠、规模固定 | 用户选择的L3抽象，不绑定作者3线程BIG／4线程LITTLE |
| 频率、时长、功率、热与期限 | 字段及相容规则明确，数值留待下一轮冻结 | L3输入；不借旧参数或服务器数据冒充匹配profile |

结构锚定不自动使整个参数包成为L1／L2。以下规则是条件性问题定义，不是硬件控制能力证明或创新成立结论。

## 2．任务、单元与合法动作

请求ID固定为A、B；每个包含S0、S1、S2、S3。两请求使用相同工作量、模型精度和Stage响应，同一个Stage类型在A／B中共享参数。允许到达和绝对期限不同，但不得通过给A、B另设性能曲线制造任务差异。

| Stage类型 | 算子ID（含端点） | 算子数 | 合法单元 | 输出到后继的张量 |
|---|---|---:|---|---|
| S0 | 0 | 1 | C1、C2 | 332 |
| S1 | 1–65 | 65 | C1、C2、N | 390–394、396、397 |
| S2 | 66–265 | 200 | C1、C2 | 594、597 |
| S3 | 266 | 1 | C1、C2 | 请求输出598–601 |

每个请求的依赖链为`S0 → S1 → S2 → S3`；每个Stage恰好执行一次，选择且仅选择一个合法单元。固定模型的267个算子完整覆盖；不删除S0／S3，不动态合并S2／S3，不让CPU和NPU共同分摊S1。选择NPU时为CPU→NPU→CPU→CPU；选择CPU时整个请求可以不使用NPU。

C1／C2各自一次执行一个Stage，二者允许并发；N一次服务一个Stage，可与CPU并发。两CPU的资源集合预先固定且不重叠，具体物理核编号及内部线程数不是本轮决策变量。没有按核热节点，C1↔C2的整体标签交换等价；同单元串行与跨单元并发仍是不同安排。

两CPU频率为L、H，共享频率域。某个Stage在CPU启动时选择频率，此后保持至完成；域内有工作时禁止换频，新启动CPU工作必须采用该域当前频率。同频可以错开并发；域内最后一个Stage完成后，允许同一时刻选择新频率并启动新工作。实现语义采用半开区间`[start, finish)`，同刻先处理完成再处理启动。NPU仅有固定模式，不把CPU的L／H标签用于NPU。

允许未启动Stage重选单元、CPU频率、顺序和启动时间；已提交执行不得抢占、迁移或改频。全体请求及模式信息预先已知，不主张未知在线到达或预测误差适应性。

首版交接／频率切换的**额外时间和额外能量均为零**，这是理想化L3边界，既不来自作者实测，也不表示真实跨设备搬运免费。张量依赖仍必须满足；模式时长定义为Stage本身执行时间，不暗中对某种映射加入额外代价。非零开销列为后续适用性问题，本轮不增加总线、通信队列或新共享资源机制。

## 3．字段级输入契约

下表为文档接口，不是已生成的JSON或可运行案例。必需数值缺失时应报“输入未冻结”，不能以0、旧案例值或默认设备参数补齐。每个参数附来源位置、`文件事实／作者报告／本研究推导／L3设定`属性、适用粒度和缺口；不使用“实测”标签描述本研究尚未测量的数值。

| 输入组 | 字段与单位 | 约束和本轮状态 |
|---|---|---|
| 身份 | `model_id, model_sha256, partition_source`；无量纲 | 固定51号工件和PR记录；不与Lite2、MobileNet或图6混用 |
| 请求 | `request_id, release_s, deadline_s`；s | A／B均已知；`0 ≤ release < deadline ≤ window_s`；数值未定 |
| Stage | `request_id, stage_type, op_ids, predecessors, allowed_units` | 八个执行实例；类型表复用四组，依赖不能按固定数组偏移推断 |
| 单元 | `unit_id, unit_kind, resource_set, frequency_domain` | C1／C2对称且资源不重叠，共享CPU域；N固定单服务模式 |
| CPU频点 | `frequency_id, ratio_to_reference`；无量纲 | L、H，参考H=1，L=q且`0<q<1`；q未定，不需要补造绝对Hz |
| 模式 | `stage_type, unit_id, frequency_id, duration_s, active_increment_W` | CPU为L／H，N为固定模式；时长有限且>0，活动增量有限且≥0；非法模式缺席，不填零时长 |
| 对称关系 | 同Stage、同频率在C1／C2的时长与增量相等 | A／B复用同一表；不同Stage类型可以有不同响应；不强行让NPU最快或最低能耗 |
| 时间域 | `window_s, start_grid_s`；s | 窗口`[0,W]`有限且覆盖全部期限；启动为`kΔ`，Δ>0；W和Δ未定 |
| 基准功率 | `idle_cpu_total_W, idle_npu_W, external_W`；W | 非负、全窗口恒定；CPU空闲项为两CPU单元的**合计**，不能每启动一个Stage重复计入 |
| 热网络 | `capacity_J_per_K[2], env_conductance_W_per_K[2], coupling_W_per_K` | CPU聚合节点＋NPU节点；热容、对环境导热>0，耦合≥0；全为待定L3数值 |
| 热条件 | `ambient_C, initial_C[2], limit_C[2]`；°C | 入口定义在窗口0时刻；逐节点上限；不因某例超温另换入口或热容 |
| 数值与预算 | 时间、能量绝对／相对容差，温度判定带宽，单方法总预算 | 下一轮与输入一起预冻结，各方法相同口径；不默认沿用旧1 ms、60 ms、60 s及旧容差 |

CPU响应可以用函数生成模式表，但评价接口以冻结后的实际表为准。若采用`d=d_ref[(1−α)+α/x]`，必须另行声明α范围及功率函数、给出各Stage参数来源；不从算子数、张量字节数或一个时延点拟合α。此式不是本轮新增必选模型。频率标签也不自动推出高频更省能或一定缩短请求完成时间。

网格只限制启动，不取整到达、期限或Stage时长。完成事件在真实结束时刻处理；后继可启动时刻再向上对齐网格。所有参考与方法使用同一启动域，不能用连续时间无热解未经核查替代网格最优值。

## 4．共同能耗、注热与输出

固定工作量、合法模式、信息和评价窗口，目标仍为满足期限／资源／依赖／温度约束后的最低系统能耗。记CPU聚合空闲、NPU空闲及边界外公共功率之和为`P_base`，则在本轮恒定基准、零额外开销、模式功率恒定的假设下：

`E_system = P_base × W + Σ_stage(Q_selected × d_selected)`。

另用全部开始／结束事件分段积分核对总能耗。固定完整配置后等待不会改变这个能量值，但会改变期限和温度可行性。这项性质依赖当前假设，不外推含温度泄漏、休眠唤醒或非零切换成本的平台。

节点注热随**实际选择的单元类别**决定：

- CPU节点：两CPU合计空闲功率＋此刻全部CPU Stage的活动增量。
- NPU节点：NPU空闲功率＋此刻NPU Stage的活动增量。
- `external_W`计入系统能耗，位于声明热边界之外；不任意全注入CPU，也不重复分摊。

S1选CPU时只增加CPU注热，选NPU时只增加NPU注热；不能因Stage编号固定就向NPU加功率。两请求均选CPU时，NPU仍保留已声明的空闲基准，不暗中关闭它获得额外节能。

沿用被动二节点线性RC形式及恒功率分段精确传播思路，检查段端点和内部驻点，覆盖`[0,W]`的完成后空闲尾段。新参数必须核对稳定性、两热模态和数值尺度；复用旧函数不等于新参数下已经验证。低于上限减带宽才记安全，高于上限加带宽记违规，临界带内记未分辨；入口也属于受检时间。不声称窗口之后或周期重复运行仍安全。

| 输出组 | 必需字段及语义 |
|---|---|
| 时间表 | 每行`request_id, stage_type, selected_unit, frequency_id, start_s, finish_s, duration_s, increment_W`；八个Stage都有对应记录 |
| 部分轨迹 | 未提交项明确未启动，可用NaN表示；已提交项不可回写。未知项不能按零工作量计成完成 |
| 完成状态 | 任务完整性、依赖／资源／域／网格／期限检查分别记录；请求完成为该请求S3的结束时间 |
| 配置 | 八个Stage的完整`(单元, 模式)`组合，与时间表分开；不再只用HH／HL编码整个方案 |
| 能量／温度 | 分段积分与活动求和双值、按实际设备分类的活动能量、逐节点峰温／峰值时刻／终温 |
| 证据状态 | 完成、安全／违规／未分辨、超时、候选耗尽；参考另列下界／上界、最优值是否证明、最优配置集合是否完整 |

只有完整、满足期限且明确热安全的方案参与有效能耗排名。已知可行见证、已证最优值、完整最优配置集合是三个不同证据等级；部分完成不能凭较少耗能胜出。

## 6．H52及对照能力冻结

**H52：在该四Stage对象及声明的L3参数下，允许全部合法映射和频率的“联合无热规划＋完整候选后缀热复核”，是否足以达到同域热参考？**

这是所测输入范围内的充分性问题，不预设成功或失败，更不把一个构造的失败外推成所有联合方法无效。参数尚未冻结，本轮不能回答H52成立与否。

### 三个对照的职责

| 对照 | 能力、信息与输出 | 不授予的保证 |
|---|---|---|
| 联合无热规划 | 从相同输入求满足资源、域、依赖、期限的最低能耗安排，允许全部合法模式；保留并列配置，统一事后热复核 | 无热最优不保证热安全；违规结果只作诊断，不参加有效节能排名 |
| 完整候选后缀基线 | 从独立生成的完整无热合法安排中，每个初始动作选一条最佳完整代表，按既定排序检查整条热轨迹，首个安全代表返回完整计划 | 不是在线每事件重规划，不是逐动作局部热准入，也不是穷尽全部后缀 |
| 同域热参考 | 在相同合法安排域中提供热安全见证、最优能耗界、必要的排除／穷尽状态；不向基线提供时间表或选取提示 | 找到安全见证不等于证明最优；网格排除不等于连续时间无解 |

基线候选来源必须包含全部合法模式与能量层，不能先锁死全局无热最优配置。无热库生成、代表选择和热评价均计入该方法预算；各方法分别生成自己的信息，不能无成本借用参考库。预算、比较容差与输入一起预冻结，超时留下未决，不用部分库冒称精确规划。

代表选择沿47号能力等级，规则明确为：先系统能量层，再两请求完成时间之和，再最大完成时间，最后固定规范键。规范键按`A.S0…A.S3、B.S0…B.S3`排序，逐Stage比较`(start, unit, mode)`；单元C1<C2<N，CPU模式L<H，N固定模式单列。能量层以固定锚点和共同容差划分，避免近似相等链改变顺序；精确容差值下一轮冻结。

初始决策时刻定义为最早到达后第一个合法网格点。若窗口0至此存在强制空闲，它仍计入能耗与温度，不跳过冷却。初始动作由该时刻**全部实际启动Stage及其单元／模式**构成，空集合表示等待；同动作的代表必须具有完全相同的同刻启动集合，不能偷偷多启动一个Stage。每动作取排序最优的一个无热完整后缀，代表之间按相同键排序，首个明确热安全者返回。

**一个重要覆盖限制：**即使完整无热库含S1的CPU和NPU模式，它们也可能落在同一初始动作的不同后缀中，仅其中一个成为代表。允许全部模式参与无热规划，不等于热复核覆盖了每种S1映射。所有代表失败应记录`no_safe_representative`，不能判定实例热不可行；多个等待后缀同属空启动动作时也一样。这是原能力等级的边界，后续诊断应区分“代表未覆盖”和“整个合法空间无解”，不能直接声称映射问题需要复杂算法。

完整后缀基线必须评价所有未来Stage、共享域安排及尾段温度，不退化为C1的当前动作热检查。成功则返回完整计划，运行中不得按另一个未声明策略改写；本轮已知请求、确定模式表的条件下不主张实测波动适应性。

## 7．判据、必要情形与未决处理

| 未来观察 | H52解释 |
|---|---|
| 基线完整、合法且安全，能耗达到同域已证热最优值／有效下界 | 支持该实例中组合足够；不要求与某条参考时间表或某个并列配置相同 |
| 基线候选耗尽且未找到安全完整方案，独立参考有安全见证 | 证明该基线的所测候选覆盖不足；检查映射／频率／时序及代表取法，不推断必须新算法 |
| 基线完整安全，但独立参考存在严格更低能耗的安全见证 | 已能证明能耗不足；若精确最优值未定，只报告已证差距下限，不伪报精确最优差距 |
| 基线实现输出违规或期限失败 | 先排查实现、输入和评价接口；修复错误不能改研究参数，不把bug写成研究反例 |
| 基线或参考超时，温度阈值未分辨，精确规划库未生成完 | 未决；可保留已验证的见证与界，不能用超时或未分辨作失败证据 |
| 无热不可行／已证同域整体热不可行 | 单独报告可行域，不据此否定基线决策能力 |

若基线安全能耗为`E_B`，参考界为`L≤E*≤U`，只有相应证据支持时报告差距区间；例如`E_B>U`可证明至少`E_B−U`的差距。参考未穷尽不必丢弃已证界，但不得凭“没找到更好”给最优标签。有效基线方案本身也可作为可行上界；证据合并发生在执行后，不反向提供给策略。

后续条件覆盖只作设计清单，本轮不填数或扫描：

| 必须保留的情形 | 要分辨的关系 |
|---|---|
| S1走CPU／走NPU | 允许真实支持的替代模式；不强制NPU更快、更省电或被选中 |
| 热约束不活跃 | 同域无热最优安全时，强组合应可达到该下界；是必要无收益对照 |
| 等待／重排已足够 | 原完整配置保留，只改时序；不能改写成映射／频率收益 |
| 并列模式与CPU标签对称 | 比较完整最优集合或能耗，不把选中不同并列代表当翻转；同／异CPU并发分配仍有意义 |
| 截止期／资源不可满足、整体热不可行 | 分开无热与热原因；未完成不参与能耗排名 |
| 代表遗漏或评价未决 | 不同映射藏在同一动作的未测后缀时，明确覆盖边界；超时单列 |

每例记录实际S1映射、全部CPU频率／分配、完成状态、请求完成时间、系统能耗、逐节点峰温、完整配置组合、候选覆盖和预算状态。NPU可能作为可替代执行单元、排队资源和耦合热节点参与；未经独立对照不归因为“NPU特有热收益”。
