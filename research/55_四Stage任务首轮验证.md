### 3.2 热复核实际改变了什么

P_high_D6_hot的首选无热代表让A.S1走CPU、B.S1走NPU，两请求S0均在0开始，完成时间6／5 ms，CPU峰温80.103114°C。基线拒绝后选择下一个初始动作的完整代表：A.S0在0开始、B.S0在1 ms开始，两个S1均走NPU，完成5／6 ms，CPU／NPU峰温78.698026／78.401247°C，能量仍44 mJ。

| Stage | 首选代表：单元／区间ms | 安全代表：单元／区间ms |
|---|---|---|
| A.S0 | C1 / 0–1 | C1 / 0–1 |
| A.S1 | C1 / 1–3 | N / 1–2 |
| A.S2 | C1 / 3–5 | C1 / 2–4 |
| A.S3 | C1 / 5–6 | C1 / 4–5 |
| B.S0 | C2 / 0–1 | C1 / 1–2 |
| B.S1 | N / 1–2 | N / 2–3 |
| B.S2 | C2 / 2–4 | C2 / 3–5 |
| B.S3 | C2 / 4–5 | C1 / 5–6 |

两个方案CPU阶段均H。改变的是**S1设备映射＋初始等待＋CPU分配／后续时序**，不能将峰温差单独归因于其中某一项，也不能说本例证明了非线性频率响应带来的收益。

完整热参考进一步区分S1映射类别（均保留CPU标签）：

| A.S1 / B.S1 | 无热合法最优配置数 | 热安全可保留 | 全部合法时序热违规 |
|---|---:|---:|---:|
| CPU / CPU | 16 | 0 | 16 |
| CPU / NPU | 28 | 24 | 4 |
| NPU / CPU | 28 | 24 | 4 |
| NPU / NPU | 32 | 32 | 0 |

因此，在**本L3参数、6 ms期限、1 ms启动网格**内，两个S1都走CPU的配置无法保留；但一个S1走CPU仍有安全最优配置。不能推导必须都走NPU、所有无热最优配置失效或最低能量提高。NPU确实参与可替代执行及资源时序；未做解除热耦合等对照，不宣称CPU–NPU耦合本身是唯一原因。
