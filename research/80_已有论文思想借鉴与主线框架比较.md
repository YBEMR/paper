# 借鉴已有论文，重新比较主线研究框架

日期：2026-09-29。性质：原文核查、框架比较与条件推导；没有运行实验、冻结参数或修改论文正文。当前模型见[61号](61_第三章正式模型与适用边界.md)，已完成的方法与实验整合见[79号](79_第三章连续热反馈方法与实验整合.md)。

## 1．结论：优先讨论周期性持续推理，尚不替换当前模型

**建议优先讨论“已知采集节奏下的持续推理部署与热安全调度”。** 借鉴DELIA的固定网络重复执行与异构流水背景，借鉴Kim、F-DTM和RT-TAS中有明确来源的周期任务语义，将研究决策放在执行前：应用及释放规则确定后，规划可重复使用的Stage映射、CPU频率和时序；运行时按合法计划执行。

这个框架比“给定一组请求”多出的实质关系是：**同一执行计划要反复使用，上一轮留下的温度影响下一轮是否还能按原配置执行。** 有限任务集不再凭空给定，而是由应用结构与声明的释放规则展开。它也解释了为什么可以在部署前承担较重求解成本，而不是把历史60 s求解预算当成毫秒请求的在线响应能力。

这是研究框架推荐，**不是已成立的新颖性判断，也不是恢复旧24号全部方案的决定**。周期热调度、未来任务预测、热安全等待均有已有方法；能否形成我们的贡献，仍取决于任务相关模式、CPU–NPU合法执行及连续热可行性之间的具体修正与求解效果。现有四Stage数据仍是L3，不能因背景更明确而升级为持续视觉设备的实测参数。

另保留两个比较对象：跨场景共享部署，以及有限已知实例的执行前规划。前者已有扎实应用来源，但引入热历史还缺场景顺序或入口状态依据；后者最接近现有模型，但必须补充实例何时可知及求解时间怎样计入应用流程。下面给出选择理由，而不预设变量更多的框架更好。

## 2．首先区分“已知”的不同含义

| 信息 | 什么可以使它已知 | 本轮不能据此推出的结论 |
|---|---|---|
| 应用结构 | 已选定的固定CNN、编译后的子图及合法后端 | 未来所有请求的释放时刻也已知 |
| Stage代价 | 同任务、单元、频率及计量边界下的profile或显式模型 | 任意输入、并发或温度下时长都不变，或者均值就是WCET |
| 请求释放 | 应用声明的周期、初始相位和触发规则；或已经到达的实例 | 连续视频流天然严格周期，未知外部事件可提前预知 |
| 可出现的运行状态 | 设计者给定应用组合或场景集合 | 场景次序、停留时间和进入每个场景的温度已知 |
| 热状态 | 给定入口条件、模型递推或运行测量 | 每次请求、每个周期或每次场景切换都回到同一温度 |

第二章可以介绍DAG等通用工具，第三章必须说明这些信息在具体决策时刻从哪里来。章节分工本身不能补足应用前提。把若干Stage写成DAG是可继承的抽象；值得研究的部分应是新增关系为什么改变可行部署、可实现能量或求解组织。

### 3.1 两个尤其容易误读的地方

Kim已具有可调度性分析、频率相关静态／动态功率、候选筛选、共享资源干扰和按场景调频，不能把它改写为“每个应用独立选最低功率设备”。其§4.1说明不讨论转移过程及初始状态，§4.3和§5.2.3说明按场景平均评价；因此若研究切换热历史，**驻留映射可以继承，热状态序列必须另行定义**。[S1]

DELIA已经纳入传输时延并具有在线局部适应；其能量和传输能量处理也需分别说明。把它概括为“静态划分、无反馈”会削弱对照。其固定双阶段、准确代价且不增加热与硬期限条件时，原双阶段搜索已能够处理它所定义的目标，未必需要我们的通用搜索。[S2]

F-DTM和RT-TAS均不是“每周期温度重置”的模型。下面用单窗口与重复运行比较，只是隔离保证范围的研究设计，不把人工重置温度归为它们的原文错误。[S3、S4]

## 4．三个候选框架及应用背景示例

候选A、B、C是替代框架，**不要求把三者同时放进论文**。F-DTM的运行期控制用于核查已有能力，不额外展开第四条在线控制方向。

### 4.1 A：固定采集节奏下的持续推理部署与热安全调度——优先推荐

| 问题 | 本候选的回答与证据边界 |
|---|---|
| 实际应用 | 固定视觉模型重复处理按指定采集／调用节奏产生的数据。持续处理依据S2；确定周期与期限语义借鉴S1、S3、S4，并明确为目标应用需声明的接口 |
| 谁、何时决策 | 设计者或部署工具在模型、释放规则、支持模式和热边界确定后离线求计划；运行调度器按计划派发。首版不要求每帧重新求解 |
| 为什么知道任务 | 网络结构与输入规模固定；周期、相位及期限由任务规格给定。已知的是执行实例结构和释放规则，不需要预知未来图像内容；数据相关时长仍需另建模型 |
| 继承内容 | S2的重复执行和性能profile；S1/S3的周期实例组织；S4的热协调动机；61号的Stage模式、合法资源和共享域表达 |
| 拟研究关系 | 同一低能量配置在第一轮有安全时序，未必能在指定速率下持续重复；配置与时序共同决定周期入口热状态。是否因此需要改变配置或仅调整时序，待验证 |
| 已有方法能做到哪里 | 原周期热调度、完整热复核和通用联合规划都应作为工具／强对照。周期固定点本身是标准分析，不构成新算法；简单复核若已足够，应保留结果 |
| 第三章／第四章 | 第三章表达重复资源占用、期限及启动／持续热约束，核查热反馈MILP的适配；第四章在同一问题上组织低能量配置的可重复安全时序搜索 |

**背景示例（拟议对象，不是已部署系统描述）：**

> 在固定调用节奏的端侧视觉服务中，同一推理网络需要连续处理后续输入。模型结构和调用规则可在部署前确定，因此可以预先规划CPU与NPU上各计算阶段的执行方式。某种低能耗配置即使能在初始状态下完成一轮推理，重复执行后仍可能受到残留温度的限制。本研究拟在给定处理速率与请求期限下，联合选择可持续使用的执行配置和时间安排，保证声明入口条件下的启动过程及后续重复执行满足温度约束。

这里不强制增加多模型或多摄像头。同一模型的重复请求已经产生跨请求资源竞争；多核作用体现为不同Stage的合法并发与频率域协调，NPU作用由真实合法支持集合限定。

### 4.2 B：多应用场景下的共享部署与热可执行性

| 问题 | 本候选的回答与证据边界 |
|---|---|
| 实际应用 | 借鉴S1巡逻机器人，不同运行状态启用不同摄像头检测应用，移动速度影响期限 |
| 谁、何时决策 | 设计时确定共享驻留映射及逐场景运行配置；运行时识别场景并执行对应计划 |
| 为什么知道任务 | 已知可能应用及组合；**不因此知道未来场景次序或停留时间** |
| 继承内容 | 场景集合、跨场景共享部署、逐场景期限及频率、候选组合与可调度性分析 |
| 拟研究关系 | 同一场景可能带着不同热状态进入，部署方案的可执行性可能不能只由场景编号判断；平均能耗权重也不决定瞬态温度 |
| 已有方法能做到哪里 | Kim已解决其假设下的共享映射和逐场景调频；先以其完整能力及热复核／简单重选作对照。不能只因没有温度变量就认定其已有部署失效 |
| 第三章／第四章 | 第三章需定义共享部署、场景运行及入口／转移热条件；第四章才有依据研究部署与运行配置的协调。当前序列、驻留及切换数据缺口较大 |

**背景示例：**

> 对在多种感知状态之间切换的端侧系统，多个应用可能需要共用一套驻留部署，而每种状态允许采用不同的运行配置。若前一状态的热量尚未消散，相同应用组合也可能面对不同的执行条件。研究可以沿共享部署框架检查热入口是否改变逐场景方案的可用性，但必须先给出场景转换或允许入口状态的依据。

本候选的跨场景牵制最明确，但本轮尚不能选定“已知序列”“允许转移集合”或“入口包络”哪一种符合目标应用。三者对应不同保证，不能同时含糊地称为场景化热调度。S8全文仍缺，也限制了更深入的新颖性比较。因此不作为本轮首推。

### 4.3 C：已知DAG实例的执行前规划——保留现有模型为比较对象

| 问题 | 本候选的回答与证据边界 |
|---|---|
| 实际应用 | 一次已经触发且任务图、输入规模已确定的计算，或由系统明确给定的有限任务计划。S5/S6支持其规划抽象；具体端侧触发过程还需目标应用依据 |
| 谁、何时决策 | 实例描述可用后、执行前，由调度器决定映射、频率与时序；若在运行期求解，规划耗时必须纳入可部署性评估 |
| 为什么知道任务 | 已提供完整实例，不预知尚未到达的请求。多个请求若合成一批，必须说明收集规则、释放时间与等待成本 |
| 继承内容 | 有限DAG、代价表、不可抢占任务、映射与资源顺序；61号及现有方法最容易保留 |
| 拟研究关系 | 沿用响应修正的条件性决策意义与连续热违规信息复用；本轮没有发现必须追加的新决策关系 |
| 已有方法能做到哪里 | 精确联合规划、完整候选热复核及通用DAG调度均是强工具；HEFT原目标不是能耗，不能直接作为被削弱的唯一对照 |
| 第三章／第四章 | 现有模型及热反馈MILP、有界搜索分工可以继续，但应用来源与运行期求解开销不能靠“有限已知”一句带过 |

**背景示例：**

> 当一次端侧计算的完整任务图及模式代价已经提供时，系统可在执行前统一安排各Stage。若多个请求共同规划，则调度器还需要知道这些请求何时进入计划、何时必须完成。此时优化重点是这份有限计划的能耗与热安全；若计划由在线请求触发，生成计划所花的时间也必须计入应用流程。

该表述能使当前假设更准确，却仍不能把60 s研究求解预算写成适用于毫秒期限的在线调度。改称离线规划同样需要具体说明实例由什么预定流程产生。S6提供的是可借鉴的实例规划方法及成本意识，不是这一缺口的自动解决方案。

## 5．为何推荐A，而不是仅给当前模型更换背景

| 选择依据 | A：重复部署 | B：共享场景部署 | C：有限实例规划 |
|---|---|---|---|
| 任务来源与已知信息 | 固定应用＋外部给定释放规则，来源较清楚 | 应用／组合来源清楚，转换及入口条件未定 | 图可知有成熟依据，具体多请求计划来源仍需补 |
| 决策与应用的时间关系 | 可部署前求解、重复复用，适合当前研究工具 | 可离线部署，但切换控制语义需新增 | 若逐实例在线求解，历史耗时不能支撑实用性 |
| 实质关联 | 配置与重复时序共同决定持续热状态 | 共享映射与场景入口状态相互制约 | 已有任务响应、资源与有限窗口热关系 |
| 必要新增内容 | 周期边界、启动过程及持续热条件 | 共享变量、场景入口／转换模型与相关信息 | 具体实例取得过程及规划耗时边界 |
| 历史工作复用 | 模式、资源表达和求解骨架可保留，热保证需重建 | 复用基础函数，多场景模型与保证改动更大 | 复用最多，但不能据此优先选它 |
| 创新与参数风险 | 周期热调度已有先例；匹配NPU数据仍缺 | 场景部署已有强方法；转换资料及近邻全文不足 | 当前贡献定位可继续，应用与代表性证据仍偏弱 |

推荐A的理由是**能从现有原文给出清楚的任务来源与部署时机，而且温度跨重复执行形成真实的约束关系**。不是因为A必然比B/C有更多节能，也不是因为周期形式天然更有创新。

原61号没有承诺窗口以外安全，因此A是研究目标向持续服务的扩展，不是发现61号数学错误。C仍是成立的有限域研究对象；B仍是可借鉴的完整框架。本轮推荐不作自动迁移，正文与现有实验继续保持原解释。

## 6．A需要补充的数学关系：仅作接口推导

### 6.1 从释放规则生成请求，而不从图像内容猜未来

对于应用类型\(a\)，若规格给定周期\(P_a>0\)、相位\(\phi_a\)及相对期限\(D_a>0\)，则第\(k\)个实例的释放和绝对期限分别为

\[
r_{a,k}=\phi_a+kP_a,\qquad d_{a,k}^{\mathrm{abs}}=r_{a,k}+D_a. \tag{1}
\]

只有在周期可公度、参数和任务结构在所研究运行段内固定时，才能用共同重复长度\(H\)描述有限模板。严格周期、无丢帧及稳定模式代价是需要声明或验证的应用条件；不能由DELIA的连续帧描述推导出来。应用类型与完整请求的区分也应保留，不能把一次CNN推理的四个Stage写成四个独立应用。

重复安排必须检查边界两侧的资源占用、依赖与频率域。若首版另行限制所有实例都在所属周期内完成，应明确这是受限模型，不能用它代表允许跨周期流水的全部安排。本轮不选定周期、相位、模板大小或边界简化。

### 6.2 窗口末温度成为下一次的入口

沿用被动线性RC，令\(\theta=T-T_a\)，\(A_{\mathrm{th}}=-C^{-1}G\)。对固定、合法重复的完整安排\(\sigma\)，其节点功率\(p_\sigma(t)\)以\(H\)为周期。先从已经按模板施加周期功率的区段起点计时；包括空闲基准在内，一周期响应为

\[
\theta_{k+1}=\Phi\theta_k+b_\sigma,\quad
\Phi=e^{A_{\mathrm{th}}H},\quad
b_\sigma=\int_0^H e^{A_{\mathrm{th}}(H-u)}C^{-1}p_\sigma(u)\,du. \tag{2}
\]

若热网络稳定，则\(\rho(\Phi)<1\)，存在唯一周期入口状态

\[
\theta_\sigma^\star=(I-\Phi)^{-1}b_\sigma,\qquad
\theta_k=\theta_\sigma^\star+\Phi^k(\theta_0-\theta_\sigma^\star). \tag{3}
\]

这是标准线性系统结论。\(b_\sigma\)随映射、频率和功率时序变化，所以不能预先把所有安排的周期入口设为同一个任意温度。还须检查周期内的连续峰值，不能只检查式(3)在边界上的数值。

在同一时间轴、相同重复功率下，正系统单调性说明：若\(\theta_0\le\theta_\sigma^\star\)逐节点成立，则该入口开始的轨迹不高于周期轨迹。该条件是一个可用充分条件；入口高于周期状态或两节点大小关系不一致时，不能仅凭周期轨迹安全而接受启动过程。原固定初温的数值包络也不能直接充当周期固定点的误差界。

**实际启动还包含资源状态。** 允许跨周期流水时，周期模板在0时刻可能含有负时间已启动的Stage，而从空系统接收首批请求不具有这些在途工作。对象契约必须同时规定初始在途Stage、资源／频率状态和启动衔接规则；先检查真实启动轨迹，再进入式(2)的重复区段。若要用周期轨迹直接界定启动过程，必须另证启动功率逐点不超过相应周期功率，不能只比较初温或擅自删除模板前缀。

### 6.3 一轮安全与持续安全为何可能不同

用一个标量稳定RC说明逻辑边界即可，无需增加数值案例。设恒功率对应平衡温升为\(\theta_{\rm ss}\)，时间常数\(\tau>0\)，且

\[
\theta_0<\theta^{\max}<\theta_{\rm ss},\qquad
\theta(t)=\theta_{\rm ss}+(\theta_0-\theta_{\rm ss})e^{-t/\tau}.
\]

达到上限的时刻为

\[
t_\times=\tau\log\frac{\theta_{\rm ss}-\theta_0}{\theta_{\rm ss}-\theta^{\max}}. \tag{4}
\]

若只检查\(H<t_\times\)的一轮，会得到安全；持续施加同一功率最终超限。该例只证明有限检查不包含持续保证，是**本研究的代数说明**，不是一项CPU–NPU调度实验，更不是对已有方法的失败证明。要证明配置选择有影响，还必须找到原低能量配置的持续不可行条件及其他合法配置的安全见证；一次重复时序失败仍不能排除整个配置。

### 6.4 与现有能量分解、热反馈的联系

若每个模板处理固定\(N_H\)个请求，功率仍可加、基准恒定、无额外开销，重复运行的平均每请求能量为

\[
\bar E(m)=\frac{P_{\rm base}H+\sum_{i\in V_H}Q_i(m_i)d_i(m_i)}{N_H}. \tag{5}
\]

这里\(V_H\)对每个重复Stage实例计数一次；跨边界活动必须按周期轨迹正确积分。初次预热能量不包含在这个长期平均表达中，须单列或在共同有限服务时域内统一计入。固定配置只改变时序仍可能不改变式(5)，但会改变其持续可实现性。这保留了当前“配置代价—时序可行性”的组织依据，不能据此预言节能。

固定热网络和\(H\)后，RC叠加以及式(3)表明：在正确表示周期活动的条件下，固定时刻的周期温度仍可由离散选项的响应组合表示。**这给76—78号热反馈方法提供了适配理由，而非已完成的实现。** 系数须纳入前面各周期的热贡献；不能沿用只覆盖一个窗口的响应系数，也不能将原可靠误差包络未经证明用于新算子。通用精确规划配合正确的周期评价可能已经足够，是否需要新的搜索改进继续由公平对照决定。

## 8．推荐框架的强对照与一项最小验证主张

本节仅提出未来可检验主张，不冻结实例或实验规模。

**H80：在固定工作量、释放节奏、模式表和热网络下，将计划从一次窗口执行扩展为声明入口条件下的重复执行，可能排除一轮最优安排；即使允许相同配置重新安排，原最优配置集合或最低可实现能量是否仍能保留，需要单独判断。**

| 项目 | 后续验证必须说明的内容 |
|---|---|
| 输入依据 | 任务结构与合法执行有配套来源；释放、期限及入口规则有应用规格或明确L3属性。使用同一参数包，不能将多篇CPU/GPU功率及NPU热参数拼成设备复现 |
| 唯一改变 | 两方共同满足同一重复模板的跨边界资源、依赖、期限及共享域约束，采用相同初始资源状态和启动衔接规则；只区别检查首轮热轨迹，还是检查完整启动／持续热轨迹。工作量、速率、模式和能耗口径相同 |
| 共同评价 | 所有输出在同一重复运行定义下复核；区分有限首轮、周期轨迹与启动过程；全过程峰值和资源边界均检查 |
| 简单强替代 | 联合无热规划＋完整重复热复核，允许保留全部合法映射、频率及必要的时序重选。若通用精确方法已达到参考，就不再声称需要额外算法 |
| 已有方法参照 | S2在其链式流水目标下的搜索／局部调整，S3的前瞻及低层反馈，S4的热均衡与运行协调；只有完成目标、动作和信息适配后才能比较，不把裁剪实现称完整复现 |
| 支持条件 | 得到结构合法、首轮热安全但后续重复热违规的见证；若声称配置改变，还需排除原配置的全部合法重复时序，或限定为所查域结论，并有其他配置安全见证。跨边界资源不合法不能归为热条件的影响 |
| 可推翻／无变化 | 原最优配置已有重复安全安排；全部允许入口和安排受安全不变区域覆盖；热只改时序而不改能量；简单完整复核已足够。均完整保留 |
| 不能当支持 | 只选一个不利并列代表；只查有限次重复就宣称无限期安全；以超时证明不存在时序；降低处理速率或漏算请求来获得节能 |
| 未决处理 | 证据不足保留界、见证及范围；不自动增大温度、缩期限或扩大任务数来制造差异 |

这项主张检验的是重复执行约束是否产生决策意义，不检验一般周期热机制是否首次提出。方法性能应在同一持续模型下另做对照，不与单窗口参照混称算法加速。

**已有方法足够的明确条件：** 当全部合法功率轨迹处于热安全不变区域，且重复资源与期限已满足时，热问题退化为无热规划；或者一个简单完整重复复核的见证达到同域能量下界时，最优值已经解决，无需更复杂热搜索。另在DELIA原固定双阶段代价模型下，其原搜索已经能求相应目标，不应为了突出本研究而另加一套更弱列表对照。
