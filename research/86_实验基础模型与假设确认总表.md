# 实验基础模型与假设确认总表

日期：2026-10-01。版本：**R86-v1，用户已确认的基础假设**。

**当前适用版本为R86-v1.1（2026-10-14，D84）：** 以下R86-v1原表保留历史，温度功率P3、注热H3及相关输入按文末§7修订。其余执行、资源、响应和安全规则不因此改变。

**本表是后续模型整理、算法适配和实验设计的统一查阅入口。** 研究对象为固定工作流的多模型端侧推理，平台包含CPU、GPU和NPU，研究任务相关响应下的温度感知节能调度。规则已确定，实验数值尚未确定；本表不代表现有程序已经支持新模型。

确认过程及文献核查保留在[85号](85_实验基础建模假设核查与推荐.md)。本次用户接受精简方案，并专门选择“CPU按固定执行单元区分热状态”。以下各项是本研究的范围选择与建模假设，文献为选择提供依据，不代表某篇论文已验证这一完整组合。后续涉及本表的变更须登记版本，不能因实验方便静默修改。

## 1．对象与术语

| 对象 | 本表中的含义 |
|---|---|
| 工作流模板 | 固定模型调用及其数据关系；模型、输入规格、精度和实际执行路径给定 |
| 请求 | 一次工作流实例，带有释放时间和完整工作流期限；不必只包含一个模型 |
| 模型调用 | 请求中的一次具体模型执行；不同调用产生不同Stage实例，只有真实数据依赖才连接 |
| Stage | 调度前确定的一组计算操作；作为不可抢占、不可迁移的原子调度对象，不在调度中拆分或合并 |
| 执行单元 | CPU单核或固定核组、一个GPU设备或一个NPU设备；设备内部并行体现在响应参数中 |
| 执行模式 | Stage选择的合法执行单元及工作点，附对应时长和活动功率；固定服务模式是只有一个工作点的特例 |
| 频率域 | 共享频率控制的资源集合；单元数量不决定域数量 |
| 功率计量组 | 用于基准去重和功耗参数化的计量边界，可能包含多个执行单元 |
| 热状态 | 所代表资源的温度；CPU各固定执行单元可区分，GPU/NPU按设备级表示；核组温度不默认代表组内最高核温 |

|---|---|
| 不同CPU温度与共享配置 | 单元可共享频率／基准但具有可区分热状态；CPU活动功率必须注入对应单元，组基准及漏电按匹配映射注入，不重复计量 |
| 共用漏电斜率与热粒度 | λ按计量组和工作点定义，不按Stage；组功耗使用哪一个或哪些单元温度，由明确的温度映射决定。共用λ不等于所有单元T相同 |
| 入口与空闲 | 初温、初始OPP均给定；空闲不默认降频／关机，尾段温度和能耗完整计算 |
| 零切换与固定Stage响应 | 瞬时切换只能在域清空后发生；时长不被其他Stage调频改写，热状态不因切换重置 |
| 功率与热反馈 | 物理RC固定；漏电系数随工作点变时，等效温度状态矩阵可能变化，须重新核对传播与稳定性 |
| 能量结构 | 一般为E(m,s)：同配置的时序可改变频率保持时间和漏电积分，零开销不能恢复旧E(m)分解 |
| 求解证明 | 安全安排给出可行上界；旧安全配置关闭、恒定基准下界、固定选项热行及二节点包络不得直接继承 |
| 数据保证 | 确定响应与可加性是模型假设；只有配套上界及条件才可讨论实际最坏保证，不将均值或L3提升为实机保证 |
| 历史范围 | 旧四Stage、两CPU一NPU及其对称RC结果保留原范围，不改称三设备、多热节点或温度漏电验证 |

已有接口符合旧恒定功率／固定RC特例时，已有联合规划与完整热复核仍可以足够处理；不能因本版需要适配就宣称新算法必要。合理基础假设优先，但正式基础确认不等于求解方法已完成适配。

## 7．R86-v1.1：本地温度修正与本地注热（D84）

用户在2026-10-14明确选择“按来源分别计算：各单元／设备用本地温度计算温度修正并注入本地节点；共享基准另按给定分布处理，需要细化现有接口”。本次修改下列空间接口，不新增热节点，不改变频率域、可加活动、逐忙段调频或连续安全规则。

| 受影响项 | 当前口径 | 保留或待填内容 |
|---|---|---|
| P3温度功率 | 每组在节点\(n\)的来源使用\(\lambda_{gn}(\xi_g)[T_n-T_g^{\rm ref}]\)，各来源求和得到组温度修正 | 系数按硬件来源及工作点给定，工作／空闲共用，不按Stage另设斜率；有效范围仍需声明 |
| H3注热 | 本地温度修正注入本地节点；Stage活动注入实际单元节点；组基准按独立、已知分布注入 | 基准只计一次；热传导由RC的导热矩阵处理，不用任意功率分摊代替 |
| §3输入与§5核对 | 补来源—节点归属、\(\lambda_{gn}\)、基准分布及物理有效域 | 匹配数据或明确L3均可登记，但不从整包功率擅自推定局部参数；共享来源不清楚时记输入缺口 |
| 正式表达与证明 | 同步[系统模型稿§4／§6](第三章系统模型_审定稿.md)；差别和仿射结构见[共同接口§10](Kim多场景共享部署_共同模型与求解接口.md) | 同一组总功率不意味着相同节点注热；旧温度传播、界与反馈系数不能未经核对直接复用 |

该细化可保留\(\lambda_g=\sum_n\lambda_{gn}\)的组参数化，但不能把求和后的修正再按固定比例分摊并宣称一般等价。原“共用系数”继续表示相同硬件／工作点下不随Stage改变，不再把一个未明确空间来源的组标量视为完整注热接口。参考温度下的漏电已经含于基准，温度项只是修正；低于参考温度时允许修正为负，完整节点／组功率须在有效域内保持物理有效。

依据：F-DTM §IV-A2式(2)—(3)使用设备自身温度计算设备功耗，并以设备功率驱动自身RC方程；Chantem TVLSI2011 §II-B式(2)、§IV-B式(30)提供逐核本地温度及注热参考。两篇不提供本题三设备局部参数，也未证明旧组平均分配等价。本轮只同步研究模型和记录，未改论文正文、程序、实验输入或历史结果。
