# 对比算法选择与遗传算法适用性审查

日期：2026-10-02。基础对象以[86号R86-v1](86_实验基础模型与假设确认总表.md)为准；承接[87号实验设计复盘](87_师兄第三章实验设计思路复盘.md)。本轮核对原文、检索及推荐，不选数值、不编程、不运行实验，不改变已确认假设。

**结论：师兄采用GA有直接文献来源，并用于提供一种不同于列表调度和MILP的联合搜索对照；我们可以采用，但没有必须采用的理由。优先保留热反馈与no-good的同实现对照，再选择一个快速的热感知列表方法；GA作为通用迭代搜索备选，Zhou方法作为近邻适配备选。选择依据是它回答什么问题及适配是否公平，而不是算法名字是否常见。**

## 1．师兄为何使用遗传算法

重新核对根目录[main.pdf](../main.pdf) §3.7开头，印刷33—34／PDF45—46页。原文明示EA-GA参考文献[18]的能耗感知场景化映射方法，即Kim与Ha的论文。师兄将染色体改为Stage的执行单元／频点联合配置，非法执行集合、资源或期限违例受到惩罚，合法个体用多场景期望能量评价。EA-HEFT则保留HEFT任务排序，以能耗和频点选择修改处理器选择环节。

**原文事实与我们的解释分开：** “借鉴Kim并适配联合配置”是明示依据；“检验另一种迭代联合搜索能否取得相近质量”是根据其对照构造作出的实验职责解释，不是作者明确排除了其他算法后的选型结论。该段没有提供证据说明GA比其他元启发式更适合这个问题。

Kim原文§5.1也说明了选择的工程原因：存在可用的GA求解工具，能够处理其多目标映射探索；支持多目标的其他元启发式也可替换。其§5.2继续用候选映射组合、映射启发式、频率决策及可调度性分析评价组合。师兄借鉴的是这一搜索思路，并非逐项复现Kim的完整流程。

因而师兄的比较可以理解为：**快速列表构造、通用迭代搜索、数学规划**三类组织方式，加上不使用DVFS的控制组。EA-GA不是LCG-MILP的组件消融；Mapping-Only只有在其他处理一致时才能隔离DVFS作用。

## 2．GA是否适合我们的对象

GA用一个“个体”表示候选方案，通过选择、交叉、变异不断尝试新方案。我们的合法模式和实验启动域都是有限离散集合，能够建立这种表示；任务相关响应可直接查表，完整能耗和热轨迹可交给共同评价器。因此它**原则上适用**，但具体基线强弱取决于编码和解码规则。

| 问题 | 为什么影响适用性 | 对我们基线的要求 |
|---|---|---|
| 个体只包含设备与频点 | 同一配置可能有多个顺序、等待和热轨迹；只给它一条最早安排会漏掉其他安全安排 | 若作为联合搜索对照，需说明如何搜索／产生顺序及等待；不能仅凭一条超温安排淘汰整个配置 |
| 交叉变异产生冲突 | 可能破坏依赖、设备独占及共享域同频 | 使用合法表示或明确修复／解码规则；修复计入本方法预算，最终独立复核 |
| 只用阶段活动能量作适应度 | R86含保持工作点的基准及温度漏电，系统能量一般依赖完整时序 | 用共同的系统积分能耗评价合法安全方案；不能用旧固定配置代价替代 |
| 给超温方案加惩罚 | 惩罚用于引导搜索，不等于满足温度约束 | 安全输出须通过完整连续热检查；仅有软惩罚不作为安全证据 |
| 参数及随机性 | 种群、算子、初始化和随机种子都会影响结果 | 事先声明规则，调参资料与正式测试分离；统一墙钟预算，多种子记录失败和离散程度，次数另行设计 |
| 给GA额外候选或修复器 | 结果可能主要来自初始化／解码／修复，而非GA本身 | 不免费提供主方法见证、最优答案或预计算库；共同基础函数可复用，候选及缓存不共享 |

GA通常能提供经过复核的安全上界，但预算内没有安全个体不表示问题无解；一次普通GA运行也不提供最优性证明。比较安全解质量不要求GA必须提供和有界搜索相同的证明能力，但状态字段须分开，不能把“证书较少”直接当作“搜索较差”。

**采用条件：** 若需要一个独立的通用联合搜索参照，而且可以明确实现模式、顺序与等待的解码和共同评价，GA值得保留。若现在只想检验热反馈增量，GA反而不如同实现no-good对照直接；若GA只搜索配置、固定最早时序，则只能称为配置搜索基线，不是完整联合调度参照。

## 3．其他论文提供哪些选择

本轮定向核查七项材料。表内“推荐”属于研究判断，不是原论文已经覆盖R86。

| 材料及阅读范围 | 原论文能力／比较方式 | 对我们可借鉴的选择 | 不能直接继承的部分 |
|---|---|---|---|
| Topcuoglu、Hariri、Wu，2002，*Performance-effective and low-complexity task scheduling for heterogeneous computing*；本地正文任务模型及HEFT／CPOP算法 | HEFT按upward rank选任务，以最早完成及插入空隙方式选处理器；输入含任务—处理器执行时间 | **HEFT基础的能耗／热感知列表调度**，观察快速构造与完整联合求解的差距 | 原HEFT以完成时间为目标；DVFS、释放、共享域、温度漏电及连续热接纳需明确适配；适配版不能冒称原HEFT |
| Arabnejad、Barbosa，2014，*List Scheduling Algorithm for Heterogeneous Systems by an Optimistic Cost Table*；IEEE官方摘要，未核算法全文 | PEFT以乐观代价表考虑后继完成代价，用于任务排序和处理器选择 | **PEFT**是比纯当前任务最早完成更有前瞻性的列表方法备选 | 目前只可确认其前瞻列表思想；不能据摘要判断所有限制或宣称可直接复现。若选它，须补算法正文；不与HEFT同时堆叠为默认组 |
| Zhou等，2018，*Thermal-aware correlated two-level scheduling of real-time tasks with reduced processor energy on heterogeneous MPSoCs*；本地§3—6重点核§5—6 | 虚拟核心表达工作点，构造热约束任务分配；§6与HWGA和A*比较 | **Zhou热感知两层启发式适配**，比单纯GA更贴近期限、能量与温度问题 | 固定周期缩放、排序条件、帧任务、原热模型与R86不同；查表替换后理论排序保证需重审；不能故意保留失配响应来证明新算法更好 |
| Kim、Ha，2023，*Energy-Aware Scenario-Based Mapping of Deep Learning Applications Onto Heterogeneous Processors Under Real-Time Constraints*；本地§4、§5重点核§5.1—5.2 | GA用于映射探索与组合选择，配套可调度性和频率处理 | **GA**作为另一种联合离散搜索组织 | 静态跨场景映射、划分／精度／吞吐等对象不能不加说明迁入固定工作流、Stage不迁移的有限规划 |
| Pierson等，2019在线／2020卷期，*MILP Formulations for Spatio-Temporal Thermal-Aware Scheduling in Cloud and HPC Datacenters*；作者全文§1、§6.3、§6.4.4 | MILP与Coolest、Spatio-Temporal启发式比较；实验对照侧重makespan，两个启发式不直接优化能量 | **温度优先或预测温升列表法**可作为温度感知简单策略；说明已有热信息足以做到什么 | 服务器入口温度、热回流、休眠及原实验目标不同；不能复制其零空闲功耗，也不能把只选最冷资源称为能耗最优 |
| Tan、Cao，2024，*Thermal-Aware Scheduling for Deep Learning on Mobile Devices with NPU*；本地§3—4及作者／机构原始页面 | HBS按时间段预测温度、筛选设备与处理速度，优化时效／精度效用；另有DRLS | **预测温度后筛选动作**支持简单热感知基线的设计理由 | 原精度权衡、处理帧数和运行期决策不是我们固定精度有限Stage DAG；删改后需称适配，不直接用HBS名字宣称同算法 |
| 师兄main.pdf §3.7开头 | EA-HEFT、EA-GA、Mapping-Only提供不同职责 | 学习分工，不要求照抄三个名称 | 原文对照没有自动解决我们新增温度、共享域及漏电模型 |

这些材料表明，对照并不必须是GA、PSO、退火各选一个。**算法数量不等于比较充分性。** 本轮没有为PSO／退火等名称建立更匹配的正文依据，暂不建议为了补数量引入；PEFT的全文缺口也不阻碍已核查候选的推荐。

## 4．建议怎样组织我们的对照

| 实验要回答的问题 | 优先对照 | 推荐理由及限度 |
|---|---|---|
| 固定时刻热反馈比逐条删除安排有什么作用 | CTF反馈版 vs 同编码、同求解规则的no-good版 | 最直接隔离反馈规则。需先适配R86后再用共同评价；原77—78号仅支持旧模型 |
| 快速构造能做到什么，联合求解值得付出多少时间 | 一个HEFT基础的能耗／热感知列表方法 | 经典骨架清楚，解释与实现成本较低。需允许明确的合法等待及完整热复核，不能把“无热HEFT＋失败即结束”当唯一强对照 |
| 另一种联合迭代搜索能否取得相近质量 | GA备选 | 与列表策略作用不同；明确模式、顺序、等待，公平计费及多种子后才可决定是否加入 |
| 与既有热感知联合策略相比如何 | Zhou适配备选 | 最接近的任务／能量／温度关系；适配成本及原保证重审较大，先做接口审查，暂不同时实现GA与Zhou |

**最简推荐：主方法＋no-good同实现对照＋一个能耗／热感知列表方法。** 若需要补一项不同搜索组织，GA与Zhou适配二选一：前者回答通用联合搜索质量，后者回答近邻热感知方法差异。PEFT是列表方法的替换备选；温度优先不再额外与多个类似贪心方法同时铺开。

响应模型对照、固定工作点对照及去热信息对照属于不同因素的控制组，不自动归入“竞争算法”。响应模型对照应保持求解能力与共同回放标准；固定工作点应声明允许哪些点；去热信息方法所得安排仍须在共同热模型下回放，违规能量不能参与有效安全能量排名。

至少保留已有方法足够的条件：热约束不活跃且列表方法已找到可信界达到的方案时，继续复杂搜索未必改善能量；GA或Zhou适配也可能达到同样质量。结果应接受这些情形，不能预定新方法获胜。

## 5．R86下的前置一致性和公平规则

1. 所有竞争方法使用同一工作量、合法支持、释放／期限、OPP与共享域、非抢占语义、启动域、初始温度及功率／RC输入；不把单设备独占偷换为内部可抢占。
2. 所有有效输出按共同评价器复核全窗口期限、资源、系统积分能量及连续温度。初温低或资源当前较冷不是全过程安全证明；等待和尾段均计入。
3. R86新增工作点基准、空闲保持、温度漏电及CPU单元热状态。旧E(m)、固定RC叠加系数、配置见证关闭与旧独立能量下界不能自动使用。**当前旧MILP也不是无需适配就已支持新模型的精确参照。** 适配问题不能只施加给GA／文献基线。
4. 增加统一评价器只是接纳标准，不代表算法已经使用热信息决策。基线如何选择模式、起点和等待需要写清；不能事后免费搜索替它修复。
5. 共同资源预算包括初始化、评分、解码／修复及热评价；事先声明随机性及参数选择规则。先分析可比较能力，再另行确定正式数值和重复次数，本轮不自动继承历史60 s或师兄50样本为新实验设置。
6. 同输入比较安全输出比例、有效能量及首解／总时间；能量配对比较注明两方均有安全解的样本数，另报告全部失败，避免只取成功样本平均导致选择偏差。认证界和solver-reported／启发式状态分列；不要求GA承担全部最优集合枚举。

**下一项最小行动：定义这个列表基线的任务顺序、模式评分与热安全等待规则，核查它和主方法能否接收同一R86评价接口；随后再决定是否需要GA／Zhou这一额外搜索参照。** 不在本轮启动实现、实验或新增算法组件。
