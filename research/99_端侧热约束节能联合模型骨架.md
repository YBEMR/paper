# 端侧热约束节能联合模型骨架

日期：2026-10-02。后续第2小目标：依据[98号继承与修改清单](98_联合模型继承与修改清单.md)，连接输入、决策、执行约束和热能耗评价。基础规则仍以[R86-v1](86_实验基础模型与假设确认总表.md)为准；本文是研究用模型骨架，不是第三章正文或求解器编码。

**优化决策只有Stage模式和启动时刻。** 模式决定执行单元、合法工作点、时长及活动功率；时间安排决定资源重叠、域工作点保持和注热过程；功耗与温度沿同一过程共同计算，得到完整请求完成情况和系统能耗。域状态、温度和能量是受规则约束的派生量，不能由评价器另行选择以改善结果。

## 1．输入：哪些信息必须先给定

| 输入 | 符号及含义 | 必要口径 |
|---|---|---|
| 请求及固定工作流 | 有限请求集合\(\mathcal J\)；请求\(j\)的DAG为\((V_j,\mathcal E_j)\)，释放\(a_j\)、绝对期限\(D_j\)、必需输出Stage集合\(O_j\) | 每个必需计算保留为Stage；全部必需汇点列入\(O_j\)，不构造无依据的跨请求依赖 |
| 执行资源 | \(\mathcal P\)：CPU固定执行单元、GPU设备、NPU设备 | CPU占核集合不重叠；每个执行单元独占。数量、支持后端与线程配置均为输入 |
| 合法模式 | \(M_i\)；模式\(\mu\)提供主执行单元\(p(\mu)\)、固定占用集合\(\mathcal R(\mu)\)、完整合法工作点要求、时长\(d_i(\mu)>0\)、活动增量\(q_i(\mu)=\sum_gq_{ig}(\mu)\) | 时长s、功率W；\(q_{ig}\)是给定的分组计量，不另优化。普通单元模式的非零增量只在其所属组 |
| 域控制 | 域集合\(\mathcal D\)、每模式涉及的域\(\mathcal D(\mu)\)及其状态要求\(\kappa_d(\mu)\)、入口状态\(z_d^0\) | 工作点来自合法离散集合；频率Hz、电压V，不独立优化电压；固定服务模式只有一个可选状态 |
| 功耗计量 | 不重叠计量组\(\mathcal B\)、单元归属\(\pi(p)\)、基准\(B_g\)、温度系数\(\lambda_g\)、参考温度\(T_{\mathrm{ref},g}\) | 基准W，斜率W/K；各组参数按相关域状态取值；活动增量与基准必须同口径 |
| 热系统 | 节点集合\(\mathcal N\)、热容矩阵\(C\)、导热矩阵\(G\)、环境\(T_a\)、入口温度\(T^0\)、温度上限\(T^{\max}\) | \(C\)为正对角矩阵，单位J/K；\(G\)为连接环境的被动导热网络，单位W/K |
| 功率与温度映射 | 基准注热\(H_B\)、温度修正注热\(H_\lambda\)、活动分量注热列\(h_{ig}(\mu)\)；组代表温度\(\Phi_g(T)\) | 映射给定，不作为优化变量；CPU活动注热保留实际执行单元身份 |
| 评价边界 | 固定窗口\([0,W]\)、入口无在途Stage、给定且与决策无关的热边界外公共功率\(P_{\rm ext}(t)\)、模型有效温区与参数来源 | \(0\le a_j\le D_j\le W\)；全过程计能和核温，窗口后安全另议 |

时刻统一用s，能量用J；温度可以统一用K，输入°C时一致换算，温差数值按K处理。没有匹配数据的字段保留来源缺口或明确L3标签，不自动填入旧实例数值。

**四种集合不能合并：执行单元决定谁占用资源，控制域决定谁共享工作点，计量组决定哪项基准只计一次，热节点决定哪里受热。** 一个CPU单元涉及多个域时，模式记录各域的要求；一个计量组覆盖多个域时，其参数索引使用状态元组。这里未增加核组宽度选择，也未假设“一单元一域、一域一热节点”。

\(\mathcal R(\mu)\)记录该模式在完整Stage期间要求独占的固定资源，含\(p(\mu)\)；普通模式为\(\{p(\mu)\}\)。这将R86的R3已有资源需求写成输入，不增加核数或多设备拆分执行决策。只有资料明确要求全段占用时，才计入附加CPU宿主资源；“曾使用宿主”不能自动变成全段预约。局部宿主计算应由预先给定的Stage或明确模式需求交代，缺失时登记输入未闭合，本轮不设计子区间占用机制。

## 2．决策与执行约束

对全部Stage \(i\in V=\bigcup_j V_j\)，选择

\[
m_i\in M_i,\qquad s_i\ge0,
\qquad e_i=s_i+d_i(m_i),\qquad I_i=[s_i,e_i).
\tag{99-1}
\]

其中\(m_i\)是一次完整模式选择，\(s_i\)是启动时刻，\(e_i\)是派生结束时刻。每个Stage仅选一个模式，整个执行区间内不抢占、不迁移、不改工作点。一般模型允许连续起点；如以后定义网格子问题，只加\(s_i\in\Delta\mathbb Z_{\ge0}\)，不取整时长或结束时刻。

**释放与依赖：** 记\(j(i)\)为Stage所属请求。前驱全部完成后才可启动；零交接开销只允许数据立即可用，不删除依赖。

\[
s_i\ge a_{j(i)},\qquad
s_v\ge e_u\quad((u,v)\in\mathcal E_j),\qquad
e_i\le W.
\tag{99-2}
\]

**执行资源：** 对不同Stage，若\(\mathcal R(m_i)\cap\mathcal R(m_k)\ne\varnothing\)，则

\[
e_i\le s_k\quad\text{或}\quad e_k\le s_i.
\tag{99-3}
\]

这允许同刻交接，禁止共享独占资源的执行重叠；即使资源集合不相交，并发仍要满足共享域规则。模式域要求\(\mathcal D(\mu),\kappa_d(\mu)\)须覆盖已声明占用资源的实际控制要求，不能遗漏附加占用的冲突。

**完整请求期限：** 以全部必需输出完成为准：

\[
C_j^{\rm req}=\max_{i\in O_j}e_i\le D_j.
\tag{99-4}
\]

这些关系保留合法等待；不要求每个Stage最早执行，不要求不同请求共用映射。

## 3．共享域与空闲工作点：用事件规则避免歧义

记\(z_d(t)\)为域\(d\)在时刻\(t\)的合法控制状态。模式开始前已选定其要求，运行期间须满足

\[
z_d(t)=\kappa_d(m_i),\qquad
d\in\mathcal D(m_i),\quad t\in I_i.
\tag{99-5}
\]

同域重叠Stage因此必须对共同控制状态兼容。状态标签描述实际共同受控的分量；它不表示所有设备共用一种电压—频率关系。若资料只给频率、同频却有不同电压或控制权限，须补齐模式到控制状态的映射，不能擅自补成可独立调压的决策。

域状态仅在Stage起止事件处考虑更新，约定先处理结束，再处理同刻启动：

| 事件时刻\(t\)的域内情况 | 状态规则 |
|---|---|
| 有Stage跨越该时刻，即存在\(s_i<t<e_i\) | 保持\(z_d(t)=z_d(t^-)\)；新启动者必须兼容，不得改变运行中Stage的工作点 |
| 没有跨越者，但有新Stage在该时刻启动 | 可按所有新启动模式共同要求的合法状态瞬时换点；要求不一致则安排非法 |
| 没有新启动者，也没有跨越者 | 保持上一状态；不能在空闲中自行降频、关机或换点 |

入口以\(z_d(0^-)=z_d^0\)表示给定状态；若0时刻有合法启动，可以按同一规则换点。最后一次执行结束后，保持最后工作点至\(W\)。零切换成本不产生额外时长、能量或温度重置。

**首尾相接不等于禁止换点。** 如果前一Stage恰在\(t\)结束、下一Stage恰在\(t\)开始且域内没有其他跨越者，可以同刻换点。不能把占用区间并集的连通分量当作必须同频的整段，否则会误删R86允许的安排。

给定兼容的\((m,s)\)和入口状态，这些规则确定域状态轨迹。若一个模式仍对应多个未决定的控制状态，应先补模式标识／兼容输入；评价器不能暗中选择最省电的那一个。

## 4．统一功耗：计量去重，状态沿时间线变化

令\(\chi_i(t)=\mathbf1_{I_i}(t)\)，\(\xi_g(t)\)为计量组\(g\)涉及的各域状态元组，\(T_g^{\rm rep}(t)=\Phi_g(T(t))\)为给定代表温度。组功率为

\[
P_g(t)=B_g(\xi_g(t))
+\lambda_g(\xi_g(t))[\Phi_g(T(t))-T_{{\rm ref},g}]
+\sum_i q_{ig}(m_i)\chi_i(t).
\tag{99-6}
\]

基准每组计一次，包含参考温度下的漏电及负载无关部分；活动增量逐Stage累加；温度项在工作与空闲时都保留。动态／静态功耗与基准／活动增量是不同划分，不能将两套分解直接相加。

普通模式有\(q_{ig}=q_i\)当\(g=\pi(p(m_i))\)，其余为零；若明确的模式需求跨计量组，必须提供相应分配并满足\(\sum_gq_{ig}=q_i\)。不能把所有活动功率都记到主设备组，后述活动注热列也须与这个计量边界匹配。

温度低于参考温度时，修正项可以为负，不单独截零；须核对有效温区内的物理组总功率及后述节点总注热非负。参数有效范围之外的轨迹属于模型适用性未获支持，不能靠外推给出热安全或实机无解结论。

同片共享电路的功耗须放入不重复计量组并正确注热。\(P_{\rm ext}\)只表示已确认位于当前热模型边界之外的公共功率；不能仅因名字叫“公共”就免除其注热，也不能重复计入profile已经包含的活动功率。

## 5．耦合温度：把共享基准与各单元活动分开注入

令\(\theta=T-T_a\mathbf1\)，以向量\(\mathbf B(\xi)\)收集各组基准，以\(\Lambda(\xi)\)为各组温度系数的对角矩阵。完整注热为

\[
p^{\rm heat}(t)=
H_B\mathbf B(\xi(t))
+H_\lambda\Lambda(\xi(t))
 [\Phi(T(t))-T_{\rm ref}]
+\sum_i\sum_g h_{ig}(m_i)q_{ig}(m_i)\chi_i(t),
\tag{99-7}
\]
\[
C\dot\theta(t)=-G\theta(t)+p^{\rm heat}(t),\qquad
\theta(0)=T^0-T_a\mathbf1,
\quad T_n(t)\le T_n^{\max}\ (n\in\mathcal N,\ t\in[0,W]).
\tag{99-8}
\]

\(H_B,H_\lambda\)为“热节点数×计量组数”的无量纲非负映射，\(h_{ig}\)为对应活动分量的无量纲非负注热列；对完整位于所建热边界内的分量，分配列和为1。普通单元模式只有所属计量组的一项活动分量非零。其他边界必须明确核算，不能任意丢热。映射由数据或明确L3设定给出；若按工作点分档，各段使用对应档，分配比例本身不参与优化。

例如两个CPU单元共用一项基准时，该基准仍只计一次，两个Stage的活动增量却分别注入其实际单元对应的节点。**不能先合成CPU组总功率，再不分单元地注热。** 基准与温度修正的物理分布未必相同，只有输入有依据时才令\(H_B=H_\lambda\)。

这里的代表温度映射\(\Phi\)仍是输入，不默认平均温度、最高核温或各单元同温。CPU温度保证只针对声明的代表状态；固定核组的代表温度不自动代表组内最高核温。

### 固定安排下能利用什么表达

起止及合法换点将时间轴分为有限段。**若输入明确给出**仿射代表温度
\(\Phi(T)=T_a\mathbf1+L\theta\)，且相应参数与注热映射段内固定，则每段满足

\[
\dot\theta=A_k\theta+b_k,\qquad
A_k=C^{-1}[-G+H_{\lambda,k}\Lambda_kL],
\tag{99-9}
\]
\[
b_k=C^{-1}\left\{
H_{B,k}\mathbf B_k+
H_{\lambda,k}\Lambda_k(T_a\mathbf1-T_{\rm ref})
+\sum_{i\text{在段内运行}}\sum_g h_{ig}(m_i)q_{ig}(m_i)\right\}.
\tag{99-10}
\]

这只是将式(99-7)—(99-8)整理后的条件表达，不预定计算算法。\(H_{B,k},H_{\lambda,k}\)取该段对应的输入映射；固定映射时各段相同。切换时温度连续，下一段接上一段末态；不要求\(A_k\)一定可逆。若\(\Phi\)不是仿射映射，不能直接使用式(99-9)—(99-10)，须按已给映射评价原热方程。

被动RC不自动保证加入漏电后的\(A_k\)稳定；各固定段稳定也不自动保证任意切换的长期稳定。参数稳定性、有效温区与有限窗口热安全分别核查：固定段不稳定不等于该有限安排必然超温，稳定也不等于峰温合格。连续安全仍须覆盖段内峰值、入口及空闲尾段，不能由端点采样或解析式存在直接宣布。

## 6．共同优化问题及结果含义

同一安排的系统能耗为

\[
E(m,s)=\int_0^W
\left[P_{\rm ext}(t)+\sum_{g\in\mathcal B}P_g(t)\right]dt.
\tag{99-11}
\]

联合问题为：

\[
\boxed{\min_{m,s} E(m,s)}
\quad\text{满足合法模式、释放／依赖、资源、请求期限、域保持及连续热约束。}
\tag{99-12}
\]

域状态与热轨迹必须满足以上状态关系，模型及参数在所用范围内有效。它们可以在以后求解编码中作为辅助量，但不能额外提供空闲自由降频、温度重置或未声明的执行动作。本轮没有将该问题认定为MILP，也未选择求解器。

**同配置不等于同能耗。** 即使\(m\)相同，不同\(s\)也可能改变工作点保持时长和漏电积分。一条安全时间表只能给出能耗上界；不能因此关闭该配置全部其他时序并宣称已找到该配置最低能耗。只有在基准对状态恒定、温度项为零等明确特例下，才可恢复旧的“常量基准＋阶段活动能量”分解。

后续共同输出至少包括：完整模式／时间表、请求完成时刻、域工作点轨迹、系统能耗、各节点连续峰温，以及执行合法性和热判定状态。可行见证、已证最优、已证无解、数值未分辨、搜索未完成分别记录；网格结论限于指定网格。没有匹配参数时，这仍是符号模型，不能输出设备级收益或实机安全保证。

## 7．纸面一致性核对及未填接口

| 情形 | 模型给出的处理 |
|---|---|
| 不同CPU单元、同域同工作点错开并发 | 资源不冲突且式(99-5)兼容时允许；活动注热分别保留 |
| 不同CPU单元、同域不兼容工作点重叠 | 域约束拒绝，不能靠设备互斥检查放行 |
| 域内所有旧Stage同刻结束，新Stage同刻开始 | 无跨越者时允许换点；若另有Stage跨越则保持原点 |
| 请求尚未到达、设备无任务或全部请求已完成 | 仍保持相应域状态，计基准和漏电，继续核温至\(W\) |
| 时长产生非网格结束 | 使用真实\(e_i\)；若有启动网格，只有\(s_i\)受限 |
| 两CPU共基准、温度可区分 | 基准一次，活动按单元注入；计量组代表温度单独映射 |
| 模式明确要求附加宿主全段占用 | 固定资源集合检查冲突，活动功率按输入计量与注热；局部占用未交代时保留输入缺口 |
| 同模式重新等待或换序 | 重新评价完成、保持轨迹、温度与能量；不沿用旧表能耗 |
| 温度系数为零且基准恒定的特例 | 能量可退化为配置代价；不证明一般R86都具有该性质 |

**尚未填写的是实例输入，不由本轮私自选择：** 模式到完整域状态的映射、跨域计量参数、组代表温度函数、基准／漏电／活动的注热映射，以及对应数值和有效范围。输入须使给定安排的域状态明确、热初值问题在有效域内具有唯一可评价的解；否则报告输入未闭合，不能让评价器猜测或默加新的控制决策。尤其不能因为便于传播，就默认代表温度映射必为线性。

本轮完成模型骨架的静态／代数核对，未运行数值轨迹、优化或预检程序。下一小目标仅为**第3项：据此核查并确定一条可继承的求解路线及适配边界**；数据缺口持续登记，不把旧CTF-MILP、热反馈系数、配置关闭或下界直接视为已适配。
