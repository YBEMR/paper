# 完整电热认证的安全增量复用诊断

**结论：值得开发独立认证增量评价原型，优先“整场景复用＋同路径前缀检查点”，暂不把后缀支配作为完整SAFE捷径。** 仅保留当前已认证基准，搜索阶段已有70.39%的已提交面板落在可复用结构内；这是运算覆盖量，不是实测加速。现有归档不足以直接恢复完整前缀检查点，本轮没有实现原型、执行电热传播或重跑方法。

来源固定为[YBEMR/paper@0de4d191966294dc673c21ed244616f1b5a6a85c](https://github.com/YBEMR/paper/commit/0de4d191966294dc673c21ed244616f1b5a6a85c)。分支后续版本不参与；全量读取U07—U10四根×四臂的855次实际评价，保持各运行原始顺序，包含845次完整SAFE和10次预算未决。16次独立post不回填搜索，构造失败及未评价方向不进入分母。四根同族、每臂一次，855不是独立样本数。

## 2. 场景、前缀、后缀有多少重复

严格身份比较绝对时间、各热节点基准/活动功率、漏电斜率、功率组、域工作点、参考温度及外部功率，并核对完整输入、精度、空闲策略、源码、初态和同一预算上下文。Stage名称不作为功率相同的依据。主表按原事件段逐段比较；功率函数相同但事件切分不同另列，不能混作现成数值检查点。

|范围|相邻已评价候选：只改一个场景|相对当时已认证基准：只改一个场景|
|---|---:|---:|
|初始化|155/591，26.23%|156/591，26.40%|
|搜索|219/248，88.31%|248/248，100%|
|合计|374/839，44.58%|404/839，48.15%|

每个运行首候选没有前驱，16个均保留在855次总数及总面板分母中。搜索基准由原`graph_proposals.base_candidate_sha256`定位，不事后选择最相似候选。相邻比较的29次双场景变化，不能推翻“每个搜索候选只改自身基准一个场景”：它们可能来自不同基准/不同场景的连续尝试。

在搜索阶段**确实改变的248个场景**中：

- 原事件公共前缀：219/248非零；中位330 ms，各自窗口占比中位32.81%；共4642/11045个事件段、4621/11240个已提交面板。29个零前缀全部保留。
- 原事件公共后缀：88/248非零；中位0 ms；共1475个事件段、1470个已提交面板。160个零后缀全部保留。
- 若仅按绝对时间上的功率函数比较，公共后缀中位248.486 ms、窗口占比中位22.90%，范围2.464—1254.630 ms。但大量差异来自末尾空闲段的起点不同；不能据此复用同一事件面板或旧温度状态。
- 88个严格公共后缀中，只有39个满足所有热节点的新入口上界不高于旧入口下界；2个方向相反、44个无法逐分量支配、3个因预算中断未保存新入口。即使39个满足充分比较条件，也不等于可以复用旧能量或形成完整SAFE。

初始化改变场景相对基准的严格前缀中位220 ms、后缀中位0 ms。全量相邻/基准比较、绝对时长、事件与面板覆盖见[3356行场景配对](results/scene_pairs.csv)；未选取相似度最高的样本。

## 3. 可省去的运算范围

下表只保留**当前已认证基准**，不建立全历史最大相似度缓存。整场景和改变场景的前缀互不重叠。

|范围|原已提交面板|完全相同场景|改变场景的相同前缀|合计覆盖|
|---|---:|---:|---:|---:|
|初始化|57435|7489|18209|44.74%|
|搜索|22352|11112|4621|70.39%|
|全程|79787|18601|22830|51.93%|

搜索阶段整场景本身覆盖49.71%，前缀再覆盖20.67个百分点。四根搜索覆盖分别为U07 64.77%、U08 66.69%、U09 76.94%、U10 69.56%；不是单个有利实例。全程40个候选没有可复用的已提交面板（含16个首候选），均在分母中。9次已尝试但未提交的面板单列，没有计入可节约量。

作为额外边界，查询**同次运行所有过去完整SAFE场景**，得到449/1710次整场景命中；覆盖20640/79787个面板，25.87%。配合基准前缀，全程覆盖53.28%、搜索72.31%，只比保留一个基准多1.35/1.92个百分点。这里是假设无限容量、无缓存成本的归档覆盖量；第一版没有必要为此引入复杂缓存管理。

原方法完整候选哈希缓存实际命中**0/855**。代码还在进入评价前用`seen`跳过重复候选；归档未单列该跳过数，因此不能把“0次缓存命中”解释成没有完整重复，也不能将其与上述潜在场景命中相加。

条件成立时，可省去覆盖面板对应的Taylor构建、连续极值包络及能量累计；合法性、身份校验、未改前缀后的传播、全场景汇总与最终回执仍须执行。面板成本不等、缓存维护有代价，且提速后搜索轨迹会改变，**51.93%/70.39%不得写成时间节约率或加速倍数**。

## 4. 安全接口与停止边界

|对象|分类|必要条件/缺口|
|---|---|---|
|同次运行完整候选回执|当前已有直接复用|相同完整哈希、固定上下文与同一root；仍执行原回执校验|
|完全相同场景的已认证数值结果|数学上可直接复用；当前接口需独立封装|每场景有独立指定初态；新候选仍全局合法，新总能量重新加权，不能挪用旧候选完整回执身份|
|相同原事件/面板路径的前缀检查点|可证明，但缺完整存取接口|须保存内部温度区间、能量分项、积分、峰/谷包络、见证、覆盖位置；现有trace只有时间、段号和温度，不能直接续算|
|相同后缀上的热状态支配|需要额外证明及接口|热系统为Metzler正系统，可条件比较上界；仍需模型有效区间、下界、尾段能量精度与新证据身份|
|仅Stage同名、后缀标签相同、重叠温度区间、跨root旧时间戳|当前不能复用为完整SAFE|不能证明同一输入轨迹或按本预算及时完成|

精确复制同路径内部区间不会额外增加误差；把区间取中心、转float会破坏外包，合并多个包络或从输出温度重新缩放会增宽。温度与能量误差目标必须原样检查，不能因缓存命中放宽。历史相同功率完整场景的数值字段、相同前缀的已存温度轨迹均核对一致；这验证归档一致性，不是新实现的正确性证明。

新候选必须在**原300秒总预算内**完成新增工作、全场景核对和汇总后，才能形成自己的完整SAFE时间戳；保留旧组件来源，不伪造旧回执的候选哈希或形成时间。沿用现有约定，截止前已形成的完整回执可在截止后只读审计与转移，但不能给只有部分组件的新候选补发SAFE。物理工作计数与复用覆盖计数须分开。完整论证与检查点清单见[接口审查](INTERFACE_AUDIT.md)。

**下一轮最小范围建议**：另行授权后，仅对这批冻结候选顺序做独立增量认证原型与原评价器的逐项对照，先整场景，再前缀；保留原精度、预算及中断边界，不启动新搜索。当前尚无实现耗时、内存开销或真实提速证据；本轮只回答“复用结构是否足够”，答案为肯定。后缀支配暂不作为首版必需项。
