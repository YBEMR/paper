# 能耗优先探索与连续热约束修复

## 问题与借鉴

决策为四网的切点和 DLA 相对绑定，以及四个场景各自的 CPU、GPU、共享 DLA 频率。所有方案均取自基准提交 `f6df387` 的 4,319,803 个代表部署及每场景 27 档组合。目标是在 500 个请求全部满足 40 ms 相对期限、四节点连续峰温上界全部 ≤80°C 的条件下，最小化 10.04 s 整窗系统能耗。四节点从 30°C 起步，场景之间传递出口温度。负载、FP16、功热参数和模型内传输语义沿用基准。

| 文献思想 | 此处具体采用的部分 |
|---|---|
| 多 DNN 常驻映射与 SetFreq | 用原实现为初始、重启和选中的新部署搜索每场景频率。[Kim & Ha](https://doi.org/10.1109/TC.2022.3218991) |
| 在约束优化中同时维护两类搜索信息 | 分开保存低能耗 SAFE 部署和低能耗超温部署，定期从后者扩展。本实现为单目标邻域搜索。[Li 等，2019](https://ieeexplore.ieee.org/document/8413136/) |
| 计算活动能耗与温度相关漏电共同决定整窗代价 | 以焦耳估计候选能耗，完整评价使用冻结的温度相关漏电积分。[Zhou 等，2016](https://ieeexplore.ieee.org/iel7/43/7514295/07329974.pdf) · [Li 等，2018](https://doi.org/10.1016/j.sysarc.2018.08.003) |
| 用未来负载与温度演化选择热管理动作 | 找出超温节点与场景，将前序场景功率变化传播至该场景，再选修复动作。[Maity 等，2022](https://doi.org/10.1109/RTSS55097.2022.00041) |
| 切点同时改变计算分布和张量传输 | 每个候选按冻结算子成本、跨切点活跃张量、串行传输及请求数累计服务时间和活动焦耳。[Kang 等，2017](https://doi.org/10.1145/3037697.3037698) |

## 决策规则

1. 给每个种子相同的八个部署起点，即 A、C 和旧域另六个无放回抽样。其 SetFreq 使用基准平台的逐场景代理，在缺少可行频率时用最高频提交给精确期限预筛。每次均匀重启可访问整个扩展域。搜索无权读取历史赢家。
2. 对已证 SAFE 或已证超温的状态，在各自档案内给每个部署保留一个最低完整能耗状态。每轮从本类能耗最小的八个不同部署中选择父状态，在能耗最优和扩展次数最少之间交替。有超温档案时，每三轮给它一次机会；缺少 SAFE 时可继续从超温状态出发。超期状态只做失败记录。
3. 每轮轮换一个网络，考察其合法切点、绑定及剩余名额，另由原目录抽取至多 32 个结构邻居，包含跨网配额转移/换绑；逐场景尝试其余 26 档频率。跨网动作在**供方、受方同时改变后的整窗能耗**上排序，因而给受方增加一个段时会计入供方放弃该名额的代价。没有另设名额惩罚常数。
4. 对每个场景用冻结服务链计算请求活动焦耳（含 XFER）、参考空闲功耗和板级功耗。用父场景入口与出口摄氏温度的均值估计每个节点的漏电增量，乘以候选频档的漏电斜率和场景时长，再加总。该近似使各项均为焦耳。根据同一帧最长串行链、GPU/DLA/XFER 最大累计服务时间及父状态最小期限裕量将提案分为“预计有余量”和“可能超期”，各组内先取低能耗。预测只影响顺序；期限失败由原事件调度器判定。
5. 确认父状态超温后，取父回放中温度上界最大的“场景、节点”。用该节点各场景**平均热功率之差**估计修复方向。令 ΔP 包含活动、参考空闲、分摊的传输/板级热与估计漏电之差，C 为节点热容，G 为到环境及相邻节点的总热导，h 为场景时长。以前一场景的 ΔT 为入口，递推到违规场景：

   `a = exp(−h G / C)； ΔT_out = a ΔT_in + (1−a) ΔP / G，首场景 ΔT_in = 0`。

   将 ΔT_out 加在父状态违规场景的峰温上界上估计剩余超温量，预计消除超温后按能耗排序。此处用场景末端温差近似峰温差，忽略其他节点温差的反馈。该值不会写入 SAFE 证书。真实四节点热回放包含全部耦合及场景内部连续峰值。
6. 把一个调频、一个跨网动作和一个单网动作的最低预计能耗提案列入回放队列；每轮最多六项，其余名额在超温父状态下按定向修复顺序补足。另对排序最靠前的未初始化部署运行 SetFreq，每八轮额外均匀重启一次。对每个首次提交的策略先按原事件调度器检查四场景，首个期限失败即可终止；全部按期才做整窗连续评价。对外只返回截至当前的最低已证 SAFE 方案。

## 伪代码

```text
初始化 SAFE 档案、超温档案、去重表及最佳 SAFE 轨迹
共同八个部署 → SetFreq → 精确期限预筛 → 连续热评价 → 更新档案
在墙钟接纳截止前重复：
    从 SAFE 或低能耗超温档案选父方案；按固定轮次从全域重启
    构造单网切点、跨网名额、绑定和调频邻居
    以期限风险分组，按估计整窗焦耳排序
    若为定向版本且父方案超温：
        从四节点回放提取违规场景与节点，估计前序与本场景的热功率变化
        在保留三类低能耗提案后，按预计剩余超温量、焦耳选择其余提案
    否则按预计焦耳补足相同数量
    对新策略做精确期限预筛，记录首个失败场景和裕量
    对按期策略连续回放，分开保存真实 SAFE 和超温结果
    若 SAFE 能耗刷新，则保存墙钟时刻、能耗与策略
返回最低已证 SAFE 及逐请求完成证明
```

`energy_only` 为直接消融。它同样保留并扩展超温父方案，使用相同的邻域、轮次、SetFreq、重启、事件预筛、能耗排序与物理认证。仅撤去超温父状态下的定向排序，用同一能耗序列补足名额。两组均有 120 s 墙钟上限，116 s 停止接纳，剩余时间留给保存证据。不同候选会导致后续父状态和单位时间工作量分化。

## 第四章 M2 接口

现有 `research/kim_scene_dvfs_admission/joint_thermal.py` 的 `compile_scene` 可以把给定事件区间时长、四节点活动功率和传输功率编译成场景核。对同一核输入不同的四节点入口温度，可通过仿射关系计算能耗与出口温度；连续峰温筛查未决时将该入口回送原连续积分器。适合在多个候选中反复出现相同活动网络切分与频档的场景。

| 复用对象 | 必须区分的键或输入 |
|---|---|
| 单网服务链 | 拓扑/精度/平台版本、网络、完整有序的物理设备与起止层、OPP |
| 事件调度与期限 | 请求流（含释放、期限与阶段配置）、场景时长与尾窗、所有活动网的实际绑定与切点、OPP 及调度规则；未激活网络的切点不影响本场景事件 |
| 热核 | 上述事件产生的时长/活动/传输功率序列，环境温度、热模型与漏电参数、频档、基准入口、峰温筛查配置；全局 DLA 互换必须同步置换温度与节点索引 |
| 已评价结果 | 另含真实四节点入口温度，或整窗场景顺序与初温。仅凭部署 ID 或单一峰温不足以命中结果缓存 |

本轮直接调用原评价器；场景核适配和第四章的加速测量留待单独验证。
