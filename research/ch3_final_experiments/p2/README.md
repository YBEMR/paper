# P2 执行代码冻结与替身验收

依据 `983027f48e2cded0cb02437a4eda608d055b8582`，冻结对象为本目录中的 Python 文件。归档结果依据 `b8187776fdf2c995cbec410032b34a5a76fa774b`。本次使用手工构造的代理分数、合成热分类和历史记录验证代码。三种方法在真实工况的解质量、找到 SAFE 的概率和可完成的代数均待测。

## 方法与边界

| 方法 | 搜索和筛选 | 可审计的输出 |
|---|---|---|
| Kim-Adapt | 每个应用一个映射基因，加稳定物理绑定索引。小域只从允许的目录代表有放回抽初代。试用种群 8、4 代含初代，每个子代用两次 Lexicase 选父母。均匀交叉概率 0.8；单点变异概率 0.2，在该位有其它等位基因时强制换值。越界、超容量、域外组合按非法子代计一次，然后在小域中等概率重抽一次合法代表 | 四场景代理向量、每次 SetFreq 尝试及其缓存命中、每代部署、非法数、完整候选池与哈希。只对第一候选作整窗回放 |
| Kim-Adapt+SAFE | 调用同一候选生成函数。两版独立冷启动，使用同一种子与生成截止。候选按四场景能耗之和排序，以每个能耗组最小值为锚，在 10⁻⁹ J 内按目录顺序、频率编码排并列。按去重后的顺序最多检查 3 条，含首选 | 每次检查的启动、结果、耗时，首个 SAFE、停止原因。空池、耗尽、K 上限、超时、故障分别记录。检查过程中数值未决可以继续下一条。个体证书只覆盖检查过的方案 |
| Thermal-GA | 部署 ID 加四个 0–26 的 OPP 索引。种群 16，最多 8 代含初代。保留 1 个精英，二元锦标赛选父母，0.8 均匀交叉，逐位以 0.2 概率在合法域重抽（可抽回原值） | 每个位置的完整基因、首次评价／缓存命中、状态、用时；逐代访问数、已完成代数、最优见证、首次 SAFE 时间；已开始与已完成的唯一评价分列 |

Kim 的阶段一候选与阶段二物理绑定取自冻结目录。算法 2 的处理器分配步骤由目录绑定取代。原文阶段二规模为种群 128、上限 10,000 代。本次试参数只用于接口与成本验收。Lexicase 先取四场景全合格者；若全代均失败，先取合格场景最多者，再按随机场景次序比较对应能耗（缺失为正无穷），用 10⁻⁹ J 容差保留并列。逐场景 SetFreq 两轮依 GPU、CPU、DLA 调整，每次从该轴最高档开始，失败时仅在低于最高档时恢复上一档，输出全程严格改善时保存的最优可调度组合。每个代理能耗取该场景实际时长，最后场景含一次尾窗。枚举诊断仅用于小域替身核对。

Thermal-GA 固定排序为 SAFE、已确认超温、已确认期限失败、数值未决。各类内分别按整窗能耗、四节点最大超温下界、已观测晚到 ID 数和最差逾期时长排序，最后按完整编码定序。期限前缀只报告已观察的完成数和裕量；全窗能耗留空。未决与验证故障分开报告，故障中止该单元。试验内部的排序约定不赋予无解证书。

## 统一物理接口

`evaluator.py` 在导入冻结代码前核验历史清单、Python 及依赖指纹。运行时只读取清单、部署目录、输入与代码；已归档的胜者、状态数组和分数只在独立测试夹具中读取。每个槽使用同一条物理回放路径 `scene_events.replay_sequence`，并用 `unit.verify_stream/completions/verify_replay` 校核绝对请求、逐请求完成时间、场景入口／出口和峰温证书。连续评价包括泄漏、传输与板级功耗，初温四节点 30°C，阈值 80°C，覆盖 10 s 服务和 40 ms 尾窗。代理评分和真实评价分别落盘。归档回放夹具为 `research/kim_pressure_feasibility/raw_execution/07/{result,requests}.json`。

## 替身验收及复核

在仓库根目录运行下列命令。`--source-root` 指向含冻结 `research/` 的检出目录；资料包分离存放时，可指向其 `source/`。依赖版本与文件指纹见历史 `research/kim_pressure_feasibility/execution_freeze.json`。为按归档字节核验 SHA-256，检出时保留仓库行尾。第二条命令写新报告，输出路径需空闲。

python -B -X utf8 research/ch3_final_experiments/p2/test_substitutes.py --source-root .
python -B -X utf8 research/ch3_final_experiments/p2/substitute_slots.py --source-root . --report p2-repeat.json

## 成本与故障结算

同一冷槽内，Kim 从槽启动至第 40 s 可生成候选；未完成的部署不入池。剩余时间用于连续认证，搜索／认证软截止为第 57 s，预留 3 s 写盘，监督器在 60 s 终止子进程。单次物理调用可能跨越软截止；跨期返回值不进入已完成评价。预算含导入、数据核验、回放、日志、结果落盘。随机数由 CPython 3.12.4 的 `random.Random(20261121)` 产生。每槽独立登记，重复占用失败，无自动重试。

双部署或四部署的 Kim 单槽最多有 32 个种群位置。每个完整部署的四场景最多 72 次 SetFreq 尝试，唯一代理调用受缓存约束。由此两个小域的唯一代理调用上界分别为 144 和 288。原版最多加 1 次连续检查，双部署 +SAFE 最多 2 次，四部署 +SAFE 最多 3 次。Thermal-GA 有 128 个位置，后七代各复用一个精英，最多发起 121 次唯一完整个体评价。冷启动、数值求解与 I/O 的真实成本需在获批小域测量。

`pilot.supervise` 是给获批执行端使用的单槽接口。审批绑定、单次消费及批次调度由外部执行端负责。替身入口显式注入 `Substitute`。一个槽的 `reservation.json`、按行刷新日志、`worker.json`、`persistence.json`、`receipt.json` 分别记录占用、逐步证据、方法输出、落盘时间及监督结算。硬截止或故障只从截止前完整写出的确认行恢复见证；未完成行、只开始的调用、仅写出的中间物理记录均无资格签发见证。正常配对用 `read_pilot.paired_slots` 核对请求、域、种子与候选池；报告另列是否有完整首检。无有效配对或无首检时，回退增益待补数据。
