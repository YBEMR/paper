# 名额耦合的双网联合切点修复

## 借鉴来源与本题改动

| 原论文中的算法步骤 | 本研究的实现与适用范围 |
|---|---|
| Shaw 的 RemoveVisits 成组移除相互制约的访问，再在固定其余访问的条件下重插。其讨论指出，单独移除受约束的一个访问可能只能插回原处。 | 每次固定两个 DNN，释放另外两个 DNN 的切点和常驻名额。只有四个网络，直接遍历全部六对，每一轮按种子打乱顺序。移除相关性来自共享的四个常驻名额和同场景资源，省去学习相关性权重。[Shaw 1998，第 2 节、图 1–2](https://neo.lcc.uma.es/radi-aeb/WebVRP/data/articles/CP4VRPshaw98.pdf) |
| Røpke 与 Pisinger 分开移除与重插，并用最佳与次佳插入代价的差衡量延迟插入的损失，其 ALNS 还根据历史表现选择子算子。 | 这里直接计算双网合法联合重插选项，杜绝一个网络先贪占容量导致另一个无处插入。保留移除/修复分工，不使用 regret-2 公式、自适应算子权重或模拟退火。[Røpke 与 Pisinger 2006，第 3.1、3.2 节](https://doi.org/10.1287/trsc.1050.0135) |
| Glover 的驱逐链使一个元素的改变释放另一元素的位置，以完整试探解评价复合动作。其 TSP 算法可变深度扩展并维护专用图结构。 | 将“释放名额→由另一网取得→形成合法部署”压缩为一个双网动作。例如总数已满时可直接从 (2,0) 到 (1,1)。只有闭合的名额分配才进入物理回放。这是固定深度的资源交换，未实现一般变长驱逐链。[Glover 1996，试探解步骤与参考结构](https://leeds-faculty.colorado.edu/glover/fred%20pubs/266%20-%20TSP%20-%20Ejection%20Chains%20DAM%201996.pdf) |
| Taillard 对流水车间插入位置复用未改变部分的前向完成时间与后向尾部，批量计算不同插入的完工时间。 | 复用“分解并批量评价邻居”的思想，缓存单网阶段活动能耗与各资源服务时间。活动能耗可加。排队、热继承及漏电仍由原回放计算。流水车间的精确递推不直接适用于这里。[Taillard 1990，第 4 节](https://mistic.iict-heig-vd.ch/taillard/articles.dir/Taillard1990.pdf) |

## 候选排序与联合决策

设当前部署为四网各自的 DLA 前缀端点及绑定，四个场景的 OPP 各取自 CPU、GPU、DLA 三域的 27 种组合。对选中网络组释放全部常驻段，列出该组合法切形及绑定的笛卡尔积，将总常驻段数超过四的组合剔除。对称 DLA 的全局互换沿用冻结目录的规范化。一个组允许只改一个网络，也允许代价较低的双网同时改变切点、名额及绑定。

在父方案频率下，每个候选先算三个数。第一项是四场景中“最长单请求无等待服务时间”和各共享资源每帧服务需求的最大值超过 40 ms 的正部，单位 ms。共享资源包括 GPU、DLA0、DLA1 与传输链路。第二项是各场景各网的单请求阶段活动能耗乘该网实际请求数后求和，单位 J。第三项是各场景最忙共享资源每帧的服务时间之和。按三项升序排序，排序同分时使用配对种子。该顺序优先避开明显超载，然后偏向低能耗。超载估计仅在父频率下生效。每组取前两个不同、尚未做 SetFreq 的合法部署。全部合法名额与切点均参与组内排序，进入昂贵物理评价的方案数受这一规则限制。

每个提案同时尝试父频率与原 SetFreq 频率。SetFreq 在某场景找不到按期 OPP 时用最高档完整诊断。对搜索起点，再对每场景的全部 27 档计算原场景代理，提出四场景局部最低值的组合及逐场景替换，所有新策略再整窗认证。中间状态按真实系统能耗选择。正式版本可从已确认超温但所有请求按期的节点继续。期限失败或数值未决的节点不作起点。

```text
输入：工况、完整规范目录、种子与进程启动时刻
在 A、C 上调用 SetFreq 和连续回放。维护独立的最低能耗 SAFE 记录
选合格探索状态中能耗最低者作起点
直到 116 s 接纳截止：
    若无起点，从全部 4,319,803 个代表中均匀重启并调用 SetFreq
    对起点提出逐场景和联合调频并认证
    打乱全部网络组的顺序
    对每组：释放名额，排序所有配额合法的组内切形和绑定
            对两个新部署分别用继承频率、SetFreq 频率认证
    将能耗至少改善 10⁻⁷ J 的本轮最佳合格状态作为新起点
    无改善则重启。每次回放后立即更新全程最低 SAFE 记录
输出：最后接纳的最低 SAFE 记录与完整证书。无解见证时记录失败
```

120 s 硬上限含进程启动、搜索与落盘，116 s 后仅办理证据输出。没有固定搜索轮数。起点 A、C 仅使用既有结构 ID，不注入历史赢家或频率。单网对照只将六个二元组换成四个单网组，排序、每组两个提案、认证和重启规则均相同。因此每轮的候选总数随组数改变。安全起点消融仅将允许作下一起点的状态限制为 SAFE，三组都可以评价超温方案，最终输出共用完全相同的认证条件。

## 与 M2 的接口

部署 ID 和层区间由 `ch3_cooperative_cuts/catalog_ext.py` 共同解码。场景频率索引按执行顺序组成四元组，兼容原有 base-27 编码。可行上界文件 `tables/m2_incumbents.jsonl` 针对每个工况选择新方法五个种子中能耗最低的已认证 SAFE 方案，包含请求流哈希、输入清单哈希、部署与绑定、频率编码、系统能耗、峰温上界、最小期限余量及原始证据位置。若无 SAFE 则该工况不产生上界。后续求解器消费前须核对工况、域和证据。仅接受原 81 个 ID 的旧接口还需接入扩展域解码器。本轮未调用 M2，也未取得扩展域最优性证明。
