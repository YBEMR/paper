# 复算与计时口径

| 方法 | 数据来源 | 初始化与停止 |
|---|---|---|
| Kim-Adapt+SAFE | 基准归档，60 次 | 保留原 24 个体 × 64 代、95 s 候选生成截止、排序回退至首个 SAFE，无回退条数上限 |
| Thermal-GA | 基准归档，60 次 | 保留原 32 个体 × 最多 96 代 |
| 原协同算法、原 no_heat | 基准归档，各 60 次 | 保留原 8 个起点、32 轮 × 每轮最多 6 个提案 |
| 联合修复、单网修复、仅 SAFE 起点联合修复 | 本轮新增，各 60 次 | A 与 C 用原 SetFreq 初始化。局部无改进后在完整域均匀重启，按进程墙钟停止 |

四种场景配置、三个环境温度和每个工况的五个种子均来自 `f6df387`。180 次新运行分配至六个物理核心，任务顺序固定随机打乱，每次独占一个单线程工作进程。截止与旧实验相同：120 s 进程墙钟上限包含启动和证据落盘，116 s 停止接纳搜索结果。新旧算法均从启动新工作进程之前开始计时，每个槽的搜索缓存、事件和结论相互隔离。复用编译好的 Numba 机器码。硬件、运行时及逻辑核记录在 [environment.json](environment.json)。

历史时间来自同一台机器的另一批次。时刻为当批实测，可能受操作系统调度、同时运行的任务及处理器频率影响。首次 SAFE 取首次完成全窗热认证的时间。首次达到最终能耗、首次达到配对 Kim 最终能耗 +0.1% 和精确追平或低于 Kim（10⁻⁷ J 容差）分别记录。目标能耗只在运行后从同工况同种子 Kim 的证书取得，搜索代码读取的物理输入不含 Kim 解。六个对照中的同种子代表相应随机实例。不同搜索机制消耗的随机数序列可不同。

在规定时点之前没有 SAFE 见证的运行保留空能耗，已提前结束的方法沿用最后一次已证安全值。成功覆盖率分母为全组预定运行，能耗差按双方均 SAFE 的配对计算。报告中的时间优势区分首次命中与作业实际结束，两者不能互换。主要统计单位为工况内五个种子，12 工况是冻结情景组合。60 个配对的合并结果用于描述。

## 复算已发布结果

从本研究分支的根目录执行以下命令，完整基准归档在父目录的 `ch3_cooperative_cuts/archives`。第一条脚本直接核对新旧归档的哈希、候选状态、最终证书与 500 条完成记录，并从事件时间戳重建历史和新算法的改进曲线。第二条命令绘图。

```powershell
$study = 'research/ch3_joint_repair'
python -B "$study/summarize.py" --source-root .
python -B "$study/plot.py"
```

独立重跑须满足历史物理评价器锁定的 Python 3.12.4、二进制与依赖指纹，以及 [config.json](config.json) 的核心编号。干净检出中可运行下面两条命令，再执行上面的核验与绘图。首次运行使用空 JIT 缓存会改变计时。比对原记录时应采用已编译的相同数值内核。先前运行无须重新求解。

```powershell
python -B "$study/execute_study.py" --source-root . --jit-cache "$env:TEMP/ch3-cuts-machine-6ec3214"
python -B "$study/archive.py"
```

`archives/<工况>.tar` 的每个方法×种子目录保存预约、回执、原始事件流、结果、标准输出和选中方案证据。事件中可复核每个修复组、两个候选的原始活动能耗及超载分数、实际回放的部署/频率、父方案与所有改进时刻。`VIOLATION` 保留连续峰温及全窗能耗，`DEADLINE` 只报告失败前缀。热不可行中间状态仅用于离线搜索，部署端只消费最终 SAFE 证书。
