# 固定候选的复核方法

研究目录的相邻目录应有第一轮冻结归档。沿用其 prepare.py 准备的运行目录和 Python 环境；依赖、原始来源及物理证书在第一轮 REPRODUCE.md、sources.json、results 中登记。使用 Linux 本地磁盘、支持 fork 的 Python 和 C 编译器。在本轮目录执行下列命令，FIXED_RUN 指向专属于本次复算的空目录。

```sh
export FAST_SCRATCH=/path/to/frozen-first-round-runtime
export FIXED_RUN=/path/to/new-second-round-run
python3 -Bu bench.py
python3 -B analyze.py
```

bench.py 绑定一个核和单线程，在中性事件上预编译。sequence.py 从既有记录恢复送检顺序，只有当前候选的设备映射及频档进入评价函数。每条流、每种方法、每次重复用独立子进程，重建当前排程的起止、积压处理、释放与期限、切换及因果空闲。构造和调频候选分别从第三章各自物理入口执行。两种方法都写出完整计划、证书和压缩轨迹；逐项落盘校验在交付计时后执行。

incremental.py 校验实际冻结热核源码的 Git 对象身份，再在其原事件循环边界加入状态保存与恢复。每个事件的起止时刻及其余功率输入逐位核对，查询范围限于同一序列此前的候选。输入散列、初态、热导、热容、环境温度、重置和严格模式共同限定可复用范围。保存温度、峰值、峰值上界、谷值、谷值下界、峰值时刻、累计节点能耗、基准能耗、温度修正、温度及能耗误差、面板计数和完整前段轨迹。历史超温前段也只提供连续积分状态，当前候选始终重新签发完整认证结果。没有把源候选的判定作为新候选的结论。

| 文件 | 内容 |
|---|---|
| results/candidate_receipts.json.gz | 所有方法及重复的原始计时回执。每条含原提交时间、阶段、候选身份、积分前事件摘要、完整轨迹摘要、静态证书摘要、全部积分核输出摘要、峰谷上下界、能量区间、来源序号、复用事件数、各项耗时和缓存载荷。 |
| results/pairs.csv、flows.csv | 完整序列的配对结果、执行先后与逐流中位改善。时间按当前候选进入物理重放到完整写盘返回，加序列缓存建销计算。 |
| results/components.csv | 互斥时间分解。replay 含合法性和外围调用，events 含排程到物理事件的交叉构建和独立重建。certificate 含证书字段、全量轨迹组装、身份及一致性断言。write 含序列化、压缩和落盘。checkpoint 含状态保存、前缀复制、缓存建销；积分函数内的边界保存用单调钟原地测量。 |
| results/summary.json | 决策门槛、核对状态、资源账本、驻留内存、CPU 与运行环境。子进程峰值 RSS 包含解释器、编译器、物理重建及计时后核验，缓存载荷单列数组实际字节。 |
| 第一轮 results/各流/physical | 当前输出已逐项同冻结归档核对。原始计划、静态证书和轨迹由完整哈希直接定位；运行时长另由本轮回执给出。原始完整输出同时保存在 FIXED_RUN/physical。 |

analyze.py 对照第一轮已归档轨迹独立重算每个序号能匹配的最长真实事件前缀，检查在线命中长度及来源。该核验安排在全部计时结束后。静态证书只剔除实际调用耗时 cert_s；该耗时保留于原始计时回执。完整核返回值的逐位摘要也包括第二个谷温界、误差累计的输出及每个事件的详细轨迹。

审阅既有结果可直接查看归档回执和静态证据，无需再次调用求解器。复算应在独立副本输出，以免覆盖已有决策归档。
