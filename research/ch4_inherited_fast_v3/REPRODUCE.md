# 运行与证据复核

冻结来源、正式规模及决策依据见 PROTOCOL.md。运行环境使用第一轮 prepare.py 物化的 Linux 本地目录和依赖。第三章 C10/energy 的历史记录只用于独立恢复检查。工作目录须同时含第一轮、第二轮研究目录和该历史见证。完整复算在独立副本中执行，INTEGRATED_RUN 指向本次独占的本机目录。

```sh
export FAST_SCRATCH=/path/to/frozen-first-round-runtime
export INTEGRATED_RUN=/path/to/new-integrated-run
python3 -Bu trial.py
python3 -Bu archive.py
python3 -B decision.py
```

| 项目 | 说明 |
|---|---|
| 搜索入口 | trial.py 直接调用第一轮 cell，两个方法均向配额生成器传 O。原程序负责选择束宽、候选数、排序、严格认证、安全或超温映射提名、调频截止和最终接纳。监督器仍执行原有绝对截止，仅在原等待接口取回子进程资源用量。 |
| 计算范围 | 每次搜索或调频子进程启动时新建一个第二轮 Integration 实例，仅绑定严格积分，热预测走原入口。调频阶段可在该进程内复用不同映射尝试的完全相同物理前缀。来自搜索的种子通过原接口传递，该种子的证书和轨迹不会填入增量缓存。 |
| 冷启动与缓存 | 中性事件和原中性模板在正式计时前预编译，回归在另一个进程执行。正式候选从空计划开始，每个阶段第一份积分的复用数必须为零。每个命中都绑定同输入、参数、初态、绝对事件和此前调用。 |
| 一致性 | 每条流每个不同的按时交付计划都从设备和频档经冻结因果重放、原完整认证冷算一次。磁盘计划散列、证书全部非计时字段、日志端点及全部 31 列轨迹逐次核对。跨环境历史见证比较计划、状态和能量区间，并另记轨迹最大差。同机完整与增量要求逐位一致。 |
| 计量 | 完整认证计入重建、积分、证书生成和写盘；按原时钟记录构造或调频的认证区间，并截在该阶段截止。积分、查询和维护以已返回并落盘的调用计量，硬中断时最后未返回的细项留在整体时钟里。内存取 wait4 提供的真实子进程峰值 RSS，缓存数组载荷另列。总 CPU 含父进程调度记账，独立冷算与归档在全部正式单元退出后启动。 |
| 物理证据 | 每流 results 下的日志按单元压缩；physical/index.json 是该流的完整排程、证书和轨迹索引。tar 中的 plan、certificate、blocks 均独立 zlib 压缩。同一流内共享内容块；按索引顺序拼接即为小端 float64 的完整事件矩阵。 |
| 复算边界 | 单元按数据登记顺序轮换方法和预算；对已有完整单元核对回执，对缺回执的部分单元停止，避免无账重跑。归档已有数据可直接复算统计，无须重新调用调度器。 |

| 表 | 用途 |
|---|---|
| tables/cells.csv、layers.csv | 逐次安全交付、最终能耗及映射、截止、工作量、完整认证与内存。中断层使用最后一次已写入的观测。 |
| tables/flows.csv、arms.csv | 各流三次成功数与能耗中位数，对应历史参照、可靠覆盖、流等权平均差距。 |
| tables/improvements.csv、targets.csv、comparison.csv | 逐次严格改善的交付时间与能量上界、两方法共同目标和对方终值的首次达到时刻、配对汇总。 |
| tables/phases.csv、stage_totals.csv | 搜索与调频分别记录的积分次数、真实复用量、积分与缓存耗时、阶段资源。 |
| tables/hot_recovery.json、verification.csv | 超温见证移交、同机完整对照、历史跨机差异、冷算复核和逾时排除数。 |
