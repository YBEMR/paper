# 统一预热条件下的限时求解确认

研究问题、适用边界和逐流结果见[中文决策报告](REPORT_zh.md)。[预登记](PROTOCOL.md)规定准入条件、预算及结论口径。

| 复核目的 | 入口 |
|---|---|
| 检查原始输入、截止、能耗区间、达标时间、严格改善阶梯及物理证据 | 在本目录运行 `python -B check.py`。可用 `--restore CASE PLAN_SHA NEW_DIRECTORY` 复原一份排程、证书和完整事件矩阵，恢复需要 NumPy。 |
| 从证书重新汇总或绘图 | `python -B analyze.py`、`python -B figure.py`。统计取本轮长预算交付的证书上界建立目标；冷启动只在历史对照列出现。绘图需 Matplotlib 和中文字体。 |
| 运行边界与资源 | [启动器](warm_confirm.py)复用上轮的进程树监督及求解入口。[归档器](collect.py)调用冻结证书核验器；聚合相同排程时保存一个完整静态证书，逐次交付与内核用时保留在原始日志。 |
| 复核原固定工作量研究 | [冻结的冷启动及固定工作量报告](../ch4_quota_transfer/REPORT_zh.md)。 |

Linux 运行环境沿用上轮冻结的 Python、研究驱动和物理依赖。启动器通过 `FAST_SCRATCH` 读取数值库及物理接口，通过 `TRANSFER_ROOT` 读取冻结驱动与已编译调频内核，并核对其全部指纹。新账本目录由 `WARM_ROOT` 指定，要求是一个新目录以避免重复发车。每一正式单元从同一批中性准备的父进程独立派生，实例、候选、温度轨迹、提名、证书与输出目录在该单元内生成。绑定不同的物理核，同流内所有重复串行。墙钟扣除截止后监督回收，实际 CPU 包含各后代及监督。公共预热的 CPU 与正式 CPU 分开。

结果表中的空时间、空能耗表示没有对应的证书或达标交付。首次达标取每一份按时交付的安全证书，严格改善采用新上界低于原下界。阶梯图从各单元第一份安全排程开始，最后持有的排程延至预算终点。
