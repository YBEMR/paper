基于143629e的未进入求解器记录，独立派生执行器；旧7b723b1代码、300秒计划和已消费授权均不修改、不复用。**当前未批准，未运行。** 输入仍为完整12次Stage／66模式auto-L R1的保存ON互补门控矩阵；不构模、不重新生成系数、不改目标、物理精度、容差或求解算法。该候选是数值入口诊断，不是端到端方法性能样本。

父起点420秒覆盖读取、身份核查、导入、初解完整评价、MATLAB启动、传输、求解、原／新行准入、解码及最终完整评价。最多一次原生请求、最多两次完整评价（初解和最终返回候选）。原生MaxTime固定240秒；预留10秒传输／调用开销及50秒验证。

- 在MATLAB就绪后及发布求解请求前均计算`420−已用时间−10−50`；不足240秒则无调用停止，不缩短时限或补跑。
- 传给原bridge的求解／响应预算使用独立绝对截止`父起点＋370秒`，父方法截止仍为420秒。并非仅在请求前检查一次“预留”。求解器和回调证据须在370秒前收到；原行验证及完整评价可用剩余时间，但必须在420秒前完成。
- 本机原生超时不是硬实时中断。原MATLAB脚本仍执行其内部保护；若实际MaxTime被缩短，标记设置偏离，不冒充240秒样本。方法与响应截止没有展期；进程看门狗500秒只服务清理，不产生新证据。

控制代码保留初解、新SAFE、严格能耗改善和下界的不同含义。仅返回同一初解不算改进；同一调度出现不相容的能耗改善区间会标记一致性冲突。原生有限界仍需与数值准入点的MILP目标核查，不能冒充独立严格证书。为避免将0等平凡界算成科研进展，在预算内从目标系数及变量上下界直接计算精确binary64有理数下界；只有原生界超过该界，才记“超越平凡界”。该计算不运行LP、不改任何约束。实际界数值本轮未计算。

根LP进入、后续阶段、候选向量、完整SAFE、超越平凡界和严格改善逐项保留。无调用与数值求解失败分开。正常超时即结束，不能重试；任何结论均以完整来源、设置及进程清理证据为条件。一次性目录采用新的固定名称，且审核新的计划SHA；旧授权不能通过新方案检查。
