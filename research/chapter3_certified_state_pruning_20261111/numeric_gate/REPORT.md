# 联合状态剪枝的归档数值前置验收

三项只读前置验收均通过：原2938个候选不可达state的29380条电热行在门关闭时对**实际导出binary64变量盒**严格冗余；原依赖路径见证在实际导出调度行上仍有严格正的排除余量；决定rho/w逻辑状态的原控制行均与活动选项和状态目录精确匹配。没有用1e−9容差掩盖任何正违反。

这些结果针对已归档完整auto-L R1 ON。它们允许继续小域验收，不替代生产实现和新模型的核查，也不单独授权完整R1新OFF/ON构模。此子任务0构模、0LP/MILP、0热评价，仅写本numeric_gate目录。

## 数据身份与方法

来源为`research/chapter3_support_autol_lp_20261111/autol_build/rev02/`的原实例、options、变量名及exported_model.npz，和`research/chapter3_joint_state_static_20261111/`的原不可达证书/逐行元数据。三个plan逐文件冻结SHA-256，并在运行及结束时检查源文件不变。没有重建矩阵，未读取新的调度结果。

实际A、b、lb、ub的binary64数通过`Fraction.from_float`当作精确有理数。CSV/JSON内的有理余量是依据；十进制float只作阅读。原exported_model.npz的intcon是零基索引，已核对所有1125个option y为原整数且界[0,1]。

## 1. 被删状态的电热行在w=0时冗余

从2938个归档state证书定位w列，再按行族和实际A列定位每state的10条条件电热行，恰为29380条。令实际导出行是a·z≤b，将其门变量固定0，在其余实际导出界上逐坐标取精确最大值：

`max(a·z | w=0, lb≤z≤ub) = Σ_{j≠w} a_j·(ub_j if a_j≥0 else lb_j)`。

全29380条的`b−max`均为非负，且最小也严格正：

`277 / 4722366482869645213696 ≈ 5.86570315973603e−20`。

失败0，最大正违反0。这里用的是导出后的外扩float界，未偷换成内部原有理界；是整个独立变量盒上的冗余证据，比只检查某些物理轨迹更强。逐行行号/tag/门名/精确最大LHS/RHS/余量见`gate_zero_rows.csv`。

## 2. 不可达见证覆盖实际导出调度行

独立从A和元数据核对12个Stage的一热上下行，系数恰±1、RHS恰±1；原8条dependency行按实际变量所属Stage和符号与原依赖边对应。

原54440个阻断见证组合全部重放：

- 29928个同Stage组合：不同资源域的见证选项集合不相交，任意完整选择若同时提供这两个见证就至少选2个该Stage选项，与原精确Stage一热矛盾。
- 24512个依赖路径组合：合并路径上的实际binary64 dependency行；在每个完整Stage一热组上取合并系数的最小值，端点Stage只允许对应见证组中的原option，其余Stage保留完整原选项域。若该最小LHS仍严格大于路径RHS之和，则不存在提供这两个见证的原整数y点。

24512次重放对应2392个不同路径/端点子域数值检查，全部严格正，最小余量约`0.0013333333333329733`（原时间系数为秒）。将每路径行RHS另放宽1e−9后，最小余量仍约`0.0013333323333329734`。没有非正余量被当作排除证据。精确余量、路径行索引、端点option身份及各Stage最小项见`dependency_unique_certificates.json`。

1e−9的附加核查只说明在**y仍是精确整数、Stage仍精确一热**的合同下，路径行轻微RHS松动不能支持这些见证；它不是“所有允许近整数的求解器接受管道都不变”的证明。

## 层级与后续实现风险

归档证据将此前仅基于精确时间语义的必要性推进到了这份实际导出矩阵的整数y语义，并严格核查了删行的门关闭冗余。未声称保持LP松弛全部点；剪枝本身可以删去不对应整数调度的分数状态。也未声称保持任意求解器容差认可的近整数点。

新生产实现仍必须核对自己的onehot和依赖导出行；遇到不可靠、非正余量、超限或未知，保留state或按明示合同失败。已删state的实际条件行需再次按新模型导出盒审计，不能仅凭旧归档通过。首版保留原energy盒、事件、温度/q盒和存活状态系数可以避免无关变化。energy_state_lower_bound原/新都是整数状态原行的必要加强，但重建后的来源行/一热证书需要单独核对。
