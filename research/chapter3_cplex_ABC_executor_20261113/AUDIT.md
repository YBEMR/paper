# D284 执行后只读审计方案
本轮仅准备；没有执行正式 A/B/C，也没有独立审查者批准文件。

1. 核对新批准绑定提交、计划和源码 hash；检查一次性批次目录，三个独立 arm claim 与进程身份、各组最多一次完整构模与 solve。允许零次 solve。
2. 验证每组重新归档的原矩阵与互补矩阵、输入、选项、约简复核和精确投影证书；检查三组只有两个约简开关不同。不能借用历史证书替代本组认证。
3. 核对原生参数完整读回、版本/DLL、完整 MIP start 的原生读回与实际接纳日志；存入/读回不等于接纳。
4. 核对共同启动成本等额扣除、独立构模/初始化/认证/读回/求解/验证/归档/清理时间；父进程响应到达 <550、科学快照验证 <590、最终归档/清理 <600。外层 *_outer_completion 和 *_outer_budget_invalidated 必须检查。
5. 原生日志、回调、最终向量分别归档；检查最终向量来源与完整字节 hash。未记录的内部事件保留 UNKNOWN，不从下界存在推断根 LP 已完成。
6. audit_result.py 对该组归档原/互补矩阵用逐行 math.fsum 重算数值残差，重核整数列、界和区间比较。形状来自本组矩阵，不固定为 C 的 23780 维。该脚本只能撤销，不能增加成功。
7. 独立核对调度差异、完整 AB/AC SAFE、初解/最终能耗区间及严格序关系。数值残差检查不是精确有理数 primal 证明；现有 SAFE 审计使用封存的原评价器证据，不声称第二套物理实现。
8. 检查累计停止集合以及跳过组原因；清理异常、身份错误、许可错误和下界冲突不得被后组超时覆盖。对普通超时，不将缺少候选写成数学不可行。
9. 列出每组分层结果、下界来源、gap、节点、原生配额、总成本与未知项。不得将本次 C 与历史 intlinprog A/B 或 D283 保存矩阵 C 拼成加速结论。
