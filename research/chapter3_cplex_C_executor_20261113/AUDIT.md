# D283 独立审计清单

本文件是下一次科研调用的审计方案，不是批准，也不是已取得科研结果。外部审查者可直接复核以下证据；执行者不能代写其审查结论。

1. **调用前身份。** 核对新用户批准、冻结提交、plan SHA、14 份源码、90 份输入历史、229 份研究源、41 份运行时文件和包版本；实际批准必须晚于本冻结成果，且只绑定一次 C 调用。D282 的消耗记录保持原样。
2. **模型与初解。** 从本次 input_identity/readback 核对全部冻结矩阵、原变量前缀、整数索引、投影证书、原生回读。start 的完整存取与实际接纳分开；确认无候选替换、整数-only fallback 或修复。检查唯一 solve 来源及参数设置/回读。
3. **时间。** 检查根钟早于导入/启动/读取，配额精确满足冻结函数；response_ack 是父进程完整读取向量后的时间且<550；科学快照父进程核验<590；最终控制/归档/清理<600。原生日志/回调的 worker 时间不能替换 parent 接收时间，迟到记录不计科研进展。
4. **来源。** 检查 callback_vector 与 final_vector 不混淆，最终向量来自唯一原生返回；无最终向量时不能用共同初解/某次回调补位。原生下界、上下界和 gap 都注明原始 API 来源及是否无穷哨兵，根 LP 需明确日志证据。
5. **数值和能量。** 审计程序用独立逐行加和复核两份矩阵残差和整数距离；审查者另按已封存向量、目标与原生界核对数值一致性。查看原独立调度合法性及原 AB/AC 完整 SAFE 记录。严格改善只能由完整能耗区间端点的有理数严格不等式得出，且调度身份必须不同。没有独立最优性证明就保持未知。
6. **成本与失败。** 检查原始 native_error、stderr、资源采样、Job 峰值/最终活动数、退出码、句柄释放、所有阶段成本。内存拒绝没有错误文本时保留退出码和资源证据，不能猜测错误根因。原生内存/数值错误停止评价；普通时限不是不可行证明。清理失败或影响范围未知时保留累计全局停止，不因后续普通结果清空。
7. **最终判定。** `audit_result.py --workspace <原工作区> --plan <冻结plan> --run <本次执行目录>` 只读已有矩阵/回执，不导入 CPLEX、不重构或热评价。输出可撤销原信用，不能将 false/unknown 升为成功。事后审计属于行政核查，不能补足方法窗口内缺失的科学工作；审计时间单列。

控制测试覆盖本清单中的拒绝分支和独立残差/区间算法，但尚无真实 D283 回执可审计。科学执行后应核查本次实际证据，不能以控制测试结果代替。
