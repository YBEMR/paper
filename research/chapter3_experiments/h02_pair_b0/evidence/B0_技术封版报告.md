## 3．已接线的真实路径（尚未真实执行）

```mermaid
flowchart LR
  C[Controller：起算120秒] --> I[读取H／展开／投影R／静态合同／身份]
  I --> P[独立planner worker：只收本视图]
  P --> H[原execute_heuristic与改造HEFT]
  H --> R[原Recorder／合法性／本视图连续评价／下界]
  R --> E[核对最终SAFE与best，原样冻结]
  E --> A[另起60秒：一次真H后验worker]
  A --> V[原validate_schedule／evaluate_candidate]
  V --> O[真H回执归档或停止]
```

具体绑定：`backends.resolve_real_bindings → heuristic_runner.execute_heuristic(method='heft',allow_auto_low=True,seed=None)`，显式传`partial(heft_method.run_heft,allow_auto_low=True)`及`thermal.evaluate_candidate`。不依赖定义时绑定的默认evaluator；auto-L内部`partial_bounds.independent_lower_bound`使用同一个根预算和视图。导入legacy `q1_case`不等于采用Q1负载，实际输入仍为完整`base__R1/R2`。

planner wrapper仅替换计时工厂及只读Recorder观察器，原HEFT规则和Recorder选择准则不改。观察器在`finally`保存已产生的best／回执／见证原子检查点，不修复、补评或调整候选。正常返回必须满足顶层`state=SAFE`，候选、完整evaluation、upper与source全部等于“已接纳最小upper、并列首项”的Recorder.best。最后一个SAFE及`search.local_base_candidate`不能代替。正常NO_SAFE同样核对输入、问题和120秒身份。

真H入口由`backends.audit_chain`实现：原样解析冻结candidate，验证真H配置／instance、raw／semantic双hash、来源、策略、精度及R/H身份；独立调用原`validate_schedule → evaluate_candidate`。校验器在评价器内再次执行也计入60秒。后验仅归档，没有反馈给规划器、修复或再选候选的回调。

## 4．进程与数据身份

controller保有原H配置、H/R配对信息及静态合同；每槽重新读取和构造，不共享候选、热缓存、见证或历史答案。

planner_H只收H公开视图；planner_R只收独立R公开视图，其config profile、mode及平均alpha全部为1。worker由`-I -B`独立Python解释器启动，使用源码白名单部署；包中没有`config_v01.json`、旧结果、A证据、真H参数表或后验回执。R只读自己的公开job、受信源码和标准库；H私有输入／后验位于其他目录，文件白名单拒绝读取。必要的授权／启动claim只含身份、槽位、预算等元数据，不包含真实H alpha或评分。

后验另建私有目录，只收本槽真H、冻结candidate和身份信封；先前planner进程已结束。所有job及返回绑定内容hash，输入副本／目录／Recorder缓存独立。部署时逐文件核对29份运行源码及2份策略文件，原数学源码字节不变。

**边界：这是受信Python代码和应用层访问守卫，不是OS沙箱。** 不能抵御同账号恶意native代码、人工改源码／权限或外部进程篡改，也未以真实HEFT运行验证全部动态行为。该信任范围须由独立审查确认；若要求OS级抗恶意隔离，仍需另行处理，当前不能声称具备。

## 5．预算、迟到与一次消费

| 环节 | 起算与截止 |
| --- | --- |
| 单槽规划120秒 | parent monotonic origin先于本槽输入读／展开／H→R投影／核对／部署／交接／worker启动和import；worker继承同一origin及完整120，不另发剩余时间预算 |
| 单次后验60秒 | 独立parent origin先于消费claim、读取封存H／candidate、hash／解析、合法性和连续评价；任何异常不重置 |
| 证据截止 | 完整receipt形成时刻严格小于120／60；等号、非有限、bool或缺失时间不接纳 |
| 外层监督 | 每50ms检查worker；根截止进入只归档阶段，固定5秒后发终止并记录实际停止延迟。宽限不是新增研究预算；不宣称OS硬实时终止 |
| Controller输入段 | 根预算在计费，读／展开前后及启动前协作检查；watchdog监督已启动worker。若父进程本身被系统IO卡住，不保证在阈值瞬间结束，不能把这段移出耗时 |
| 迟到回执 | 只保留截止前已形成且身份完整的证据；正常截止后的序列化不补搜索、热计算或候选选择 |
| 强制终止 | 保存原始回执和已发布检查点；没有完整最终方法回执时，不把prefix猜成最终best，不自动触发H后验 |

三个消费层次均使用排他创建：①固定authority_store中的唯一authorization_id绑定唯一运行目录，换输出目录／复制checkout不能重用；②每槽planner及每candidate后验claim；③内部worker再次核对并消费同一启动claim，直接重复worker命令也不能另获预算。崩溃、超时、输入错误或数值未决均不退款、不重试。

真实gate当前为false，批准引用、授权ID和唯一运行目录留空。未来只允许在用户另批后登记授权元数据／开启执行字段并重新绑定其hash；**科学policy hash不变**，修改槽位、算法、次数、预算等会失败，不能靠重新hash把范围漂移洗掉。

## 6．INVALID分类及异常保留

六项可验证的真实约束reason为`BEFORE_RELEASE`、`WINDOW_EXCEEDED`、`REQUEST_DEADLINE_EXCEEDED`、`DEPENDENCY_VIOLATION`、`EXECUTION_UNIT_OVERLAP`、`FREQUENCY_DOMAIN_CONFLICT`。逐项对照原候选Stage、请求、依赖边、真H时长和半开区间重算具体不等式；不签发整张安排SAFE。

`MALFORMED_INPUT_OR_CANDIDATE`、`UNSUPPORTED_IDLE_POLICY`、输入／模式／计量错误、未知reason及伪造／不足证书统一`INPUT_OR_INTERFACE_ERROR`并STOP。启动网格和共享部署已受前置身份约束；仅给domain而无可核查Stage证据的reason也保守作接口异常。它们不是科学不可行证据，更不是单调性反例。

只有已冻结完整R-SAFE、同候选及P1/P2合同有效，并得到已核实约束违规或可信点温度见证时，才触发`MONOTONICITY_CONTRACT_ANOMALY`。普通数值未决不作违规。技术状态递归检查到scene层；保留已有见证／best同时技术STOP，不继续后验或下一槽。

外层截止时先保存已返回的合法性原回执；若证书分类未在60秒内完成，仅记未决，不能补为新违规证明。后验超时或失败不会擦除原规划SAFE身份。真实worker已进入后再异常，计量记未知或读取原始entry/claim，不能一律虚报0。
