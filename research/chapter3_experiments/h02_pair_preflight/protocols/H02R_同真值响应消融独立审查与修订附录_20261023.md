## 1. 冻结事实与不可混淆的两种模型

唯一真实系统：主线 `base__R1` 与 `base__R2` 的非统一 H 响应；400 ms 完整窗口、5 ms 起点网格、AB/AC 独立场景各权重 1/2，A 的同名 Stage 在两场景共享具体执行设备；CPU1/CPU2 共用一个 CPU OPP 域，GPU/NPU 各自独立；域空闲立即回 L。四节点初温 50°C、环境/参考温度 25°C、温限 80°C、模型适用范围 20—100°C；外部 0.30 W 计入能量、不注热。主线 H 是**声明的抽象真值**，不是实测硬件真值。

R 不构成第二套真实物理平台。R 是同一物理系统下**规划器对持续时间响应的错误/近似认识**：每个合法 Stage-执行单元-OPP 的 `d_ref`、`q_ref`、频率、电压、域基准、热网络和请求合同不变，仅使规划响应 α=1，并准确重算受影响的时长、活动能量及规划内推导值。历史 P1 的 `response_R__Rj` 不能直接作为另一套真实系统参与最终能量比较。

固定 Stage 模式，令参考 OPP 为最高 H，有

\[
d^H=d_{\rm ref}\left[(1-\alpha)+\alpha\frac{f_{\rm ref}}f\right],
\quad
d^R=d_{\rm ref}\frac{f_{\rm ref}}f,
\quad
q=q_{\rm ref}\left(\frac V{V_{\rm ref}}\right)^2\frac f{f_{\rm ref}}.
\]

主线原始各 profile α∈[0.1,0.9] 且 `f≤f_ref`，所以 `d_R-d_H=d_ref(1-α)(f_ref/f-1)≥0`；最高档相等，低档 R 单向高估。`activity_power_W` 必须严格相等，`activity_energy_J` 在每个规划视图按 `q*d/1000` 计算。

## 2. 数学命题、证明边界与可检查条件

### P1：固定候选合法性保持（成立）

对同一个完整 candidate 的各 Stage，固定其**绝对** `start_ms`、`unit`、`opp`。由于 `d_H≤d_R`，H 的半开执行区间逐项包含于 R 的相应区间。若 R 下全场景 Stage 完整、模式合法、起点合法、资源互斥、同域同 OPP、DAG、release、deadline 和窗口均合格，H 下不会新增执行重叠、同域异档重叠、前驱未完成、期限或窗口违规。所需前提还包括两个视图相同的 Stage 身份/支持集合、同一 `start_domain` /网格、同一静态部署约束、不改变候选起点和无额外切换延迟。

**P1 不是“任何 R 规划过程都必定找到 SAFE”**；HEFT 可以在有限预算内没有构成完整候选，也可以在数值评价时 `UNRESOLVED`。

### P2：固定候选连续温度与能量的比较（条件成立）

定义温升 `x=T-T_a`，并要求 `T_ref=T_a`。相同 candidate 在 H/R 两视图重建功率，形式为

\[
C\dot x_X=(-G+\Lambda_X(t))x_X+b_X(t)+a_X(t),\quad X\in\{H,R\}.
\]

需要对**每个节点、每个时刻**成立：

1. `C` 正对角，`-C^{-1}G` 非对角非负（Metzler），导热为被动接地网络；
2. 初始化 `x_H(0)=x_R(0)≥0`，非负注热使 `x_R(t)≥0`；
3. H 活动区间包含在 R 的相应区间内；控制域在活动时取该模式 OPP，完全空闲时**立即回 L**，无额外延迟、滞回或切换能耗；
4. 各域 L/M/H 的基准功率、逐节点漏电斜率非负且按档位非递减；OPP 对基准热源的空间分配非负且两视图一致；活动功率与注热位置逐模式相同且非负；
5. 功率参考温度与环境均 25°C；能量积分在同一个完整 400 ms 窗口，外部公共功率相同且无局部注热；
6. R 的整窗温度已证在物理模型有效温区内；H 的下限可利用 `T_a=25°C>20°C` 和 `x_H≥0`，上限由比较及 R SAFE 约束保证。

令 `w=x_R-x_H`，则

\[
C\dot w=(-G+\Lambda_H)w+
(\Lambda_R-\Lambda_H)x_R+(b_R-b_H)+(a_R-a_H).
\]

后三项逐节点非负，线性演化算子正，因此 `w(t)≥0`，即 `T_H(t)≤T_R(t)`。再根据各时刻相同活动源与 OPP/温升的单调功率关系，可得固定 candidate 的 `E_H(\pi)≤E_R(\pi)`。该式**不意味着不同候选** `E_H(\pi_H)≤E_H(\pi_R)`；后者只可经 H 真值评价确定。

**已读主线配置支持这些前提**：热容 `(0.04,0.04,0.08,0.06)` J/K 均正；导热矩阵对称、非对角非正、各行和正；CPU/GPU/NPU L→M→H 的域基准和逐局部节点漏电斜率递增；各域的 `baseline_heat_distribution` 非负且和为1；各活动源对应执行单元的局部热节点。CPU 基准**按整个共享域一次计费**，其漏电斜率按 CPU1/CPU2 两局部节点适用，不能复制一个 CPU 基准收费两次。

**特别注意**：现有 `resolve_idle_policy` 会验证 auto-L、零开销、L 为最低频点，以及部分非负项，但**并没有完整证明所有域基准/漏电斜率在 L/M/H 上逐档单调**。因此主线⑦必须新增仅检查冻结配置的静态合同门，不能因控制策略字符串匹配就视 P2 全部假设已通过。

结论形式：若 R 规划已取得**完整且在 R 模型中有严格 SAFE 回执**的固定 candidate，则该 candidate 在数学真 H 中应合法、连续热安全，并且真 H 能量不超过该 candidate 的 R 预测真模型能量。**这不保证 60 秒真 H 数值评价必能发出 SAFE 证书**：精度或预算不足可返回 `TRUE_H_UNRESOLVED`，而非宣称模型违例。

## 3. 配对视图的精确数据隔离合同（实施阻断项）

### 3.1 同一问题身份、两类视图

每个 `base__Rj` 的只读原始 H 源经正式 auto-L 适配后，形成单独密封的 `truth_H(j)` 与 `planner_H(j)`。R 视图是从该问题的 H **规划实例副本**进行响应投影，绝不能读 P1 旧实验结果、旧 SAFE 种子或 H 后验缓存。R 的 config 也不能留有 H 真值 profile α 或 H 加权平均 α。

**当前源码的具体陷阱**：
- `inputs._expand_modes` 依据 `response_variant='R'` 生成每个模式时长 α=1，但 `_mean_alpha` 仍从原始 `stage_catalog.profiles[*].alpha` 计算；单独切换标签不会清除 R 视图配置/实例中的真实 H α 信息。
- 若简单把根 `defaults.response_variant` 改为 R 后再次调用 `build_instance`，现有 `build_instances` 还会遍历 `conditions`，导致 `base` 与 `response_R` 有相同有效 `settings`，触发“Duplicate effective condition”。**不得借修改原始物理条件、合并历史条件或改已有输入生成器的全局语义来绕开**。建议先以原始 base/H 建合法实例，再通过独立、纯函数投影构造 planner_R，并明确不对投影后的全局 R config 重新运行原多条件枚举构造器。
- `heft_method.run_heft` 使用展开 `instance`，进入搜索后不读 config，但运行器使用 config 精度/控制声明；为将来其它消费者防泄漏，不能依赖“目前 HEFT 不读原始 α”作为合同。

### 3.2 精确白名单

对 `planner_H` 与 `planner_R` 作按字段**逐值**检查；只允许以下规划信息或其必要派生字段改变：

| 层 | 允许变化字段 | 必须满足 |
|---|---|---|
| 规划 config（不是真值 config） | `defaults.response_variant`；`stage_catalog[*].profiles[*].alpha` | R 假设标为 R；R 能读取到的 profile α 全为1；其它功率/时长参考数值不改 |
| 规划 instance | `response_variant`、`settings.response_variant` | R 仅标记规划响应假设；`id/condition_id/sample_id/experiment_group` 与 H 一致 |
| 模式表 | 每个 `stage_modes[*][mode_id].alpha`、`duration_ms`、`activity_energy_J` | R α=1，时长用精确分数公式，能量=`activity_power_W×duration_ms/1000` |
| 响应统计 | `catalog_duration_weighted_mean_alpha` | R 统计由 R 已遮蔽 profile 重算为1，不留 H α |
| 后续规划内部变量 | 预计结束、候选可行性、控制驻留、温度/预计能量、搜索先后 | 只可由本视图重算，属于结果而非外部输入变更 |

在两个视图间**绝不允许**改变的项目至少包括：所有 Stage/scene/request 身份和支持 `mode_id`，`d_ref_ms`、`q_ref_W`、`activity_power_W`、OPP 频率/电压、基准及漏电参数、热节点及 `C/G`、模型温区、入口温度、场景权重、DAG、release/deadline、`start_grid/start_domain`、400 ms 窗口、auto-L 的全部控制规则与 entry OPP、精度目标、外部公共功率。列表外差异一律拒绝，不因“看似只改变描述字段”而默许。

实现时按 `(stage_id, unit_id, opp_id)` 匹配模式表，拒绝重复键、缺失键和换序伪装；保留原 JSON SHA，并增加**按身份规范化**的语义 SHA 供比对。验证 `d_R≥d_H` 及 H 档相等。若两候选选出完全相同的设备、OPP、绝对起点，其 H 真值能量应一致（容许评价区间误差）。

### 3.3 身份与访问边界

至少保存：`source_commit_sha`、`truth_H_sha256`、`plan_H_sha256`、`plan_R_sha256`、`physical_projection_sha256`、`support_sha256`、`scenario_sha256`、`policy_id`、`accuracy_sha256`、`candidate_raw_sha256`、`candidate_semantic_sha256`。物理投影必须先用显式白名单**剔除/规范化响应假设及其派生量**，不能用一个宽泛“删除所有不同字段”功能掩盖其它物理差异。

R 规划器的 input loader、方法回调、缓存、日志或停止条件不得接收 `truth_H`、真实 H profile α、H 评价回执。审计器只在规划 candidate 冻结和哈希后接触真实 H。故意注入泄漏、不同功率参数、非法场景/OPP/预算身份的模拟负例，均应在零正式调用预检中被拒绝。

## 4. 已有接口、遗漏项和接纳条款

现有 `schedules.validate_schedule(instance,candidate)` 只接受 Stage id/具体执行单元/OPP/绝对起点，使用传入 instance 的模式时长重新构造完整多场景合法性和整窗分段功率。`thermal.evaluate_candidate(instance,candidate,accuracy,budget)` 检查连续温度峰/最低值、模型适用温区及全场景能量区间。`heuristic_runner.execute_heuristic` 在规划视图内保存经过 `CandidateRecorder` 接受的 `safe_candidate`，不会自动提供双视图/单真值配对。

新 `truth_H_post_audit` 只能：冻结原候选→核验来源与 SHA→在真实 H 用 `validate_schedule` 原样重建结束时刻→以新的单次后验预算调用 `evaluate_candidate`→核验全部场景、连续 SAFE、能量区间及严格截止时间；**不能**修改起点、挪动后继、更换OPP/执行单元或选取规划途中其它候选。后验候选绝不反馈规划器。

接受 `REAL_H_SAFE` 的充要接口合同（数值证据层面）：Stage/scene 全部齐备；合法性通过；评价器 `state='SAFE'` 且 `rankable_energy=true`；加权能量区间完整且上下界有序、`safe_upper_bound_J` 等于上端；后验接纳时间 `completed_at_elapsed_s<60` 且源/真实输入/候选哈希一致；物理模型的连续峰和适用范围得到证明。现有 `thermal.Budget`/`MethodBudget` 属于协作式检查点机制，需另存启动/结束时间和外部监督证据，不能将 720 方法+后验预算误称为总墙钟强制上界。

建议状态：
- `PLAN_SAFE`：规划视图有完整、及时、已接受 SAFE 候选。
- `PLAN_NO_SAFE`：已正常完成预声明有限搜索，但没有形成规划 SAFE（**不是不可行证明**）。
- `PLAN_UNRESOLVED`：预算/计算/接口中断，未有完整规划 SAFE。
- `TRUE_H_SAFE`：完整真实 H SAFE，可以按严格能量区间排名。
- `TRUE_H_INVALID`：明确 Stage/互斥/DAG/期限/窗口等合法性违规。
- `TRUE_H_THERMAL_VIOLATION`：物理模型有效温区内的真实连续超温证书。
- `TRUE_H_UNRESOLVED`：精度、超时、模型温区无法确认安全或数值结果不完备。
- `INPUT_OR_INTERFACE_ERROR`：输入差异、身份冲突、泄漏、回执或物理合同错误；不得当作研究负结果。

**异常停止约束**：若在完整 R-规划 SAFE、P1/P2 预检均通过且原 candidate 未变的条件下，H 后验给出明确资源/DAG/期限或热违反证书，应标记 `MONOTONICITY_CONTRACT_ANOMALY`、封存证据并暂停其余调用。先查数据路径、策略、候选身份、数值证明是否一致；不能直接发表为“R 建模导致真实违规”。`UNRESOLVED` 本身不是数学反例。

## 5. 固定四槽、预算、指标和不支持的外推

| 槽 | 问题 H 真值 | 规划信息 | 真实后验 |
|---|---|---|---|
| 1 | R1 | H | R1/H |
| 2 | R1 | R | R1/H |
| 3 | R2 | R | R2/H |
| 4 | R2 | H | R2/H |

同一个现有确定性改造 HEFT，`execute_heuristic(method='heft',allow_auto_low=True,seed=None)`。每槽**120s 根方法预算**（方法所需输入读取、内部评价和搜索均计入），每个成功冻结的候选仅**一次 60s 真 H 独立后验**，总最多 480+240=720 方法/后验秒；输入前置纯检查、封存和归档另外列账但不得制造或延长研究 SAFE；外层 watchdog 由⑦在单独授权中锁定。没有规划 SAFE 时不补候选、不补方法、不恢复旧缓存。无正式授权不得跑这四槽。

同时保留两个真实 H SAFE 才可比较真实能量。若

\[
\overline E_H(\pi_H)<\underline E_H(\pi_R)
\]

才认证该题 H 响应规划严格节能；若反向区间严格分离，则 R 更优；相交称 `ENERGY_ORDER_UNRESOLVED`。相对效果以 **R 规划候选在 H 真值下的系统能量**作分母，而非 R 的预计能量：

\[
\eta=1-\frac{E_H(\pi_H)}{E_H(\pi_R)}.
\]

在双方真实能量严格为正时按 H02 的上下界公式报告认证区间。外部 0.30W×0.4s=0.12J 虽不改变两方案的绝对能量差，仍必须计入完整系统能量与相对节能分母。

结论只允许覆盖所选 `base__R1/R2`、声明的抽象 H 和既存改造 HEFT（含其一遍能量下降尝试）的预算内结果。不得宣称统计普遍性、真正硬件测量、算法最优性或单独“截止期模型改进”的收益。C19 的共享域计量非可加性证据是**另一独立命题**，不得当成本消融的实证结果。
