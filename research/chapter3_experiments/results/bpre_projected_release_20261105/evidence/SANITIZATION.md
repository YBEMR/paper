# 脱敏与哈希规则

- 采用白名单提取：源码及测试、输入/配置、投影证书、三完整已提交回执、在线初解、必要原生事件与响应、预算和清理记录。去除重复完整控制器/worker 输出、海量内存采样、原运行环境、授权凭据及二进制。
- 原工作区前缀符号化为 `<WORKSPACE>`；其他本机可执行路径符号化为 `<LOCAL_PATH>/文件名`。JSON 字符串内的路径（包括异常文本中双重转义形式）同样处理。
- 敏感字段如会话令牌、口令、账号、授权信息的值替换为 `<REDACTED>`。源码中的令牌创建/核验逻辑和测试用 `offline-token` 是代码或固定测试夹具，不是本次会话凭据；保留以便审查。
- JSON 以 UTF-8 紧凑格式重写；科学数值、区间十进制字符串、源哈希、状态和时间均保留。公开文件标识 sanitized，不把重写后的字节声称为原始字节。
- `provenance.json` 每条记录注明源文件的工作区相对路径、原字节 SHA、提取位置和公开副本 SHA。嵌入证据中的原 SHA 仍指向原始内容，不要求其等于脱敏后文件 SHA；投影内部 `certificate_sha256` 也不等于整个 JSON 文件的 SHA。
- `SHA256SUMS` 覆盖除其自身以外的全部公开文件；源码并未由于脱敏而被重新试验验证。
- 最终扫描覆盖完整公开目录的文本、路径和凭据模式；扫描器对固定词的误报按上下文核查，保留数值中偶然重复的数字，不以删除科学数据来消除误报。
