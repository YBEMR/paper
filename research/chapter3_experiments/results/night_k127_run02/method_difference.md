# 原输入N1与HEFT输出差异：搜索范围与能量记账

**本次HEFT输出更低能耗、方法调用更短；N1仅开放本地后缀，确实冻结了HEFT采用的若干决定。** 这解释了为何K.126的初始化改善不能直接推成优于HEFT；尚未证明单个决定的因果收益，也没有证明任一安排最优。

本记录只读取`base_n1/result.json`、`base_heft/result.json`及各自输入副本，按已存模式时长和能量回执作精确有理数加权／相减。未构造新安排、重放温度、调用求解器或进行反事实评价。两输入的场景权重均为1/2，完整窗口400 ms，原80°C温限及auto-L策略相同。

## 1．实际输出

| 指标 | N1 | HEFT |
|---|---:|---:|
| 预算内最终完整SAFE上界/J | 0.962884840560 | **0.881087997281** |
| 方法耗时/s | 139.828 | **46.047** |
| 首个完整SAFE/s | 0.969 | 0.765 |
| 最终来源 | 本次种子N1内层MILP | 原HEFT能量下降遍历 |

HEFT上界比N1上界低0.081796843279 J，约为N1输出的8.4950%。两份完整能量区间严格分离，差距远大于其误差宽度；保留原区间作为判断依据，表中数值仅作显示。单次耗时不构成统计加速结论。

## 2．N1冻结、HEFT实际改动的决定

N1的外层共享A指定为`CPU1→NPU0→CPU1`；本次新种子还固定所有Stage设备。A三个Stage及本地B/C的pre保持种子的频点与精确起点，只有B/C的main、post可变原合法频点／起点。

| 决定 | N1最终／冻结内容 | HEFT最终内容 | 是否超出本次N1搜索范围 |
|---|---|---|---|
| 共享A.pre设备 | CPU1 | **CPU2**，两scene一致 | 是，共享具体单元被冻结 |
| A.pre频点、起点 | H，0 ms，两scene相同 | **L，5 ms**，两scene相同 | 是，A频点／起点被冻结 |
| A.main频点 | NPU0-H，两scene相同 | **NPU0-L**，两scene相同 | 是；两方法均未更换此Stage的设备 |
| A.main起点 | 两scene均10 ms | AB为**70 ms**，AC为**20 ms** | 是 |
| A.post频点、起点 | CPU1-H@40 ms | CPU1-**L**；AB@115 ms、AC@70 ms | 是 |
| B.pre设备、频点、起点 | CPU2-H@0 ms | **CPU1-L@0 ms** | 是 |
| C.pre设备、频点、起点 | CPU2-H@0 ms | **CPU1-L@5 ms** | 是 |
| B.post设备 | CPU2 | **CPU1** | 是，虽然该Stage频点／起点开放，设备仍固定 |
| B.main频点／起点 | NPU0-L@85 ms | NPU0-**M@25 ms** | 频点／起点本来开放；单行选择不被N1单独禁止，但HEFT整套安排不在其域内 |
| C.main频点／起点 | GPU0-L@40 ms | GPU0-L@25 ms | 频点／起点本来开放；两者都选L |

因此，HEFT保留跨场景A共享部署要求，并未违反问题约束；只是选择了另一个共享A单元及频点／时序。A在两scene的频点恰好相同是本次结果，模型本来允许场景间选择不同频点。

## 5．对本次公平比较的含义

- 可以说：同原输入、同300 s上限及同完整连续安全接纳条件下，**本次HEFT输出优于本次N1**；这是真实应保留的限制结果。
- 可以说：N1证明在本次新初始化之外存在可找到的严格安全改善，但局部开放范围遗漏了HEFT实际使用的自由度。
- 不能说：N1在其邻域已最优、打开共享A必定得到这份HEFT结果、某个冻结决定独自造成全部差距，或HEFT普遍优于MILP。
- 不能将整体MILP的尚未收敛、N1局部内部界、HEFT非完备遍历的节点／状态混作同范围证明比较。

夜间不因该输赢增加N2或改变已冻结方法。下一阶段若讨论扩大优化范围，应先承认上述搜索范围差异，再决定是否有必要调整求解组织；本记录不启动该工作。
