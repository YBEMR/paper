# 完整三Stage小域精确对照：静态设计v1

**建议保留此域，先适配共同接口，再单独申请有界成本预试；现在不申请完整穷举／MILP预算。** 本目录只设计、计数和核对静态调度合法性；没有热积分、能量评价、优化求解或新SAFE。

## 1．从什么原输入派生

唯一读取K187归档`method/input_instance.json`，原字节SHA256为`01eacb2a653d56419c32f38740021a787ea01ac9e7ade407bef2edd81ec6ef89`。不读取历史候选、初解、最优时序、能量或热轨迹。输出[restricted_input.json](restricted_input.json)保留AB/AC两场景、12次Stage执行、9个共享Stage身份、全部pre/main/post、原H时长／功率、四热节点、400ms窗口、5ms网格、期限、50°C入口、80°C温限、场景权重及auto-L。

这是**主动限制的独立质量参照域**，不是原P0完整域，也不是新的硬件支持声明。

## 2．预先声明的缩域规则

| 对象 | 保留范围与由来 |
|---|---|
| A.main | CPU1／GPU0，各M/H；CPU与加速设备分别按原合法unit ID字典序取首个 |
| B.main | CPU1／NPU0，各M/H；同一规则 |
| C.main | CPU1／GPU0，各M/H；同一规则 |
| 所有pre/post | 原CPU2/H模式；取字典序末CPU，不删除Stage |
| pre起点 | 请求原释放向上对齐网格，加应用字典序序号×本场景最大pre/H时长向上对齐值；本输入A为0，B/C为15ms |
| main起点 | 本请求pre结束向上对齐，以及再晚一个原网格；A为10/15ms，B/C为30/35ms |
| post起点 | 所有保留main模式与起点产生的结束时刻向上对齐之并集，仅用原期限过滤 |

A.main跨场景仍须选择同一具体设备；M/H与时序可逐场景改变。所有main在静态合法安排中均实际保留两个设备、M/H两档及两个起点。CPU/M模式虽然在输入域保留，但可能由共享频点冲突或原期限排除；这不通过删参数掩盖。

原NPU0仍在平台、功率账本和热模型中，A.main合法NPU模式被本参照主动排除。pre/post固定CPU2/H也排除了许多原合法安排；所得最优值只能说明此受限域。

[design.json](design.json)由[design_static.py](design_static.py)以`Fraction`精确算术直接重建。原物理／场景字段逐项不变；所有保留模式是原记录的逐字典拷贝。只检查释放、截止、依赖、执行单元互斥与共享域重叠时同频，未调用生产评价器。

| 规模 | AB | AC | 合计／跨场景 |
|---|---:|---:|---:|
| Stage—模式—起点选项 | 31 | 31 | 62 |
| 场景原始笛卡尔组合 | 2688 | 2688 | 5376 |
| 静态合法完整场景安排 | 548 | 139 | 687 |
| 其中A.main=CPU1 | 90 | 73 | 6570个跨场景组合 |
| 其中A.main=GPU0 | 458 | 66 | 30228个跨场景组合 |
| 共享部署匹配后的完整AB/AC安排 | — | — | **36798** |

该静态计数在本机约0.25秒完成，**不能用它估算热积分或MILP用时**。62仅是选项数，不是完整MILP变量数；控制／电热辅助列、热约束规模与数值稳定性尚未构造测量。

未来完整穷举不必做36798次整批重复热评价。原模型场景入口彼此独立，目标是场景能耗加权和，唯一跨场景未固定关联是A.main具体设备。故可按该设备分组，完整评价AB的548份和AC的139份，共**687份场景轨迹**；每组分别取安全能耗的最小包络，再按原1/2权重合并。这是独立覆盖参照的计算组织，不改变MILP待求的联合问题。

必须逐项覆盖全部687份：热不安全、未决、数值未分辨分别登记。未决项不能当不可行丢弃；若其可能优于当前最优，最优性仍未决。相等显示值不等于精确相等，需保留能量区间和温度误差。没有声明目前已有任意热安全解或独立最优包络。

## 4．全部方法同域的接口缺口

1. 受限模式表与完整`start_domain`已经显式存入输入。后续MILP、HEFT、图搜索及穷举均须读取同一实例并在最终接纳门核对；不能只限制MILP，而让HEFT在原域运行。
2. 原`inputs.expand_options`与`start_domain.explicit_start_sets`可表达这些起点，但当前未运行这两个生产入口，未接MILP。需零求解核对其生成的模式—起点集合与本目录62选项逐项一致，并核查期限必零／预消元等优化不会扩域或丢域。
3. 完整评价器具备`evaluate_piecewise`分场景物理接口；穷举需要独立枚举与场景合法性适配、身份计数、全部费用记录和跨场景共享部署合并。当前未实现、未运行，也不复用历史热缓存免费计费。
4. 原C算法固定A.main=NPU0，与本域A.main=CPU1/GPU0不兼容；不能直接套用后称公平质量对照。第四章先选确实同域的方法；是否改造C另行讨论，不为适配本参照暗改算法。
5. 穷举结果及MILP输出都必须回到完整三Stage、原400ms窗口和auto-L热能耗标准。小域成功不能证明原大域的数值问题已修复。
