# K.137：两遍搜索实现与小域正确性

**已实现同一调用内“旧N1→全Stage工作点／起点”的两遍搜索，最终99/99必要预检通过。** 原基准未求解，未产生新的节能或热反馈结论。第二遍能继承本次自己的完整安全安排，并在新模型下重新完成x0；数值或接口失败不再开启后续搜索，已有完整SAFE保留。

## 实现范围

新增[staged_method.py](../../staged_method.py)，复用[neighborhood_method.py](../../neighborhood_method.py)的同一生命周期；没有复制一套热评价器或修改MILP物理表达。旧N1默认仍先准备所有场景，再逐场景搜索，原协议及条件含义保持。旧单遍／固定设备／增广入口的回归均通过。

| 环节 | 本版行为 |
|---|---|
| 初始化与设备 | 一次fresh输入、一次种子构造流程；全部设备D由本次初始完整SAFE锚定，两遍不改。A共享具体设备，场景内频点和起点可以不同。 |
| 第一遍 | 按调用方明确给出的旧N1开放集与原场景顺序搜索，保留原60秒合作片；不自动推断Stage名称。 |
| 第二遍 | 各场景的全部原合法OPP／起点开放，逐场景重建模型、事件、系数及x0；准备后分配`min(60秒，剩余时间/待处理场景数)`，无余量就停止。 |
| 完整账本 | 原子保存`safe_candidate＋aggregation＋U`及其匹配场景回执。下一场景只使用最后成功完整聚合，不拼接局部最新记录。 |
| 进程与接纳 | 一个MethodBudget、一个底层worker；第二遍用现有逐请求增广映射及原矩阵原容差门。旧向量、事件索引及补变量映射不能直接搬用。 |
| 失败与界 | 请求已结束、consumer已解绑且实际底层worker可复用才继续；失败锁存跨场景／阶段保留。原L0、局部内部界和完整U分别登记，未决不判无解。 |

第二遍只重用本次已核身份的原输入物理回执，重新核当前范围成员资格；模型视图缓存与每次新模型分开。缓存中的局部改进若未完成原聚合，随后再次出现时仍须经过完整汇总才可更新U。

`committed_safe_snapshot`是跨阶段warm的唯一完整代际；`phases`保存各遍条件与求解记录。顶层`condition/opened_by_scene`保留第一遍定义，`scenes`是最新局部记录，可能先于已提交系统U，不能混配。此契约同时写入结果的`staged_record_contract`。
