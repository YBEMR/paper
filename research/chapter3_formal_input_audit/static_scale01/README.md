# 正式输入适配前的静态规模核查

本目录只读取既有归档标量，计数当前 whole MILP 表达所需的选项与事件目录；未转换正式输入、构造选项对象、调用生产模块、构模、求解或热积分。该计数不是正式性能实验。β=1.3只用于核查现有候选配置，不在本目录冻结正式β。

复跑入口：`F:/Anaconda3/python.exe -B research/chapter3_formal_input_audit/static_scale01/static_count.py`。依赖仅为 Python 标准库。输出 `static_scale_counts.json` 含源代码哈希、每份归档哈希、人工算术自检、72个原基础归档的计数与范围，以及C20的S1子集和7.37秒实际错峰样本。约11秒为本静态读档计数耗时，不是MILP构模耗时。

## 计数合同

假定未来适配器无损保留画像、工作量、释放、绝对期限及5 ms起点，采用现有whole路径的 `prefilter_deadlines=True`、auto-L、单位/OPP聚合、辅助整数连续化及能量下界强化，不引入邻域或固定部署。P0实际入口为 `research/chapter3_experiments/p0_batch/dispatch.py:27–30`；辅助量与能量下界的原标志由 `run_warm_diagnostic.py:81–83`、`run_initial_witness_diagnostic.py:32–33`传入。

每份档案均断言：同一shared Stage在各场景和请求中的合法设备集合一致，且等于其画像的设备集合。若新输入不满足，该脚本直接失败，不能沿用本计数。变量与行界按所选场景实际出现的shared画像计算；保留未出现画像带来的多余变量和行另列，不建议适配器保留这些无效项。

`inputs.py:286–317`先产生窗口内全部合法模式/起点，再由 `milp.py:867–875`去除必超期项。因此同时报告初始展开数量和期限过滤后的Y，前者仍影响现有实现的峰值存储。仅启用末尾 `fix_late_options`（1097–1102）不会缩小事件目录。

对某执行实例、设备和工作点，令时长为d、释放为r、绝对期限为D、窗口W、步长Δ=5 ms，期限过滤后的选项数为：

`max(0, floor((min(W,D)-d)/Δ) - max(0,ceil(r/Δ)) + 1)`。

Y为所有这些数量之和。时长直接用归档非统一响应的有理数表达计算，不取整。

**5 ms只约束起点。** `milp.py:939–941`对0、W、全部可能起点及全部精确结束时刻取并集，得到事件区间数K。因此K通常远大于W/5。脚本以“除以5后的余数＋整数索引区间”合并算术数列，精确计数这一并集，不枚举选项或事件点。

## 结构公式与精度边界

设S为场景数；T为执行实例总数；J为实际出现的shared Stage数；X为其合法设备数之和；U为每个执行实例对应shared合法设备数之和；DAG边总数为D；K为场景区间数之和；Q为各区间联合OPP状态数之和；A为非空单位/OPP活动锁定行数之和。

四节点、三个控制域、每域三个OPP下：

- `K ≤ Q ≤ 27K`，`0 ≤ A ≤ 12K`。
- 变量：`V = Y + X + 4S + 21K + Q`。
- 不等式：`R = (2J + 3T + 2U + D + 8S) + Y + 48K + A + 10Q`。
- 非零项保守下界：`NNZ ≥ 10Y + 66K + 2X + 2U + 8S`。

变量依据：`milp.py:885、905、985、989、1034、1048–1052、1063–1078`。行依据：927–937、978–1041、1069、1082–1091及702；所有等式均由336–340导出为双向不等式。U包含没有期限内选项的合法设备，因为928–929仍生成其共享映射连接行。

非零下界保留Stage/共享映射/期限/启动行的8Y，资源互斥和单位/OPP锁定至少2Y，固定小行48K，联合状态/边缘化及物理等式目标列至少18Q，再用Q≥K；不计依赖行、更多活动系数与条件门系数。未声称完整非零数精确。

Y/K是上述合同下的精确目录基数；V/R是结构界，未真正构造矩阵。场景权重不改变这些基数。反馈新增行、累计前驱切面、增广数值表达及新算法版本均未计入。

## 内存与耗时的解释

`milp.py:92–115、298–334`每行保留独立行字典、系数字典及两元素rhs区间列表。本次CPython 3.12.4的三个浅容器大小分别为184、至少64、72字节，故仅这三种容器即至少320R字节；尚不含任何系数条目、变量、选项、活动列表或矩阵副本。C20上述四项对应的浅行容器下界为0.149、3.730、55.939、81.355 GiB。这是当前对象布局和结构计数推导的下界，**不是实测峰值内存**。

更紧凑的CSR不能直接代表当前Python构模内存。即使采用float64值和int32索引，只按上述非零下界，其矩阵存储也至少为`12*NNZ+4*(R+1)`字节；尚未计向量、求解器复制及原对象。导出时还建立三份Python坐标列表并转换COO→CSR（456–468）。

活动目录也随规模增长：961–971按每个事件区间保留活动候选及按节点分组的列表；其总访问量取决于`H=Σ区间活动候选数`，不能只看Y。物理系数又按“联合状态＋精确片段时长”缓存（`milp_coefficients.py:121–164`）；随机有理时长增加不同片段长度，会影响缓存命中和有理数计算成本。

K.187的既有实测为27,971变量、176,953行、1,983,981非零、构模12.093秒（`research/完整MILP长预算诊断_K187.md:13、29`）。K.196的受限小域为2,201变量、9,215行、65,167非零、构模5.015秒（`research/完整链小域整体MILP结果_K196.md:40、44`）。两者的事件目录、缓存复用、初始化与求解条件不同，不能按行数比例外推新实例的构模或求解秒数。

**结论：适配后的数据语义可检查，但当前whole MILP的24/96 Stage大事件目录不能直接作为常规50根批量任务启动。** 这是当前表达和对象存储的实施风险，不是原优化问题不可行的证明，也不构成缩小正式合法域的授权。正式适配和小规模实际预检仍须由主线另行提交、用户授权。
