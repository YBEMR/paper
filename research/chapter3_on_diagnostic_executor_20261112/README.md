# 独立 ON 诊断执行器：冻结待批准

仅针对完整 auto-L R1 已保存的互补门控 ON 矩阵。任务是完成执行器、控制测试和冻结，**本次提交不授权运行**。旧四槽入口及历史矩阵、表达、参数和结果不改。

固定范围：最多一次原生请求；MATLAB R2023b，全部设置与已存 OFF 回执一致；原生 `MaxTime=240` 秒，父进程总窗 300 秒。源文件核对、导入、读取、初解完整评价、启动、传输、求解、原／新行验证、解码及最终完整评价均计入总窗。初始化沿用已存调度与 x0，不重构或搜索。最多两次完整评价：初解一次、最终返回候选最多一次。不会补跑、改参数、调用 OFF、LP 松弛诊断或正式 A/B/C。

`control.py` 将状态、进展、正确性分开；`adapter.py` 接原始科学代码；`guard.py` 校验身份与单次授权；`run_on.py` 管理独立进程、一次性记录及清理。`prepare.py` 只执行控制测试与保存数组只读检查，禁止启动进程或物理评价；它产出 `plan.json`、身份文件、测试／预检回执及未批准模板。完整物理核、MATLAB脚本及原生选项不修改。

运行保护：

- 没有单独批准，CLI 和原生入口均拒绝启动。批准须绑定冻结计划 SHA 及实际用户决定来源；不能将截图、此提交或模板自动改写成批准。
- 固定目录的一次性记录采用排他创建；即使启动失败或尚未调用求解器，也不自动回收。直接重复工作进程同样被排他记录拒绝。
- 读取与启动后余量不足 250 秒，或发布请求前余量不足 250 秒，不提交求解请求。MATLAB仍使用原脚本的预算保护；若异常延迟使实际原生设置缩短，记录设置不一致，不能当作同设置诊断或补跑。
- 300 秒是严格证据截止，380 秒仅为清理看门狗；原生时限本身非硬实时中断。只清理由本次工作进程创建且身份核对的进程。异常退出、捕获不完整或强制清理均阻止完整验收结论。监控仅保证已观察身份，不能声称操作系统级不可逃逸。
- 软件批准记录不能证明填写者身份，也不能替代用户授权；这些机制用于防误运行、漂移和重试，不是密码学签名或系统权限隔离。

验收分别记录：根 LP 进入／后续阶段、有限原生下界、可用向量、数值准入、完整 SAFE、新调度和严格能耗改善。普通超时不会抛出旧式“未通过可行入口”的统一错误，也不会丢弃此前及时取得的回调。只有 rootlp 标签不算完成；内部候选计数不替代向量；求解器返回相同初解不算新 SAFE 调度。

新行及原行检查沿用原容差，并记录互补等式、固定常数的精确 binary64 残差；数值准入不冒充严格有理数证书。SAFE必须使用原评价器完成所有场景。能耗改善要求候选上界严格低于初解下界。

下界附来源、接收时间与原生目标单位，核对与已准入的数值 MILP 点目标是否冲突；这只是数值一致性检查，**不产生独立严格下界证书**，不能用物理能耗区间直接拼出 MILP gap。无下界或无回调时保留未知。回调向量原样归档但不追加热评价；只有最终返回向量进入完整验证。

300秒后允许只读核对身份和清理，不能读取迟到向量后补做评价、补记下界或回溯时间。工作进程回执保留观察；最终是否可用以 `controller.json` 的完整性和 `progress_usable` 为准。控制测试是模拟时钟／回执测试；保存 ON 预检仅检查接口和数组，均不能证明 MATLAB 已稳定求解。

批准后执行方式（当前不可执行）：将 `approval.template.json` 另存为批准记录，只有在获得实际用户明确批准后填写 `approved=true` 及对应决定来源。随后从同一工作区使用 `python -B run_on.py run --workspace WORKSPACE --plan plan.json --approval APPROVAL_FILE`。不得删除一次性记录重跑或复用旧计划剩余槽位。

运行结束无论结果如何均停止。有进展后再决定是否用统一表达开展自费重构的 A/B/C；没有进展则优先另议 LP 松弛、尺度或其他求解器诊断，不继续原样完整求解。本次不执行这些后续研究。
