# 稳定电热 MILP 表达：首个候选尚未通过完整入口

研究方向按用户要求更新为“实现并验证较大规模完整 MILP 的有效求解”。保留 MILP 路线，先解决稳定表达，再做统一 A/B/C 求解对照，最后决定推广或分解；不以变量／行数下降替代求解成果。

**互补门控候选通过数学等价和小实例物理一致性，但完整 OFF 首次入口超时、没有返回候选。按预先选定规则停止 ON 及复核，未启动性能对照。**

候选：引入 `h=1-g`，将 `a*x+alpha*g<=b` 写为 `a*x-alpha*h<=b-alpha`。不压缩非零宽度区间、不改原目标／变量边界／整数集合／物理精度。OFF、ON各一条右端不能以单个binary64精确表示，采用 `r=hi+lo` 和固定连续列 `t=lo` 的精确展开。每条原行经逆代入恢复，原连续松弛及整数调度投影都保持不变。

| 验收 | 结果 |
|---|---|
| 转换与入口纯测试 | 20 项通过 |
| 可枚举小实例 | 12 调度，6 合法／6 期限非法；3 组共36次结构检查、36次完整物理评价通过 |
| 完整保存矩阵 | OFF／ON逐行精确证书及共同x0身份通过，未重建完整R1 |
| OFF首次原生入口 | exitflag=0，达到原生240秒上限，无候选、无有限下界、无已观察根LP完成 |
| 其余入口 | ON1、OFF2、ON2按失败即停规则省略 |

本轮用户明确选择最多4次、每次父进程总窗300秒，失败即停。OFF实际intlinprog调用241.188秒，完整诊断回执259.516秒；清理通过。原生240秒是启动前冻结的求解上限，为回执、原行检查及完整物理评价留时间；其他求解选项和原脚本未改。实际传输数组与冻结表达一致。无重试、无A/B/C性能调用。

小实例仅含一个原参数A.pre Stage，三组最终选项相同，**不能证明约简贡献**。完整入口使用保存矩阵和保存x0，每槽刷新初解完整SAFE；这是数值表达诊断，**不是构模与初始化均自费的性能样本**。完整两矩阵的转换、认证和准备共107.468秒，未来正式A/B/C必须计入方法总成本。

数学等价不保证数值容差等价：原行可能承受 `alpha*(g+h-1)+(t-lo)` 残差。因此程序同时要求新行、原行及完整物理SAFE验收；原生异常即使有正退出码也拒绝。此次无返回向量，未进行返回候选评价，不能把原初解SAFE算成求解器成果。

该次没有重现 `-2`，但超时且无正常进展证据，**不能宣布数值问题解决，也不能据一次超时断言表达普遍无效**。停止的是本候选的追加原生调用，不是MILP路线。阶段一仍需新的有针对性表达设计，通过门槛前不进入性能比较。
