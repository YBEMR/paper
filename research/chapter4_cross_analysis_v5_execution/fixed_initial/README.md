# 第四章两种初解上的虚拟期限检查

在其他请求都保留各自初始配置时，同一个节能动作可能在两种初解上产生不同的期限结果。F1 的 69 个可直接比较的单请求动作，在第三章初解上全部导致至少一个请求超期，在第四章 Q4 初解上全部满足虚拟期限。F2 的变化方向相反。

| 工况 | 可直接比较的单请求动作数 | 第三章初解导致超期 | 第四章 Q4 初解导致超期 |
|---|---:|---:|---:|
| D1 | 97 | 97 | 96 |
| D2 | 85 | 37 | 0 |
| F1 | 69 | 69 | 0 |
| F2 | 60 | 0 | 24 |

每行只比较同一工况内的动作。请求编号、原设备与频档、目标设备与频档完全相同，两个初解对该动作的参考忙态节能也相同。其余请求按各自初解执行。表中“导致超期”表示单独施加该动作后，在原 FIFO 虚拟时序中至少有一个请求越过硬期限。D1 的两种初解都限制了几乎所有这类动作。D2 和 F1 在 Q4 上可以直接尝试的动作更多，F2 上更少。

## 数据口径

按冻结的 `feedback.targets` 枚举四类目标，并用原 `feedback.virtual` 重放。两个初解均已取得 SAFE 证书，未施加动作时的虚拟时序也均满足期限。每个目标只改变指定请求的 main 配置。四个工况、两个初解、四类目标共 3,656 条记录。同一物理动作可以同时属于两个类别，按类别分别保留。枚举使用种子 101 确定并列目标的遍历顺序，覆盖各类中的全部目标。

[逐目标明细](targets.csv.gz) 记录请求及其原始配置、目标配置、参考忙态节能、最大超期、超期总和以及超期请求数。参考忙态节能单位为 mJ，超期量单位为 ms。每个目标均由固定初解单独产生，无后续补偿或重新优化。

[分层汇总](summary.csv) 保留类别分母和超期目标数。包括全部目标、两种初解共有的目标，以及原配置也相同的共同目标。参考忙态节能按非正值、(0, 1)、[1, 10) 和至少 10 mJ 分层。分母为零时比例留空。

该检查衡量的是初解对虚拟节能动作的期限容忍度。判断反馈能否通过补偿改善最终安全能耗，还需要同工况、同种子的 C/D 正式终点和实际动作记录。检查没有调用优化器，也没有将虚拟目标视为经过连续热认证的完整排程。

[复算脚本](../initial_targets.py) 从第三章 A/B 正式记录和第四章 C/D 共用的 Q4 池读取已核验的初解。示例调用如下，输出目录应为新目录。

```text
python -B initial_targets.py --repo <第三章原工作树> --run <第四章正式输出的formal目录> --out <新目录>
```
