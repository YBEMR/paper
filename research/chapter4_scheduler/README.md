## 实现了什么

| 文件 | 职责 |
|---|---|
| [graph_core.py](graph_core.py) | 资源关联Stage对、完整共享域冲突重建、精确合法起点传播、非温度能量排序值 |
| [method.py](method.py) | 同次HEFT初始化、完整SAFE冻结、联合重构与严格改善、单300秒根计时和证据归档 |
| [run_precheck.py](run_precheck.py) | 可复跑的人工夹具/模拟回执检查，阻断真实HEFT、热评价、求解器、进程与网络调用 |

新接口位于独立目录，不替换原C，也没有改写第三章实验入口。`variant="pair"`是新建议；`variant="single"`只实现K.179中约定的普通单Stage对照，使用相同图解码和完整评价接口。

流程为：**本次HEFT → 最低上界完整SAFE → 相关Stage对的合法OPP与资源方向 → 两种起点模板 → 原完整电热评价 → 严格改善才更新**。首版细化固定HEFT实际选择的具体设备；A跨场景共用设备，工作点/起点仍按各场景分别决定。

核心规则已经落地：

- 新OPP与所有第三方任务重新核查共享频率域冲突；同域同OPP保留并发，同设备及同域异OPP定向互斥。资源方向与任务依赖成环时只拒绝该骨架。
- 起点取原网格或显式合法集合的下一个成员，时长/结束时刻不取整。支持最早模板及保留非后继任务起点下界的模板；原完整SAFE始终单独保留。
- 排序值按全窗口、全场景权重计活动、auto-L域基准和公共能耗；共享基准不按CPU核重复计费。它不含温度项，不作真实能耗下界或剪枝条件。
- 初始化继承的是同次有效最佳完整SAFE，不是HEFT最后一次尝试或`local_base_candidate`；不能向原C暖锚强塞另一部署或历史答案。
- 联合阶段只有`new.upper < current.lower`才换方案。重叠区间即使上界更低，也只记观察；重新接受后依据最新完整SAFE重建关联对。

## 安全与预算接口

`execute_reconstruction(loader, workdir, bindings=..., seconds=300, variant="pair")`在读取输入前创建唯一根时钟。初始化、身份绑定、图构造、排序、缓存及完整评价全部计费，不重新分配300秒。`Bindings`必须显式提供初始化器与评价器；真实绑定只接受原HEFT函数与原完整评价函数，并绑定本次源hash。本阶段所有测试绑定均为`MOCK_ONLY`，顶层输出为`MOCK_SAFE`且`usable_as_research_evidence=false`。

复用现有完整回执审计，检查原合法性、场景覆盖（含零权场景）、声明的完整窗口（主线为400 ms）、各热节点、温限、能量分项和加权包络；不使用仅有`state=SAFE`的简化回执。绑定输入/精度/源码、具体部署及同次根token，缓存仅本调用可用。输入突变、错误候选回执和预算漂移会停止；先前完整证据保留。

截止规则沿用共同评价器的证据形成时刻：预算内已经完成的完整回执或违规见证，可在外层停止检查前转存，即使返回略晚；记录实际超时量，不再开始候选或热计算。预算后形成的SAFE不得补U。无效时间戳与正常截止分开，非法NaN只作为带类型标记的失败诊断保存，不修成合法数值。停止后仅序列化。
