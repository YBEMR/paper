**实现规则已固定。** 目标按同设备模式的`q×d`正加权节省量排序，再按场景、Stage、目标OPP稳定决胜；不假定低频必省能。沿用原资源关联伙伴、伙伴合法OPP、原次序／反向和earliest／preserve两模板。没有此类目标时结束该搜索，不宣称整个原问题不存在更好方案。

无额外边的骨架先完整传播，收集全部可定义时序的超期任务。每个超期任务追踪一条确定最大前驱链：前驱结束并列取Stage标识最小，释放或保留起点下界相等时优先停止追踪。资源阻塞边按原方向的两个Stage标识排序、去重。该规则可能漏掉其他修复路径，是有限启发式范围。

`core.reconstruct(..., extra_resource_edge=(u,v))`表示**反转原方向u→v**。它会重新计算同一个无额外边骨架，只有该边确实在其超期链上、是资源互斥边、且不兼有任务依赖、也不是原主资源对，才允许反转。每个候选最多一条额外边；每次均从原骨架独立重建，不在上一次修复上继续追加。有环、显式起点用尽、仍超期或需更多联动时，只拒绝该骨架。所有第三方共享域异OPP冲突重新检查，同域同OPP并发保留，结束时刻不取整。

设备与共享部署保持，OPP按场景分别选择。全场景（含零权场景）、全窗口及全部热节点的完整回执要求继承原安全接纳器；非温度值只排序。只有完整SAFE且`new.upper < old.lower`才替换，不接纳变贵中间方案。结构层只返回`COMPLETE_LEGAL_CANDIDATE`，温度状态仍为`NOT_EVALUATED`。

`method.execute_reconstruction(loader, workdir, bindings=..., seconds=300, budget=...)`沿用原MethodBudget及完整回执规则，新增源hash绑定。传入调用方根时不重置，输入、初始化、目标计算、路径、重构、缓存和完整复核都计费；初始化完成后才进入新动作。预算内已形成的完整证据先保存，预算后形成的SAFE不补U；未决或故障保留先前完整SAFE并单列停止原因。缓存仅同次调用共享。
