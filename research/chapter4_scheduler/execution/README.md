## 要回答什么

采用P0原H响应的`base__R1`、`base__R3`两个公开开发题，比较以下四组：

| 方法 | 本调用如何取得初解 | 后续可调整内容 | 主要用途 |
|---|---|---|---|
| C | 原构造器，共享A固定CPU1/NPU0/CPU1 | 原两阶段4开2闭与固定锚预消元 | 保留既有方法的质量与成本参照 |
| HEFT | 原HEFT完整搜索 | 原映射、OPP及启动调整规则 | 核新方法的收益是否只是来自HEFT |
| SINGLE | 同次原HEFT的最佳完整SAFE | 固定其设备，单Stage OPP＋图重构 | 核普通单Stage改动的作用 |
| PAIR | 同次原HEFT的最佳完整SAFE | 固定其设备，资源关联Stage对的OPP／必要次序＋图重构 | 核联合动作是否比单Stage更有效 |

C与后三组的初始化及设备自由不同，其差异只能作端到端质量比较，不能全部归于联合重构。三个HEFT版本分别从原输入独立开始，不传递候选、U、缓存或见证。HEFT本身已有局部能耗调整；不能把所有后续改善概括为“首次使用局部搜索”。新算法规则仍见[K.179](../../第四章算法方案设计与可行性分析.md)及[K.180](../README.md)。

初始化归因比较**最佳完整SAFE的语义时间表、部署、能量区间与是否完成初始化**。语义时间表按场景、Stage排序，核模式标识及精确起点，忽略来源标签、时间戳与本调用token；不能比较整份回执hash并据此认定初解不同。初始化未完成或初解不同，只报告各自继承值与后续改善，限制单因素归因。两个题不承担泛化或统计稳定性结论。

## 固定输入、顺序与待批上限

沿用AB/AC跨场景共享具体部署、400 ms窗口、5 ms合法起点、四热节点、50°C入口、80°C温限及auto-L。活动时长和结束时刻不取整，连续温度仍覆盖完整窗口。C原60秒场景片、原求解器设置和预消元保持；不接K.170筛选，不恢复K.175、K.168或期限组24次。

| 顺序 | 调用 |
|---|---|
| 1—4 | R1：C → HEFT → SINGLE → PAIR |
| 5—8 | R3：PAIR → SINGLE → HEFT → C |

这是在任何新结果出现前确定的开发顺序。建议预算：8×300＝2400方法秒；每份正常完整SAFE唯一一次≤60秒独立复核，最多480秒；整批日历4800秒。**这些数值是待确认上限，不是本轮消费或执行授权。** 方法可以自然早停，不重启、睡眠凑满或转移余量。

每个真实子进程从入口建立唯一300秒根，起点先于授权/身份核对、所选方法导入、输入重载和初始化；C继续使用同一个根，HEFT／图接口现可接受该根，不另起300秒。输入展开、构模、MATLAB启动、求解、候选准备、排序、缓存及完整热评价均计费。公共解释器启动和入口前公共模块加载计入进程／批次墙钟，停止后的纯序列化单列；不能据此补搜索或新U。

方法证据只接纳根预算内已经完成的完整回执。正常到期返回略晚时保留已有SAFE及超时记录，未完成的末请求保留未决。正常无SAFE可以继续下一槽，但不记全问题无解。技术／数值故障、身份漂移、MATLAB清理不明或独立复核失败，保存证据并停止后续槽，不退款或补跑。

独立复核从准备前单独计≤60秒，核原完整候选、合法性、全部场景与连续热能耗，要求能量区间重叠；原结果/U字节保持，不替换成post新能量。300秒方法返回监督上限420秒、单槽480秒，仅容纳停止清理和归档；它们不延长科学证据截止。剩余日历不足一个完整槽，或剩余单槽不足60秒post时，不启动相应部分。

## 实现与审查

| 文件 | 职责 |
|---|---|
| `protocol.py` | 固定八槽、C原配方、输入／源／历史档案hash、环境、关闭的准备声明、独立授权绑定、一次消费 |
