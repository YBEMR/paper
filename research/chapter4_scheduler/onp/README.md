# ON-P：结构必要条件预筛（研究代号）

本版本只增加精确结构不可行判定。I1、180秒初始化新工作准入、300秒总预算、完整连续电热评价、目标/伙伴/模式/模板遍历、候选排序及严格区间接纳均沿用冻结版本。ON-P启用原额外边机制；OFF-P仅使用共同基础预筛。名称尚非论文算法定名。

## 判定范围

每轮绑定当前完整初解/安全档案，固定设备。每个基础组合固定场景、所选Stage、OPP、主资源方向和earliest/preserve模板。缓存只在这一轮使用，键包含场景、所选Stage、模式及模板；不跨接纳状态共享。

基础组合只有两类证据允许整体跳过：

1. 任务DAG给出的最早起点大于最晚起点，或不存在允许起点。这与其他资源边方向无关，因此该固定模式/模板下的所有额外边也无法修复。
2. 主资源边反转与既有任务路径闭合成环。必须先确认新OPP下确实存在该资源边。任务边和所选主资源边均不允许被额外修复反转，因此该环无法由允许的额外边消除。

其余基础构造照常调用原`blocking.core.reconstruct`。取得原基础超期见证后，按原顺序逐条检查原`blocking_edges`列表：

- 若拟反转边不在某条超期见证路径上，该路径仍在，拒绝本条额外边。
- 对原方向`u→v`反转为`v→u`，若`next_allowed_u(max(ES_u, ES_v+d_v)) > LS_u`，或不存在该允许起点，拒绝本条额外边。
- 一条额外边失败只执行`continue`，不会跳过整个组合或其余方向。没有必要条件证据的候选一律交给原构造器。

设`b_i`为release、0及preserve模板适用的原起点下限；`D_i`为请求截止期，`W`为窗口。忽略资源边在任务DAG前后向计算：

`ES_i = next_allowed_i(max(b_i, max_p(ES_p+d_p)))`

`LS_i = previous_allowed_i(min(min(D_i,W)-d_i, min_j(LS_j-d_i)))`。

普通网格分别向上/向下取整；若输入声明显式网格子集，则在该集合上二分查找下一/上一允许起点。全程精确分数，等号保留。任何合法排程必满足这些界，所以违反是必要条件证据。判定不产生SAFE、不替代热评价，也不证明原实例全局无解。

## 合法候选及顺序保持

被跳过的基础组合连同所有允许额外修复均不可行；被逐条跳过的额外构造自身不可行。因此原合法构造全部保留。其构造函数、调用参数、遍历位置、去重和`(非热能耗, 完整候选哈希)`排序不变，输出合法packet序列保持。原接纳循环直接执行，没有复制或修改；完整SAFE及`new.upper < incumbent.lower`规则不变。

此保持性针对固定状态下未被墙钟截断的候选序列。预筛改变工作耗时，有限预算内实际访问长度及最终接纳路径仍可能不同，这正是第二阶段要测量的效果。初始化也可能因180秒门限及耗时波动而输出不同初解，必须报告，不能强行视为纯机制配对。

`method.py`只在独立串行进程中注入候选提供器和版本/源码身份；原方法退出后恢复所有绑定。原I0/I1/ON/OFF文件不修改。四臂使用同一构造调用计数器；P臂所有预筛准备和检查均计入原方法根预算，不复用基础传播结果给幸存额外构造，不混入其他优化。

## 验证与阶段边界

阶段一包含人工小域独立枚举、完整合法packet序列对照、显式起点/小数时长/边界等号/preserve缓存/同频域条件、模拟生命周期、预算到期及“先拒绝一边仍保留下一合法修复”的检查，并核对全部归档必要条件和指定状态的有序前缀。无真实电热评价；原测试失败记录保留。

用户选定阶段二为U03/U04–24四臂各一次，共8次；每次300秒、I1准入180秒，最终另做最多60秒完整复评。固定串行顺序：

| 根 | 顺序 |
|---|---|
| U03–24 | ON → ON-P → OFF-P → OFF |
| U04–24 | OFF → OFF-P → ON-P → ON |

报告实际基础/额外构造次数及中断、预筛计数/耗时、初始化候选与能量是否一致、搜索时间、完整评价数、终解和失败原因。各臂独立初始化、无共享候选或缓存，不补跑以获得相同初解或有利结果。单次墙钟对照不建立统计显著性或稳定加速倍数。

U03/U04仅用于开发回归和原因验证。阶段三的新参数根在本轮成本结果明确后另行预登记；本轮不生成或筛选新根，不启动48 Stage、更多场景、I2或SA。

执行入口：`python -B -m research.chapter4_scheduler.onp.checks --out <新检查目录>`；正确性通过并冻结提交后，`onp.run prepare --checks <checks.json>`冻结方案，`onp.run batch`消耗8个一次性槽。程序不自动重试；完整科学调用需与用户已确定的范围一致。
