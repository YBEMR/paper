# R2/R5 六槽验证入口

本入口只对应用户确认的 R2/R5 小规模验证，原提案保持原字节。
新的实际计划、授权说明、源码及环境身份另存到
`research/chapter4_scheduler/results/validation_execution_20261107/plan.json`。
不能使用旧 R1/R3 声明、claim 或已消费预算。

冻结顺序为 R2：HEFT→OFF→ON，R5：ON→OFF→HEFT。
每槽独立现场展开原输入并运行原增强 `heft_method.run_heft`；
HEFT 使用与 OFF/ON 相同的 `blocking.CompleteRecorder`，在原 HEFT 完整搜索结束后停止。
该封装替换的是记录层，不修改 HEFT 算法，不另跑 `heuristic_runner` 的下界预计算，
因此不声称继承那个旧封装的下界证书或完全相同的运行成本。
OFF/ON 直接调用原 `blocking.execute_reconstruction`，唯一搜索开关为
`allow_blocking_edges=False/True`，原参数、合法选择及完整接纳门不变。

每次共用调用方已开始的唯一 300 秒根，导入、身份检查、输入、初始化、排序和评价都计费。
正常最终完整 SAFE 最多一次独立新进程 60 秒 post，复用同一原评价器；
这不是另一数值实现的交叉验证。六次方法共最多 1800 秒、六次 post 共最多 360 秒、
日历 3600 秒；正常早停不转移余量。外层 420/70 秒监督只控制故障与归档，不增加证据预算。
技术／数值／身份／post 故障或不确定超时停止后续槽；不重试、退款、换例或调参。

实际运行前先执行原 109 项人工夹具回归，再执行本模块 12 项自动人工夹具测试。
它们阻断真实 HEFT、热积分、求解器和网络，不当作原问题实验。
`prepare` 只在预检通过后创建新的冻结计划；每个真实槽和 post 独占 claim。
运行后 `analyze` 只读审计原完整回执、初解身份、评价计数及能量区间，不新算热轨迹。
具体命令及启动／结束时间保存在执行目录的 `command_*` 和每槽的 `*_command.json`。

本轮只选同一自设输入目录的两个开发机制之外的样本，各臂一次。
保留失败、正常无 SAFE、无改善和退化，不推统计稳定性、外部泛化、紧热收益或全局最优结论。
没有 MILP；没有自动提交、合并或推送。
