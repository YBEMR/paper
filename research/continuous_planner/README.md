# 连续候选规划原型 CP-runtime-1

已实现 **连续MILP结构查询 → 全模式E/M/L三代表 → 原联合评价器**，没有切回时间网格。面向CP1诊断包，原合法响应、物理参数和评价器未修改；这不是完整连续时间优化器或正式节能对照实验。

## 1．实现与保证

| 部件 | 实现与输出 |
|---|---|
| `planner.py:Model` | 全部合法选项二元变量、实际冲突方向二元变量、连续起点；依赖、模式唯一性、执行单元和同域异频互斥、共同轮级期限。以加权活动能量引导查询 |
| `worker.m` | 本机R2023b `intlinprog`，归档实际版本、许可、公开选项和原始返回。Python与MATLAB通过每次独立JSON文件传递矩阵和结果，不共享历史候选 |
| 精确重构 | 解码整数结构后，重新用有理数传播最早／最晚起点和中点；独立检查真实半开区间。求解器浮点起点不直接成为安全方案 |
| 代表与去重 | 全模式all_E、all_M、all_L，精确去重；不添加逐模式混合代表。查询排除仅含已选选项和实际冲突方向，未选辅助方向不改变签名 |
| 评价与缓存 | 完整方案调用原联合评价器，有限U1有效能耗与持续安全分开检查。问题／方案／入口／证明材料／精度／源码身份全部相同才复用完成记录 |
| 输出与界 | 安全能量区间上端更新U；原域L₀独立算得28 mJ。内部MILP界仅属剩余结构查询域的活动能量代理，不提升为原问题认证界 |
| 预算与异常 | 输入加载、MATLAB启动、矩阵构建、所有查询、代表、缓存与评价计入同一墙钟。保留处理中结构及已提交违规，迟到安全能量不接纳。输入／身份／证据冲突结束为接口异常 |

固定配置的真实能量仍与时序相关，因此最早表安全后继续评价M/L。阶段活动量排序不代表真实目标排序。区间重叠记`overlap_or_tie`；按上端择优输出不宣称区间之间已有严格优劣。

给定正时长、完整方向图后，有环或精确最早超期可排除对应无热结构；普通实现错误不得使用这一排除标签。三代表完成后，该结构的其他连续安排仍记未查。无新整数候选、代表用尽、预算结束均不等于原问题无解。

## 2．可复跑入口

在仓库根目录执行，输出目录必须尚不存在：

```powershell
python -B research/continuous_planner/run.py precheck --output research/continuous_planner/results/precheck_new
python -B research/continuous_planner/run.py prototype --output research/continuous_planner/results/prototype_new --receipt research/continuous_planner/results/precheck_new/checks.json
python -B research/continuous_planner/run.py postcheck --output research/continuous_planner/results/postcheck_new --receipt research/continuous_planner/results/prototype_new/search.json
```

`prototype`只接受全部通过且源码／输入／协议哈希匹配的凭据。输入为原`../continuous_planner_precheck_draft/inputs.json`，测试答案与参考表不传入生产搜索函数。MATLAB路径固定为本机已核路径，进程偏好目录为工作区`.runtime/matlab_prefs`；未安装新求解器。许可不可用时停止，不自动换后端。

运行设置沿包：总墙钟120 s、最多4结构；单查询`MaxTime`至多15 s，单评价20 s且受总剩余时间限制。求解器时间限制可能有停止延迟，外部墙钟决定结果接纳；返回的非最优但合法整数结构可以评价，不称代理最优。MATLAB等待通信也受外部总时钟控制。源码快照、预检和事后复核独立计时，不作为搜索预算内证据。进程关闭与结果序列化发生在已保存的搜索计时结束后，不产生新方案。

仅适用本包已静态核查的固定释放、完整工作覆盖和非负剩余功率条件。当前实现没有为任意外来输入建立通用数据验证与下界认证入口。

## 4．本次结果意味着什么

最终4个结构均选择全CPU-L，区别在A/B两个独立前驱的执行先后；4张all_E持续安全、8张M/L因给定转换过程的期限违规被拒。最小安全上界 **105.1561068032451 mJ**（展示值，完整区间端点保存在JSON），L₀ **28 mJ**。4张安全表的6组两两区间均重叠，没有证明其中一张严格更节能，也未证明连续域最优。

独立参考结构使用CPU-H与NPU：E的有效能量约118.621373 mJ，位于预先声明的[117,127.88] mJ粗界；M/L分别由真实执行重放发现1.5/13 ms超期。窄证明盒得到未决，没有被当成物理违规。这个参考用于接口核对，不是刻意削弱的节能基线；不能把与105.1561 mJ的差直接写成算法收益。

原型前4结构没有选择NPU，NPU编码能力由独立强制选项测试支撑。整个CP1合法选项集合均受给定温度盒保护，因此本次热筛选不活跃；温度漏电仍进入能量计算。保留S01—S10范围：单CPU＋NPU主夹具、共同轮级期限、指定入口、给定共同盒、有限给定反例、L3参数，以及三代表遗漏链内等待和跨模式混合安排。

**下一项仅制定首轮方法对照协议：明确验证问题、简单对照和成功／无收益判据，再决定是否进入研究实验。** 不自动扩平台、加代表、调整热参数或补精细持续分析。
