# P1 多场景连续任务流最小立项验证

本目录复现任务书 v1.0 的 E0/E1 验证。精确参数见 `config/p1_frozen.json`，任务书原文见 `config/taskbook_v1.md`，结论见运行生成的 `decision.md`。统一主目标是固定服务量下的全窗系统能耗。

## 输入及时间

画像生成器按 Git 对象格式复核五个 EdgeEngine JSON 和四个历史 blob。CSV 中的有理数保留 JSON 十进制精度。ResNet 高温最高频来自第二个高温文件。GPU 的独立十档、负载特异忙态割线与空闲斜率分别保存。NPU 表中最高档 28/26 ms 已包含 2 倍时长设置，最高档忙态功率扣除基准后的主计算活动能量等于 GPU 对应值。R1 报告位于基点之后的提交 `9c4e4a6`，以独立 blob 身份复用。

D0 按任务书的轻载例外，A1、B1 均从 10 FPS 切换为 20 FPS。其他工况 A1/A2 的 20 FPS 相位延续，B 流每场景重设释放相位。绝对时刻单位为 0.1 ms，释放及期限另存精确分数。所有排程共享同一个跨场景时间轴。三个域的初末均为最低档，降档权限按空闲间隙选择；末端可以立即降档，也可以于窗口末端前完成恢复。请求内三条 Stage 用顺序编号 `3r,3r+1,3r+2`。

## 冻结的执行规则

- 开发顺序 D0、D1、D2、D3。留出 H1–H3 只在开发阶段出现有热贡献证据、严格节能且优于同规模普通邻域的恢复正例后执行。输入生成覆盖全部七个工况。
- 共同构造按 100 ms 内同型请求的释放顺序分配配额。主参考将最先 2A、5B 放在 GPU 最高档，其余在 NPU 最高档。备用参考将最先 1A 及全部 B 放在 GPU 第六档，其余在 NPU 最高档。低载区块的配额按实际请求数截断。CPU 使用最低档。流水线允许上一块请求延续。
- HEFT 适配在同释放时刻按各链剩余最快时长排序，采用最早完成插空。预置六组主任务档位构造，GPU 的从零开始索引为 9、5、3、2、1、0，NPU 索引取两者中较小者（上限 2）。候选合格后以完整安全能量选初解。各方法的输入、初解身份及首次 SAFE 时间记入回执。
- ETA-TS 适配 Li 原文的分层余量分配与固定映射、单元次序的逆序 LFT 调整。每条请求链有自己的真实释放和期限，三层分摊初始余量。实际 LFT 同时受后继、同单元、跨核共享档位和切换占用限制。遍历可用 OPP，离散档位未用尽的余量取半移位；每项接纳均作连续热复核。
- SA 使用温度递减的 Metropolis 接纳。普通 LNS 在同初解上破坏、重建 2–9 个 Stage，混用同域、请求链及随机邻域，可调整设备、档位、次序、起点及空闲控制。G2 保留功耗温区限制，G3 额外要求 80°C。运行时间达到预算时保留已认证方案。每个工作进程末尾最多留 2 s 写回，外层施加硬超时。
- R/F 在绝对 5 ms 网格及各 Stage 原始起点上递归枚举。R 固定原单元及相对次序，F 开放设备和次序。两域均枚举允许的空闲控制组合，优先枚举保持原档的不同放置。保留未遍历分支，超时用已知可行上界和条件解析下界构造 Δθ 区间。
- G4 先在完整 0.1 ms 起点域做差集。仅当整个域为空才能证明纯时间阻塞。非空时遍历合法起点与空闲策略，遇到 SAFE 即排除受阻判断，未遍历完且无 SAFE 记未决。解除时间冲突后另存合法超温见证。目标排序只使用未含交接的 35°C 增量活动节能潜力。B1–B4 共用实际辅助 Stage 数，热关联按违规节点处的传播贡献排序。贡献排序使用分段仿射状态转移及段内温度近似，认证仍取完整模型。
- 全窗三组共用同一排序、局部起点与接纳权限。直接 A+B 与 A+B+Δ 各在相同预算前 20% 内执行 ETA 余量优化，两者主要差异是普通或按阻塞原因选择的邻域。只有 G4 已证实时热关联正例才执行。
- 所有随机发生器在各方法入口独立设为 101，普通随机对照邻域用 102。可通过初解、随机序列入口、已存移动次序及冻结代码复查候选生成。墙钟限时取最后一个在时限内完成认证的结果，机器速度会影响候选数。

## 复现与归档

在冻结源码的干净检出中从本目录执行 `python execution.py batch`，需 Python、NumPy、SciPy、Numba、SymPy 和同提交的 `research/v1_evaluator/interval.py`。已有调用账本时入口拒绝重复执行。需要重新生成画像时，将五份原始 JSON 以原文件名放入同一目录，执行 `python profiles.py <目录>`。运行不依赖网络。

`instances/` 保存释放与期限。各方法目录保存结果及计划 SHA-256。完整计划、邻域随机次序、实际调用在 `logs/`。每个最终候选在 `certificates/` 保存逐 Stage、资源边、切换、逐段连续轨迹和相同排程的边界重置对照，压缩 JSON 可用 Python gzip 直接读取。重置诊断只重置温度。热证书的积分边界和下界推导见 `numerical_bounds.md`。预算上限和调用总数汇总于 `manifest.json`。结果快照 `RESULT_SHA256.json` 覆盖结束事件和各文件字节，另以分支提交固定。
