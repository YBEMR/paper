# P1 多场景连续任务流与时热协同节能调度
## 最小立项验证任务书 v1.0

**任务性质：E0/E1 正确性及机制诊断，附有限的算法价值筛查。非第三章正式实验。**

### 1. 研究目标与执行边界

验证以下假设：

H1：异构多速率任务流在连续热继承条件下，存在因时间资源约束和热约束而受阻的低能耗执行配置。

H2：通过追溯时序、热关联任务进行联合优化，能够在相同合法权限和预算下，相比普通邻域搜索进一步降低完整安全能耗。

唯一主要优化目标为全评价窗口系统总能耗最小化。

所有请求必须按期完成，固定精度和服务量。禁止丢弃请求、执行中迁移、抢占、动态精度、强化学习。

第三章优先能耗和解质量，第四章的正式提速实验暂不执行。

### 3. P1 冻结物理模型

#### 3.1 平台及合法执行

四个热节点顺序：

CPU1、CPU2、GPU、NPU。

CPU 双核共享频率域，允许同频并行。GPU、NPU 各自互斥，不同设备允许并行。

每个请求包含：

CPU pre → GPU/NPU main → CPU post。

pre、post 均允许选择任一 CPU 核。

A、B 各有一条预构建的 GPU 路径和一条 NPU 路径，共四条常驻执行路径；每个加速器具有两个抽象驻留槽。执行期间不发生加载、驱逐或模型重配置。

路径合法性、算子支持与等精度作为本合成模型的明确前提，不将其解释为特定商业芯片已经实测支持。

每次主任务执行前可选择合法路径。不得执行中迁移。

主任务增加输入、输出交接时间各0.2 ms，共0.4 ms。交接与主计算共同占用对应加速器，按该任务的忙态功率计能。CPU pre/post 包含 host 侧处理。

P1 不额外建模共享内存竞争、独立 DMA 调度及 DPM。

CPU/NPU 忙态采用域基准、活动功率及局部温度修正之和。

#### 3.3 GPU 数据生成

筛选 batch_size=1、CPU频率2035200 kHz、内存频率1866000000 Hz、control_scenario=6、threads=6、num_isolated_cores=6、core_affinity=false。

每个网络、温度组及频率必须唯一匹配。

保留全部十个 GPU 频档：

420.75、522.75、624.75、726.75、854.25、930.75、1032.75、1122、1236.75、1300.5 MHz。

A 对应 ResNet 响应形状，B 对应 MobileNetV2 响应形状。

低温组运行时长取 runtime_ms 中位数。

`d_iG(f) = d_iG(H) × median_low(f)/median_low(H)`

最高档参考时延 A=14 ms、B=13 ms。

观测最大时延敏感性：

`d_iG,max(f) = d_iG(H) × max(runtime_low(f),runtime_high(f))/median_low(H)`

分母始终使用低温最高档中位数，不对最大时延重新归一化，不强行拟合单调性能曲线。

功耗取 `mean(power_readings.p_gpu[4:-1])`。

实验温度取 GPU 测量前后平均值。由配对记录生成割线：

`P̂_if(T) = P_low + (P_high−P_low)/(T_high−T_low) × (T−T_low)`

P1 GPU 忙态功率：

`P_iG,busy(T,f) = P_iG,ref × P̂_if(T)/P̂_iH(35)`

A、B 的参考功率分别为5.9 W、5.4 W。

令 `x=(f−420.75)/(1300.5−420.75)`。

GPU 空闲功率参考为 `0.4+0.5x` W，空闲温度斜率为 `0.004+0.004x` W/K。

GPU 忙态功率直接替代该节点空闲功率，不重复叠加基准与漏电。

所有公式使用原始数据精度生成 JSON/CSV，不使用报告中取整展示的数值作为输入。

#### 3.4 DVFS 切换

所有域在完全空闲时才允许切换工作点。

每次频率切换：

- 延迟0.5 ms。
- 额外能量1.5 mJ。
- 切换期间资源不可用于执行。
- 以原频率空闲功率计能，叠加3 W切换功率。
- 额外切换热源分配至对应节点；CPU 域两个节点均分。
- 切换完成后采用目标频率。

每个空闲间隙统一提供两种权限：保持原档直至必要的下一次切换；或者尽早降至最低档，再按需于下一任务启动前完成升频。

选择低档空闲时，必须为所需切换预留足够时间。

所有方法使用相同的切换重建规则，不允许免费调频。

初始工作点为全部最低档；所有方法必须在评价窗口结束前恢复全部最低档。

#### 3.5 热模型与能耗

四节点热容量：

`C0 = [0.04, 0.04, 0.08, 0.06] J/K`

热导矩阵：

```
G0 = [
 [ .064, -.010, -.008, -.006],
 [-.010,  .064, -.008, -.006],
 [-.008, -.008,  .088, -.012],
 [-.006, -.006, -.012,  .074]
] W/K
```

`C=c×C0`，`G=g×G0`。

连续热方程：

`C·dT/dt = −G·(T−Ta)+p(T,state)`

温限80°C。

仿射功耗模型有效温区20–100°C。GPU 在原观测温区之外属于声明的合成外推。

初始温度由全部最低档空闲状态的稳态方程唯一确定。

必须检查：

- 全合法状态功率非负。
- GPU 忙态不低于同档空闲功率。
- 各状态热系统稳定性。
- 公共比较矩阵的有效性。
- 热量与能量单位一致。

外部公共功耗固定0.30 W，计入系统能耗，视为四节点热网络之外的热源。

目标函数为完整窗口中四节点功耗和外部公共功耗的积分，覆盖所有执行、空闲、切换及末端恢复。

#### 3.6 时间语义

启动时刻使用0.1 ms绝对时间网格。

释放时间及绝对期限保持精确有理数。任务启动不能早于真实释放。

执行时长向上取整至0.1 ms；增加的时间按忙态计能。

所有占用区间为左闭右开。

跨场景继承温度、已释放请求、依赖、资源占用、工作点、未完成切换。

统一评价窗口为最后场景释放结束后再加301 ms。所有算法必须在固定窗口内完成请求和频率恢复。

### 5. 分阶段验证

#### G0：正确性预检

生成全部画像、请求表、初始温度及完整配置。

验证共享频率域、资源互斥、DAG、切换计能、连续继承、热矩阵稳定性及能耗积分。

利用单节点解析解、固定工作点稳态解和旧热核测试交叉核查。

D0必须能够构造全低频安全安排。轻负载解析温度上界为65°C。

高负载必须核实全低频容量不可行；构造固定高档的非热可行安排。

预检失败则停止，不进入优化阶段。

#### G1：建立共同初解及基线

使用事先固定的100 ms流水线区块参考构造和 HEFT 类构造器。

CPU优先使用最低档；高负载参考安排为每100 ms：

GPU执行2A+5B，NPU执行2A+1B，均使用最高档。

额外允许一个预先声明的参考安排：GPU 930.75 MHz执行1A+6B，NPU最高档执行3A。

仅以完整合法性及安全能耗选择共同初解；如无SAFE，则保留合法非热初解与失败原因。

建立以下参考方法：

- 适配 HEFT。
- 热感知 ETA-TS：保留其余量分配和固定映射/资源次序的LFT阶段，明确多DAG与共享频率适配规则。
- HEFT/SA：允许映射、频率、资源次序及启动时间变化。

记录每种方法的SAFE结果、首次SAFE耗时及完整能量。所有参考方法使用同一初始输入与完整评价器。

#### G2/G3：验证热约束影响与优化空间

使用普通强LNS分别求解同一工况：

G2：不强制80°C温限，但仍保留连续热传播、温度相关功耗、20–100°C有效温区。

G3：恢复连续80°C温限。

使用相同合法决策域、相同初始化和预算。

计算可靠下界，至少包含：

- 全窗各域最小合法基准能耗。
- 各Stage最小合法增量活动能耗。
- 外部公共能耗。
- 可选的设备容量/期限窗口松弛。

下界需要说明数学依据；未经认证的求解器内部界另列。

判断规则：

若G2已证最优且其方案SAFE，热安全代价为零。

若安全问题可靠下界大于G2可行上界，证明热约束增加了最优能耗。

若仅发现超温的低能耗候选，记录为机制线索，不能直接宣称全局最优决策发生变化。

#### 小规模 R/F 充分搜索

在各非D0且具有SAFE初解的工况中，固定第一场景边界。

按初解的主任务启动时间选取边界前最后一个及边界后第一个main，并纳入其post，共四个Stage；缺少对应任务则登记跳过。

固定其余Stage。

移动Stage的候选起点为初始起点前后50 ms内的绝对5 ms网格及初始起点本身，并与真实合法时间域取交集。

R：保持原设备与资源相对次序，优化工作点和起点。

F：开放所选任务的合法设备、工作点、次序和起点调整。R必须包含于F。

四组使用相同的空闲及切换权限、完整全窗目标与固定外部任务。采用枚举、分支定界或可靠小规模求解器。

分别获得：

`E_R^0、E_R^θ、E_F^0、E_F^θ`

定义热安全代价减少量：

`Δθ = (E_R^θ−E_R^0)−(E_F^θ−E_F^0)`

利用可靠上下界给出Δθ区间，只有区间下界为正时才确认联合域减少热安全代价。

未完成搜索时保留可靠界与未决状态；严格限定结论为该局部有限域。

不得以巨型整体MILP未返回结果作为核心实验结论。

#### 跨场景热继承诊断

对相同时间表额外执行一次非物理温度重置诊断：仅在场景边界将温度重置为空闲稳态，其余执行状态完全不变。

比较重置与真实连续传播下的：

- 热安全判定。
- 峰温与热点位置。
- 目标配置可行性。
- 完整能耗及决策排序。

重置模型产生的候选必须经过真实连续热模型验证，才能参与SAFE能耗比较。

#### G4：时热关联机制验证

只有出现真实热阻塞线索且存在SAFE初解时，才执行此阶段。

统一采用已完成G1/G3方法中能耗最低的完整SAFE方案作为机制初解。

按参考温度下的正活动节能潜力，对main降频或换设备目标排序；每工况最多检查前8个不同请求的目标，最多选取2个真实受阻目标。

必须验证目标不可行原因。固定其他任务时，不能以单个启动点失败就判断该目标的整个允许起点域不可行。

如目标首先受时序阻塞，再检验解除时序阻塞后的热可行性。

固定目标配置，使用统一子问题优化器：

| 组别 | 邻域选择 |
|---|---|
| B0 | 仅目标Stage |
| B1 | 目标+最多4个时间关联Stage |
| B2 | 目标+最多4个热关联Stage |
| B3 | 目标+2个时间关联和2个热关联Stage |
| B4a | 目标+4个普通资源邻域Stage |
| B4b | 目标+4个普通随机邻域Stage |
| B5 | 从单目标开始按实际失败原因自适应扩展，最多5个Stage |

时间关联按依赖路径、资源边、期限阻塞及候选延长时间排序。

热关联按实际违规节点/时刻的分段热贡献排序；包括前序场景任务和其他处理器任务。贡献仅作邻域选择依据，不用于直接排除合法候选。

B1–B4固定相同实际邻域规模，无法凑齐时缩小至共同规模并记录。

所有组使用相同的局部启动时刻候选生成规则、优化器、接受条件和时间预算。

记录：

- 目标工作点是否成功恢复。
- 完整窗口净节能。
- 实际改变的Stage及资源边。
- 热违规节点与连续热证据。
- 邻域大小、候选评价数及计算时间。

禁止将扩大邻域本身的收益解释为时热关联选择的独立收益。

#### 有限全窗筛查

仅在G4取得有热关联价值的正例后执行。

从相同完整SAFE初解开始，分别进行一次有限预算改进：

1. 普通LNS。
2. 直接A+B：ETA-TS余量优化+未来热评价+普通联合调整。
3. A+B+Δ：以实际时序/热阻塞原因选择联合邻域。

三组使用同一目标生成规则、同一局部优化器和接受条件，同等映射、调频、重排权限。

HEFT、ETA-TS和SA结果作为参考；上述三组是本轮同初解、同改进预算的核心算法比较。

不开发完整第三章正式算法，也不实施第四章专门的剪枝提速方案。

### 7. 独立安全认证与指标

对所有最终候选重新构造完整功耗事件序列，并使用独立连续热评价器复核。

热评价必须覆盖事件区间内部的温度极值，而非仅检查事件端点。

使用仿射传播、区间包络或带有可靠误差控制的连续求解方法。目标峰温包络宽度不超过0.001 K，能耗积分绝对误差目标1e−6 J。

只有温度上界不超过80°C且满足所有非热约束的结果可以标为SAFE。

无法在预算内认证时标为UNRESOLVED，不视为SAFE或已证超温。

严格节能以新方案能耗上界低于旧方案能耗下界为准。

主要指标：

- 完整SAFE系统总能耗及相对节能率。
- SAFE可行率。
- 热安全代价与可靠最优差距区间。
- 低能耗配置恢复率。
- Δθ及其可靠区间。
- 同规模时热关联邻域相对普通邻域的净收益。
- 分项能耗、峰温、期限余量。
- 首个SAFE时间、最佳SAFE能耗随求解时间的变化。

没有SAFE结果时不得填写虚假节能率。

### 8. 立项判据与止损规则

**第一道门槛：问题价值**

开发工况中应存在完整SAFE方案，并观察到真实热阻塞或具有可靠证据的热安全能耗代价。

若所有开发问题的无温限最优均已证SAFE，则停止本研究点的热约束驱动路线。

若缺少可靠最优证据，则标为证据未决，不能判定不存在优化空间。

**第二道门槛：机制价值**

至少出现一个真实时热阻塞配置，通过联合调整关联任务成功恢复，并取得严格完整SAFE节能。

在固定邻域规模及预算下，联合时热邻域应优于普通邻域，同时体现热关联参与的作用。

仅存在普通重排收益时，收缩为时序机制，不宣称已验证时热联合创新。

**第三道门槛：第三章候选算法价值**

本轮预设实用立项目标：有限全窗A+B+Δ筛查相较普通LNS与直接A+B，在至少两个工况中均取得1%以上完整SAFE能耗改善，其中至少一个为留出工况，并具有可追溯的热关联证据。

该1%为本项目的工程立项阈值，不是通用学术标准。

低于阈值但有可靠机制收益时，保留E1证据，暂不批准进入第三章正式实验。

禁止为达成阈值临时增加算例或改变参数。
