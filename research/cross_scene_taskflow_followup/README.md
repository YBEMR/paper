## 目标与时间域

保留 mechanism.targets 给出的正节能请求，并对同一请求补全正潜力的合法降档或换设备配置。潜力按 35°C、无交接的主计算活动能耗差精确计算。排序为潜力降序、原起点到场景边界距离升序、Stage 编号、设备和频档。先各取有时间可行见证的单任务、调整 post、必须移动资源竞争任务各一项，且请求不重复。其余席位按同一排序填满。候选分类与见证只读释放、期限、DAG、设备占用和频档切换信息。竞争类别要求每个原始局部候选起点均有其他请求或资源 Stage 的直接冲突。记录每个起点的阻塞者、原单任务合法起点范围和局部见证。覆盖类别的查找受选择时间限制，未获见证不算覆盖。

每个邻域优先纳入直接阻塞者、后继 post 和冻结 timing 的时间关联排序，普通资源排序补足，不超过五个 Stage。绝对 5 ms 网格只取原始起点前后 50 ms 内的点，另保留原始起点。用冻结 ranges 与 gridpoints 生成各 Stage 相对外部任务的可选放置，再以共享域切换、互斥和依赖逐对组合。为限制旧 rebuild 对任意空闲间隙的随机改写，本轮复用其放置原语并单独重建控制。物理间隙按域、起止 tick、前后 OPP 匹配。匹配的间隙强制继承控制，只有新增或确实改变的间隙可选保持、降档。每个完整计划交冻结独立事件重建及热评价器认证。

确定性遍历交错访问新放置和局部间隙控制。固定种子随机重构补充访问顺序。所有访问使用相同合法域，筛选按真实连续全窗能耗，无 80°C 接纳门槛。不同排程按归档 G3 同一规范计算 SHA-256。每个目标保存按真实能耗及身份排序的前 24 个 C0 有效候选，另存原始 G3 及全搜索中找到的最佳固定目标 SAFE 参照。收全目标清单后才开始搜索，收全候选池后才进行反事实评价。

## 判据与预算

C0/C1 共用同一次连续复算。C2 复用 evaluate(reset=True)，始终用连续能耗排序。所有共同池身份和排序均可从文件复核。门控参照同工况全部目标搜索发现的最佳连续 SAFE，包括未进入前 24 的安全参照。用所有已发现 SAFE 的最小能耗下界减候选连续能耗上界作为可靠净节能下界。固定活动、基准、切换及外部能耗以有理数从域驻留和执行时长重算。逐候选对照配置、资源边和域控制。严格节能但低于 0.1% 且非温度能耗下降的结构性冲突单列。对具有实质净收益且结构发生变化的热效应，保留非温度变化的符号和大小。

若触发，选可靠净节能差最大的单个目标，复用冻结的热贡献和六种邻域选择，共用本轮的局部重构器。B1–B4b 实际规模一致，比较原始 G3、阶段一最佳 SAFE 及普通对照。三组反事实评价时间包含完整轨迹写入。每工况预选择时间计入该工况第一个目标的 120 s，不借用其他预算。搜索结束前预留最多 2.5 s 写回。每项有独立进程墙钟保护，整轮上限 1800 s。最后复核用另一路功率事件构造和 SciPy 仿射矩阵指数对全部共同池计划复算两条轨迹。

## 结果入口

`results/decision.md` 为中文结论，`summary.csv`、`targets_summary.csv` 和 `candidates.csv` 位于同一结果目录。`source.patch` 记录相对结果基点的冻结源码差异。plans 保存完整排程，certificates 的 JSON 保存物理变化与能耗分解，NPZ 的 events、continuous、reset 依次为冻结热核的 14 列功率事件和两份 17 列连续积分证据，列定义沿用 P1。targets、pools、counterfactual、gate.json、calls.jsonl 和 snapshot.json 分别保存选点、池冻结、同域比较、严格门控、预算和快照。结论只适用于本轮访问和认证范围。
