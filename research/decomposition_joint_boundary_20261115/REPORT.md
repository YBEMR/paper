# DJ-M1：分解式与联合式电热优化的适用边界

**本轮没有找到配置/时序必须联合优化的剩余收益。** 在全部128个条件下，固定热不感知方案选出的映射和频率，仅完整优化时序，即达到九千余条候选组成的相应有限域联合最优。热感知配置基线TC1无需保留第二个映射也达到同值。原NT方案最多多耗0.02984%，差值来自温度漏电的微小时序效应，没有形成值得开发专门联合算法的证据。

**覆盖限制同时成立：共享频率一致性约束没有排除任何候选；温限虽淘汰部分候选，却没有改变任何方法最终选择。** 因而不能把结果解释为已验证“共享频域、合法模式和热耦合同时起作用时，分解总是足够”。这是一次受限问题上的负结果及覆盖缺口，不是整个方向的否定。

## 1. 近邻方法约束了什么结论

完整矩阵及正文定位见 [LITERATURE_MATRIX.md](LITERATURE_MATRIX.md)。Zhou 2018通过虚拟核关联选择处理器与频率；Li 2019的一般模型已含映射、速度、起点及耦合热方程，算法已有余量降频与冷却延迟；RT-TAS已按CPU/GPU热耦合协调执行。因此不能把这些关系重新包装成未解决空白。

Jiang 2018把映射作为输入，在该边界内优化任务频率、起点、通信和空闲/睡眠；其最优性并不包含重新映射。Li 2018出版方可确认热感知分配与速度优化的两阶段思路，但本轮未取得全文，不能替它补写共享频域或硬温限的保证，也不能断言它没有这些能力。

“分解”不天然意味着次优。令m为映射，V(m)为该映射下对全部频率和时序求得的安全最小能量，则联合问题等价于 `min_m V(m)`。实际损失发生在第一阶段提前固定了不够好的m、错误估计V(m)，或过早删去候选。本轮用条件最优来分辨这种损失与第二阶段求解不充分；这只是基本优化关系，不作为新理论贡献。

## 2. 冻结问题与数值来源

来源固定到 [635b21c的config_v01.json](https://github.com/YBEMR/paper/blob/635b21cd537d66b22f4139e995988cf86c41d736/research/chapter3_experiments/config_v01.json)及同版`thermal.py`。源文件明确声明`parameter_origin=self_set`；热传导、线性温度功率修正与完整窗口核算结构已有验证，但这些具体常数**不代表某一真实CPU/GPU/NPU平台**。没有混入A2-M1的Xavier参数。

四Stage构成 `S0 → {S1,S2} → S3`，是新建合成分叉—汇合图；每个Stage复用原画像，未冒称完整推理网络。

| Stage / 源画像 | 合法执行单元 | H档时长ms / 活动功率W / 频率敏感系数α |
|---|---|---|
| S0 / A.pre | CPU1、CPU2 | 10 / 1.0 / 0.4 |
| S1 / B.main | CPU1、CPU2；NPU0 | CPU：100 / 3.5 / 0.9；NPU：35 / 4.0 / 0.6 |
| S2 / C.main | CPU1、CPU2；GPU0 | CPU：90 / 2.5 / 0.7；GPU：45 / 4.5 / 0.8 |
| S3 / A.post | CPU1、CPU2 | 5 / 0.8 / 0.3 |

使用原L/H两档：CPU为0.8/1.6 GHz、0.70/0.90 V；GPU为0.4/0.8 GHz、0.65/0.85 V；NPU为0.5/1.0 GHz、0.65/0.85 V。原M档不属于本次预先限定的问题，不能据此声称原全部档位最优。

```text
d = d_ref × [(1−α)+α f_ref/f]
P_activity = q_ref × (V/V_ref)^2 × f/f_ref
θ = T−25°C
C dθ/dt = P_activity + P_base + diag(λ)θ − Gθ
E = E_activity + E_base + E_temperature_correction + E_external
```

C为diag(0.04,0.04,0.08,0.06) J/K；G单位W/K：

```text
 0.064 −0.010 −0.008 −0.006
−0.010  0.064 −0.008 −0.006
−0.008 −0.008  0.088 −0.012
−0.006 −0.006 −0.012  0.074
```

CPU/GPU/NPU域L/H底座分别0.60/1.30、0.40/0.90、0.25/0.60 W；CPU域只收一次并平均注入两CPU节点。节点温度斜率分别CPU0.002/0.004、GPU0.004/0.008、NPU0.003/0.006 W/K。环境25°C，外部共同功率0.30 W不注入芯片热节点。全部活动、空闲、频率相关底座及结束后的尾段计费。

Stage非抢占、不可迁移、内部频率固定；CPU1/2共享频域，真实重叠时必须同频。域空闲时才能切换，空闲保持最后频档，入口全L。沿用源的零搬运/切换时延与能量；该理想化不是实际开销测量。

起点网格20ms，持续时间保留公式值，不向网格取整。期限115/149.5ms来自CPU最高档关键路径115ms的1.0/1.3倍；所有方案共用400ms完整评价窗口。入口温度为全部节点50或78°C，温限80°C；自然预热可达性未实测。工作形状W0为原值，W1仅把S1/S2时长分别乘1.2/0.8。同一算例各方法的工作、精度假设、合法动作、期限和窗口完全一致。

协议在计算候选结果前冻结，见 [PROTOCOL.md](PROTOCOL.md)、`protocol.json`及`freeze.json`。四个候选池分别256、4,288、352、4,512条，总计9,408条；这是完整有限网格域，不是连续时间全局最优或任意DAG保证。

## 3. 公平对照与消融

所有方法共用同一完整评价器和同一个候选池，不比较运行效率，不把条件穷举叫作可扩展在线算法。基线全部标为**适配基线/条件最优参照**，不声称忠实复现任何原论文。

| 方法 | 第一阶段保留什么 | 后续允许什么 |
|---|---|---|
| J | 所有合法方案 | 完整安全域内最小总能量 |
| NT | 按活动+底座+外部能量选原方案，不利用温度 | 原样后验完整电热评价；超温则不算节能率 |
| DelayRepair | NT映射、频率；起点不早于NT | 同一网格内找安全最早完成方案，能量破平局 |
| D_C | NT映射与频率 | 所有合法起点中的安全最小总能量 |
| D_M | NT映射 | 全频率、全起点中的安全最小总能量 |
| TC1/2/4 | 遍历每个配置的最早完工代表，完整热评价后保留1/2/4个不同映射 | 每个保留映射内完整优化频率和时序 |

TC第一阶段已有温度信息，仍可能因代表时序不佳而删掉本有安全解的映射；该风险通过`mapping_conditionals.csv`保留，不能把“代表超温”解释为“映射不可行”。D_M则给任何保留NT映射的修复所能达到的最佳值，避免用过弱修复制造联合收益。

全因子开关：C跨节点热耦合、L温度相关功率反馈、S共享频率域、H温限。共8基础例×16臂=128条件。C关闭时同时消去横向热导和对应对角增量，**到环境热导保持不变**。L关闭只令λ=0，底座不删。S关闭把CPU域分成两半底座的独立域，避免凭空改变功耗口径。H关闭仍记录温度与20–100°C模型有效域。

非热参照为C=L=H=0、S保持相同；只关闭C不是无热因素。每个消融臂内全部方法共用相同合法集合；开关S跨臂的权限变化明确标识。

### 4.2 三种情况没有混为一种

1. **原热不感知方案超温：本轮没有发生。** NT全部安全，不能用“避免NT超温”宣称收益。
2. **安全修复后仍有损失：** 最早完成式DelayRepair最多保留0.02984%微差；D_C和D_M均无损失。这里不是修复失败导致的可行性优势。
3. **强热感知分解仍有损失：本轮没有发生。** TC1即达到J，TC2/4没有新增收益。没有在不安全方案之间计算节能率，也没有把失败当作零能耗。

### 4.3 微小差值来自漏电时序，不是配置/资源协调的剩余差距

| C耦合 | L温度反馈 | NT最大多耗/J，S开或关结果相同 |
|---:|---:|---:|
| 0 | 0 | 0 |
| 1 | 0 | 0 |
| 0 | 1 | 0.0298402% |
| 1 | 1 | 0.0297863% |

关闭L后微差消失，说明这部分确属模型中的热能量反馈；开启C只轻微改变数值，**跨设备耦合不是产生差距的必要条件**。不能把这张表解释成共享频率与跨设备热耦合共同造成了不可分解损失。

以W1、149.5ms、78°C、C=L=S=H=1为例，NT和J都用CPU1→{NPU0,GPU0}→CPU1，四任务均为L档：

| 方案 | S0/S1/S2/S3起点ms | 活动J | 底座J | 温度修正J | 外部J | 总量J |
|---|---|---:|---:|---:|---:|---:|
| NT | 0 / 20 / 20 / 100 | 0.169661387 | 0.500000 | 0.206190553 | 0.120000 | 0.995851939 |
| J=D_C=TC1 | 40 / 60 / 60 / 140 | 0.169661387 | 0.500000 | 0.205925336 | 0.120000 | 0.995586723 |

两者只差约265.217μJ温度修正能量。该例同一频档下热方程为线性定常系统，初态响应与任务发热响应可叠加；把发热推后，改变固定终点400ms前的温度积分，同时改变终点储热。两方案无需达到相同终温，因而这包含有限窗口的热时序效应，不能直接外推成周期稳态或墙插净节能。

所有温态配对中，50→78°C均未改变任何方法所选动作，说明“考虑温度相关能量”与“需要根据当前热状态改决策”在本轮仍须区分。没有新增终端冷却实验来放大或淡化这点。

### 4.4 温限与共享频域的实际活跃情况

完整模型、78°C入口时，宽期限W0的4,288条候选有960条超温，W1的4,512条有352条超温；其余完整模型条件均无超温候选。**温限对候选可行域有作用，但未影响所选最优。** 开/关H后所有方法选出的候选ID和能量完全一致。所有最终方案的峰温保守上界≤78.23638°C，至少约1.7636°C余量。

S开/关时，四个候选池的合法条数完全相同：没有不同CPU核上重叠且异频的候选。原因是本期限/工作量/档位/网格组合下，较慢CPU低档主计算难以与另一CPU主计算形成合法异频重叠。域联动仍可能改变空闲CPU的底座和温度斜率，但**一致性约束本身没有约束力**；最终最优映射也未使用并行CPU主计算。

因此，本轮未覆盖用户核心问题中“三者同时约束决策”的情形。协议冻结后没有放宽期限、修改工作量或温限来补一个正例。不能从此次停止推断未来活跃共享频域下没有边界问题。

## 5. 验证、适用边界与停止判断

两套不同枚举过程逐行一致：生产枚举按DAG边界生成，独立验证使用笛卡尔起点组合再过滤。四池完整覆盖冻结域，所有温限分类均已判定，没有未决候选。矩阵指数给分段精确线性流，另用DOP853独立核验；峰温采用连续区间二阶导上界，而不是只验采样点。全原始轨迹最大热守恒残差7.78×10⁻¹⁴ J。

96个不同最终见证再从5ms面板收紧至1ms，能量最大差2.0×10⁻¹⁵ J，峰温界最大宽4.90×10⁻⁵°C。完整复算76份结果一致（summary仅耗时变化）。这支持**本有限网格域的数值最优参照**；浮点矩阵指数不是向外舍入区间证明，也不是硬件认证。

本轮局限为：合成参数、粗20ms起点网格、L/H两档、四Stage、两工作形状、两初温、零切换/搬运成本、无热降频/空间细粒度热点、无周期终端条件、共享频域一致性未激活。8个手工参数组合不是统计总体，不能宣称真实平台上的稳定边界。

**停止判断：完成本轮后停止新算法开发。** 有热漏电导致的微小时序效应，但没有配置与时序之间必须联合处理的剩余损失；强分解已追平。更不能用一个热不感知弱基线与J的差值来证明新联合方法必要。

若未来重新进入这一问题，应由已有真实场景或独立文献提供同时合法的CPU异频重叠需求、跨设备热影响及可改变可行性/映射排序的证据，再固定问题验证；不要从这套合成输入反复调参寻找失败。Li 2018全文也需补齐后才能给出完整近邻保证比较。本轮不提出新的MILP或高效算法，不更改旧实验记录或最终论文选题。
