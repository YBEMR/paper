# P1 紧凑频域联合优化模型与条件节能价值验证任务书

**阶段：E0 + E1 立项诊断**

**研究目标：第三章高质量安全节能求解**

## 1. 研究目的与执行边界

本轮仅完成两项工作：

- E0：建立紧凑的局部频域联合优化模型，验证其与原 P1 事件构造器的双向合法域一致性、事件语义一致性和能耗一致性。
- E1：在现有归档安全排程基础上，量化不同联合决策权限能够实现的额外安全节能价值。

第三章始终以最终安全系统能耗及解质量为核心。搜索加速、增量评价、快速筛选暂不作为本轮创新机制。

不开发完整频域驱动 CP-LNS，不启动 E2 算法级比较，不重新寻找特殊热冲突，不修改物理参数制造正例。

## 3. 模型与合法域要求

完整继承 P1：

- CPU 双核共享频域，GPU/NPU 独立频域。
- 固定服务量、任务依赖、合法设备与频率选项。
- 0.1 ms 整数时标、原始释放与期限。
- 非抢占执行、原交接时间及取整规则。
- 调频耗时0.5 ms、附加能耗1.5 mJ。
- 原空闲保持或提前降至最低档的控制语义。
- 三频域全窗口初末均为最低档。
- 原完整计能窗口、301 ms 尾段及四节点连续热模型。
- 全过程80°C温限、20–100°C模型有效温区。

禁止改变任何物理参数、任务数量、期限、频率画像或热状态继承方式。

### 3.1 紧凑模型

优先采用 CP-SAT 或其他能够表达可选区间、条件约束与整数时序的求解器。

基本表达：

1. Stage 可选执行区间及唯一配置选择。
2. 任务依赖、释放、期限和设备互斥。
3. 按频域任务起点排序的后继关系。
4. 频域占用前沿的最大值递推。
5. 共享频域重叠时的同频约束。
6. 空闲间隙、频域驻留及切换控制。

排序语义须与原 `transitions()` 一致，包括相同起点的确定性排序规则。

CPU 忙区间按两个核心占用的并集计费，不允许重复计算频域基准能耗。

切换期间沿用原事件构造器的频率状态及附加功率定义。

只构造局部可变决策和必要的固定边界结构，不建立全部任务乘全部时间刻度的整体模型。

对局部可变任务的所有允许放置范围及合法目标设备，保留所有可能受到影响的固定任务、共享频域边界和相邻间隙。不得因简化边界而遗漏潜在竞争任务或合法放置。

### 3.2 目标函数与真实评价

紧凑模型准确表达35°C参考能耗：

E35 = 活动能耗 + 域基准能耗 + 切换附加能耗 + 公共能耗。

温度相关能耗及最终连续热安全继续由冻结评价器计算。

E35 仅用于生成和组织候选，最终以原连续热模型计算的真实系统总能耗排序。

不得把参考目标最优直接称为真实电热目标最优。

## 4. E0：紧凑模型等价性验证

### 4.1 双向合法域一致性

在声明的有限决策域内验证：

**完备性：** 原事件构造器接受的每个合法物理排程，均可被紧凑模型表达。

**可靠性：** 紧凑模型接受的每个排程，均能转换为原模型接受的合法排程。

一致性应针对规范化后的物理排程，而非无实际物理作用的冗余空闲控制标记。

原模型中不起作用或产生相同物理事件的控制标记应规范化，避免将等价编码误认为不同可行解。

同时提供紧凑表达与原事件递推之间的双向对应说明。

### 4.2 小域穷举与边界测试

至少覆盖：

| 测试类型 | 必须核查的内容 |
|---|---|
| 单设备串行 | 资源互斥及合法换序 |
| CPU 同档重叠 | 合法并行及忙区间并集 |
| CPU 异档重叠 | 正确拒绝 |
| CPU 嵌套占用 | 前一任务尚未结束时，占用前沿不能错误回退 |
| 切换时间边界 | 恰好满足、差一个 tick、零间隙等情形 |
| 空闲控制 | 保持、降档、重新升档及等价控制 |
| 映射变化 | GPU/NPU 迁移后的源域与目标域事件 |
| DAG 与期限 | 精确边界、固定前后继、超期拒绝 |
| 局部边界 | 与外部固定任务、频域状态及间隙的衔接 |
| 场景边界与尾段 | 温度不重置、首末最低档、尾段完整计能 |

采用冻结画像和原合法语义，设计可完整枚举的小型测试域。单个穷举夹具的理论候选规模应在执行前限定，建议不超过50,000种编码。

分别由独立枚举器调用原事件构造器，以及由紧凑模型枚举全部合法解。

比较规范化后的合法排程集合，不能仅抽样比较几个可行解。

### 4.3 能耗与事件一致性

对合法排程比较：

- 每个频域切换事件的起止、原档与目标档；
- 各节点事件区间内的参考功耗、温度斜率和基准功耗；
- 活动、域基准、切换、公共能耗分项；
- 全窗口真实连续能耗区间；
- 连续峰温区间和 SAFE 判定。

参考能耗优先采用有理数核算。若 CP 目标必须整数化，应记录缩放尺度、舍入误差上界及整数溢出检查。

事件比较采用共同时间划分，避免因等价事件区间的合并或拆分造成假不一致。

使用紧凑模型所表达的事件流与原独立事件构造器分别核对，不能仅将两份相同的原评价器输出互相比较。

### 4.4 真实排程回放

至少回放：

- D1、D2、D3 原 G3 排程；
- D1、D2 的 v1.1 最佳 SAFE 排程。

要求上述五份归档计划能够被紧凑模型完整表达，并与原能耗、事件及安全认证一致。

### 4.5 E0 门控

小域合法解集合须完全一致，能耗与事件核对须全部通过。

数学表达的双向对应必须成立。有限穷举通过仅代表已测域的一致性证据，不替代一般性说明。

若发现差异，保存最小反例并修复模型表达。未通过 E0，不进入 E1。

## 5. E1：联合决策权限与真实节能价值

### 5.1 四个嵌套子问题

| 子问题 | 空闲控制 | 频率 | 起点 | 资源次序 | 设备映射 |
|---|---|---|---|---|---|
| P0 | 可变 | 固定 | 固定 | 固定 | 固定 |
| P1 | 可变 | 可变 | 可变 | 固定 | 固定 |
| P2 | 可变 | 可变 | 可变 | 可变 | 固定 |
| P3 | 可变 | 可变 | 可变 | 可变 | 可变 |

P1 的固定资源次序指每个执行设备上的原任务相对次序，包括可变任务与固定任务之间的相对次序。CPU 两核之间的起点顺序不额外冻结，仍须满足共享频域约束。

P2/P3 允许局部任务与固定任务重新形成资源邻接关系，但外部固定 Stage 自身的配置和起止时刻保持不变。

四组必须共享相同的局部任务集合、起点允许范围和空闲控制权限。

### 5.2 局部合法域

可变 Stage 的起点允许范围统一为原起点前后50 ms 内的全部0.1 ms合法时刻，与原释放、依赖、期限及窗口约束取交集。

这不是 v1.1 的5 ms稀疏起点网格。

冻结每个可变 Stage 在全部允许配置下可能占用的时间包络。

空闲控制权限采用统一规则：涉及该包络或可变任务的原有间隙可重优化；因合法移动新增或物理状态改变的间隙可重优化；其他未变化间隙保留原控制。

原有间隙通过频域、起止时刻和前后频档等物理签名识别。

四组均须包含原 G3 排程，确保可行域嵌套且存在共同安全初解。不得针对某一组增加额外控制权限。

### 5.3 E1-a：D1、D2 历史案例

固定两个已有局部区域：

- D1：Stage 148、149、133、147、139。
- D2：Stage 289、295、296、310、311。

不固定某个目标必须采用预期节能配置，允许各组在自身合法权限内联合优化。

首先验证 v1.1 已知改善排程是否属于 P3 指定局部域，并检查其分别能否属于 P0、P1、P2。

历史最好解作为已知见证单列保存，不作为新算法找到的收益。各组实际求解仍从共同 G3 初解出发。

D2 重点分析：

- Stage 289、295 属于第一场景释放的请求；
- Stage 310 属于第二场景释放的请求；
- 三者跨场景竞争 NPU，已有联合降频和时序协调见证；
- Stage 296、311 还涉及 CPU 后处理映射及资源边变化。

比较四组真实安全能耗，区分各类权限的贡献。不能直接将既有75.349 mJ全部归因于 P1。

### 5.4 E1-b：D3 预选区域

D3 原场景转换发生在5000 ms。预先确定四类区域：

| 编号 | 选择位置 | 重点资源 |
|---|---|---|
| R1 | 5000 ms场景转换附近 | GPU |
| R2 | 5000 ms场景转换附近 | NPU |
| R3 | 2500 ms低负载场景内部 | GPU |
| R4 | 7500 ms高负载场景内部 | NPU |

每个区域选择四个完整推理请求，共12个 Stage。

选区规则：

- R1/R2：在4800–5200 ms内按主 Stage 原起点距场景边界的距离排序，分别选择两个第一场景请求及两个第二场景请求；优先选择当前映射至指定资源者，相同条件按 Stage 编号排序。
- R3/R4：在对应中心前后300 ms内选择四个所属场景一致的请求，优先指定资源，再按主 Stage 原起点距中心的距离及 Stage 编号排序。
- 若指定资源上的请求不足，按事先规定的同一排序规则从另一加速器补足。
- 若仍不足，记录该区域不可构造，不再寻找替代正例。

场景归属由请求表确定，不由任务实际执行时刻确定。

所有区域成员、起点域、固定边界和空闲控制权限须在首次求解前一次性冻结。区域若有重叠，明确记录，不作为独立样本处理。

不得按照求解结果重新选区或扩大范围。

## 6. 可靠解质量证据

对每个局部子问题 Pj，输出真实连续安全最优值的可靠区间：

Lj ≤ Vj ≤ Uj。

其中 Uj 来自已经完整独立认证的安全排程；Lj 必须来自对真实目标有效的数学下界或完整遍历证据。

35°C代理目标的最优值及求解器内部 gap 单列，不能代替真实能耗下界。

可优先验证 D1–D3 的40°C公共温度下屏障，并以固定下界温度计算功耗下界。必须先核对初始状态、各合法状态的功耗斜率及热方程比较条件；若无法证明，退回原可靠下界。

对整数化下界进行保守舍入。

若采用候选枚举与认证结合的方式，必须保存未搜索空间的下界，完整处理 HOT、UNRESOLVED 及有效温区违规状态。

只有代理目标较差不能成为永久排除真实能耗更优候选的依据。

## 7. 节能价值计算与结果分类

四个子问题满足：

V3 ≤ V2 ≤ V1 ≤ V0。

分别报告：

- V0 − V1：联合频率与时序优化价值；
- V1 − V2：进一步解除资源次序限制的价值；
- V2 − V3：进一步解除设备映射限制的价值；
- 原 G3 能耗与各组最佳 SAFE 能耗之差。

对于相邻权限 A、B（B 的合法域包含 A），条件最优节能价值的可靠区间为：

[max(0, LA − UB), UA − LB]。

若更大的权限组在有限预算内找到的解较差，应继承较小权限组的已认证可行解作为数学上界，同时分别报告独立搜索所得结果，不能把有限搜索差异解释为权限增大导致最优能耗升高。

结果状态至少区分：

| 状态 | 判定 |
|---|---|
| 已证严格额外节能 | 新权限安全上界严格低于旧权限可靠下界 |
| 观察到额外节能 | 新权限找到更低的安全能耗，但条件最优差距尚未闭合 |
| 已证无改善 | 有完整证明说明两权限条件最优值一致 |
| 已证改善不超过容差 | 可靠上下界证明潜在改善不超过预先声明的数值容差 |
| 有限搜索未发现改善 | 没有找到更优解，且尚未完成证明 |
| 证据未决 | 存在认证、求解状态、实现或证据链问题 |

所有严格改善均使用能耗认证区间判断，不以浮点点估计直接宣称严格改善。

数值容差与研究价值判断分开记录。

本轮不设置必须节能1%的硬性门槛。

## 10. 立项与止损

本轮不以求解速度作为核心成功标准。

若简单空闲控制已经获得主要收益，停止复杂频域联合机制立项。

若固定映射、固定次序的 P1 已经能够取得主要节能收益，则第三章优先研究频率与时序联合优化，不强行增加复杂换序和映射机制。

若 P2 或 P3 提供具有实际意义的额外节能证据，则重点解释产生收益的联合决策结构，并据此设计后续算法。

若各组仅有宽松下界、未找到改善或证据未决，按实际证据状态结束本轮，不把有限搜索失败解释为不存在节能空间，也不据此直接宣布立项成功。

只有 E0 通过且 E1 支持具有研究价值的联合节能机制后，才讨论 E2：普通 CP-LNS 与拟研究算法的充分预算解质量比较。

本轮结束后停止执行，提交完整结果及研究判断，等待下一阶段授权。
