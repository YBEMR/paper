# E2-b：跨资源时间余量协调与多任务联合节能优化

## 1. 研究目标

在冻结 P1 连续电热任务调度问题上，开发完整任务流联合节能优化算法，验证其相对于普通 CP-LNS 的独立解质量优势。

主要研究机制：

- 多任务执行配置联合选择；
- 配置组合驱动的跨资源时序支撑域；
- 时间缺口驱动的补偿配置与资源次序协调。

第三章以最终完整安全系统能耗为核心，不以搜索加速作为主要贡献。

## 3. 拟研究算法

### 3.1 初始排程与全任务流覆盖

各工况统一使用原归档 G3 最佳 SAFE。

按请求释放时间划分250 ms搜索区间，循环覆盖完整任务流。场景转换处不设置不可跨越的边界。

每次联合重优化均以当前完整排程为参照。禁止直接复用 E1 局部区域的旧边界、固定任务关系或假定局部收益可以叠加。

### 3.2 执行配置组合生成

在当前搜索区间选择具有潜在节能价值的任务。

固定设备下的初始配置排序可采用：

`参考执行增量能耗 = (忙态功率 − 该节点最低档空闲功率) × 占用时长`

此式仅作为提案排序，不作为真实能耗、共享域边际能耗或可靠剪枝界。

选择一个主要目标任务，并从当前及相邻搜索区间选取最多7个有潜在价值的辅助目标。保持确定性的排序和轮转规则。

对目标配置分别计算其时序支撑集合，优先组合支撑集合具有交集的目标。每次初始组合最多包含3个目标配置；不存在相关组合时允许单目标。

不得永久排除单独看来增加能耗的执行配置。最终 CP 子问题保留被释放任务的全部合法频档。

### 3.3 时序支撑域构造

在暂定配置及原次序骨架下，建立跨资源时序约束图：

- 请求内部任务依赖；
- 同设备执行次序；
- 暂定频档下的共享频域条件分隔关系；
- 释放、期限及局部起点边界。

CPU 跨核尚未确定的异档先后关系可按原起点顺序构造试探骨架，不得直接作为最终 CP 的强制次序。

计算最早起点 L 和最迟起点 U。

若骨架满足 L ≤ U，按拓扑顺序构造时序支撑解：

`s[i] = max(L[i], min(s0[i], U[i]), 所有前驱的完成及分隔要求)`

将所有起点需要改变的任务纳入时序支撑集合，并保留目标配置任务。

多个目标组合后重新传播，不能简单相加各任务的独立时间余量。

### 3.4 时间缺口协调

若出现超期路径或起点域冲突：

1. 记录条件时间缺口及对应约束路径。
2. 将路径上存在更短执行配置的任务作为补偿配置候选。
3. 在允许换序的迭代中，选择路径上的资源次序关系，构造合法的次序释放范围。
4. 若某个任务需要越过多个资源邻居，完整释放对应的相对次序关系，不能仅删除一条邻接边。
5. 请求内部依赖边始终保持，不允许释放。

补偿配置可以增加单任务能耗，最终由联合系统能耗决定是否采用。

条件骨架不可行不代表原完整问题不可行，不允许据此永久删除任务配置。

若支撑集合超过预定规模，先减少初始配置组合后重新传播；仍超限则采用普通邻域作为补充。不得静默截断必要支撑集合后宣称已完成时序协调。

### 3.5 联合 CP 子问题

构造：

- Sf：配置可变任务；
- St：时序可变任务；
- Sr：可改变资源相对次序；
- Sg：合法受影响的空闲控制。

调用 E2-a 完整参考能耗 Core。

初始组合中的暂定配置只用于构造支撑域，正式子问题不强制采用该配置，允许重新选择所有授权的合法频档。

局部 CP 必须共同优化配置、起点、频域驻留及切换控制。

从当前排程重新建立全部可能影响的频域边界、固定任务、迁移源域与目标域。新区域身份必须绑定当前排程 SHA，而非原 G3 的静态身份。

### 3.6 搜索过程

采用以固定映射调频移时为主、次序调整为辅的迭代结构。

建议每四次迭代包括：

- 两次固定映射、固定资源次序的联合优化；
- 一次固定映射、允许资源次序调整的联合优化；
- 一次普通全权限邻域，保留设备迁移能力。

普通 CP-LNS 与拟研究方法采用相同的权限轮转安排。

每次生成多个不同物理排程，全部按原完整电热评价方式核验。严格改善的 SAFE 方案更新最佳安全解。

通用的候选去重、精英解保留和停滞后的重新选点策略由所有 CP 方法共用，不作为拟研究机制的独立增量。

## 4. 对比方法

| 代号 | 方法 |
|---|---|
| G3 | 冻结版原随机重构 LNS，延长搜索预算 |
| CP-FO | 普通联合 CP 搜索，始终固定原设备映射及资源次序 |
| CP-LNS | 通用时间窗口、重叠任务、设备及请求链邻域 |
| Proposed | 配置组合驱动的时序支撑域及跨资源次序协调 |
| Proposed-Single | 与 Proposed 相同，但每次子问题至多改变一个任务的执行配置 |

CP-LNS 是最重要的直接组合强基线。

它必须使用 E2-a 完整参考能耗模型，具有独立配置、时序和次序释放权限，也允许保持原配置的相关任务参与移时。

不得将其弱化为同时冻结邻域外全部时序变量的普通局部修复。采用合理的通用邻域混合及相同停滞处理策略。

该方法称为适配的普通 CP-LNS，不声称完整复现 Kasapidis 的全部 ALNS-CP 算子。

Proposed-Single 通过 Access.max_changes=1 实现，设备与频率变化均计入配置变化次数。保留多个任务移时及合法次序调整能力。

Single 允许通过多次迭代逐渐改变多个配置，因此该消融检验的是一次联合改变多个配置的实际算法价值，而不是限制其最终合法域。

另建议在 D3 增设 Proposed-NoOrder 消融，关闭专门的次序协调算子，并将对应迭代替换为固定次序联合优化；保留共同的普通全权限迭代。该消融只衡量专门次序协调机制的贡献。

## 5. 工程预检

正式运行前冻结算法实现与全部参数。

建议初始公共规模上限：

- 配置可变 Stage：12个；
- 时序可变 Stage：24个；
- 单次联合子问题：30秒墙钟预算；
- 起点范围：当前起点前后500 tick，结合原合法约束。

所有 CP 方法使用相同规模上限。

注意原 Master 采用 ±500 tick 起点域。E2-b 必须统一以当前排程为中心重建该域，迭代间允许累计移时，但始终满足原任务释放和期限约束。

在 D1、D2、D3 各选取普通和拟研究方法的首个预定联合子问题，共6次进行可用性预检。

只检查模型合法性、边界正确性、候选返回及预算执行，不依据节能大小调参。

若正确性失败，立即停止。若实际规模无法正常产生合法联合候选，记录工程问题后再决定是否统一调整规模，禁止直接启动正式批次。

同时重新执行 E2-a 相关回归及权限接口测试。

## 7. 主评价指标

第一主指标：

1800秒预算结束时的完整系统 SAFE 总能耗。

同时报告：

- 相对共同初解的净节能率；
- 相对普通 CP-LNS 及其他强基线的配对节能量；
- 各种子的最终值、中位数及范围；
- 活动、域驻留、温度修正、调频能耗分项；
- 最终安全认证及期限合法性；
- 多配置联合改变、移时任务数和换序贡献；
- 180、900、1800秒的能耗—时间记录；
- 原可靠全局下界及仍未闭合的质量差距。

不得使用35°C参考目标的 CP 内部下界代替真实连续能耗的全局下界。

不将1%设为硬性立项标准。

三个随机种子仅用于初步稳定性判断，不据此宣称充分统计显著性。

## 9. 验收与立项判断

若 Proposed 在较充分预算下相对普通 CP-LNS 具有稳定的最终安全能耗优势，且消融支持多配置联合及跨资源时序协调的价值，则支持第三章核心算法立项。

若优势主要来自资源次序协调，则调整第三章主次机制定位，以实际证据为准。

若 Proposed 与普通 CP-LNS 最终能耗接近，只是更早获得相同质量解，则将相应结果归入求解效率研究，不包装为第三章独立节能贡献。

若 Proposed-Single 与 Proposed 最终能耗基本一致，则多配置同时改变的独立价值尚未建立。

若各方法在1800秒末仍明显改善，报告未收敛状态，不将有限时间终点称为全局最优。

不因结果不理想追加搜索轮次、改变物理参数或重新选择有利区域。
