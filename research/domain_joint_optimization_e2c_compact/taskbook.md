# E2-c1-r：支撑约束联合配置辅助模型紧凑化

## 1. 研发目标

针对 E2-c1 在 D3 上的辅助求解超时问题，实施一次有限修订：

1. 直接保留并评价原 warm_candidate() 构造出的合法候选。
2. 基于支撑规模约束进行时序变量消去与起点域紧化。

不增加新的节能算子，不改变配置候选选取规则，不启动混合算法完整实验。

## 3. 可行提示直接评价

严格复现原 warm_candidate()。保存其完整赋值、实际配置变化、时序支撑集合及参考收益。若出现配置变化，立即通过原物理构造器及权限检查。按照原 E2-c1 方法生成继承控制和参考能耗优化控制两种合法空闲策略，参加真实连续电热认证。不因后续 CP 超时丢弃已构造的候选。

原求解器返回的有效辅助赋值仍可构造后续 Core；没有有效赋值时，允许以已验证的非平凡提示构造支撑域。两种对照采用完全相同规则。

## 4. 紧凑辅助模型

### 4.1 全图约束构造

复用原辅助模型的请求链、同设备次序及 CPU 跨核条件分隔关系。对所有可能有效的边，计算其在授权频档组合下的最大约束权重 w_bar。对于当前起点 t0，定义最大残余时间压力：

a_bar[i,j] = w_bar[i,j] − (t0[j] − t0[i])

分别计算各任务由于合法起点边界变化可能产生的最大提前、延迟需求。

### 4.2 支撑规模有界传播

从全零提前及延迟包络开始，使用同步更新执行24轮正反传播。

延迟包络：B_new[j] = max(0, 最大起点下界增加量, max(B_old[i] + a_bar[i,j]))

提前包络：A_new[i] = max(0, 最大起点上界减少量, max(A_old[j] + a_bar[i,j]))

每轮包络限制在500 tick以内。最大权重仅用于计算保守包络，正式辅助模型仍采用实际配置决定的原始条件约束。不得将最大权重直接作为所有正式时序边的固定约束。

### 4.3 变量消去

当某任务不是配置候选，并且正反传播包络均为0时，将其起点和配置替换为原排程常量。其他任务保留原模型变量，并将起点域与传播包络取交集。保留全部与固定任务有关的合法边界约束。若配置候选的传播包络为0，仍需保留其合法频档选择能力。原提示若不属于紧凑域，仍保留其完整物理候选评价，但不得将不合法赋值作为紧凑 CP 的提示。

### 4.4 数学验证边界

理论目标是保留原辅助模型各固定配置组合的可行性和原字典序最优目标。不要求两种辅助模型拥有完全相同的全部物理排程集合。证明应基于固定配置下的差分约束：在最小支撑及最小总移时方案中，正向或负向移时存在紧约束来源；沿同方向追溯的实际移动任务数量不超过24。检查该论证对原条件 CPU 边、整数起点、配置变化但起点不变的任务及配置组合排除约束是否成立。若发现反例，停止紧凑化推进，保存反例，不静默缩小可行域。

## 8. 评价指标

逐前态保存原模型和紧凑模型的变量数、约束数及保留 Stage 数，构模、传播、辅助求解与认证耗时，辅助求解状态及真实可行赋值，原提示是否产生多配置变化，提示直接评价的真实安全节能，辅助 CP 相对提示产生的额外安全节能，后续 Core 相对辅助候选产生的额外节能，最终完整安全能耗，是否发生普通邻域回退。必须区分提示生成、辅助 CP、后续 Core 三个阶段的实际贡献。

## 9. 本轮门控

紧凑化首先必须通过正确性及辅助目标等价性检查。其次检查 D3 是否出现不依赖普通回退的真实多配置联合节能证据。重点比较 Compact-Hint 与 Full-Hint，判断变量消去是否真正改善了有效联合方案的取得，而不仅是变量数量下降。如果 D3 仍缺乏有效多配置节能方案，或者新增辅助模型不能在原预算内发挥作用，则暂停该辅助 CP 路线。不因个别正例自行修改样本、参数或追加回放。本轮结束后提交中文报告、原始数据、代码及 GitHub 固定归档。不启动 E2-c2，不启动 H1–H3，不启动第四章实验。
