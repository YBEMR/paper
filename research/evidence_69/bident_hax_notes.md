## 2．HaX-CoNN：首先作为强否定对照

HaX-CoNN已经把层组自身时长、跨设备交接和并发访存减速联合用于映射；“把隔离时长用于并发会失准”“GPU/DLA共享内存也有交接代价”均不能再次作为我们首次识别的缺口。

| 位置 | 原文事实 | 使用边界 |
|---|---|---|
| §3.1，PDF第3页 | 合并可融合算子，避免切断硬件流水；结合后端支持确认合法切换点 | 不能把任意算子边界当成合法Stage边界 |
| §3.2，Table 2，PDF第3—4页 | 实测GPU/DLA层组时长与双向交接；交接涉及私有缓存输出回写与下一设备输入 | 已有数据交接与布局/融合处理能力 |
| §3.3，PDF第4—5页 | 隔离profile与争用模型分开；用请求带宽、外部流量预测减速，并按并发开始/结束形成区间 | 不是简单对所有并发统一加常数，也不是只做整模型争用 |
| §3.4，式2—8，PDF第5—6页 | 完成时间组合孤立时长、减速和IN/OUT交接；式7—8按重叠区间计算影响 | 没有从现成公式推出CPU–NPU温度模型；公式抽取版存在排版噪声，不逐字重抄复杂式7 |
| 式9—11及§3.5 | 有设备冲突限制，目标为吞吐或最大完成时延；借助通用约束求解；D-HaX动态重新产生/渐进改善安排 | 不能说作者只会静态孤立映射，或简单重新求解未被考虑 |
| §4 Table 4 | 实验为Jetson GPU–DLA及Snapdragon GPU–DSP，最多两种加速设备 | 平台有CPU不等于实验已给CPU–NPU层组频率、功率和热参数 |

正式模型中未见把频率选择、能量目标或瞬态温度作为联合决策；这是本文研究范围，不是“它不可能扩展表达”。若只加入热评价器或新的profile维度，可能仍由原约束规划直接处理。

仓库证据：[HaX-CoNN](https://github.com/ismetdagli/HaX-CoNN)，当前浏览分支为`ismet-dagli`，未取得可靠提交SHA，不能称版本冻结。README承认运行模式/软件版本可改变数据，当前artifact采用MAXN；论文默认功耗模式和artifact不能混成同一测量批次。

- [layer_results.json](https://github.com/ismetdagli/HaX-CoNN/blob/ismet-dagli/output_expected/layer_results.json)：实际打开，有GoogleNet分组GPU时长数值，例如0—9组的`total_gpu_time_ms`；README标为作者预收集数据。
- [transition_results.json](https://github.com/ismetdagli/HaX-CoNN/blob/ismet-dagli/output_expected/transition_results.json)：实际打开，有标记位置的平均时长与交接差值；可追踪部分GPU–DLA边界数据。
- [output_expected目录](https://github.com/ismetdagli/HaX-CoNN/tree/ismet-dagli/output_expected)：还列DLA时长、EMC与运行结果；本轮只核查目录存在性，未把未读文件视为已核实数据。
- [z3_solver_multi_dnn.py](https://github.com/ismetdagli/HaX-CoNN/blob/ismet-dagli/src/z3_solver_multi_dnn.py)：直接核查。过渡代价和带宽数组注释有“the current data is dummy”；代码另含至多一次设备切换限制。**不能把所有硬编码数组当实测，也不能把演示代码的能力范围替换成论文一般公式。**

结论：有可复用的结构、部分时长/交接数据和现成求解思路，但没有形成CPU–NPU活动增量功率、并发功率与RC的配套包；不需要重下载HaX全文。

## 3．BIDENT：须采用v2澄清后的边界

以下依据[BIDENT v2](https://arxiv.org/html/2606.05271v2)；本文为CC BY 4.0公开预印本，仍未确认同行评审结果。

| 位置 | 可核查事实 | 不得扩张的结论 |
|---|---|---|
| III-A | 固定形状、固定融合边界；按支持设备分别编译和profile；另测并发对的时延 | 不是只测单独运行；不能说作者完全忽略争用 |
| III-B | 串行链的路径代价可加；并行支路独立选择属于启发式；两请求仅在声明状态空间内最优 | v1较笼统的最优表述不能作为攻击当前版的依据 |
| III-B | 同模型请求锁步；混合模型双方未结束时各前进一步，只有剩余尾段单独推进 | 这是搜索域限制，不等于已证真实损失；与任意异步到达/调度并不等价 |
| III-B、IV-A | 单次运行的整包平均功率参与算子能量计价；CPU/GPU/NPU共用一个功率计量域 | 不是Stage活动增量功率，也不能直接分配到CPU/NPU热节点 |
| III-B | 并发能量由各请求solo功率分别计价，作者明确称近似；未直接测并发package功率 | 未提供idle扣除规则；不能声称已测出基准重复量或确定误差方向 |
| III-B、IV-E | 所有报告结果的保守实例对每算子都收H2D+D2H，与邻居映射无关；此时串行逐算子贪心等价于最优 | 执行图原则上已经支持映射相关边代价，不是“无法表达切换” |
| IV-F | 端到端部署观测到设备边界调用开销，小预测收益可能被抵消 | 只是该部署实测边界，不是所有后端的常数；作者提出resident executor方向 |

功率口径关键短原文：`package power under co-execution is not measured directly`（III-B）。时长包括单独计量的执行、派发、H2D/D2H；共同图实例如何收取边界须按上表区分。BIDENT并未给出我们可直接使用的频率曲线或瞬态温度参数。

并发时延定义也不是统一的`max(孤立时长)`：同设备采用屏障同步的实测共同执行代价；同模型使用对称平均、混合模型使用对的makespan；跨设备有profile时用共同执行观测，否则退回solo最大值。其能量中的功率仍是solo口径，因此“已测并发时延”不能推出“已测并发能耗”。

v2对HaX重实现设置的单切换、整设备减速不能代替HaX原文。特别是HaX正文已经有层组和争用区间，本轮不采用BIDENT表格或二手评价来断言HaX只是整模型映射。

数据可用性：本轮查arXiv、作者主页和其论文页，只定位论文入口，未取得BIDENT公开源码、逐算子原始profile或并发功率轨迹。检索词为`"BIDENT" "Hoseok" github`与`"BIDENT" "2606.05271" code`。这是本次范围内未找到，不是断言作者没有数据；需要的是数据而非再下载已有公开全文。

## 4．两个条件性入口（均未证明创新）

### 入口A：solo能量可加，是否掩盖了并发安排的实际能量与注热？

**事实出发点**：BIDENT v2明确使用solo package功率近似并发能量；HaX已证明并发重叠能够改变时长。前者不是后者的功率测量证据，两篇数据不拼成同平台。

**研究推导，非论文原式**：设同一平台、同一窗口内的单独功率可分解为`Psolo_i=P0+Qi`。记安排σ的阶段时长为`d_i(σ)`、并发交互功率为`ΔP(σ,t)`，则待核查的计量是

\[
E(\sigma)=P_0W+\sum_i Q_i d_i(\sigma)+\int_0^W\Delta P(\sigma,t)\,dt.
\]

这里有三个独立问题：公共基准只计一次；争用可能改变时长；活动功率是否还存在非可加交互。只有第一项不一致时，统一基准即可纠正，不构成强创新。第二项已有HaX类模型可处理。第三项目前缺匹配测量，不假设其一定为正或很大。

对两种相同工作量安排σ、σ′，若近似代价差与被省略修正项之差符号相反、后者绝对值超过前者，排序可能翻转；还需两方案在同一deadline与完整热评价中可行。这个代数条件不是已发现真实损失。

**温度为何相关**：并发选择与延迟改变实际功率区间和持续时间；正确能量计价与正确节点注热应共享同一执行轨迹。整包功率不能全部注入CPU，必须补节点分配或诚实使用平台级热边界。不保证低总能耗就低峰温。

**最小修正/强替代**：先去除公共基准重复，再比较固定pair时长/活动功率表＋完整重排。若这些已足够，不要引入动态微架构或新的复杂热算法。若固定配置、固定活动时长、无交互且窗口固定，则等待不会改变活动能量；原61号分解仍成立。

**缺口与可实施性**：有明确假设入口、现实时长争用依据；还缺同平台CPU–NPU共同功率与有效热分配。本轮只可给条件推导；无硬件时如拿不到公开配套数据，不得称已证端侧收益。适合作为优先核查卡，而非直接升级为论文主线。

### 入口B：算子局部收益，是否足以支付实际的子模型边界调用？

**事实出发点**：BIDENT IV-F显示边界调用能抵消小收益；HaX§3.1—3.2已主动处理融合、重排格式与交接。目标不是“第一次考虑通信”，而是核查某一后端的profile代价能否组合成实际调用成本。

**符号条件**：把连续CPU片段的一部分改到NPU，局部节约Δt；若新增调用/同步延迟`h_in+h_out`大于Δt，则时延优势消失。能量要比较整窗口CPU主机派发、NPU执行及边界活动增量，而不是用时延比代替；热关系可能来自额外CPU参与和功率重叠，但本轮无配套热测量。

**简单方法足够条件**：边界代价只依赖邻接执行设备、张量和固定准备状态时，直接加入边权，原最短路或联合规划即可处理；这是普通适配。只有边界状态因驻留、复用、并发或热控制而变化，且有独立证据，才值得进一步研究状态依赖代价。本轮未证明后一层。

**当前排序**：保留为低优先级备选。它有部署证据，但温度联系较弱，且常数边代价已有充分工具；不能为凑成热方向而附加RC。

## 5．本分项结论

优先保留入口A的“计量口径→并发代价→调度选择”条件核查。先问公共基准去重与pair查表能否解决，不能把普通访存争用或交接重新包装成新机制。入口B作为普通边权适配可能足够的对照。

本轮没有需要用户下载的缺失全文；真正缺的是BIDENT/同平台CPU–NPU的原始共同功率和边界调用数据，以及温度映射。HaX已有作者预收集部分数据，但演示脚本含dummy值，不能直接构造真实平台包。
