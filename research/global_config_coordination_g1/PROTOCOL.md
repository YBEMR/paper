# G1 第一阶段执行冻结

本任务以 P1 四节点连续电热系统的最终 SAFE 总能耗为主指标，比较强配置基线和完整联合 CP。固定仓库 YBEMR/paper，分支 codex/global-config-g1 从 E2-a 的 d313094505db8eb1114b0d5859210b058f7bfa76 建立。P1、E0/E1 的提交分别为 be641ce06a4f496d2b1f233a09bdfc3776738668、57feace657d4ecd495df3b1211ec42161cfee763。逐文件 Git blob、SHA256、软件版本见 input_lock.json。实验只读固定资产，输出在当前目录。E2-b、P2、H1–H3 和 C2 均在本阶段范围之外。

## 物理平台与实例

逐请求执行不可抢占 pre、main、post，在 CPU1/CPU2、GPU、NPU 上按 P1 配置映射。CPU 共用频域，每次切换 5 tick，旧频驻留至切换完成，完整计入附加功耗；三域首尾最低频。全程连续继承任务、频率及温度，温限 80°C，有效区间 20–100°C，尾段 301 ms。D1、D2、D3 逐行复核 P1 CSV。S16、S32、S80 直接调用原 requests 生成器，将两个场景的时长分别指定为 1/10、1/5、1/2 秒。各场景 A 的两流均为 20 Hz，B 的两流在 L/H 分别为 10/30 Hz，同类第二流偏移半周期，按精确释放时刻与流名排序。释放向上、期限向下取整到 0.1 ms。新实例环境 35°C、热容倍率 1、期限 300 ms；原 D3 使用其固定倍率 10。

## 参照、构造与证据

w 为场景内相对释放 tick。B0 在 L 将 A1 分给 NPU0，其余 GPU1；H 将 A1 和 w%1000<500 的 A2 分给 NPU1，其余 GPU5。B1-a 在 L 将 A1 和 w%2000=250 的 A2 分给 NPU0，其余 GPU0；H 保持 B0 映射并将 GPU5 改为 GPU4。B1-b 同 B1-a 的 L；H 将 A1 和 w%5000 属于 {250,1750,3750} 的 A2 分给 NPU0，其余 GPU5。D3 联合配置仅对 H 的最后三个 500 ms 批次额外把相位 475 ms 的 A2 分到 NPU0，最后两个批次其余 GPU 任务改为 GPU4。另固定请求 796–799 的 main 为 GPU2、GPU2、NPU0、GPU3。

各参照均按请求序在 CPU1/0 安排 pre；main 按请求序在指定设备最早启动，换档允许利用已有空隙；post 在 CPU2/0 按 main 完成时刻与请求编号排序。每个方案评价保持和逐间隙优化，Fraction 精确比较 hold 与合法 early-low，平局保持，使用 E1 的 normalize。D3 的五个 9 位核对值采用末位半单位加 0.01 末位数容差，约值 45.037736 J 使用 0.000001 J 容差。核对值依次为 49.086003096、46.952210277、45.455626019、45.058877597、45.051708031、约 45.037736 J。每个不同计划均用 transitions、event_arrays、independent_events、evaluate(cert=True) 核验，逐事件比对，固定 SHA 存完整证书及轨迹。任何合法性、参考能耗核对失败留证停止。

固定 CPU 的自动构造逐步扩展全部 13 种 main 配置。状态是两加速器完成时刻和当前频档，成本以全窗最低驻留为公共项，另加每种配置的忙态超额、每段最佳空闲超额及切换成本，最终补两域尾段。以全部 Fraction 分母的最小公倍数作单位，整数运算精确。相同状态只合并参考成本，保留一个确定性回溯，合并仅服务构造，不宣称连续温度历史支配。保守 post 判据以请求释放前 300 ms 至 main 完成时所有可能排在该 post 前面的工作总量预留时间；它仅用于此处。宽度 1 为最低增量构造，宽度 64、256、1024 分别按累计成本或累计成本加后续容量松弛价格排序。对接下来最多 16 个 main 放松两资源容量，在固定非负乘子组上取对偶下界最大值作为排序项。每实例 180 s 共享，剩余时间在尚未执行的方式间等分，超时只保留已经恢复和认证的完整计划。S 实例同时构造三种已有参照。所有参照与自动结果中，按最小 SAFE 区间上端及 SHA 字典序选共同初解。

D3 固定联合配置前缀，4、10、12 请求后缀的 13 种配置用两套搜索核对。独立深度优先枚举可以按可证明的剩余忙态与不可避免末次切换下界剪枝，逐层 DP 按同前沿精确合并。二者在每请求最短 post 可满足的主任务窗上核对最优参考值，然后用原 post 排序和完整认证确认最优见证实际可达。

## 完整联合域与目标

FullMaster 从 E1 master.py 派生，完整保留两两调频、可选区间、每资源不可重叠及请求链约束。开放所有阶段配置、合法时刻及次序。每个具体配置以请求释放加前序最短工时、期限减后续最短工时、首尾换档剩余时间收紧。频域节点的时间上下界由同一合法窗推出，首端接所有可能首节点，末端固定 H/0；仅删除必不可能的时间逆序弧。共享 CPU 可同档重叠。复用 E2-a 的 _path 传播按 (start,end,frequency,stage) 排序的前沿，按占用并集计驻留。无 FIFO、固定 CPU、起点邻域、配置改动上限或保守 post 约束。小域在枚举完成时比较合法物理集合、切换和逐项目标，再扩大。原 E0/E1 四组、E2-a 八组与权限夹具重跑，新增一组紧期限全 tick 穷举和一组含 >500 tick 移动、映射与共享 CPU 的有限域夹具。

C0 搜索完整 E35。C1 取节点温度屏障 l=(42.5,42.5,42.0,40.9)°C 和公共斜率下界 b=(.002,.002,.0039,.003) W/K。用 Fraction 高斯消元复核初始平衡，检查导热非对角非正、所有节点在屏障的最小净输入、所有状态功率温度斜率及忙闲差。切换附加功率非负。令 y=T-l，活动输入 a 为对应节点在屏障温度处该忙态相对同频闲态增加的功率。边界非负和正耦合给出 y>=0；对每个节点逐段有 C y' >= -(Guu-b)y+a。与初值零的标量线性系统比较，将功率中的 b*y 从活动时刻积分到 H。活动最晚在 D_i=min(H,deadline-后续最短工时) 前结束，得到系数 b/(Guu-b) 乘以 1-exp(-(Guu-b)(H-D_i)/C)。由 exp(x)>=1+x，下界为 b*(H-D_i)/(C+(Guu-b)*(H-D_i))，时间均为秒。L_ET 是完整屏障温度能耗加此系数乘各选中 Stage 的屏障活动能量。C0 单独复核 35°C 屏障。忙态增量、每 tick 驻留率及热补偿均分别向下取整到 pJ，切换及公共项精确，故整数目标不高估真实能耗。C1 条件失败仅跳过 C1。

## 时间、公平性及判定

单工作线程，随机种子 101。正确性预检累计至多 600 s，含原内核预热、夹具和后缀诊断。D 参照每实例 60 s；六实例构造每例 180 s。S16、S32、S80 的 C0/C1 每方法各 900、1800、3600 s。计时自父进程启动工作者前开始，含导入、建模、求解、恢复、认证与逐次归档。父进程设硬超时；总墙钟 16200 s。运行期间不修改协议或搜索代码。程序性故障保留 traceback 和耗用，排程、计能或模型正确性门控失败停止对应后续研究，预算到期不追加求解。S16 后先统计建模时间、求解状态、分支和候选，再判断瓶颈。

C0/C1 共用初解与候选政策，单片至多 60 s。保留最先 11 个及最后 1 个回调解，不足 12 则全保留。按冻结的三片参数周期重启，随机种子恒定。所有保留候选按真实证书评价，预算内未及认证的保留候选记为 pending。重复计划可复用同 SHA 证书。只对评价已落盘的规范化物理排程加 no-good。各自用 floor(U·10¹²) 做安全剪枝。切除部分的真实能耗下界为当时 U；已评价部分保留各自可靠下界；未评价部分留在残余 CP 域中。每片起点的三者下界取最小，再与历次完整覆盖下界和解析全域界取最大。解析界来自最低驻留与各阶段最低配置项；全局差距以该界及 SAFE 上端报告。仅当新区间上端严格低于对照下端时确认严格改善。重叠区间保留。180/900/1800/3600 s 填入预算内已归档最佳 SAFE，实例预算外留空。种子为时间零可用解。仅有未证最优解时按实报告。C1 只改善界或早期速度时，归为质量证明或效率用途。

## 运行

从本目录执行 `python -B freeze.py` 生成输入锁与 S 实例。核对并提交冻结后，`python -B -u run.py` 单次运行；设置 G1_ORTOOLS 可指定固定 OR-Tools 9.11.4210 环境。阶段记录在 results/jobs.jsonl，计划、证书以计划 SHA 检索；所有时间按本机单调时钟计。报告与汇总属于事后只读分析。
