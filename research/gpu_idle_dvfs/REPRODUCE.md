# 复算

结果提交检出后，直接读取原始记录，不需要再跑实验：

```powershell
python -B -X utf8 research/gpu_idle_dvfs/verify.py
python -B -X utf8 research/gpu_idle_dvfs/analyze.py
```

第一条核查冻结源码/输入哈希、原始文件收据、阶段持续时间和功率、资源排他性、固定GPU顺序、切频不可抢占、500请求期限、能量分解、连续热状态继承和证书。它不重新积分物理模型。第二条输出CSV、报告和PNG/SVG；需Matplotlib，其他计算依赖版本见environment.json。

原始证据位于 `raw/<工况>/<开销档位>_<策略>.json.gz`，配套 `_trace.npz` 保存全部温度轨迹。每个证据包含完整系统能量各分量、连续峰温上下界、所有请求完成时间、阶段起止、切频事件、频率段及逐段热状态。`raw/<负载>_input.json.gz` 保存请求、部署、原Kim事件时间轴、固定GPU顺序和H参考时间轴。原输入来源及哈希见execution_manifest.json；没有生成新请求流。

`all_results.csv` 同时保存相对同开销Kim、相对历史零开销Kim的节能率。实际SAFE条件不满足时，安全节能字段应为空。此次全部SAFE。正节能率表示省电，负值表示耗电增加。`energy_components.csv` 使用新策略能量减Kim，符号相反；各差值分量之和等于总差值。切换热/能耗已在activity_J中积分，分量表将其拆出而不是重复计能。

要独立复现实验，应在执行冻结提交0b63a417f73cbe4f9307633ec9dba1fa40e09e5b的新检出目录运行 `python -B -X utf8 research/gpu_idle_dvfs/run.py`。执行器拒绝已有raw目录，整批900秒硬上限。不要重新冻结哈希、覆盖归档或增加候选。本次已完成一次正式批次；这里仅给复算入口，不自动再执行。

零开销Kim回放是六工况回归检查，同时属于正式78次评价。预测的H参考只做一次确定性事件时间轴构造，不进行额外热认证或候选搜索；其构造成本记录在负载输入文件的prepare_s中。单个策略事件规划在两个环境温度间共用，规划/物理/归档时间分别保存；本轮不据此主张算法求解速度优势。

本轮严格只判断声明策略和参数。最有利的固定Kim忙时频率理想参照只运行零开销：不能用它代替非零开销净收益，也不能以它给所有阶段L/H决策提供全局上界。
