## 1．把验证问题说准确

研究问题：在A03的CPU/GPU/NPU抽象设备及已冻结Stage画像下，**独立Stage活动能量排序**与在统一A04模型下所得的**完整六Stage安排能量排序**是否一致？如果不同或同模式不同起点产生能量差异，哪些来自活动能量、模式相关基准和连续温度相关漏电？设备互斥对完整调度时间轴又有何作用？

**不研究**真实芯片的功耗标定、热安全阈值的实际限制、跨场景共享部署，亦不比较新算法与HEFT/MILP。A03有两个请求A、B，各`pre→main→post`，**不是AB/AC等多个场景**，没有“同一个共享Stage跨场景必须同设备”的变量；不能用B01证明C04的跨场景部署贡献。

A04已有Python21/21与MATLAB8/8 TEST_ONLY通过，可以对**完整六Stage时间表**做合法、1秒尾段、能量及连续峰温核查。它**不接受缺少Stage的“单Stage安排”**，所以所谓“独立Stage能量”只能是从冻结模式表抽出的排序代理，而不能冒充A04对一个不完整时间表的物理能量。

## 2．本轮已能从冻结输入直接推导的静态事实（非实验）

模式 \(m\) 的活动能量代理定义为
\[
a_i(m)=d_i(m)\,[q_{i,\mathrm{local}}(m)+q_{i,U}(m)].
\]
此值同时包括本地活动与共享U活动，**不包括**OPP基准、温度相关漏电、完整窗口的空闲尾段或并发影响，故不是“独立Stage真实系统能耗”。

| 模式（仅L） | 时长ms | 活动能量mJ |
|---|---:|---:|
| A.main @ CPU0 L | 117.1875 | 46.58203125 |
| A.main @ GPU0 L | 62.5 | **25.1328125** |
| A.main @ NPU0 L | 70.3125 | 27.4306640625 |
| B.main @ CPU1 L | 35.15625 | **10.21728515625** |
| B.main @ GPU0 L | 31.25 | 21.046875 |
| B.main @ NPU0 L | 35.15625 | 22.306640625 |

因此该**自设抽象输入**中，活动能量排序使计算型A.main倾向GPU0-L、访存型B.main倾向CPU-L；说明当前模式表确实能表达不同Stage的设备偏好，**但这不是整机最优或新物理效应的证据**。

另有一个模型内可证明的模式支配性质：**B.main在NPU0的L/M/H三档时长均为35.15625 ms**，但本地活动、共享U活动、NPU基准和漏电斜率随档位单调增加。保持其他Stage、起点、设备及同NPU独占约束不变，并在声明的25–85°C模型温区内、非负温升下将B.main的NPU-M/H改为NPU-L，执行资源时序不变，热源和温度相关功耗不增；由被动协同RC的比较性质，安全性不会更差、完整能耗不会更大。这是**A03特定参数下的普通支配关系**，不是通用NPU真实性质或新算法理论。不能将B01所观察到的差异升级成实机NPU结论。

## 3．第一层：9个固定时序、全L完整候选（首轮唯一建议实验）

目的：只改变A.main与B.main所选设备，不把时序改变混入设备画像比较。固定其余4个Stage的完整模式与起点：

| Stage | 模式 | 精确起点s |
|---|---|---:|
| A.pre | A.pre@CPU0@L | 0 |
| B.pre | B.pre@CPU1@L | 0 |
| A.main | `CPU0@L`、`GPU0@L`、`NPU0@L`之一 | 1/8 |
| B.main | `CPU1@L`、`GPU0@L`、`NPU0@L`之一 | 1/4 |
| A.post | A.post@CPU0@L | 3/8 |
| B.post | B.post@CPU1@L | 3/8 |

按A.main三选一×B.main三选一枚举**正好9张完整时间表**。用A03原模式ID填六行，不改输入JSON；时间使用精确字符串或分数，不用Python浮点冒充精确输入。

**合法性可事前分析**：两个pre均在23.4375 ms结束；A.main最迟结束 `125+117.1875=242.1875 ms`，早于B.main的250 ms；B.main最迟结束 `250+35.15625=285.15625 ms`；两个post于375 ms开始、384.765625 ms结束，均在500 ms期限前。main彼此不重叠，即使选择同一GPU/NPU也不冲突；两CPU同时活动的片段全是L，不触发CPU共享OPP冲突。完整窗口仍须由A04覆盖至1000 ms。上述只是**离散模式/排程合法性的纸面论证**；实际A04完整回执如遇技术未决应保留未决而非代填SAFE。

**更强的事前数学零假设**：九张安排全部使用各域L档，因此全窗口基准恰为 `(0.1+0.1+0.18+0.14+0.65)W×1s=1.17 J`；其余pre/post活动和为`7.0751953125 mJ`。于是
\[
E(a,b)=1.17\;\mathrm J +0.0070751953125\;\mathrm J
          +a_A(a)+a_B(b)+E_{\lambda}(a,b),
\]
其中 \(E_\lambda\) 是A04的温度修正项。更重要的是，**所有域始终L使矩阵 \(-G+\operatorname{diag}\lambda_L\) 不变**，两个main起点被固定，其电活动波形分别独立于另一个模式，故线性RC叠加与能量积分推出
\[
E(a,b)-E(a',b)-E(a,b')+E(a',b')=0.
\]
这是**该9例受控模型的数学预期**；若从A04精确能量区间算出的交互差异不包含0，应先审查输入生成/共享域/漏电/证书数值，不应把它解释成“发现强耦合”。即使整体最低候选与活动能量代理预测不同，固定时序下的改变也只能来自**各模式的温度修正贡献**，而非A/B互相改变Stage时长。

**如何报告**：列全9候选的六模式、确切起点、请求完成、SAFE/INVALID/UNRESOLVED、基准、活动、温度修正、全1秒能量区间和五节点峰温；明确“9个已声明候选里最小E”，**不得写“全局最优”**或误报算法节能比例。

## 4．第二层：3个预定义的“允许起点变化”对照（首轮审阅后独立决定）

目的：在**完全相同的模式组合**下，对比“上面固定时间槽”和按资源/依赖规则尽早开始的时间轴。只给出3个事前固定类型，不从9组结果中挑有利样本：

| A.main / B.main 的L档设备 | 为什么选 | 变化 |
|---|---|---|
| GPU0 / NPU0 | 两个主计算可并发 | 同模式，比较并发起点与固定250ms错峰 |
| GPU0 / GPU0 | 同GPU互斥，B须等待A完成 | 同模式，检查资源引起的排程依赖 |
| NPU0 / NPU0 | 同NPU互斥，两个Stage不同时长 | 检查另一类加速器的等待与时序影响 |

确定性尽早排程规则：保留pre/post固定的CPU0/CPU1模式L；两pre在0启动，按 `A.main` 优先于 `B.main` 的固定顺序，在前序完成、设备空闲且CPU域L一致时安排最早合法起点；post在自身main完成及CPU空闲时尽早启动。全部结束仍须不晚于0.5秒。**这是构造候选的确定性规则，不是优化器，也不保证得到最低能量或普适最早全局排程。**

对每个模式组合，比较同一组模式的 `E_ASAP-E_slot`。两时间表的基准及Stage活动积分相同（所有模式均L且各Stage运行时长不变），所以**差值只来自温度修正积分**；再由原时间表检查哪些变化确实由同单元互斥引起、哪些只是有意提前执行。观察到时间差异≠发现新的访存争用或热安全约束收益。

若要执行这3例，须在9例结果完整审阅后另行冻结；不得自动按本文件启动。第一层9例＋第二层3例最多12份完整安排；建议每次A04评价限额最多60 s，仅作为**未来预算量纲**（上界12×60=720评价秒，不含材料核查及若另行安排的进程准备），此数字**不是已批准或消费的研究额度**。

## 5．可证伪的结论分级与提前停止条件

| 观察 | 最多能支持的结论 | 不能越界 |
|---|---|---|
| A/B的活动最小设备不同 | 冻结模式表具有任务相关的设备偏好 | 不证明全局最优，也不证明新物理建模 |
| 固定时序9例完整E排序与活动排序一致 | 这9个候选中未观察到模式排序翻转 | 不证明所有OPP/连续起点、所有真实平台均一致 |
| 固定时序发生排序翻转 | 在同一A03物理模型与固定时序下，完整电热记账改变了局部活动排序 | 不是热限导致；需以模式相关温度修正及数值区间解释 |
| 固定时序交互差异非零且区间不含0 | 与当前“全L＋线性RC＋固定起点”模型预期矛盾，先查技术/输入 | 不当新科研发现 |
| 固定模式换起点导致E改变 | 温度相关漏电随完整活动时间轴变化 | 不是安全限活跃，也非实际节能测量 |
| 所有排序与结果都简单、无明显差别 | B01如实结束；A03仍是正确性/机制基准 | 不为制造翻转挑参数/降低温限或扩大搜索 |
| UNRESOLVED/数值超限/证书不完整 | 不产生可排名能量；记录原因并先处理可靠性 | 不补0或将MATLAB名义值冒充SAFE |

**事前排除强热主张**：C02在A03现有被动RC和功率上界下已给出所有t≥0的保守上界35.624°C，远低于本输入U 65°C和计算单元70°C温限。B01不能检验“热安全约束改变调度”。温度相关**漏电能量**仍受活动安排影响，两者不能混淆。
