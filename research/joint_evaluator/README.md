# 固定方案的能耗与持续安全联合评价

## Material Passport

- 2026-10-07；ARS experiment-agent／run，按Codex适配规则在本会话执行、记录和核验。
- 对象：V1有限路径能耗＋V2基础持续安全检查的接口整合。无优化器、参数扫描或节能对照。
- 输入来自原V1／V2预检包。12 ms与14 ms分别保留；原输入、代码及历史结果不改。

## 1．本轮解决什么

同一份`candidate`提供平台、物理参数、模式方案、周期、期限及执行规则。V1与V2均从它生成自己的输入，不允许在`safety`或`evaluation`里再次覆盖期限、方案或平台。

输出分成两层：

| 输出 | 可以说明什么 |
|---|---|
| `finite_path_energy.aggregate` | 声明U1有限路径全部完整、有效且达到误差要求后，才计算加权能耗；仅描述这些路径 |
| `certified_candidate_energy` | 输入身份一致、路径属于保证域、V2取得持续安全证书且U1能耗有效后，才提供可用于已认证候选比较的能量区间 |

例如，12 ms方案在F1／F2上的平均能耗有效，但另一条合法F3过程会超期。因此第一层可以保留诊断数值，第二层没有能量字段。不能因为所选路径较容易，就将该方案标成持续安全。

**12 ms和14 ms属于不同服务输入，不是同一优化问题中的两个可替代方案。** 本轮用它们核对接口，不比较节能收益，也没有选择正式研究期限。

## 2．输入和身份绑定

`inputs.json`保存五组完整整合夹具及原文件哈希，`expected.json`保存运行前声明的结果状态。

| 字段 | 内容及检查 |
|---|---|
| `candidate` | 唯一平台、固定模式方案、执行语义；期限保留在每模式方案内 |
| `safety` | 完整初始状态集合、提交的共同温度盒与片段清单、可选反例过程；不接受候选参数覆盖 |
| `evaluation.paths` | 每条路径明确入口的模式、工作点、温度、相位、切换时钟、未完成工作与事件侧，以及V1完整路径字段 |
| `evaluation.weights` | 非负、精确和为1，与路径一一对应；不丢弃无效或零权重路径后重新归一 |
| `evaluation.accuracy` | 原V1误差要求；不把容差当成计算误差保证 |
| `window_policy` | W1共同窗口；全部释放工作期限被覆盖，窗口端点不释放新工作；不自动改为W2 |

逐条检查入口属于某个声明安全块，路径入口与执行字段一致；不要求是第一个入口块。切换须满足允许边和最小间隔，时间保持精确数值，不引入网格。当前初始零相位、无旧工作范围继承V2，运行后的切换相位不受此限制。

结果绑定五类身份：候选、入口保证域、所用安全分析输入、U1评价输入和源码。数值身份采用有理数规范化，12与12.0相同，12与12.00000000000000000001不同；字符串不伪装成数值。内部两侧记录身份不同或执行中源码改变时拒绝合并。

没有历史结果／外部缓存导入入口。哈希用于防止错配和追溯，不是对人工伪造结果的数学认证器。保证来自检查器实际运算及其证据；后续若比较不同候选，还须统一工作负载、服务要求和U1口径，本模块不自动完成跨候选公平比较。

## 3．运行及停止规则

```powershell
python -B research/joint_evaluator/run_joint.py precheck --output research/joint_evaluator/results/new_run
```

输出目录必须不存在。固定候选API为`evaluate_joint.evaluate_bundle(bundle)`；当前命令行提供`precheck`模式。

一次候选默认共用30 s诊断限额，从输入核对、V2证书验证到全部V1路径、汇总均计时；不为每条路径另获30 s。中断后不发布新的联合候选能耗；先前已形成的证书、轨迹或违规记录按原状态保留。内层数值未分辨、覆盖不足和资源中断均不能产生有效候选能量。

| 联合状态 | 含义 |
|---|---|
| `certified_candidate` | 持续安全和指定U1能耗均有效；不代表最优 |
| `candidate_violation` | 有具体合法违规过程；可能仍存在有效的有限路径能耗诊断 |
| `unresolved` | 安全未决、能耗未达要求或中断；不推成违规／不可行 |
| `input_invalid` | 输入缺失、不相容或超出首版接口；不构成物理反例 |
| `identity_mismatch` | 两侧记录或当前输入／源码身份不一致，拒绝合并 |
| `evidence_conflict` | 持续证书与包含路径上的具体违规矛盾，应查实现，不能排名 |

V1聚合直接复用已有`aggregate_energy`，先验全部路径有效，再读取、加权能量区间；前缀能量不进入汇总。所有安全输出仍使用原可靠连续热包络。精细持续分析保持`not_implemented`。
