# Kim case β / FSM-A 常驻部署输入冻结

**结构准入，数值仿真未准入。** 原文能够确定两套部署的切点、执行资源类型、频档和请求期限。尚无可信区间能在同一块板、同一精度和运行政策下同时约束 A/C 各自的阶段服务时间、完整板功率及温度响应。因此本轮没有可报告的实测或仿真焦耳差、温升、节能率或期限通过率。检索与核查截止 2026-11-18。

## 两套部署如何构成

## 两种差值现在能约束到什么程度

对共同可行、同频率策略的一对部署，令 $I_m$ 为各场景从共同参照温度出发的总能量，$H_m$ 为连续热继承比该独评多计的能量。最后一段与尾窗连在一起。若 A 在独评中的优势为 $d=I_C-I_A>0$，连续评价中 C 反超的充要条件为 $H_A-H_C>d$。若热约束使一方不可行，应直接报告可行集合变化，只有双方都可行才讨论节能排序。

以 25 FPS 为例，独评差等于 **0.20 s × 全窗平均板功率差**；历史修正差等于 **0.16 s × 后四周期平均修正功率之差**。如果独评差为 10 mJ，反转要求后者严格超过 62.5 mW。这是单位换算与窗口几何给出的判别门槛，10 mJ 是例示量。公开资料未给这里两个功率差的可信绝对范围。在现有约束下，实际焦耳差和方向都未识别。[完整区间、不确定性和三个帧率的数值系数](bounds.md)

另有一个可用的结构条件。SC2、SC3 和尾窗中没有 YOLOv2 请求。如果额外常驻引擎在这些窗口内不改变板级待机功率、内存行为及伙伴执行，各段重置到共同初温后这三段时间的 A/C 差均为零。此时独评差只可能来自 SC0、SC1，时长分别合计 0.100、0.080、约 0.0667 s（20/25/30 FPS）；逐时功率差若有上界即可用上述时长乘该界。连续轨迹进入 SC2、SC3 时仍可能带入不同温度。没有常驻功率和执行等价的证据时，应使用完整五周期的保守界。

**停止判断。** 保留两条结构合法的输入。要以最少的新证据推进，优先取得同栈、同切点的 YOLOv2 后缀/中段及交接服务时间、两套完整部署的待机/运行板功率，以及在相同散热条件下能限制历史功率修正的测量或已验证区间。若只取得吞吐，仍无法签发此次期限和能量证书。现有材料不支持宣称原筛选损失，也不支持宣称两部署等能。
