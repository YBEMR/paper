# Kim case β 两套固定部署的输入证据

截至 2026-11-18，Kim 的论文给出了任务名称、部分层切点、部署示例、频率列表和系统级吞吐量。现场可确定的是**算哪些任务、有哪些固定映射，以及频率归一化的参照**。两套部署在同一输入、软件、频率和功耗通道下的逐阶段数值仍待补。本文使用 A、C 表示只改变 app0 的两个比较部署；它们的标签分别源于 Kim 表 3 的流水线选项 A、C。Kim 的 case α / β、FSM-A 和基线 BS 是三个不同的维度。

## 逐阶段响应及复用规则

[stages.csv](stages.csv) 按完整请求展开，`AC` 表示对两个部署都适用，`A`、`C` 表示各自 app0 分支。每项 `STAGE` 紧跟它的内部角色，每项 `EDGE` 记录相邻处理单元间依赖。两部署分别展开后有 15、16 个计算阶段和 11、12 条边界；CSV 用共用行引用相同伙伴。CPU0–CPU3 是按 app0–3 指派的逻辑单元，不代表原实验的核亲和记录。两 DLA 共用一个频率选择域是本次模型口径，单独记录每颗 DLA 的占用与注热。原文表 3 说明 DLA 可对换；表 9 的简写 D 不指定具体绑定。

* app0 的 DLA0 [0–29] 和 CPU 前后处理可以共用基础 profile 的条件是同一权重、融合/编译产物、输入输出格式、线程、测量边界与频率一致。DLA0 后继从 GPU 换为 DLA1 时，其边界响应须分开；若该变化改变生产者内核、融合或缓冲布局，就要拆分两个 DLA0 profile。
* A 的 GPU [30–53]、C 的 DLA1 [30–40] 和 GPU [41–53] 分别需要独立的持续时间与活动功率。每段包含的层数不能作为耗时或功耗分配比例。伙伴应用沿用相同基础 profile；共用时资源排队和竞争产生的实际开始/结束时间仍可不同。
* 边界行是**逻辑依赖**。需确认输出格式、共享缓冲、重排/拷贝、同步以及使用哪条通道。一次动作只计一次；若已包含在生产者或消费者 profile，应记录归属并把额外增量记为零。零拷贝或零开销须有接口依据。未核实的 `UNKNOWN` 保留未知。CPU 前处理已包含的装载/布局转换不得在第一条边重复计入。
* 频率仅归一至各域论文最高档。设 \(r=f/f_{\max}\)，Kim 的时间模型是 \(t(f)/t(f_{\max})=1/r\)。表 7 使 CPU 的 \(r\) 从 0.525424 到 1、GPU 从 0.490741 到 1、DLA 从 0.394495 到 1。相应的**模型内倍率**上限为 1.903226、2.037736、2.534884。这些量无单位，不能推出绝对毫秒数，也不能作为某个融合子图的实测慢化包络。若使用实测查表则相对比值与误差范围另报，转换/DMA 不能强套生产者域的 1/r。
* 对计算、必要传输分别记录参考频档下的 ACET 与 WCET（ms），须有样本及定义，且 \(0\le\mathrm{ACET}\le\mathrm{WCET}\)。时限分析要考虑释放、排队、互斥及完成边界；仅有稳态 FPS 不够。能耗与热轨迹按所声明实际或情形时长计算。若使用 WCET 时间线计算能量，另标为保守执行情形；不得把按 ACET 的热轨迹自动升级成最坏温度保证。
* 功率以 W 记录。直接路线在相同窗口积分同一整板通道，以输入电源或经核准的整板读数为准。分解路线分别记录空闲组基准、局部温度项、活动增量及公共功率，活动项保留各节点的注热映射。平均处理器/整板功率不能逐阶段叠加；整板通道与其已包含的子轨不能再次求和。重叠执行时，同一域基准只计一次。若只拿到板级积分，可以判定窗口能量差，不能从单个标量恢复逐节点热源。边界及空闲尾段使用相同计量政策。

## 核查版本与公开文件

**可用于核对的弱时间约束。** 在原文的同一 256×256 profile、资源绑定、频率与可调度性模型下，若某一应用的串行阶段确实通过隐式期限检查，则阶段的估计 WCET 总和不超过该应用期限（排队及干扰时间非负）。表 9(a) 的原 case β 32 FPS 对应 31.25 ms，原 case α 47 FPS 对应约 21.2766 ms。因而在**相应原论文条件内**单个阶段亦不超过该期限；这个必要条件既不分解各段，也不能给出有正下界的绝对响应区间。跨组合移入的 β/A、重新绑定的物理引擎与本研究的派发规则需要独立校验；两张表没有给能确定逐阶段能量的相应功率下界或上界。
