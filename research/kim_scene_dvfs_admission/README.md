# 逐场景 DVFS 联合决策准入实验

**建议保留逐场景调频和连续热复核，把联合穷举留作小规模参照。** 25°C 下，独立选频已经找到连续热约束下的全局最优方案。联合评价能剔除 4,707 条被独立评价误收的超温序列，但最优方案没有落在其中。30°C 下，任何前序调频都救不了 SC2。两组条件给出了热安全复核的理由，目前没有发现必须依赖专门搜索算法才能获得的可行解或能耗收益。

本轮直接沿用合成平台 `301b06e5` 的四节点热模型、计能、任务图、部署和频档。新增协议及代码已在目标负载运行前冻结于 [9b261166](https://github.com/YBEMR/paper/commit/9b261166f3b0f2231bd86bd24934ec9944669b8c)。只开放真实场景边界处的 DVFS，常驻部署始终固定。实验采用 25 FPS、相同的 500 个请求、10 s 服务窗及 40 ms 尾窗，初温均为四节点 30°C，模拟温限均为 80°C。热模型开启温度相关漏电，恒定工作点下的服务时间不受温度影响。切档时温度连续，切换延迟和切换能量取零。[冻结协议](protocol.md) · [合成参数出处](../kim_synthetic_platform_v1/parameters.md)

## 三种方法选了什么

表内计能均来自同一个连续物理模型，包含图像预处理、推理、后处理、交接、空闲及尾段。每种方法都可以选择部署 A 或 C。三字母按 CPU、GPU、共享 DLA 频域排列，例如 LHL 代表 1190.4 / 1377 / 550.4 MHz。四段按 SC0 至 SC3 排列。

| 环境 | 方法 | 部署与四段频率 | 选策时的估计 J | 连续复核 J | 请求期限；连续 GPU 峰温 |
|---|---|---|---:|---:|---|
| 25°C | 整窗固定，连续评价 | C，LHL / LHL / LHL / LHL | 47.996293 | 47.996293 | 500/500；77.527°C |
| 25°C | 分场景独立选择 | C，LLL / LLL / LHL / LHL | 42.535282 | 43.110758 | 500/500；76.506°C |
| 25°C | 连续热联合选择 | C，LLL / LLL / LHL / LHL | 43.110758 | 43.110758 | 500/500；76.506°C |
| 30°C | 整窗固定 | 无可行方案 | — | — | 54 个候选均未同时通过期限和温限 |
| 30°C | 分场景独立选择 | 无可行方案 | — | — | 两部署在 SC2 均无可选频率 |
| 30°C | 连续热联合选择 | 无可行方案 | — | — | 118,098 条满足期限的序列全部超温 |

**逐场景调频的作用。** 25°C 下 SC0 和 SC1 的 27 个工作点均能按期完成，SC2 和 SC3 只有 GPU 为高档的 9 个工作点能够按期。固定法因后两段必须使用高 GPU 档，全程保持 LHL；两种分场景方法都只在进入 SC2 时将 GPU 从低档升至高档。四段连续能量从固定法的 8.0850、9.7101、15.4770、14.7243 J 降至 5.9980、7.0292、15.3727、14.7109 J。前两段降频也把 SC2 的 GPU 入口从 49.01°C 降至 37.80°C。完整物理节能为 **4.885535 J，约占固定法的 10.18%**；联合搜索相对独立选择额外节能 **0 J**。最小期限裕量从 5.496 ms 变为 2.721 ms。两部署各自比较，也都选中相同频序；联合物理能量 A 为 43.171319 J、C 为 43.110758 J，相差 0.060561 J。以上数字属于冻结合成条件。[六项对照及四节点峰温](summary.csv) · [逐段物理重放](raw/decisions.json) · [分部署结果](raw/by_deployment.csv)

**跨场景热状态的作用。** 即使选择一致，独立法对 C 的最优频序仍低估了 0.575475 J。25°C 下，两部署合计 118,098 条期限合法序列，在独立重置温度时全部通过温限；连续传温后只有 113,391 条安全。A、C 分别有 2,742、1,965 条超温，未发现反向改判。举例而言，C 的全程 HHH 在原平台同窗下独评 GPU 峰温 77.55°C，连续重放为 80.77°C。对两种部署，先把集合限制为真实连续可行，再按独立能量排序，首选频序仍相同。由此可以同时解释候选误收与最终选择不变。[可行集合交叉核验](raw/comparison_sets.json) · [固定 HHH 的同窗原始记录](../kim_synthetic_platform_v1/raw/candidates.csv)

**30°C 无解可以局部解释。** SC2 活跃的是 YOLOv2tiny、YOLOv3tiny 和 YOLOv3，它们在 A、C 中部署完全相同。对每种部署，SC2 的 27 个动作有 18 个超期，其余 9 个从四节点 30°C 起跑也全部超温。此时环境和初温相同，非负热源、被动散热与节点间传热使各节点始终不低于 30°C。同一工作点及段内活动下，输入温度逐节点升高不能降低后续温度（热系统的非对角耦合系数非负）。因此先前场景无法提供比这次独评更冷的入口。联合枚举与这个局部无解证据一致。[逐场景、逐频档记录](raw/local.csv)

## 搜索规模和时间

每个环境中，固定法检查 2×27=54 个整窗候选。独立法比较 2×4×27=216 个局部动作，对每一套常驻部署分别求四个局部极小值，再用四段总焦耳选部署。联合法覆盖完全相同的逐场景动作空间，显式分类 **2×27⁴=1,062,882 条完整序列**。每部署 472,392 条即可由期限排除，余下 27×27×9×9=59,049 条均有连续物理能量和安全状态。两个环境总计保存 2,125,764 条分类，没有未决温限。过温能量只供诊断，超期条目能量留空。

| 单线程墙钟秒数，两部署合计 | 25°C | 30°C |
|---|---:|---:|
| 共享热模板编译 | 2.8631 | 3.0172 |
| 整窗固定搜索 | 0.0132 | 0.0039 |
| 分场景独立搜索 | 0.0093 | 0.0091 |
| 连续热联合搜索 | **53.9098** | **0.0417** |

另有一次两环境共用的事件排程 1.0659 s、玩具预热 0.5216 s。表中搜索计时已使用相同的预计算，未含写文件或最终逐事件复核。25°C 的选中方案复核及选定开销分别为固定 0.0964、独立 0.0210、联合 0.0209 s；固定项还含读取旧结果进行核对。计时是该机器一次运行的量级，不是设备在线延迟。独立法单独使用时并不需要为任意热入口编译全部联合搜索模板。[原始计时](raw/timing.json)

**耗时差的具体来源。** 在每个环境，复用相同前缀后实际进行 132,732 次段级入口评价。25°C 的快速连续峰温包络有 113,773 次不能直接判定，需要回退到原始热核；30°C 的快速上界或超限见证点均能给出结论，回退为零。回退次数反映这套证书实现的松紧，不能直接解释为有相应数量的最终方案接近 80°C。四段全枚举可完成；若将其用于大量重复离线评价，连续热安全检查是本次有计时证据的成本来源。[各深度计数与回退次数](raw/counts.json)

## 后续判断

本轮成立的研究问题是：**如何在逐场景选择低能耗工作点后，用继承的温度状态确认整条部署方案仍然安全；若独立方案失败，是否能以小代价找到另一个安全解？** 第一部分已有误收案例和连续复核依据。第二部分在本轮尚未出现：正常环境的局部选择本身就是全局最优，压力环境已有局部无解证据。建议以逐场景独选加一次连续复核为简单方法，保留完整联合枚举作为离线标尺，暂缓 MILP 和标签剪枝。

边界也很具体。只有四个场景各出现一次，只有一次理想切换出现在优胜方案中，动作固定在场景级，未模拟实机调频延迟、热节流或预测误差。若未来每一次场景出现都能独立决策，自由度随出现次数增加；若始终为四种场景各固定一条频率表，延长运行时间只增加热复核长度。两种设定的搜索规模应分开讨论。

## 核验与复现

12 项小测试通过。独立核验检查所有完整序列的期限掩码和结果编码，108 条恒档对角线与上一轮冻结结果一致。对预先指定的 {LHL, HHH}⁴ 两档子空间、两部署、两环境，共 64 条逐一使用原事件与热核独立重放；6 项方法选择或无解状态均核准。安全结论是冻结模型和既有浮点护栏内的数值判定。[独立核验结果](raw/validation.json)

整库检出后进入本目录，在原平台 Python 环境内运行。完整节能与安全数组在 `raw/space_{25,30}_{A,C}.npz`，第 i 项索引为四位 27 进制、按时间顺序编码，档序为 CPU/GPU/DLA 各自 L→M→H 的笛卡尔积。`status` 为 0 超期、1 可行、2 超温、3 未决；`energy_j` 为整窗焦耳，超期为 NaN。

```sh
python -B -m unittest discover -v
python -B run.py --freeze 9b261166f3b0f2231bd86bd24934ec9944669b8c
python -B verify.py
python -B summarize.py
python -B postprocess.py
```
