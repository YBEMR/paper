# 首轮冻结协议（V1，价值实验前）

用途是判断在一套公开方法启发、自设响应和物理参数的有限模型内，是否值得继续开发前瞻算法。外部实测与自设数值见 sources.md。继承核、输入与历史版本见 reuse.md、legacy_sources.json、inputs.json。本轮保留三类应用的固定精度、固定工作量、固定部署，完整窗口为 8 × 240 ms 加 100 ms 全低档尾段。禁止变更输入参数和基线寻找正向结果。

- 数据用 inputs.json 和 workload.py 确定，输入原始请求随各例存档。轻/重负载、全节点50/78°C、101/202/303、交错/成组两顺序，共24条。配对顺序有完全相同的场景多重集和请求。分析按场景及其第几次出现对齐，不把顺序本身当作选频变化。
- 每段CPU/GPU/NPU频域的候选是全部8个L/H组合。CPU1、CPU2共域。段内包括空闲都保持所选档，段末没有未完成工作才允许换档。100 ms尾段实行共同全低档。非抢占、确定性事件派发，就绪者按最早绝对期限优先，同期限按请求ID排序；各法共享逐请求绝对期限和80°C连续上限。温度影响漏电与安全性；计算时长按模式固定，不模拟驱动热节流。
- A 按 Kim Algorithm 3 搜索、按期限筛选，在标称50°C用模型计算场景能量作为适应度。配置表不读真实热状态、不因顺序变动。支持把查表结果离线预计算。温度连续用于实际重放。B 每段枚举全部合法配置，在实际入口状态下求段能耗最低（最后一段包含固定必付尾窗）。D 同样模型与物理执行，已知完整顺序，搜索全序列。频率串CPU/GPU/NPU。严格比较/平局策略由 solvers.py 固定；近机器误差的并列不解释成节能。
- D 每条最多100000个候选访问或60秒搜索；不给超限病例追加预算。若 D 未证最优，显示可行上界与有效下界或未决。独立正确性对照用真实输入的两段子问题，另做热复位可分离性检验；不把正确性用例混入24条。
- 所有方法运行同一个分段功率、热传播和计能评价器。热不可行者不进入能耗比较。保留完整24例、失败状态、每档动作审计、请求和执行时间线、功率段、段内连续温度表示、最终状态、末尾能耗。各方法准备/搜索成本与复算输出成本分开。
- 先执行输入与时间线核验、独立热参考校验、精确搜索对笛卡尔穷举、断开跨段热状态后的退化校验。失败则暂停价值调用，先定位实现问题；不根据价值结果更改实现口径。代码、输入协议和正确性证据在运行前提交，另记录输入文件散列。
- 在三者共同可行、D已证最优的实例上，分别报 (A−B)/A、(B−D)/B，通过率另报，零差及负差保留。若B已取得相同选择/极小剩余且未出现D独有的可行解，优先保留简单控制或暂停候选。只以本组样本作结论，不设置追求收益的调参或补跑分支。


- 预定工程筛查线：若D均已证最优、B未损失可行例，且共同可行上D对B最大节能≤0.1%，则视作这组输入上近似一致。保留原始焦耳差，不把此阈值解释为统计显著性。
