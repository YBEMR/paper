# 独立留出的补充机制评价协议（结果揭盲前）

冻结基础为 149967e99510f53ca10de18b796a084b64c5251e。原留出清单、协议、算法及 HT 模块判据直接引用同级 m1e_thermal_quota_ablation 目录。本登记在六条次序第一次运行前单独提交。前批八条为公开开发证据，本批六条为独立留出，分别汇总。无新算法、参数或额外调度权限。

## 比较对象

| 基线 → 候选 | 判读对象 | 控制 |
|---|---|---|
| NC → NT | 相同非热几何配额下，主动热风险前缀排序对可行率与安全能耗的独立贡献 | 相同生成器、终端热状态及排序，仅切换中间风险 |
| OT → NT | 热排序下，用非热几何方法放置多配额候选的贡献 | 两者原本都有多个配额，同父同频率对名额相等，开放动作和频档相同 |
| C2 → NT | 候选算法面对全普通方法的端到端竞争力，以等实际时间为主 | C2 按原协议采用 legacy 终端且免规划热传播 |
| OC → NT | 补充端到端对照 | O 与普通中间风险，携带终端热状态，使用与候选相同的 safe_energy 终端序 |
| NT → HT | 增加热容量生成模块的代价与收益 | 使用旧协议原判据；结果仅决定 H 模块去留 |
| NT → BT、BT → HT | 复核热边界坐标与生成器内部热优先选点的归因 | 原定束宽四、认证四次，仅固定预算 |

OT、NT、HT 均与 C2 配对；三者互相比。拟选择的全体候选及 NC、OC、BT 的终端热排序相同。C2 保留历史原形，并用 OC 提供同终端序的公平性参照。所有组共享冻结 P1、请求与服务量、频档、期限、切换/空闲权限、窗口、连续认证器。每条次序全量服务，不丢弃请求。C2 以外的方法各自支付其所需热计算。所有方法独立从空开始，无跨方法证书或前缀复用。

## 运行与计量

按原清单顺序执行全部六条，先运行 HT 取得该工况共同截止点，再按照冻结代码 METHODS 的按工况序号轮转顺序执行已登记的 OC、OT、NC、NT、C2，最后单独执行 BT。复用未修改的 experiment.run。固定规模为束宽 4、前 4 次独立连续认证。等时预算为 HT 第四份完整证书写盘完成的从空墙钟，用原加宽及增验机制和最优解保留规则。BT 仅为固定预算诊断。单次、单核、单线程、统一预热。计入全部建池、排序、认证及原始物理证据写盘。区分预算内已完成、超时完成和未知。原程序若因合法池为空等原因无法完成，保留失败并核对原因，禁止因质量差重跑换计时。环境或数据完整性错误须单列。计时过程中不并发启动另一条测量任务。

## 判读与候选定型

每种比较按同一次序配对。先报告成功数、仅一方成功的身份、共同 SAFE 上的胜平负和逐例能耗。节能率取（基线−候选）/基线，失败不得填零；能耗认证区间重叠计平。分别报告双 SAFE 节能率均值、中位数、首次 SAFE、总耗时、完整证书数、合法池覆盖、最优 SAFE 峰温。分解建池排序、认证归档及剩余控制时间。统计单位是负载次序，不把证书当作独立样本。以固定和等时都不少解、且分别胜多于负为跨预算节能支持；成功数增加且逐项无新增失败记为可行覆盖扩展。两种机制贡献分开判读，二者可只成立一项。若能耗与覆盖结论相反，两者都报告。

实践竞争力以等时 C2 为参照，报告额外解决与丢失、双 SAFE 的能耗方向、幅度及分布，固定四次结果用于解释成本。HT 的原判据保持原实现，重算两种预算下相对 NT 不少解且双 SAFE 胜多于负，以及等时对 C2 不少解且胜不少于负；BT 仅用于归因。该判据只适用于将 H 保留为扩展。

候选按实现复杂度 OT、NT、HT 从简到繁。先比较 OT 与 NT。若 NT 在两种预算均不少解，且至少一种预算增加成功数，或在两种预算均不少解且等时胜多于负、固定胜不少于负，则推荐 NT，否则优先 OT；覆盖改善伴随能耗代价须写明。只有 HT 通过原判据，且相对上述较简候选也满足同一增量选择规则，才推荐 HT 为主版本。等时 C2 与 OC 的实际表现决定推荐的应用边界，不用于整体否决热感知研究。保留逐工况相反证据；原八条只支持解释一致性，不能事后替换本批判据。全部工作止于独立留出、机制证据与定型建议。
