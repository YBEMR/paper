# M1-e　瞬态热容量配额生成的独立贡献

**在相同热风险排序下，热容量生成 H 和非热几何生成 N 均在 8/8 条次序取得 SAFE。** 固定四次认证时，H 在三条次序节能，两条耗能上升，三条取得相同能耗。逐次序节能率的算术均值为 **0.0383%**，中位数为 **0%**。按 HT 的实际用时给其他方法扩展，八组 NT–HT 的配对结论相同。NT 在每条次序都更早取得首个 SAFE。这批公开样本支持保留完整 H 做独立复验，尚不足以将容量边界单独列作节能贡献。

**只把热边界坐标引入 N 的诊断组 BT，在八条上逐一返回了与 NT 相同的最佳计划哈希。** 完整 H 同时在生成器内部按温度风险选择稀缺的送审候选。打开这项热优先选点后才观测到上述三胜两负；本实验未单独测量取消几何边界、只保留热优先选点的效果。

## 六组消融与原始 C2

O 为原配额，N 为非热几何配额，H 为热容量配额。C 用时序负载风险保留前缀，T 用热风险保留前缀。六组都使用同一终端热安全能耗排序；原始全普通 C2 保留原来的终端四位置。下表同时列出求得 SAFE 的工况数和连续认证的成功次数。时间中位数均从空搜索开始计，首次 SAFE 只涵盖该方法成功的工况。

| 方法 | 四次成功工况 | 四次 SAFE/送验 | 首次 SAFE 中位（s） | 四次总耗时中位（s） | 等时成功工况 | 等时 SAFE/送验 |
|---|---|---|---|---|---|---|
| OC | 6/8 | 24/32 | 0.804 | 1.137 | 6/8 | 162/240 |
| OT | 7/8 | 28/32 | 0.818 | 1.132 | 8/8 | 221/235 |
| NC | 6/8 | 24/32 | 1.845 | 2.296 | 6/8 | 65/79 |
| NT | 8/8 | 32/32 | 2.104 | 2.284 | 8/8 | 73/73 |
| HC | 6/8 | 24/32 | 2.158 | 2.545 | 6/8 | 29/36 |
| HT | 8/8 | 32/32 | 2.460 | 2.627 | 8/8 | 32/32 |
| C2 | 6/8 | 10/32 | 0.423 | 0.699 | 7/8 | 110/170 |

在固定四次下，把风险排序从 C 换成 T，O 从 6/8 到 7/8，N、H 均从 6/8 到 8/8。N 已经找回 H 的全部可行工况。六组的 C 都计算终端所需的热状态，审计从提案重算了包括 C2 在内的 141,277 个普通风险值，逐窗重建互补位置和加宽补位。C 组的前缀保留只读取能耗、排空时间、时序负载风险和确定性平局键；HC 的生成器按定义使用热量。

原始 C2 四次时解决 6/8，HT 在这六个共同 SAFE 工况中五胜一负，平均节能 3.982%。等时 C2 在每条次序都完成束宽 8 的终端建池，及时认证 18–25 次，最终解决 7/8。HT 对 C2 在七条共同 SAFE 次序中四胜三负，平均节能率为 −0.435%，中位数为 +0.367%。HT 额外解出的 L640 轻载开头次序单列。L800 重载开头的 C2 从 50.691756 J 改进到 46.271067 J，超过 HT 的 47.688571 J。这份 46.271067 J 证书来自束宽 8 的第一个送验计划，是同一轨迹的第九次认证。七条 C2 成功次序的最优证书均在加宽后第九或第十三次认证取得。继续运行到实际截止用完了预算，本批第十六次之后未再刷新 C2 的最低能耗。等时 OT 也能解决全部八条，L640 轻载开头取得 38.9504 J。

## 生成器归因与候选覆盖

旧 N 的末窗三点使用 250 ms 账本网格，旧 H 使用 50 ms。此次两者在末窗均用 50 ms，开窗均用 250 ms；末窗校准涵盖 1 s 窗及 301 ms 尾段。两者对候选预测采用同一 250 ms 传播网格并保留尾段实际长度。每个父前缀、每个 GPU–NPU 频率对的三个非共线点都由同一个时序中心和负载平面确定，候选名额取该父状态下 O 的不同配额数。N/H 共享校准能耗拟合、候选回填、去重、时序合法性检查、连续认证及平局规则。切换容量平面会同时影响几何候选和生成器内部选点；80°C 最终由 P1 独立判定。

NT 和 HT 各访问 6,000 个“窗、父前缀、频率对”组合，直接重合 3,000 个。在这些位置，名额、9,000 个校准点、细网格、校准热矩、参考能耗及全部非热输入指纹逐项相同。对已分叉的其余父状态，按其实际账本独立重建 O 名额与校准点。审计共核对 59,760 个频率组。不同父状态可能给出不同名额，生成后也会因时序淘汰及物理配置重复而得到不同合法池。

|---|---|---|---|---|---|

| 800 · HHLHHLLHLL | 568 | 608 | 0 | 566 | 556 |
| 640 · LHLLHHHL | 443 | 491 | 0 | 436 | 422 |
| 640 · HLLHHLHL | 458 | 638 | 0 | 458 | 448 |

在 L800 和 L640 的四条次序上，NT 与 HT 的合法终端计划完全不重合，但两组各有两条能耗较低。BT 与 NT 八个末窗池的计划集合也都有差别；四次预算下最佳仍逐一相同。池覆盖按完整配置哈希计算。未认证计划的物理可行性和能耗最优性均未知。

## 冻结、留出与复核

完整 H 达到运行前注册的复验门槛。冻结 HT、NT、C2 和归因诊断 BT，按固定哈希在 L800、L640、L480 各预留一轻一重的六条未用于本轮的次序。L320 在等量、排除两段式及纯交替并去掉已用次序后已无剩余。下批逐条比较同网格、同配额的 HT/NT，同步复核 BT/NT 与等时 C2，沿用本轮门槛并报告所有反向结果；六条均未在本轮建池或认证。当前论文口径采用“热风险保留前缀可提高这批工况的可行率，完整 H 有局部能耗收益”，保留更简单的 NT 作为对照。[冻结实现与六条留出清单](holdout_freeze.json)

同机单核单次运行。共同预算取各工况 HT 第四份证书完成的实际时刻，计入建池、排序、连续回放及原始三件套写盘。其他轨迹在同一墙钟上逐级加宽、增加认证并累计保存最佳；所有等时成绩只计截止前完成的证书。每一级是否加宽取决于实测剩余时间和建池代价。各次计时有机器与执行顺序波动，等时排名属于这次实测。八条输入均曾公开，本文不据此估计新负载上的节能率。

第一次启动在首份研究证书生成前遇到 NumPy 2 将精确能耗整数隐式缩窄而溢出。M1-e 接口改为用 Python 整数传递 FIFO 的结束时刻和频档，重新从空运行全批。HT 和 C2 在全部八条上的前四个物理计划、证书状态、能耗和峰温均与 M1-d 原记录吻合（64 份）。全部 948 次认证覆盖 796 个不同的物理排程，已核对配置与计划哈希、事件连续性、各节点峰温、期限余量、能量守恒、证书区间和实际完成次序。P1、第三章、第四章均沿用冻结内容，本轮止于 M1-e。
