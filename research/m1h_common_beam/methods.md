# 比较对象、审计与证据读取

## 只有哪两席会变

同一中间窗口先把给定父集合的全部 N 提案送入同一 FIFO 账本。原生成器决定每父每频率对的校准点与配额名额，保留热预测需要的状态；不满足期限的前缀与重复配置在此时分出。供四席选择的池只含合法、去重后的配置。下表中的各席均依次排除已选身份。

| 席 | 共同选择规则 | 随中间键变化的部分 |
|---|---|---|
| 1 | 参考能耗最小，同值按配置字节 | 无 |
| 2 | 排空 tick 最小，同值按参考能耗与配置 | 无 |
| 3 | 风险最小，同值按参考能耗与配置 | 整个风险键 |
| 4 | 参考能耗、排空、风险三项在全池的经验名次相加；同分按参考能耗与配置 | 综合名次中的风险项，以及已被第 3 席选走的配置 |

经验名次精确定义为池里**严格优于**该项的候选数量。并列项的名次相同，并列的多个候选分别计入后面候选的名次。举例，风险键依次为 (0,2)、(0,2)、(0,5)、(1,0)，其内部紧凑编码为 0、0、1、2，进入综合席的风险项为 0、0、2、3。此处理保持整个字典序，没有把“违反一次期限”等价为若干个模式名次。束宽大于四时，后续各席沿用参考能耗回填。即使两个方法在第 3、4 席交换了顺序，相同的保留集合也可能通向同一个终端解，审计另外记录集合是否改变。

| 方法 | 用于第三席和综合席的风险键 | 热计算及终端 |
|---|---|---|
| NT | 累计预测峰温和一秒热延拓两者的最大值 | 冻结 NT |
| NC | 原负载平面的最大风险 | 中间仅用普通风险，保留终端热状态 |
| ZQ-Beam | （已达预测峰温严格超过 80°C，当窗每个主任务的 Zhou 虚拟模式名次之和） | 超温候选进入软排序，原 ZQ 的硬筛与单束成绩留在 M1-g |
| LQ-Beam | （当窗主阶段完成时刻超过 Li 子期限的请求数，当窗每个主任务的 Li 热耗散模式名次之和） | 参考计算从空，窗口内不做 LFT。严格大于子期限才记违反 |
| C2 | 冻结的普通风险 | 原 O 生成器、普通终端，无规划热计算；作为实际效率基线 |

前四种方法用同一 N 生成、FIFO、终端序与连续认证；C2 本轮重新计时。终端依次比较预测是否超温、正超限量、参考能耗与配置。SAFE 最佳解依据**实际完整系统能耗**选定。每个文献键的专用建表和 Li 子期限参考均在该条运行的第一轮构造中计时。线上 LQ 直接读取已有 FIFO 账本的主任务完成 tick；审计用冻结 M1-g 的独立全前缀重算和逐请求名次求和交叉校验。[同核入口与风险键](framework.py) · [冻结选择器](../m1_transient_thermal_quota_20261126/search.py) · [M1-g 的独立准则](../m1g_literature_comparison/experiment.py)

## 同父及同池核对

- **同父重建。** 以工况、窗、父配置哈希为键。对实际 W4 路径上出现过的每个父前缀从冻结 N 重新生成整池，逐项比对校准、配额名额、候选身份、重复/时序失败/合法、参考能耗、预测峰温、排空与余量。分叉后的不同父前缀不会被当作相同输入。
- **同池换键。** 对中间窗的每个非空独立父池，以及每个实际到达的不同父集合，独立计算四种策略的四席。后者同一父集合按同一顺序只计一次。用公开风险二元组与每候选完整字节恢复平局，另一个实现计算风险与综合名次；核对实际路径的保留身份与 W4/K4 终端送验顺序。针对第四席还分两步核对：先固定左方法的综合评分，只换为右方法已选的第三席，随后固定该排除项，只换综合评分的风险名次。两种条件变化可能同时发生或互相抵消。单父池中的四席是假定“该父单独竞争”的离线结果。
- **较大束宽。** 在四个同核方法的全部已完成中间窗口，核对记录中各父的全量提案和校准指纹，以及四席与参考能耗回填的实际保留序列；在所有已完成终端池核对对应认证调用的排序位置。截止中断、尚未产生保留序列的末窗不参与这项检查。C2 的逐次结果和证书全部验证，其 O 候选池不计入 N 同池统计。
- **证据边界。** 同池换键直接验证某评分能否改变选择；实际多窗结局还包含之后的搜索、加宽尺度与认证顺序。固定规模证据比等时结果更直接地对应替换评分的影响。只在两方都 SAFE 时计算逐工况节能率，分母是比较表的右方方法。相同计划或能量认证区间重叠记平。[审计实现](pool_audit.py) · [按工况的风险特征、四席与较大束宽指纹](data/pools)
