# 设计、物理核验与证据读取

## 任务流与试验单位

P1 的四条流为 A1、A2、B1、B2。每秒两个 A 流合计 40 个请求，两个 B 流在 L/H 窗分别合计 20/60 个请求，所以轻窗有 60 个请求，重窗有 100 个请求，任务阶段数始终为请求数的三倍。12 条任务流各有独立的新次序。热敏感性使用其中两条流，每条只保存一份请求 CSV，在三个环境条件下读同一份文件。登记表列出全部 16 个工况、12 份输入哈希、真实请求数、截止时域与对应关系。[输入与分组](registration/cases.json) · [历史输入和去重哈希](registration/history.csv) · [枚举、排除与选中摘要](registration/selection.csv)

按冻结树可识别的历史 P1 整秒次序及 M1 实际请求表进行去重。请求身份核查使用流名、任务类别、释放 tick 和期限 tick，因物理场景分段标签不同但请求相同的历史输入也会被识别。历史范围限于仓库留存的记录。去重及选样在计算新工况成绩之前完成。[选样代码](design.py) · [选样协议](PROTOCOL.md)

## 温度参考与物理连续性

以实际温度向量 $T$ 表示四个节点，$c$ 是节点热容，$G$ 是冻结导热矩阵，$b$、$s$ 分别是 35°C 参考功率与功率温度斜率，$T_a$ 是实际环境温度。P1 瞬时功率为 $b+s\odot(T-35)$。在坐标 $x=T-35$ 下，同一热方程写作

$$
\mathrm{diag}(c)\dot{x}=(\mathrm{diag}(s)-G)x+b+G\mathbf{1}(T_a-35).
$$

空闲平衡由 P1 的原始初始化器解出。在 35°C 下，前缀近似直接调用原传播器；25/45°C 的适配仅在仿射项加入环境驱动。每个非终端窗保留原 250 ms 热计算网格，终端沿用冻结校准及分箱。跨窗继承状态，最后完整积分 301 ms 尾段；连续认证仍逐实际事件积分。NT 的一秒热延拓、ZQ-Beam 的预测超温软排序、NC 的普通风险与共用终端热预测、C2 的普通构造和终端，均沿用 M1-h。[适配器](adapter.py) · [冻结风险实现](../m1h_common_beam/framework.py)

物理适配核验包括以下三项。

- 在 35°C 复用 M1-h 的 14 条旧次序。逐方法核对 W4 全部提案记录、每窗保留身份、终端池数量、前四个排名身份和连续证书。四种方法共 224 份证书，全套非计时物理字段及原版逐事件 NPZ 的 SHA-256 全部一致。
- 在登记的 16 个工况核对节点空闲平衡、每秒真实发布数、逐请求期限、阶段数、场景边界、初温及尾段，按相同功率矩在整个时域逐窗复算解析矩阵指数与冻结连续积分的温度。两者的最大末状态差小于 $10^{-12}$ K。
- 在两条温度配对流上，用同一项事先固定的快速设备分配作为物理探针。三个温度的事件时刻、功率基值与斜率输入逐字节相同。真实 FIFO 分箱功率矩与 P1 原事件加权平均的最大绝对差为 $1.78\times10^{-15}$，同矩逐箱末温误差为 $1.71\times10^{-13}$ K。该检查只考察输入和同矩积分的一致性；分箱预测相对原始事件积分仍有近似误差。物理探针不进入主搜索或最佳解。[核验回执](registration/verification.json) · [逐工况核验](registration/checks) · [热配对探针](check_events.py)

## 墙钟与统计单位

每个工况的四方法三重复固定在同一核，八个工况并行；从空构造，同编号是预定的对照重复。首次启动在导入阶段遇到 M1-e 与本目录的归档模块重名，尚未进入计时或读取任何新搜索结果。修正导入顺序并更新清单后才执行主批次。[主批次实际冻结版本](https://github.com/YBEMR/paper/commit/9c1d1b073477756f5a3c18460184a14a35a152ae)统一预热通用 FIFO 和物理认证内核，记录四个数学线程环境变量并验证 CPU 亲和性。专属评价建表、搜索、终端排序、连续认证及原始排程/证书/事件落盘均在钟内。批后归档和核对在钟外。带有 60 秒硬截止的独立循环沿用原四席、候选和加宽条件。唯一有行为差异的边界是各阶段统一检查时间，记录无合法池、少于四次与跨截止认证。每个方法可在合法池耗尽时停止。[轮换次序](registration/rotation.csv) · [运行器](runner.py) · [核与环境](data/environment)

以同一时刻已落盘的最优 SAFE 排程形成阶梯；在第一份 SAFE 之前能耗为空。每个工况的可靠成功以至少两次获得 SAFE 为准，同时给出 1/3、2/3、3/3 分母。配对以工况为单位，各用本方法成功重复的中位能耗，左右能耗区间分别取成功重复上下界的中位数，两区间重叠记平。只有双方可靠成功才给工况配对节能率；编号重复的原始配对只在该重复双方 SAFE 时计算。两个成功重复的中位能耗可以是两个实测能耗的算术中点。峰温、期限余量和各类耗时分别取对应字段中位数。各组平均节能率是工况百分比的等权算术平均。D 的两条流按 25、45°C 分层，35°C 基准引用 A/C。D 的能耗变化同时包含热泄漏变化与优化器可能更换排程的影响。[统计实现](analyze.py)

在与登记环境一致的完整仓库中，于本目录运行以下命令可对任意原证书重新取证。输出目录须为新目录。

```sh
python -B replay.py CASE PLAN_SHA256 NEW_DIRECTORY
python -B replay.py CASE PLAN_SHA256 NEW_DIRECTORY --events /path/to/CASE.zip
# 从原始事件包直接恢复逐字节匹配的 NPZ，可跳过物理仿真
python -B event_files.py CASE /path/to/unpacked-volumes --restore PLAN_SHA256 --out rebuilt.npz
```

重建主批次按 `design.py`、`audit_physics.py`（ambient 与 14 条历史输入）、`check_events.py`、`freeze.py`、`batch.py` 的次序执行。最后对各工况执行 `export_evidence.py` 和 `event_files.py`，再用 `analyze.py`、`figures.py` 生成汇总。批次使用新工作目录，避免旧结果进入本轮计时。
