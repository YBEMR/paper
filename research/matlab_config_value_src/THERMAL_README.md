# 第二轮：热约束、等待与配置

在本目录运行 `run_thermal_value`（MATLAB R2023b）。默认偏好目录不可写时使用35号README的进程级MATLAB_PREFDIR。旧`run_config_value`和历史结果保持不变。

15项冻结输入：三个旧案例×三种初温，另三项热态断耦合对照及三项热态0.5 ms复查。输入为抽象模型；温度以摄氏度展示，状态为相对25°C环境温升。CPU/NPU的空闲与活动增量进入各自节点，0.5 W其他恒定功率仅计系统能量，明确位于该热模型边界之外。

每段恒功率响应利用对称化导热矩阵的特征分解得到两个实衰减模态，检查端点和每个节点可能存在的内部驻点。重复特征值退化为单指数。分类用1e-6°C带宽；阈值带内不直接判安全或不可行。图与采样只作诊断，不决定峰值。

启动网格1 ms／0.5 ms，原时长不取整。这批时长和最早开始均位于两个网格上。每模式先检查全部最早顺序代表，再尝试合法的共同延迟，最后必要时逐CPU顺序、NPU顺序枚举四阶段全部网格启动时刻。前两项只是搜索次序，不删掉其他合法安排；最早代表不满足期限意味着任何更晚同序安排均不满足期限，可直接排除该顺序的资源／期限分支。

找到一个安全见证即可确认模式可行，因为同一窗口下模式能耗恒定。只有全部合法网格安排排除且没有阈值未分辨记录，才能称网格不可行。每案例60 s协作式预算检查；timeout/unresolved均不得记不可行。若未决模式可能更省能，best_found不等于证明的最优。达到35号无热最优下界的安全见证可以证明模型内能量下界可达，但不能据此声称已收齐全部最优模式或时间表。

输出在thermal_reports独立时间戳目录：inputs.json/MAT、source/、results.mat、summary.csv、modes.csv、earliest.csv、witnesses.csv、checks.csv、console.txt及figures/。峰值按0–60 ms完整窗口记录；不保证窗口后或重复运行安全。三张热态图各展示一条最早代表和一条最佳已找到安全见证，不代表全部最早安排都超温。
