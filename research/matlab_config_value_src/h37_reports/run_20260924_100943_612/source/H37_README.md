# H37冻结协议 v1（2026-09-24）

运行入口 `run_h37`，MATLAB R2023b，内部单位s/W/J/°C。
复用thv_cases的15项输入，不修改35/36号源码或历史结果。

配置模块独立调用无热联合配置求解，仅向策略交付modes/duration/increment，丢弃所有资源顺序和时间表。全部并列最优组合分别运行。P0/P1各案例共享60 s预算，包括配置规划及该版全部并列组合；协作式预算检查，不是硬实时看门狗。

优先级为期限减乐观完成预测。预测只计算自身剩余CPU→NPU链、释放及正在执行工作的占用；不排定其它未启动任务。并列按期限、到达、请求编号、阶段编号。阶段开始即提交，执行中不可改变；未启动任务无资源预订。完成时以观察到的确定时长更新估计。本轮无测量误差。

每一网格时刻，按优先级检查就绪且设备空闲的阶段；启动一个后重新计算，再启动另一设备上的合法工作。P1用已提交全部轨迹加一个候选、未启动工作按空闲到60 ms作热过滤，不预查完整未来后缀。拒绝后继续其他候选。全部无动作时前进下一网格；中间的完成/释放事件即时处理但非网格时刻不派发。超期限的乐观下界只说明已提交前缀失败。

P0只改变热过滤开关，完成后仍以同一温度评价器复核。阈值带候选不启动，日志分别标记violation/unresolved；没有把部分完成能耗放入排名。advance_without_start包含资源都忙的正常时刻，不等同主动散热等待时长；应结合reject与设备状态判断。

策略本身不读历史结果，不调用热参考搜索。配置模块的无热求解属于基线组成，而非将35号答案预置；其耗时纳入预算。历史结果仅在所有策略执行结束后由评价端读取。

正式主比较15项×P0/P1（当前最优配置均唯一）。附加诊断复用两项R1热态断耦合HH，分别跑P0/P1；不计H37主样本，不改参数。软件检查还复用35号已存在的并列案例，并检查合成事件边界；检查夹具不作为研究胜例。

输出inputs.json/MAT、source快照、本规则副本、results.mat、summary.csv、events.csv、schedules.csv、diagnostics.csv、checks.csv、console.txt及SHA256清单。reference comparison在策略后执行。报告使用全部结果，不用执行耗时支持新算法主张。
