# 配置价值首轮验证（无热约束）

MATLAB R2023b，基本MATLAB功能即可；在此目录运行 `run_config_value`。不调用旧实验目录，也不修改其参数。

输入全部为33–34号条件构造的抽象值，不是设备测量。内部单位s/W/J；CPU模式1=L、2=H。14个冻结案例：4个R1、6个R2、3个N1和1个不可行测试。N1未在用户表中单列的功率沿用R2补偿超过案例，其他公共参数一致，仅B的NPU时长改变。

入口先建立独立时间戳目录，保存inputs.json/MAT、环境信息和源代码快照，再作数值评价。单案例预算60 s，有限枚举每个候选检查预算；异常保存后不扩大预算、不重试。这个预算是小型计算的协作式截止检查，不是外部硬实时看门狗。

参考法枚举4个模式组合×2种CPU次序×2种NPU次序。固定模式能耗不随时序改变；对固定次序，CPU/NPU依赖组成无环先后图，最早安排逐阶段不晚于任何其他安排。故它足以判断无热条件下的期限可行性，并穷尽最优模式组合。无启动网格、无时长取整。等待产生的无限多时间表不逐个枚举；记录的是每种资源次序的最早代表。此证明不适用于有热约束的等待选择。

响应规划的全部最优代表共同回放：保留模式、资源次序和原启动下界，只作必要延迟；不提前执行、重新优化或暗中修复。输出原时间表在共同时长下的合法性以及回放后的结果。最优模式集合比较保留组合关联，不取逐阶段集合的笛卡尔积。局部方法为请求独占系统时按完整期限选最低活动能耗，不冒用Crown名称。

输出：

- inputs.json、inputs.mat：输入与环境；source/：本次源码。
- results.mat：全部16候选、原始共同模型检查、回放、条件最优值及局部建议；包含不可行代表便于审计。
- summary.csv：全局最优模式、共同回放能耗范围、条件价值及逐请求局部组合可行性。
- schedules.csv：候选／回放时间表、合法性、能耗分项；不可行行能耗仅用于审计，不纳入最优或节能排名。
- queue.csv：N1固定后缀结果，非全局优化。
- checks.csv、console.txt：必要检查及日志。

温度一律标记not_evaluated，不使用“热可行”。热模型、真实参数、复杂算法和尺度性能均不在本轮范围。本轮运行时间只用于执行审计，不构成算法必要性证据。
