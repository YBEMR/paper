# 共享内存与热频率限制：联合调度价值准入结论

**当前不进入新算法开发，也不启动联合数值扫描。** 硬件机制有依据，但可复用同平台参数不足，尚不能判断相对最强简单方案是否存在≥1%的完整能耗空间。结论是“数值证据未闭合”，不是“收益为0”，也不是“问题物理上不成立”。

本轮按用户指定问题核查HaX-CoNN、OPTiC、RT-TAS与Orin官方EMC文档。结果仅包括文献/数据审计、符号条件、冻结评价协议、静态复算与归档。没有沿用TF20261114的合成数字，没有提高功率、降低温限、增加任务或筛选正例。

## 1. 问题是否值得继续投入

|用户关心的问题|本轮可支持的结论|
|---|---|
|联合机制是否真正改变最佳调度？|一般性能建模中已有直接近邻OPTiC；本轮固定服务总能耗实例尚无合格数值输入，不能声称最优选择已改变|
|多少来自热限制，而非普通争用？|未知。已定义M10选择在M11中的后悔值及固定安排交互量；未运行四组数值，不把争用改善冒充热收益|
|相对最强简单方案是否仍有≥1%空间？|未检验，数值为null。没有证据支持投入复杂算法|
|是否存在无需联合热感知的条件？|有解析充分条件：热cap全程不绑定；带宽约束不活跃；或强简单类含共同最优。条件及额外能量前提见符号模型|
|是否依赖无依据极端参数？|本轮未填这些参数，不能宣称存在有依据的正收益区域；符号区域仍需证明实际可达|

**研究投入判断：保留问题，暂停算法投入。** 目前值得保留的是辨识缺口与条件判据，不是再构造一组能出正结果的仿真数字。OPTiC已经联合内存竞争和计算热降频，本轮若继续，价值必须落到固定服务/完整能量、EMC热限制与强简单方法之间的实证差额，不能仅凭新增机制命名贡献。

## 2. 已核实的依据与数据缺口

- **HaX-CoNN**：可复用层组时长、转移与竞争方法；原始工作树有部分预采集摘要。Orin与Xavier使用不同精度/软件版本；DLA引擎可能回退GPU，不能直接作为两种独占设备的合法支持表。
- **OPTiC**：已经把内存竞争与热降频共同纳入CPU/GPU执行时间预测，并有机制消融；其XU3内存控制器不可调，仲裁特征也不能移植到Orin。目标不同不意味着方法不能适配。
- **RT-TAS**：有Tegra X1热耦合、CPU/GPU分段功率和时长数据；其两段不是可选设备实现。关风扇、65°C设定属于该实验，不是Orin出厂门槛。
- **Orin官方**：确认EMC/DRAM DVFS会受热管理限制；只证明机制存在，不给出本轮任务的实际cap、带宽、热惯性与系统能量参数。

上述逐项来源、阅读范围和边界见[文献/工件审计](SOURCE_AUDIT.md)与[source_registry.json](source_registry.json)。

固定HaX作者提交`87f5f25e6571ae04b577d1c38ddd241ffacab983`，核对54个文本工件；另核对7.32MB Zenodo公开归档。共61份缓存来源逐一核对哈希，静态提取65行摘要：10组GPU时长、10项DLA差分、25个EMC峰值百分比和20项转移相关时长。未运行作者求解器或硬件采集。

两个直接阻碍：DLA差分有3个负值，保留而不截零；EMC脚本只保留百分比并取最大值，丢失运行频率、时间、温度和功率关联。它们不能分别作为真实任务时长和GB/s带宽曲线。公开归档工作树也未补齐联合数据。所有发现均可用[静态审计结果](results/artifact_audit.json)及[提取表](results/hax_extracted_summaries.csv)复核。

[参数可辨识性表](parameter_identifiability.csv)列22项，20项联合数值输入尚未闭合；部分资料存在不等于可以为联合模型赋值。模型值保持null，包含有效带宽/仲裁、任务随频点的执行进度、计算与内存功率、基础能耗、热动态、传感器到cap映射及延迟。负载与窗口也未擅自填成TF的数值。

## 3. 已冻结的模型和消融口径

只冻结两条二节点链、X/Y两个抽象资源和一个共享内存资源；实际任务支持、频点、工作量、到达/期限与热状态机数值待识别。任务不可中途迁移，候选必须显式包括映射、工作点和重叠/串行选择。一般进度函数依赖实际计算频率与得到的带宽，完整窗口计计算、内存、基础、转换/传输、监测与共同尾段，禁止重复计电。

|选择模型|争用|热cap|本轮状态|共同M11复评|
|---|---|---|---|---|
|M00|无|无|NOT_RUN_DATA_GATE|未运行|
|M10|有|无|NOT_RUN_DATA_GATE|未运行|
|M01|无|有|NOT_RUN_DATA_GATE|未运行|
|M11|有|有|NOT_RUN_DATA_GATE|未运行|

无争用只解除带宽共享约束，不删除内存工作/功耗；无热cap只关闭频率限制反馈，不删除温度递推与温度相关能耗。各模型选择后必须统一放回M11评价，不比较各自理想世界的能耗百分比。只有完整服务且期限均可行才计算节能率。

强参照已定义为最佳固定、仅争用优化、热感知固定重叠规则、最佳至多一次切换、完整有限目录；结果全部NOT_RUN。离线预排知道未来和准确参数，不冒充在线阈值控制。特别地，若只有一或两个重复窗口，至多一次切换类等于全模板序列空间，额外收益为0是集合恒等；不能靠增加任务数逃避这个边界。

详见[运行前协议](PROTOCOL.md)、[符号模型/条件判据](SYMBOLIC_MODEL.md)、[准入结果](results/admission.json)、[四组状态](results/ablation_status.json)、[强对照状态](results/baseline_status.json)。协议哈希在protocol_freeze.json；从未启动调度数值运行。

## 4. 正例条件、无收益条件与停止

符号模型给出一个**尚未实例化的条件构型**：冷态带宽足以支撑两个阶段重叠；重叠引发EMC cap，而串行不引发；cap后的剩余访问完成时间和总能量损失超过原并发优势，才可能改选串行。这里的cap强度、进入时刻、切换暂停、功率、尾段与期限必须同时满足约束；缺数据时不能任选。计算cap也可能降低请求带宽、缓解争用，交互不必总偏向串行。

无收益条件不能省略：全目录无热cap时热独立价值为0；无有效争用时没有共享竞争贡献；强简单类已达目录最优时复杂算法空间为0。仅“运行时间不变”不足以判定能耗无变化，还须核查内存功率与尾段。

本轮停止于**同平台数据准入未通过**。不宣布热感知假设已被否定，不提交伪造的正/负数值实例，不恢复B或旧MILP/ON-P。后续若另行授权，应先补证据或做有限符号研究；本轮没有自动安排新的仿真、硬件或算法开发。
