# K.28：TP-1独立输入与必要预检

TP-1是用户批准的L3压力输入，不是设备标定。本包只做预检；没有正式四组合诊断入口，没有计算四组合的完整U1或选出最佳组合。旧CP1、HT-1、评价器和历史结果均只读。

## 已实现与复跑

`input.json`保存全部参数、14行响应、四方案、原F1/F2及使用权重。只改变K.27批准的C、G和两行NPU活动功率；加载时与原HT-1问题逐字段精确比对。原问题ID保留CP1以避免扩展旧严格接口，包版本TP-1负责区分新输入。

`adapter.py`复用合法性、展开与证书工具；逐候选生成完整片段笛卡尔积，包含初始保持工作点，不删不可达组合。单模式探针绑定其自身A/B入口。`finite_evidence`、`aggregate`是内部结果分流接口，尚未接成正式诊断流程：有限安全不等于持续安全，完整但违规的能量最多保留为诊断值，不能进入有效U1。

运行必要预检：

```powershell
F:/Anaconda3/python.exe research/thermal_pressure_precheck/precheck.py --out research/thermal_pressure_precheck/precheck_new
```

仅重查输入／证书／状态接口：增加`--contract-only`。每次必须使用不存在的输出目录，失败记录不覆盖。两种入口均不运行研究四组合；部分检查通过不构成正式运行凭据。

连续计算新增纯数值片段细分包装：每个工作点与活动状态固定的片段按精确有理数分割，令增广矩阵范数乘片长不超过1/4，再调用原区间Taylor工具。分割不增加任务、调频、释放或功耗事件，不改变轨迹方程；只避免旧1/2上限处舍入触发异常。准备和积分共用20秒预算。此包装尚未接入旧`evaluate_trace`或正式诊断入口。
