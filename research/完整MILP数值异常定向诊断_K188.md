# K188：K187完整MILP数值异常的定向诊断与最小调用提案

日期：2026-10-26。依据：K187冻结数值载荷与源码，以及K106、K165、K167原始记录。本轮只读分析，新增优化调用、MATLAB启动、模型构造、热积分、候选评价均为0。原历史结果不改。

**结论：已有证据足以把数值兼容性列为当前优先排查项，但尚不能把K187失败归因于某一条约束或求解器缺陷。建议先做一次“固定原整数选择、保留原目标和原矩阵”的300秒原生诊断；暂不具备直接重启长预算性能比较的条件。此处预算只是待批准提案。**

## 1．已确认的异常，以及尚未分清的原因

K187原生求解700.076秒后返回`exitflag=-2`、空向量，方法在744.719秒停止，远早于3600秒上限。它不是“长预算用完仍找不到解”。同次原x0通过原数值容差，完整初始化SAFE也有独立连续热复核。因此必须先处理“原数值接纳与原生无解状态不一致”，不能把无解状态直接用于论文的不可行或最优性结论。

原P0与K187的矩阵、目标、界、整数索引和x0完全一致，仅剩余预算不同；K187原生入口明确收到27971维x0，响应正常归档，没有进程崩溃或传输失败。[K187逐项核对](chapter3_experiments/results/whole_long_budget01/readonly_matrix_identity.json)、[原生回执](chapter3_experiments/results/whole_long_budget01/method/matlab/request_000001.response.json)保存了依据。

三个解释目前不能混为一谈：

| 解释 | 当前判断 |
|---|---|
| 只有组合搜索太大、需要更多时间 | 不足以解释此次提前返回−2；但自由调度的求解效率仍可能受此限制 |
| 条件物理行、浮点消去或内部数值处理影响接纳 | 有具体结构及历史受控诊断支持，值得优先隔离；K187因果归属未完成 |
| 物理任务无合法安全方案 | 不成立为本次结论；已有完整SAFE，原生数值状态也不是独立不可行证书 |

日志只给出零分支节点，未提供有效根LP界或内部阶段轨迹。不能由“零节点”进一步断言时间全部耗在某个确定的LP步骤，也不能把数值问题和连续子问题规模视为互斥原因。

## 2．本次对原矩阵的静态核查

可复查脚本与最终机器结果：[matrix_inspection.py](chapter3_experiments/results/k188_readonly01/matrix_inspection.py)、[matrix_inspection_final02.json](chapter3_experiments/results/k188_readonly01/matrix_inspection_final02.json)。只读已保存的二进制浮点数组，未重建电热系数、搜索新向量或调用优化器；同目录较早JSON是补核前草稿，最终分析耗时11.726秒。

| 核查项 | 结果 |
|---|---|
| 原载荷规模 | 27971列、176953不等式、1983981非零、1681实际整数列 |
| x0原数值接纳 | 最大浮点正残差2.1316×10⁻¹⁴；437行有正残差，0行超过1e−9；界与整数违反均0 |
| 逐行舍入估计 | 标准binary64运算模型下最大估计4.3063×10⁻¹³；正残差未超过各自估计。它不是形式区间可行证书 |
| 系数尺度 | 非零绝对值约1.2499×10⁻⁸至60.2706，最大行内跨度约4.8008×10⁹ |
| 固定实际整数后的结构盘点 | 剩26290个非intcon列，其中1688列原界已固定；174585行仍含这些列，相关非零1576910 |
| 不含剩余变量的行 | 2368条纯整数／空行，按原二进制数的精确有理值逐行代入，全部满足 |

**具体敏感行已定位，但没有发现由该行对构成的矛盾。** 原MATLAB一基行114303／114304含同一个辅助门列16306，其x0值为1。仅为分析该切片，将门值代入后，其余系数严格相反，两行允许带的精确宽度为

\[
\frac{1}{140737488355328}=7.105427357601002\times10^{-15}.
\]

原x0在这两条存档行上的精确有理残差均非正，但浮点稀疏点积将第二行算为正2.1316×10⁻¹⁴。这给出了真实的取消／求和敏感示例；门列本身不是实际整数列，本提案不会额外固定它。

另一组一基行103691／103692宽度同样为正，其中第二行的精确有理残差约正7.9562×10⁻¹⁶。因此不能把“原容差接纳”升级为“x0严格满足每条存档有理不等式”。选定相反／近相反行对的精确核查未发现固定配置矛盾，但没有穷尽一般行组合或证明全连续子问题可行。固定整数后的整体带宽扫描使用浮点代入右端，只作结构统计；局部精确结论另由原数组的有理数证书给出。

数值风险主要来自下列具体表达，而不只是矩阵大：

1. **条件传播和段能量等式拆成两条不等式。** 原冻结`milp.py`的`eq`、`conditional_eq`、`affine_conditional_eq`及`thermal_propagation/complete_energy`组装，将形如`aᵀz=d`的关系写成带门变量的上下行。忽略已明确计入的外包余量时，其结构为

   \[
   a^Tz+M_uw\le d+M_u,\qquad
   -a^Tz+M_lw\le-d+M_l.
   \]

   当`w=1`时，大项抵消后需要恢复很窄的允许带。浮点存储、求和及求解器内部变换可能对该结构敏感。**允许带很窄不等于它是矛盾，也不等于已找到本次−2的原因。**
2. **物理量、控制变量与短片段系数同处一行。** 温升、活动功率、段能量和门变量尺度不同；小系数与约60量级的项并存。系数跨度是可定位的结构指标，不是矩阵条件数，不能据此直接证明病态。
3. **实际整数列固定后，大量连续辅助量和物理行仍然存在。** 消除组合选择自由度不等于删除整个控制／物理系统；它有助于区分故障层次，但不能保证原生求解很快完成。

这里采用原冻结源码定位表达类型，不把归档MAT中没有保存的`names/row_tags`臆造出来。逐行机器证据报告原MATLAB一基行列号；具体数值示例的语义归属仍以可核对的源码结构为限。

增广的典型关系是引入`v=1−w`，将`aᵀz+Mw≤b`改写为`aᵀz−Mv≤b−M`。精确实数投影可等价，但实际实现只变换能无损改写的行，并必须复核原矩阵。它不是更强的能量下界，也不自动提高调度质量。

**本轮不采用增广。** K187归档MAT没有完整列名／行标签，直接猜门变量不可靠；重建当前模型又可能混入新版本。若固定配置诊断后仍需要增广，应独立建立数值版本、绑定原载荷及映射，保留原整数选择和目标，并以原矩阵、增广矩阵、link及完整电热评价器复核实际输出。K168是另一题的待批准诊断，不能挪用。

## 4．建议批准的最小实验：固定原整数选择，保留原目标

目的只有一个：**原先已构造的整数选项全部固定后，原数值系统能否在原生接口中得到通过原矩阵检查的返回向量？** 它是固定配置的辅助变量求解诊断，不是新的调度质量实验。

令原MAT实际整数索引集合为`I`，只执行

\[
\ell'_j=u'_j=x^0_j\quad(j\in I),\qquad
(\ell'_j,u'_j)=(\ell_j,u_j)\quad(j\notin I).
\]

| 项目 | 拟冻结设置 |
|---|---|
| 唯一基础载荷 | K187的`method/matlab/request_000001.mat`，SHA256=`3e415a16cd517815d8594c4e66dfac8df5393cf7321f4b425e40b19cb4110b4a` |
| 固定什么 | 原`intcon`的1681个选项列。先核x0这些坐标恰为0/1，再直接复制；不取整、修复或替换原x0 |
| 保持什么 | 全部27971列、176953行、原`A/b/Aeq/beq/c/intcon/x0`，其余坐标原界；不删行、消元、缩放、加cut或增广 |
| 目标为什么不置零 | 保留原`c`，减少同时变化的因素；这与K106的“全部逻辑固定＋零目标”不是相同试验。返回辅助目标不当作新真实能耗 |
| 原生接口 | 原冻结R2023b、`MatlabSession.solve`和`solve_model.m`，只发一次请求；保持原回调与求解器选项，`MaxTime`仅取本次根剩余预算 |
| 数值标准 | ConstraintTolerance=1e−9、IntegerTolerance=1e−6、LPOptimalityTolerance=1e−7，LP/IntegerPreprocess=none，其余按K187保存值核对 |
| 明确绕开 | 不走会重新构模、初始化、解码或热评价的whole Recorder／正式方法入口；Python仅保存原生事件并做数值核对 |
| 科学输出 | 原矩阵接纳结果、固定界残差、原生状态、是否返回原x0、辅助坐标变化及时间；不生成新调度、SAFE或U |

**1681个实际整数列不等于22734个原逻辑列全部固定。** 映射、控制状态等辅助变量已连续化；本提案让它们和物理变量保留原数值约束，不按`[0,1]`界猜测列身份再额外固定。原Stage选项已包含设备、工作点和起点，固定后不会形成新的调度选择。

### 预算、入口与停止边界

- **待批准：最多1次原生请求，300秒根预算；0次电热post；整项日历上限480秒。** 300秒从读取诊断载荷前开始，含科学模块导入、hash与矩阵核对、界复制、初始点接纳、MATLAB启动、传输、原生求解及返回向量数值核查。当前尚未实施执行入口，也未消费此提案预算。
- 保持原回调，不为观察点重启；记录载荷／准备、MATLAB启动、原生进入、返回和检查完成时点。根预算到时请求取消，迟到向量仅归档，不补记预算内成功。清理最多40秒、进程返回监督420秒，均受480秒日历上限约束，额外时间只用于停止和留证。
- 获批后先完成一次性入口和纯模拟检查：一基／零基索引转换一次、只允许固定界变化、其余数组精确一致、固定值0/1、预算前后回执、异常停机与禁止二次请求。核对宿主环境、内存及原生版本；资源或身份不符时不启动请求。
- 原载荷与历史文件只读，新请求保存新目录；一旦原生调用发出，不自动重试、改选项或追加零目标／增广／长预算版本。载荷漂移、数值拒绝或接口故障均停止留证。

300秒是单次诊断的工作上限，不是预计一定能解完。历史固定子问题26秒只说明该方式有低成本辨别的可能，不能用于保证K187的时长。

### 结果验收与解释

| 实际结果 | 本次能回答什么 |
|---|---|
| 预算内返回非空向量，原矩阵、原容差、固定界及整数检查全通过 | 此固定配置的原生数值路径本次可用；即使等于原x0也算诊断通过。不证明自由调度修复或有限域最优 |
| 原x0接纳，但原生仍返回−2 | 冲突不需要开放整数选择也能出现，数值表达／内部连续求解值得进一步隔离；不能据此证明数学无解或归罪某条行 |

不申请独立热复核，是因为本项不生成新调度或新的物理SAFE结论；K187既有SAFE仅作历史见证。辅助段能量在浮点允许带内变化，也不能被写成节能改善。未来若使用增广返回值支持实际物理结论，则必须按独立协议经过原矩阵和完整电热评价，不能借本项省略。

## 5．是否可以恢复长预算比较

**现在不建议。** K187已经证明“继续等待”可能走到数值状态冲突，而不是正常收敛；继续放大时长无法区分原因。本次只读检查也没有建立原浮点矩阵的精确可行证书。

即使固定配置诊断通过，仍需另行判断开放整数选择后的原生接纳是否可信、是否能输出可核候选／界，以及若采用新表达能否保持原域、原容差与完整电热检查。只有数值版本明确且这些接口可靠，长预算试验才有可解释的性能意义；它仍需另行授权，不能由固定子问题成功自动触发。

对第三章，目前可以写“完整电热MILP的该数值实现存在待解决的接纳一致性问题，同时自由调度模型有显著规模成本”，不能写成“求解时间不足已被证明”或“调度问题无解”。本报告不评判第四章算法优劣。
