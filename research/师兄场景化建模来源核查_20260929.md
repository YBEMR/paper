# 师兄场景化建模来源核查

日期：2026-09-29。对象为仓库根目录的[师兄论文](../main.pdf)，不是 `research/latex/main.pdf`。本次仅作定向溯源，不改变研究对象或恢复跨场景方向。

## 1. 结论与直接引用证据

当前本地版本绪论§1.2、正文第4页明确将文献[18] Kim与Ha、[21] Spieck等列为场景化离线优化的方法参考。最接近“激活应用组合＋跨场景静态部署＋场景内调频”的是Kim论文，这有全文依据。

引用可以确认论文声明的方法参考；不能据此还原作者实际构思过程、认定唯一来源或判断具体公式直接移植。师兄§3.2.1的场景定义没有紧邻来源标注，需结合绪论理解。

## 2. 与Kim全文的对应

Jangryul Kim、Soonhoi Ha，*Energy-Aware Scenario-Based Mapping of Deep Learning Applications Onto Heterogeneous Processors Under Real-Time Constraints*。IEEE Transactions on Computers，72(6)，1666–1680，2023（2022年在线发表）。

[IEEE入口](https://ieeexplore.ieee.org/document/9935258/)；[DOI](https://doi.org/10.1109/TC.2022.3218991)；[本地全文](../papers/2023_Kim_Energy_Aware_Mapping.pdf)。

| 结构 | Kim全文定位 | 师兄对应内容 |
|---|---|---|
| 场景由运行应用组合区分 | §4.1、§4.2，p.1670，巡逻机器人四向摄像头对应检测应用，状态包含不同激活应用集合 | §3.2.1，pp.19–20，按激活应用集合区分稳定场景 |
| 场景／条件影响期限 | §4.1，机器人速度提高时检测期限收紧 | 不同场景可关联不同期限 |
| 静态映射跨场景保留 | §1，p.1667，引擎加载耗时限制迁移，要求映射驻留于全部场景 | §3.5.1的映射变量不带场景下标 |
| 按场景配置频率 | §1，p.1667及§4.3，p.1671，输出静态映射与各场景、各期限条件下的频率 | 场景内频率及时间安排 |
| 多场景能量评价 | §4.3及§5.2.3，pp.1671、1674，以场景平均能量为目标，并说明有概率信息时可调整计算 | 关联场景权重，以概率或时间占比评价 |

Kim的实验采用等驻留时间／场景平均，不能说其已完整实现师兄全部权重处理。Kim的具体方法为分阶段映射探索、可调度性分析及调频；周期应用、平台/SDK规则也与师兄模型未必相同。因此只能确认重要结构有前例，不能说两者完整模型、约束和算法相同。

## 3. Spieck及更早沿革

师兄[21]：Spieck、Wildermann、Teich，*A Scenario-Based DVFS-Aware Hybrid Application Mapping Methodology for MPSoCs*，ACM TODAES，2024，[DOI](https://doi.org/10.1145/3660633)。[FAU机构记录](https://cris.fau.de/publications/320897331/?lang=en_GB)确认题名、作者、年份与期刊。本次ACM全文访问失败，不能将其认定为某一具体公式或共享映射约束的直接来源；不据摘要判断其方法遗漏。已有Kim全文足以支持当前来源判断，无需把下载该文作为回答前置条件。

Kim §2.1（p.1668）还明确引用：

- [15] Gheorghita等，*System-scenario-based design of dynamic embedded systems*，ACM TODAES，14(1)，Article 3，pp.1–45，2009。[DOI](https://doi.org/10.1145/1455229.1455232)；[TU/e机构摘要](https://research.tue.nl/en/publications/system-scenario-based-design-of-dynamic-embedded-systems-2/)。摘要说明按代价相似性组织系统场景，在设计时优化、运行时预测和切换，并进行校准。本次未独立阅读全文，不称其为历史上最早工作。
- [16] Schor等，*Scenario-Based Design Flow for Mapping Streaming Applications onto On-Chip Many-Core Systems*，CASES 2012，pp.71–80。[DOI](https://doi.org/10.1145/2380403.2380422)；[ETH机构记录](https://www.research-collection.ethz.ch/entities/publication/7d3886f5-dee0-4806-8b57-758bc278c48a)。元数据由机构记录核对；Kim正文将其描述为有限状态机场景与驻留映射探索，并指出自己的有限场景框架与该文相近。本次未独立阅读全文，技术描述限于Kim的转述。

已核实引用关系：Gheorghita、Schor分别被Kim引用，Kim被师兄引用；Spieck另被师兄直接引用。未核实前两篇之间或Spieck与Kim之间的引用，不强行串为单一路线。

## 4. 对当前写作的含义

场景化、跨场景静态映射和场景内调频已有前例。师兄的进一步贡献应针对具体统一模型与求解处理评价，不能仅因有“场景”就判断创新更充分。

我们是否引入场景取决于是否研究跨场景共享决策，不取决于第三章是否需要与第二章形式不同。第二章解释DAG/Stage通用概念，第三章规定本题请求、到达、期限、合法模式和决策即可。本次不改变当前主线。
