## 2. 三种方法及待批准预算

固定串行顺序：whole → HEFT → SA101；各用一个新Python进程，whole另起一个新MATLAB worker，确认清理后才进入下一项。三者信息与安全标准相同，独立初始化沿用各自原规则。

| 方法 | 冻结调用及限制 | 方法根预算 |
|---|---|---:|
| whole MILP | `formal_milp.execute_formal_milp`，conditional反馈；期限预过滤、期限必零、单位OPP聚合、辅助整数连续化、能量下界开启，累计前驱切面关闭；无固定部署或邻域 | 1次×300秒 |
| HEFT适配版 | `execute_heuristic(method='heft', seed=None, allow_auto_low=True)`；沿原构造及下降过程 | 1次×300秒 |
| SA适配版 | 同入口，`method='sa', seed=101, allow_auto_low=True`；原HEFT构造/HML及随机重启 | 1次×300秒 |

whole保留原最多3份初始化模板和50轮反馈上限；**1次方法调用可能包含多个原生求解请求，但全部共用原300秒截止，不因反馈重置。** MATLAB使用原R2023b、`CutMaxIterations=10`、绝对/相对gap=0、约束容差1e-9、整数容差1e-6、两类预处理none；MaxTime仅由根剩余预算派生，不添加调参或增广数值版本。

whole在自己的loader内计费计算独立L0；HEFT/SA在各自原生命周期内计费计算，公共loader不能重复算或免费提供。任何缓存和候选不得跨方法继承。whole必须先得到可数值接纳的`SAFE_POINT_READY`才进入原生整数求解；保留这一现存限制，不为本次接入临时改算法。

**预算提案：3次方法调用、合计最多900方法秒；每份正常有效的最终完整SAFE最多1次60秒独立事后复核，最多3次/180秒；整批日历上限1800秒。** 每个方法Python进程从启动到退出另有480秒监督上限，包含启动/导入/清理/归档，不额外赋予搜索时间。启动门、序列准备和事后复核均受整批上限约束。未获SAFE不安排post，剩余额度不转给其他方法；不重跑、不补时、不替换输入。

独立post仅用同一输入、最终候选和原完整评价器重查，不能修复或择优。其60秒从监督器启动新的post Python进程前计起，包括启动、导入、输入核对及完整评价；超时不另补算。若证明非法/不安全或出现技术故障，保存证据并停止后续项；仅预算内未完成则记录post未决，原方法结果与独立复核状态分别保留。post不计为方法搜索结果，也不用于首次SAFE计时。

## 3. 计时与内存范围

| 量 | 起止/来源 | 说明 |
|---|---|---|
| `ST_method` | 原`MethodBudget`输入loader前 → 搜索证据截止 | 含读取/核输入、L0、初始化、构模、MATLAB启动、导出、原生求解、内部候选合法性/完整热评价及反馈；上限300秒 |
| `ST_process` | 监督器启动新Python前 → 进程退出 | 含解释器和模块导入、方法、清理和归档；不能把它与`ST_method`混称一个数 |
| `cleanup/archive` | 原时钟和外层进程记录分别提取 | 只能清理或保存既有证据，不再搜索/评价/接纳晚到解 |
| 初始化时间 | `initial_schedule_construction`、`initial_continuous_evaluation`、x0补全及接纳 | whole初始SAFE与原生求解产生的SAFE分列 |
| 构模/导出 | `BuildObserver`、预算phase、`model_complete/matrix_complete` | 留阶段耗时、事件/变量/整数/行/非零，部分构模只标部分计数 |
| MATLAB/原生求解 | `startup_wall_seconds`、入口事件、原生`phase_seconds.intlinprog_call`及exitflag/output | `solver_started`旧字段仅指worker ready，实际整数入口看`integer_solver_entered`；无回执时原生耗时/界可为未知 |
| Python内存 | 构模观察器当前/生命周期峰值RSS，及监督器按PID每1秒采样 | 新Python进程使lifetime范围清楚；不称分配增量 |
| MATLAB及进程树 | 新增监督侧按PID同次采样，记录MATLAB、Python和同次RSS之和的采样峰值 | 不把各进程不同时间的lifetime峰值相加；采样可能漏短峰，RSS之和可能重复计共享页；缺测须明确标记 |

现方法入口默认在模块导入后建立根时钟，本方案保留原时间定义，另列完整进程墙钟。MATLAB启动始终在方法根时钟内。不能只报告`intlinprog`时间作为ST，也不能把解释器导入外置后仍声称300秒包含进程全部成本。

实际启动前复用原资源门：物理可用≥2GiB、系统可提交余量≥4GiB、磁盘可用≥2GiB、无遗留MATLAB、非AppContainer。门失败时0调用停止，不临时退为1场景或降低标准。门通过不等于内存峰值已保证。

## 4. 成功与失败怎样留下回执

所有方法保存共同输入hash、独立初始化来源、首候选/首合法/首完整SAFE时间、最终候选与完整电热评价。whole另外记录初解、x0接纳、原生入口及回调/返回候选，区分重复初解、不同但未改善候选、严格改善SAFE。求解器界/状态只如实保存，不自动当独立最优或无解证书。

统一回执保留三个维度：运行终态`execution_status`、停止阶段`stop_stage`、完整安全结果及其来源。另列输入/源码身份、候选与安全时间、模型是否完整、原生是否进入、方法/进程/post耗时和内存字段；没有数据填未知而非0。有SAFE同时故障时，安全见证与故障状态同时保存。原始`result.json`、构模JSONL、MATLAB请求/回调及stdout/stderr不以汇总表替代。未启动项单列NOT_RUN，不生成虚假的失败方法回执。

| 现象 | 必须记录及解释 | 是否继续下一方法 |
|---|---|---|
| 输入或源码漂移 | 调用前拒绝；不修改数据迁就入口 | 停止，0新增调用 |
| 构模预算截止 | `model_complete=False`、构模阶段和部分计数；未进入原生求解 | 正常截止可继续 |
| 构模内存/接口故障 | 原始异常、资源采样和部分模型；不是正常求解超时 | 停止 |
| 初始化未取得SAFE | `NO_SAFE_INITIAL_WITNESS`或对应未决原因；不称原问题无解 | 正常结束/截止可继续 |
| 已有SAFE但x0补全或接纳失败 | 保留完整SAFE，注明原生未进入；确有数值拒绝仍单列数值异常 | 数值/技术异常停止 |
| 原生真实预算截止、无SAFE | 保留原生入口、截止原因及未决；不称技术故障或问题无解 | 正常截止可继续 |
| 已有SAFE、最后候选未完成复核 | 保留原300秒内完整SAFE与U，最后请求未决；不接纳晚到SAFE | 正常截止可继续 |
| 有SAFE同时技术故障/数值冲突 | 既有见证保留，运行仍标故障/异常，不能改称正常完成 | 停止 |
| MATLAB清理未确认、日历上限到达 | 保存证据及剩余NOT_RUN，不复用worker或补跑 | 停止 |

三方法得到同一安排、未改善、无SAFE或正常超时均允许出现。验收逐项回答：读入成功了吗、独立候选形成了吗、全场景SAFE了吗、whole实际进入原生求解了吗、成本测到了吗。**不把三个方法全部SAFE或whole更节能设成接入成功的必要条件。** 某阶段没有实际经过，标“未验证”，不靠其他样本或模拟补称已实际通过。
