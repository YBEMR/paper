## 3. 确定性规则建议稿

### 3.1 将V1的负载描述补成唯一公式

V1尚未指定“最高频点负载”如何跨设备聚合。建议使用以下版本供确认，而非将其冒称原协议已确定：令完整族场景权重为输入给定的\(w_s>0\)，且\(\sum_s w_s=1\)；\(O_{s,\tau}\)为场景s中共享身份τ的所有执行副本。

\[
\ell_\tau=\sum_s w_s\sum_{j\in O_{s,\tau}}
                 \min_{u\in\mathcal U_\tau}d^H_{j,u}.
\]

它表示按场景权重计入的最快合法H时长，不是最优安排。按\((-\ell_\tau,\tau\mathrm{ID})\)排序。场景权重由生成合同给出，参考器不暗设均匀权重。

```text
L[s,u] = 0                         # 各场景、各单元分别记账
for τ in sort_by(-load_score, shared_stage_id):
    for u in sorted(U[τ]):
        trial = copy(L)
        for s in full_family:
            trial[s,u] += sum(d_H[j,u] for j in occurrences[s,τ])
        cost[u] = (max(trial[s,v] for all s,v),
                   sum(w[s] * sum(trial[s,v] for v) for s), u)
    chosen = lexicographic_argmin(cost)
    mapping[τ] = chosen
    L = corresponding_trial(chosen)
```

主代价取全部场景和设备的最大负载；次代价取场景加权设备总负载。所有场景分别累计，未把互斥场景当作同时运行。ID用规范化字符串的固定字典序，数值使用精确有理数。完整族映射及其来源hash固定后，S1子集只取对应场景；子集权重的重新归一化不能反向改变参考映射。

### 3.2 最早合法空档

每个场景分别处理：源点拓扑层级为0，其余为前驱最大层级加1。每次从前驱已安排的Stage中，按`(请求释放时刻, 拓扑层级, 请求ID, Stage实例ID)`取最小者。

```text
earliest = max(0, release[j], finish[p] for p in predecessors[j])
t = ceil_to_grid(earliest, 5 ms)
duration = original_response(j, mapping[shared_id[j]], chosen_opp)
for occupied interval [a,b) of that unit, ordered by start:
    if t + duration <= a: break
    if t < b and a < t + duration: t = ceil_to_grid(b, 5 ms)
place j at [t, t+duration)
```

允许插入已有空档，不只是排到设备尾部。一次参考构造中，每个频率域的所有活动采用同一档位，因此CPU并发自动具有共同档位；独立检查仍必须拒绝人为构造的异档重叠。全域空闲按auto-L，零切换开销沿用原模型。

有限DAG、正且有限时长、非空合法设备域、无预设截止上限时，该规则可以逐个放置：即使没有更早空档，已有有限占用区间之后仍有合法网格起点。超时或实现失败记为未完成，不能记为任务不可行。不同频档可能改变空档插入和资源次序，**不能额外假设每个请求必有\(F^H\le F^M\le F^L\)**；阈值按各份实际时间表计算。

### 3.3 期限、派生与辅助下界

基础期限仍为\(D_r=a_r+\beta(F_r^H-a_r)\)。只有生成该期限的基础H表在\(\beta\ge1\)时具有时间准时保证。S4换拓扑、S5增负载、S7增请求继承期限后，不继承这个保证，也不能据此报参考器错误。

派生记录保存基础相对期限\(b_r=D_r^{\rm base}-a_r^{\rm base}\)。对已有请求原样复制绝对期限；对获准的新请求，由预声明的来源请求和释放规则确定\(D_{\rm new}=a_{\rm new}+b_r\)。这条S7规则是**建议**，新增请求释放时刻尚待确认。派生条件的通过判定直接用继承期限减实际完成时刻，不用派生H完成时刻再次生成期限。

辅助下界不调用优化器：

- 逐请求：用各节点最快合法时长计算关键路径下界，与该请求\(F_r^H-a_r\)比较；忽略资源竞争和外部依赖只会使其更乐观。
- 全场景：枚举四设备的15个非空子集\(V\)，对只能映射到V的执行实例累加最快时长后除以\(|V|\)，取最大值。这里计执行副本，不能只计共享身份。
- 将上述容量时长下界加场景最早释放时刻，与各请求“释放＋关键路径”下界取最大，才可和场景\(C_{\max}^H\)比较。忽略共享频率及热限制，故仍为乐观界。
- 可另报固定参考映射下的设备负载界以定位等待；该界**只约束这个映射**，不能作为全局最优下界。

这些界只帮助解释参考器是否保守，不用于生成期限或证明热可行。首版不增加更强下界求解。

## 4. 首个实现阶段的测试与停止点

授权后建议仅使用人工、非随机小夹具，验证以下八类性质；尚未执行，不能称测试已通过。

1. 兼容域交集、缺档、重复ID、缺失节点、非法依赖与环分别被识别。
2. 乱序输入不改变映射和时间表；各场景分别计负载；副本计数正确。
3. 一般分支汇合、多请求释放、跨场景共享具体单元正确；S1嵌套只取子集。
4. 超过400 ms的任务仍能构造；非网格结束时刻、空档插入及首尾相接正确。
5. CPU同档并发通过、异档并发及同设备重叠被独立拒绝；auto-L身份明确。
6. H/M/L只变OPP，响应参数和映射不变；期限/阈值/逐请求余量一致。
7. S3/S4/S5/S6/S7的期限继承不得误调用基础期限生成；S4三种拓扑共用预声明基准的期限及来源身份，不继承基础H表的准时保证；S2增加真实节点与工作量，S7只复制请求，计数分别保存。
8. 构造与检查相互独立；禁止进入MILP、HEFT、SA、功率段重建、热积分及正式输入导出。未来端到端衔接再由原正式安全门检查。

完成标准是“接口与这些性质有可复跑测试”，不是“24族校准通过”。保留旧初解器、旧输入及历史结果不动；首阶段不适配正式算法的随机任务入口。
