## 1. 实现是否符合协议

| 协议要求 | 实际实现 |
|---|---|
| 唯一共享映射 | 对同一Stage全部出现位置求合法设备交集；按§3.1加权最快H负载排序，候选按最大场景设备负载、加权总负载、单元ID决胜；副本计入各自场景 |
| H/M/L参考时间表 | 同一映射、同一响应参数，仅改变频档；按释放、拓扑层级、请求ID、Stage ID选取ready任务，插入最早合法空档；5 ms起点、精确结束时刻、无400 ms截断 |
| 独立时间检查 | 独立重算响应时长和结束时刻，再检查完整覆盖、共享部署、释放、网格、依赖、设备独占及CPU同域频率；不调用构造器或其时长函数 |
| 期限和诊断 | 显式β及基准拓扑ID；由基础H完成时刻计算期限，M/L阈值与逐请求余量均保存；不自动选择β |
| 继承与身份 | S1取完整族已有表，不重排；S3/S4/S5/S6/S7/E2显式继承来源；S7新释放不设默认，原请求期限和释放不变；禁止借继承删除旧请求 |
| 保留旧系统 | 独立新目录，无旧求解器/热模块依赖；181份原顶层Python源及配置运行前后hash一致，原实验目录无本轮改动 |

辅助时间下界也已实现：逐请求关键路径、四设备15个子集的乐观容量界，和明确标为“仅固定参考映射”的负载界。它们不调用优化器，也不用于生成期限或宣称热安全。

## 3. 尚不支持什么

本次实现只接收**显式时间合同**。它不生成24个随机校准族或50个正式族，不提供正式S2/S3/S4/S5/S7随机变换器，不导出MILP输入，也不代替原完整安全评价。期限继承检查不等于证明任意任务变换保持全部物理含义。

H参考准时保证只适用于用该H表生成期限的基础输入。改拓扑、加负载、增加请求后沿用期限，可能超期；低频参考通过也只说明该固定参考时间表准时。任何输出均没有SAFE、能耗上界或最优性证明。

## 4. 进入随机校准前需要确定

1. **任务与画像：** 工作量分布、设备合法组合、参考时长/α/功率的生成关系；S2节点计数与S7执行副本分开。
2. **场景与结构：** 完整场景族的应用组合、共享Stage身份及权重；S4基准拓扑和随机边规则；S3细分与画像守恒规则。
3. **服务与计量：** S7新增请求释放及相对期限来源；E2参考资源条件；新规模共同评价窗口。
4. **校准执行：** 24根的覆盖表、与正式50根隔离的种子、派生清单、实际参考构造数和时间上限；“明显余量”数值口径及分组预警处理。

建议下一项集中形成上述**一份候选生成配置与覆盖表**供审阅，再申请独立时间校准执行。当前实现已完成并停止，未启动校准、正式对照或任何暂停中的研究调用。
