# 第三章随机任务期限独立校准协议 V1（2026-10-28）

> **状态：候选科学协议，尚未数值校准、尚未最终参数冻结。**  
> **授权边界：本文件仅供第三章实验设计与后续 Work 实现审查参考。本次提交不授权修改求解代码、生成正式任务、运行校准或实验，不涉及第四章。**

## 1. 目的与适用范围

在正式生成第三章主要实验点的50个独立随机任务族之前，用**独立校准任务**检查期限生成方法是否满足：

1. 能处理多场景共享部署、一般DAG、多请求、设备兼容性、CPU共享DVFS与合法启动网格；
2. 不因期限生成方式使不同规模和结构的任务**普遍过松或过紧**；
3. 对同一任务条件，完整MILP、HEFT、SA、联动局部MILP及专项对照均使用**完全相同的已冻结期限**。

校准只用于选择**任务生成规则和期限难度**，不是评价上述正式算法的优劣，也不是为某个算法取得预期SAFE率而调参。

## 2. 固定模型与既有证据

- 沿用第三章现有四执行单元：CPU1、CPU2、GPU0、NPU0；四节点耦合RC；CPU1/CPU2共享频率域；空闲立即降至最低OPP（auto-L）。
- Stage不得抢占、迁移或在执行中切换OPP；同一固定Stage身份跨场景及请求副本绑定同一**具体执行单元**，各场景的时序独立。
- 参考执行时长沿用当前模型：
  
  \[
  d_{i,u,k}=d^{\mathrm{ref}}_{i,u}\left[(1-\alpha_{i,u})+
  \alpha_{i,u}\frac{f_u^{\mathrm{ref}}}{f_{u,k}}\right].
  \]
  
  新合成Stage可由抽象工作量与设备画像生成参考时长，但不得另造与正文不一致的DVFS响应机制。
- 参考调度只用于**时间期限生成**；其时间合法不保证连续热安全。正式SAFE仍须完整独立合法性与连续热评价。
- 原R1—R5、E4a、P0/P1/P2及历史400 ms窗口不自动构成新随机任务的期限校准结果。旧两节点热反馈研究不属于本协议的期限证明。

## 3. 唯一参考调度规则（候选定义）

**不引入另一套性能基线。** 期限参考器只执行一次确定性映射，并据此生成H/M/L三个固定工作点时序。对于同一任务族及参数，固定输入排序与平局规则，输出完全可复现。

### 3.1 跨场景固定映射

1. 对每个固定Stage身份 \(\tau\)，取其全部出现位置可用具体执行单元的交集 \(\mathcal U_\tau\)。交集为空属于输入合同错误，不能通过私自放宽共享部署修复。
2. 对完整预生成场景族（S1最多8场景）统一映射一次。按Stage的参考最高频点负载由大到小排序，平局按固定Stage ID排序。
3. 依次选择合法单元。候选单元的代价优先取**各场景预计设备负载的最大值**，其次取各场景加权总负载；再按单元ID破同分。场景负载按该场景中各请求实际出现的Stage计数，不把互斥场景当作同一时间的并发任务。
4. 对完整场景族得到的映射固定不变；S1的1/2/4/6/8场景嵌套子集沿用这份映射，已有场景期限不得随新增场景重新计算。

这一映射是**透明、确定性的负载平衡参考**，并非全局最优映射，不参与正式性能排名。其具体排序与代价计算的机器可执行伪代码应在实施前写入冻结配置；不得根据正式算法结果改动。

### 3.2 高／中／低工作点时序

1. 对同一映射分别采用各控制域的最高（H）、中间（M）、最低（L）合法OPP。当前平台具有L/M/H三档；若将来某Stage没有指定档位，必须事先定义合法替代或将该输入判为合同不符，不得运行时任意选择。
2. 按请求释放时刻、DAG拓扑层级、请求ID、Stage ID组成的固定优先顺序，逐步处理前驱已安排的Stage；每次安排到满足释放、依赖、设备独占、CPU同域工作点及启动网格约束的**最早合法起点**。采用同一确定性平局顺序，不使用HEFT向上排序权重或结果导向的能耗搜索。
3. 所有参考调度采用同一共享映射，不因M/L档较慢而重新选设备。活动期固定相应OPP，完全空闲期遵守auto-L。
4. 参考器不预设原400 ms截止窗口；先在可扩展时间轴形成完整时间表，再据此生成期限和评价窗口。
5. 参考器必须由独立合法性检查确认完整调度合规。若参考构造未完成或违反约束，记录为**参考器失败**，不能直接将其解释为任务数学不可行。

六Stage**可以**构造分支汇合DAG；若每场景固定两应用且每应用仅3 Stage、禁止跨应用依赖，则单个应用不能构成典型四节点菱形。S4若需要该结构，需事先选择合法Stage分配（如4+2），且三种拓扑对照使用同一Stage分配。

## 4. 期限数学定义与β诊断

对于请求 \(r\)，设释放时刻为 \(a_r\)，H/M/L参考调度中完成时刻分别为 \(F_r^H,F_r^M,F_r^L\)。基础输入的候选绝对期限为：

\[
\boxed{D_r(\beta)=a_r+\beta(F_r^H-a_r)}
\]

- **候选β：1.0、1.3、1.6、2.0；优先检查1.3。** 此优先级不是已通过校准的结论。
- H参考必须满足 \(F_r^H>a_r\)；若违反，按输入或参考器错误处理。
- 在**生成期限的同一基础输入**下，β≥1时H参考调度满足时间期限，但不保证连续热安全、实际算法SAFE或扩展条件下可行。
- M/L参考调度各构造一次，即可计算全部β候选的时间可行性，无需针对每个β重复运行参考器：

\[
\beta_M^{\mathrm{req}}=\max_r\frac{F_r^M-a_r}{F_r^H-a_r},
\qquad
\beta_L^{\mathrm{req}}=\max_r\frac{F_r^L-a_r}{F_r^H-a_r}.
\]

某候选β不低于上述阈值时，对应的**这份固定M/L参考调度**满足全部请求时间期限；这不证明其他M/L时序均可行或不可行。另需保存逐请求余量，不能只留全场景最大比值。

辅助计算：DAG关键路径时间下界、按异构设备容量构造的乐观下界，以及参考完成时间相对下界的差距。**下界不等于可行调度，也不能直接用作期限。**

E2资源掩码对照必须使用同一绝对期限。CPU-only共同兼容任务可采用事前声明的CPU兼容参考条件生成期限，但不能在不同资源组合内分别计算期限；这种E2专项合同与全异构规模合同须分别标识，不能错误复用运行记录。

## 6. 独立校准任务与覆盖

- **候选规模：24个独立校准根任务族**；另有正式主要实验点50个独立任务族，二者种子池和派生ID完全隔离。
- 校准覆盖代表性S2规模6/24/96 Stage，三种DAG，2/8场景，1/2请求，CPU共同兼容及一般异构设备画像。
- 在对应基础任务上配对考察S5的1.0与1.25倍；这些压力派生仅诊断期限变化后的难度，**不得重新生成期限**。
- 不要求所有因素完全笛卡尔积；但校准前须冻结一份覆盖表，保证各主因素及关键边界均出现。24是**独立根种子数**，不是参考调度调用次数，也不能把同一根种子的派生视为新的独立样本。
- 校准可记录初温热安全诊断，但不得依据高初温超温来直接放宽时间期限。连续热评价与时间期限诊断分开报告。
- 全部配置、种子、派生ID、输入哈希、生成器版本及参考器版本应随结果保存，正式任务不能根据后续方法表现重采样。

## 7. 校准记录和验收

每份校准输入应至少记录：

1. 任务族/派生ID、场景数、每场景Stage数、固定Stage数、执行实例数、DAG边数/关键路径、请求释放、设备合法域；
2. H/M/L参考调度的完整性、独立合法性、固定部署、各请求完成时间及时间表身份；
3. \(\beta_M^{\mathrm{req}}\)、\(\beta_L^{\mathrm{req}}\)，各β下的逐请求截止余量和全场景满足率；
4. 关键路径/资源容量下界与H参考完成时间的差距，按规模、拓扑及请求分组的分布；
5. 输入合同错误、参考器失败、仅时间未通过、热安全不满足、数值未决等**不同状态**。

**硬性门槛：** 所有进入期限统计的有效校准输入均须得到独立验证的合法H参考调度；任何未解释的共享映射、DAG、资源占用、释放或共享频率域错误，均应停止冻结并修正。输入合同错误或参考器失败不能默默从分母删除。

**宽松预警，而非数学定理：**
- 基础校准任务中，M参考满足全部请求期限的比例若低于10%，提示期限可能过紧；
- L参考在超过90%的基础任务中满足期限且仍有明显余量，提示期限可能过松；
- 对6/24/96 Stage、不同拓扑和请求组分别检查，不能用总体均值掩盖某一组明显失衡；
- 如果H参考完成时间远离乐观下界，须核查参考映射或排序是否过于保守，不能只靠调整β解决；
- 以上10%/90%是**事先候选筛查线**，不是统计显著性阈值，也不是保证所有方法均有SAFE的要求。“明显余量”的定量口径须在校准实际运行前确定并记录。

**β选择流程：** 首先评估1.3；出现过紧预警时按1.6、2.0检查，过松时检查1.0。如果不同规模的诊断相互矛盾或所有候选均明显失衡，输出问题清单并停止自动冻结，不允许按某算法的成功率、能耗或输赢反向调β。通过独立校准并经人工确认后，才冻结用于正式测试的共同β与期限规则。

## 8. 校准通过后才能冻结的项目

- 生成器工作量分布与Stage设备画像、DAG结构控制、场景应用组合及请求释放规则；
- 参考映射/列表调度的确定性伪代码及边界处理；
- 校准覆盖矩阵、种子与正式集隔离规则；
- β及其过松/过紧诊断口径、参考期限和评价窗口生成规则；
- 对所有正式方法一致的期限、SAFE和能耗评价合同。

S3特别需要检查5 ms启动网格对短子Stage的额外等待；不得只改变细分组的启动精度。正式新规模任务的评价窗口须在算法运行前按期限和声明热评价范围确定，不能机械沿用400 ms，也不得因算法超时而调整。
