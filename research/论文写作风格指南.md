# 论文写作风格指南

更新：2026-09-30。适用于本项目论文正文的撰写、润色和叙述审查；普通研究记录、实验日志、代码任务不强制套用。正文仍以 `research/latex/` 中的 LaTeX 文件为唯一主版本，本指南中的短示范不另行维护为正文。

本指南依据 [main.pdf](../main.pdf) 与[《草稿》](../草稿.pdf)的代表段落提炼，并以用户修改后的[第三章3.1—3.2](latex/chapter03.tex:5)为本项目正面范例。学习重点是让读者沿着“为什么需要—如何定义—怎样使用”理解研究，不追求复刻作者原句。两份参考是外部论文，不据此声称已识别用户个人的完整写作风格。

## 1．写作时先遵守的规则

1. **先交代需要，再引入术语。** 读者应先知道正在解决什么问题，再遇到新概念、变量和缩写。已有定义可直接使用，不必每次重讲背景。
2. **让每段承担一个主要任务。** 定义、解释、推导和结果分析可以前后衔接，不要在同一段频繁切换到程序检查、研究历史和防误读说明。
3. **先讲清实际要求，再引入变量和表达式。** 新变量的对象、取值和含义就近说明，使公式成为文字关系的自然结果。必要解释放在读者需要的位置；前文已经讲清时，公式后可以直接结束，只在还有未尽含义、推导或用途时继续解释，不机械复述公式。
4. **用具体主语和动词组织句子。** 明确是调度器选择模式、执行单元释放资源，还是热检查器发现违规，少用多层抽象名词替代动作。
5. **必要假设就近保留一次。** 使结论成立的条件不能后移到读者已据此推理之后；重复边界和实现注意事项可集中放置。
6. **同一概念使用同一名称。** 不为避免重复而混用配置、模式、映射、安排，也不把请求、模型调用与Stage当作同义词。
7. **观察、解释和证明分开写。** 数值变化是观察；原因可能需要对照；最优或不可行需要相应证明。表达流畅不改变证据等级。
8. **先改信息顺序，再改措辞。** 不机械规定句长、段落数和连接词频次，也不把所有段落套成相同结构。

正文按读者理解所需的顺序展开。研究汇报“先给结论”的习惯，不等于正文必须先抛出尚未定义的定理、变量或方法缩写。

## 3．把规则落实到用词与段落

### 3.1 用词应指出对象、动作和条件

| 常见障碍 | 推荐处理 | 示例（表达示意，不新增技术结论） |
|---|---|---|
| 多层名词连缀 | 找出谁执行什么动作 | “完成热可行性评价结果的反馈利用” → “将热检查发现的违规条件反馈给求解器” |
| “这个、上述、其”指代跨越多个对象 | 重复必要术语 | “其仍可能失效” → “该候选仍可能违反温度上限” |
| “显著、有效、全面”等没有指标 | 写明变化对象和条件 | 用“在所测五个条件中减少求解轮次”，不笼统写“显著提高效率” |
| 为避免重复而换概念名称 | 保持术语稳定 | 配置是模式组合，安排还包含启动时刻；不交替使用 |
| 连续使用“需要指出、值得注意、事实上” | 直接给出必要内容 | “安全结论覆盖评价窗口”即可，不再加一层提示 |
| 把档案用语当论文术语 | 正文先表达研究含义，追踪信息另记 | 正文写“预先确定的抽象仿真参数”；L3等级及冻结文件号在来源说明中解释 |

“设”引入对象或假设；“记”约定符号；“其中／式中”解释刚出现的量；“因此／由此”连接可推出的结论；“为此”连接已说明的问题与后续动作。它们不是每段必备的起句。

技术术语可以准确重复。证据不足时，“可能”“在本组条件下”“与该解释一致”有明确用途；它们不能替代缺失的论证，也不能把已证明的结论写得含糊。

### 3.2 不同内容采用不同展开方式

| 段落任务 | 推荐顺序 | 读完应能回答 |
|---|---|---|
| 概念与变量 | 实际需要 → 概念 → 符号／取值 → 用途 | 为什么引入它，哪些是输入、哪些由优化决定？ |
| 公式与约束 | 实际要求与关系 → 必要变量及条件 → 表达式；有未尽含义时再解释 | 式子对应什么要求，限制了什么选择？ |
| 方法 | 具体困难 → 设计理由 → 输入、处理与输出 → 保证边界 | 这一步为什么存在，结果交给谁？ |
| 实验 | 验证问题及条件 → 观察结果 → 有依据的解释 → 适用范围 | 改善了哪个指标，证据不能支持什么？ |
| 节间衔接 | 前文已有结果 → 尚待解决的问题 → 本节任务 | 为什么现在需要读下一节？ |

这些是组织思路，不是逐段填空模板。几条公式共同表达一件事时，可统一解释；已有定义无需再次逐项翻译。公式前已经说明要求、变量和作用时，表达式可以成为该段的终点；公式后确有新推导或必要说明时，也不为追求短段落而删去。

例如，从功率模型转入温度模型，可先交代“总能量相同的安排仍可能有不同的功率分布，因而需要沿时间轴计算温度”。这比只写“下面介绍温度模型”更能说明两节的关系。

**约束段落：把一项要求讲完整。** 段落清晰取决于信息是否围绕同一要求递进，不取决于字数是否足够少。写作时逐项检查：

- 先说明任务或设备实际应怎样执行，再选择表达该要求的变量；不以抽象的“统一形式化表达”代替具体需要。
- 新变量出现时，及时说明它表示什么、取值怎样对应执行选择；已有符号直接使用，不集中重讲一串时长、功率等暂时用不到的量。
- 先讲选择或执行规则，让读者读到公式时能够理解为何是等式、不等式或互斥关系，而不是自行猜测公式意图。
- 当前约束说明完整后收束。任务分配段不提前展开执行时间、能量比较和求解性质，这些内容在各自承担任务的位置引入。
- 相邻段落沿实际决策递进，例如选定模式后才安排执行时刻。使用“为此”“因此”前，核实前后是否确有需要或推导关系。
- 使约束成立的假设就近保留；实现细节和重复的防误读说明集中放置，不让每段反复岔开。

### 3.3 技术内容放在承担相应任务的位置

- **主叙述：** 对象、关系、设计理由和主要结果。读者无需先了解研究过程中的报告编号。
- **定义与必要条件：** 紧邻所支撑的公式或结论。固定窗口、功率可加等若是推导前提，必须在使用前明确。
- **数学性质与证明：** 用相邻命题或专段承载，不在参数解释中突然展开另一条长证明。
- **实现与数值保证：** 容差、误差包络、预算停止和未决状态集中说明，并在依赖这些保证处引用。
- **来源与追踪：** 报告编号、输入哈希、路径和版本历史放研究记录或附录；正文保留理解结论所需的来源与范围。

**章节应在职责完成处收束。** 约束汇总为目标函数和完整优化问题后，读者接下来需要知道怎样求解，应自然进入方法部分。与当前推进无关的结构性质和长证明集中放在补充部分或实际使用的位置，不在完整问题之后重新铺开一组集合与命题。方法本身依赖的定义、假设和关键依据仍须在使用前交代。

分层不等于删除限制。尤其不能将“求解器报告无解”润色成“已证不可行”，或将“已取得安全安排”改成“已得到最优解”。

## 4．写作示范

4.1—4.3中的“原段落”为2026-09-29读取的第三章节选，省去LaTeX排版命令；4.4依据2026-09-30讨论的师兄论文段落拆解叙述方式。所有改写只演示信息组织，公式、数据和适用条件沿用各自模型，不据示范修改正文。公式交叉引用在实际采用时仍应使用原 `\label`／`\eqref`，不能手工硬编节号。

### 4.1 模型说明：先说明功率计量，再解释系统能耗

来源：[3.3.1“运行状态与系统能耗”](latex/chapter03.tex:121)。原段落是两个相关解释段，中间的能耗公式在下方保留；符号定义沿用该节上下文。

**原段落**

> CPU活动增量按所有运行Stage求和，聚合空闲项只计一次。即使某方案不使用NPU，其空闲功率仍计入窗口。\(Q_i\)是相对于共同基准的活动增量，不能直接用未扣除公共部分的整机功率代替；只在任务活动期间出现的固定开销属于\(Q_i\)，不属于全窗口基准。
>
> 固定配置下，各Stage活动能量和窗口基准能量均固定。等待与重排改变功率出现的时刻，但不改变其积分。这一性质同时依赖固定窗口、恒定基准、固定模式响应和零额外开销，不意味着等待一定可行或一定降温。

**改写示范**

系统功率由持续存在的基准功率和正在执行的Stage所增加的活动功率组成。设\(p_C^0\)为全部CPU单元的聚合空闲功率，\(p_N^0\)为NPU空闲功率，\(P_{\rm ext}\)为热边界外的恒定公共功率。CPU并发执行时，各Stage的活动增量相加，聚合空闲功率仍只计一次；NPU即使没有执行任务，其空闲功率也计入评价窗口。这里，\(Q_i\)只包含相对于共同基准增加的部分，任务活动期间才出现的固定开销也归入该项。因此，采用整机功率数据时，应先区分已计入基准的公共部分。以\(z_i(t)\)表示Stage的运行状态，节点注热与系统功率为

\[
\begin{aligned}
p_C(t)&=p_C^0+\sum_{i:u(m_i)\in\mathcal U_C}Q_i(m_i)z_i(t),\\
p_N(t)&=p_N^0+\sum_{i:u(m_i)=u_N}Q_i(m_i)z_i(t),\\
P_{\rm base}&=p_C^0+p_N^0+P_{\rm ext},\qquad
P_{\rm sys}(t)=p_C(t)+p_N(t)+P_{\rm ext}.
\end{aligned}
\]

在固定评价窗口、恒定基准功率、固定模式响应和零额外开销的条件下，每个Stage在窗口内执行一次。将系统功率在\([0,W]\)内积分，可得

\[
E(m,s)=\int_0^W P_{\rm sys}(t)\,\mathrm dt
=P_{\rm base}W+\sum_{i\in V}Q_i(m_i)d_i(m_i)
\equiv E(m).
\]

上式表明，配置确定后，基准能量和各Stage的活动能量均已确定。等待与重排只改变功率出现的时刻，不改变总能量；它们是否满足期限及温度约束，仍需结合完整时序判断，也不能由此推断延迟一定降温。

**调整理由：** 将“哪些功率计在哪里”放在公式之前，将能量不随时序改变的前提放在推导之前，读者可以顺着计量关系得到结论。最后保留等待的可行性与温度边界，没有削弱条件。两条公式与原文对应表达一致；公式后的解释属于第二个说明段的延续。

### 4.2 方法说明：先说明为什么要把违规信息反馈回去

来源：[3.6“完整候选的连续热检查”](latex/chapter03.tex:473)及[“固定时刻热约束的线性反馈”](latex/chapter03.tex:495)。下面两段为非连续节选；第一段本身已经顺畅，示范重点是与后续反馈理由衔接。

**原段落**

> 上述MILP只保证资源、依赖和期限合法，其候选仍可能超温。为判断候选是否能够实际采用，首先按被选选项恢复完整时间表，再按所有启动和结束事件生成节点功率轨迹。每个恒功率段使用式\eqref{eq:ch3-14}传播温度，检查端点与区间内导数为零的位置，直至评价窗口结束。即使起点只在网格上，热轨迹仍按连续时间评价。
>
> 完整赋值排除利用了连续热检查的判定结果，却没有充分利用违规原因。式\eqref{eq:no-good}只说明选项集合\(J^*\)不能同时出现；只要改变一个起点，新的组合就不再被该式排除，即使它仍在同一节点、同一时刻形成过高温度。为复用这一信息，本文将违规轨迹中的节点与时刻固定下来，把该处的温度上限转化为作用于全部选项的线性必要条件。这样既保留同一配置的全部热安全时序，也能限制不同配置中具有相同超温原因的安排。

**改写示范**

满足资源、依赖和期限要求的MILP候选仍可能超温，因此每个候选都需要接受完整热检查。检查器先根据选中的执行模式和启动时刻恢复时间表，再用全部启动、结束事件划分恒功率段，逐段传播温度并检查端点与内部驻点，直到评价窗口结束。这样，启动时刻虽然受网格限制，温度仍在连续时间上评价，任务完成后的空闲尾段也包含在内。

发现明确超温的候选后，仅排除当前完整赋值可以避免重复选择该安排，却无法限制只改变了一个起点、仍在相同位置超温的其他安排。为使后续求解利用这一信息，本文固定违规节点\(n\)及其时刻\(\bar t\)。记\(b_n(\bar t)\)为入口状态与空闲注热产生的基准温度，\(h_{no}(\bar t)\)为选项\(o\)在该位置的活动温升，\(y_o\)表示是否选择该选项。由固定入口状态、线性RC与可加功率下的响应叠加，该处的温度上限可写成全部选项共同满足的条件：

\[
\sum_{o\in\mathcal O}h_{no}(\bar t)y_o
\le T_n^{\max}-b_n(\bar t).
\]

由于全部热安全安排都必须满足这一必要条件，它可以限制具有相同温度违规的其他组合，同时保留同一配置的安全时序。有限个观察时刻仍不足以保证全过程安全，后续候选仍须接受完整连续热检查；实际约束的可靠系数和右端按后文误差界构造。

**调整理由：** 先说明候选为何要检查，再说明只删一条安排还遗漏了什么信息，在公式前交代各项含义，最后引出反馈约束。公式后的有效性、连续检查及数值保证说明包含必要的新信息，因此保留。公式保持原义，没有把必要条件改写成充分条件，也没有据此宣称求解一定加速。

### 4.3 实验分析：将结果、解释与范围分开

来源：[3.7“入口热压力下的求解表现”](latex/chapter03.tex:871)。原段落选取两处结果说明，二者之间的其他结果在正文中保留，不用本示范替代整小节。

**原段落**

> 两方法各32次调用中，NG取得26次预算内安全输出，TF取得30次，其中达到独立下界的次数分别为12和16。双方均有安全输出的26个配对，能量全部相同。低功率包在79.5和79.75°C下的四个条件，以及高功率包6 ms、79.5°C条件，两次重复均减少求解轮次并缩短墙钟；例如低功率、10 ms的两档高温条件均由12轮减至2轮。这五个条件的最终时间表在方法之间有所不同，表明相同能量可以对应不同安全安排，不能将能量相同写成配置或时序相同。
>
> 入口较低的结果限定了反馈收益的适用条件。78与79°C共8个条件，两种方法的首候选均安全，全部一轮结束且零反馈；16个配对中TF恰有8次较快、8次较慢，不能把这些时间差归因于未执行的热行。两档较高初温的8个条件首候选均违规；全部32个配对的首候选选项集合相同，因而轮次差并非由不同初始候选造成。两次顺序平衡重复支持当前观察的一致性，但不足以估计方差、置信区间或跨平台的稳定加速。

**比较条件保持不变：** NG为完整赋值排除，TF为固定时刻热行反馈。16个预定条件各运行两次，两次交换方法先后顺序；每次方法调用独立采用60 s总预算。任务、模式、1 ms启动网格、20 ms窗口、RC、求解容差及安全接纳规则相同，不共享候选或安全见证。以下示范沿用正文的抽象输入与有限网格范围。

**改写示范**

在每种方法的32次调用中，NG与TF分别取得26次和30次预算内安全输出，其中分别有12次和16次达到独立下界。双方均成功的26个配对所得能量相同，说明本组比较中观察到的差异在于预算内安全输出和求解过程，而非这些配对的能量降低。低功率包79.5与79.75°C下的四个条件，以及高功率包6 ms、79.5°C条件，在两次运行中均减少了求解轮次并缩短墙钟时间；其中，低功率包10 ms的两档高温条件均由12轮降至2轮。这五个条件下，两方法最终给出的时间表不同，说明相同能量仍可通过不同安全安排实现。

上述变化出现在热反馈被触发的条件下。78与79°C的8个条件中，首候选均安全，两方法都只求解一轮且未执行反馈；对应16个配对中，TF有8次较快、8次较慢，这些时间波动不能用于解释热行的作用。两档较高初温的8个条件中，首候选均违规；全部32个配对的首候选选项集合又完全相同，排除了初始候选不同这一解释。因此，现有观察支持本组热压力条件下反馈对求解过程的作用，但两次顺序平衡运行不足以估计方差、置信区间或认定跨平台稳定加速，结论仍限于本章抽象参数与有限网格。

**调整理由：** 先交代主要结果，再报告具体条件，随后用未触发反馈的结果限定解释。保留26／30、12／16、26个配对、五个条件、12→2、8快8慢等全部数字；没有把32次调用当作32个不同条件，也没有新增节能率、统计显著性或因果分解。正文中双方无输出、超时及仅求解器报告无解的段落必须继续保留。
